# WhatsApp 连接与同步迁移

基线 `b2a4db10`。依据用户提供的开发方案及二次评估报告实施；用户已明确公司专用业务号允许全部会话，包含群聊。请求范围是连接与消息同步；新增 AI 云供应商、翻译设备 actor 重构、真实账号关联与生产部署不包含在本地候选交付中。

## 执行与验收

1. Connector 使用锁定的 Baileys 7.0.0-rc14，移除新运行链路的浏览器依赖。每个业务账号保持原 account_uid；认证状态加密、事务化保存，包括 Signal key 删除。单主机 SQLite 存储上的租约与 fencing 拒绝过期写者；数据库不可复制为多个主机的协调器。多主机扩容需更换统一存储适配器。
2. 协议事件先持久化，标准消息和变更序号原子更新。方舟消费 sequence 游标而非消息时间；Baileys 默认每 5 秒、每号最多 500 个变更消费，旧 Provider 保留独立的分钟调度；同步在线程执行，不阻塞 API 事件循环。检查授权版本和接入代次，业务入库与游标在同一事务提交。实时、历史、重复、同秒、迟到、编辑、撤回均测试。未知类型保留占位；历史只声明平台已提供范围。轮询间隔不是已测得的端到端延迟保证。
3. 所有读取和后台采集实时校验员工状态。管理员管理连接元数据不自动获得正文；账号持有人显式授予正文读取与 CRM 共享。原文、CRM 共享、AI 外发为独立权限；本期不启用新的 AI 外发。停用员工在 Connector 授权轮询周期内停止接入，API 即时拒绝；恢复员工不会自动恢复已暂停账号授权。
4. 既有客户会话三元组和消息 ID 保留。仅有确定的完整旧源 ID 对应时关联新源；群成员与 LID 不猜测合并。消息版本更新传播到已有 CRM 投影，使旧分析和建议失效；撤回清除投影正文，晚到历史不能复活。
5. 管理页显示连接与同步两个状态、历史缺口、分步解绑，补齐分页、自动刷新二维码和同 UID 重新关联。Baileys rc14 的 logout 返回只证明本地请求发送；默认显示远端未确认，持有人核对手机后通过独立操作记录 owner_confirmed，不冒充协议 ACK。二维码只在内存返回，不持久化到业务库或日志。
6. 验证采用隔离 SQLite 和合成事件；运行 Node、受影响 pytest、前端构建、约定检查、独立审查和 Git 本地快照巡检。真实 WhatsApp、目标服务 Node/原生库、MySQL 迁移演练与生产切换另以实际证据验收。

## 契约

保留 `/api/whatsapp` v1 绑定、账号、同步计数、会话/消息分页；新增按账号授权、状态与重新关联操作，内部 Connector 授权查询以服务 Bearer key 验证，不依赖员工 JWT。新 Connector `/internal/v2/changes` 返回持久变更序号、has_more 和账号授权代次，应用成功提交后才推进本地 checkpoint。绑定先提交本地保留的账号/操作 ID，再调用幂等 Connector；超时按确定操作 ID 回读，不自动再次发送写请求。

## 迁移与边界

使用增量 Alembic `192_wa_sync_fencing`（父 186），避开另一 worktree 未合并的 187–191。后续集成需核对全部分支和当前部署 revision，不能盲目 stamp 或降级。迁移不删除旧账号、消息、游标和绑定，仅清除已无业务意义的过期二维码。现有账号首次需持有人确认公司业务号授权并按原 UID 关联 Baileys；不转换或自动读取旧 LocalAuth。旧数据持续保留，未授权新采集默认关闭。生产迁移只能由项目部署入口执行。本地实现不证明已上线，也不承诺全部历史、免扫码或账号不会被上游限制。

当前标准消息与 Connector 当前投影不保留已撤回正文；已有客户不可变信源版本保留审计证据，编辑后标 superseded 并从普通证据、Agent、画像读取中排除。正文/附件/历史审计的最终保留和物理销毁策略仍需单独批准，不能借迁移删除审计。新媒体仅同步元数据，不下载二进制；不自动创建 AI 分析任务。原翻译扩展及设备鉴权保持原链路，不引入假设备或新云供应商。

上游协议仍会进行必要握手及离线 presence 通知（rc14 `markOnlineOnConnect:false` 的库内行为）；本服务没有业务发送、已读、聊天修改、presence 或任意 Socket 调用 API。
