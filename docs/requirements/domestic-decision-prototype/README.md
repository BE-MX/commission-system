## 推荐体验顺序

1. 经营总览：查看六项指标、期间趋势、规则信号与需沟通客户。
2. 订单与产品：切换工艺、发色、网帽、尺码、发长、发量、发型系列；点击热力图查看命中明细。
3. 更多筛选：组合业务员、产品、工艺、颜色、尺码等，观察指标同步变化。
4. 客户经营：搜索门店，打开画像，查看完整购买偏好与资金时间线。
5. 创建客户跟进：保存任务，刷新后进入行动与简报，登记结果。
6. 充值与资金：核对期初、充值、扣款、期末账户桥接，展开账本。
7. 业务员画像 / 需求趋势：查看当前客户组合与本公司需求，保留样本与归因限制。
8. 保存视图 / 生成简报 / 导出：本地保存筛选、生成规则演示简报、下载CSV或文本。

## 已实现交互与边界

| 内容 | 原型表现 |
| --- | --- |
| 七个专题 | 均有独立内容，可切换 |
| 数据 | 18家虚构门店、353笔订单、502条模拟账本；金额和余额可对账 |
| 日期 | 固定北京时间2026-10-08，提供近28/90/180天 |
| 对比 | 28/90天与上一等长期间比较；180天禁用未覆盖历史的环比和比较线 |
| 产品筛选 | 多个属性在同一条明细命中；产品金额/件数与相关整单分开 |
| 资金筛选 | 仅应用业务员/城市/日期，不按产品分摊客户充值；资金页订单额同样不按产品过滤 |
| 图表下钻 | 展示匹配件数/金额、相关整单件数/金额，命中明细标记“●” |
| 客户画像 | 全部产品购买范围，保留全局时间窗口；不把属性筛选后的间隔当客户整体间隔 |
| 任务与视图 | 仅保存到本浏览器 localStorage；建议认领按来源去重，完成必须选择结果 |
| AI | 本地规则生成的呈现演示，不调用模型；没有真实预测或自然语言问数 |
| 权限 | 全团队演示范围；业务员选项是筛选，不是生产鉴权 |
| 外部动作 | 不充值、不改价、不发消息、不写数据库、不产生真实业务承诺 |

不包含：生产数据接入、真实权限校验、后台任务、审核凭证、完整RFM模型、历史归属事件、预测模型、完整自定义透视或外部市场分析。这些能力在功能设计中定义，需后续开发。

## 文件

- `index.html`：轻量入口。
- `tokens.css`：原型全部颜色与基本设计令牌，沿用方舟色系快照。
- `style.css`：桌面、窄屏、弹窗和图表样式。
- `data.js`：可复核的确定性演示事实。
- `app.js`：页面、筛选、图表、证据抽屉、表单与本地交互。
- `standalone.html`：由上述文件合并的离线交付物。
- `evidence/`：桌面/手机截图、浏览器验证脚本和验证结果。
