# 客户经营第一期：每日工作流

## 目标与范围

将现有客户经营能力串成业务员每天可以完成的流程：识别今日优先客户 → 审阅背调与证据 → 判断开发资格 → 处理行动 → 登记结果并安排后续跟进。

本期包含今日工作台、资格审核入口及队列语义、可读的研究摘要与证据、客户详情就地处理、机会证据选择、带日期的后续行动。OpenClaw 迁移、邮件生成和发送、完整策略编辑器、主管转化分析属于后续范围。

## 产品与数据约定

- 经营雷达升级为今日工作台并前置；原有 URL 保持可用。普通用户默认“我的待办”，可切换本人有权查看的协作范围；全量能力仍以既有客户数据权限为边界。
- 待办卡包含待首触、今日到期、逾期、高优先级待跟进、今日完成；增加待安排、后续及延后筛选。按行动计数并明确同一客户可有多个动作，卡片可能重叠。统计基于服务端完整筛选范围，不根据当前分页推算。
- 首触为未记录过真实对外沟通的可开发客户；历史已互动关系阶段及外发消息/已登记外部联系均排除，内部复核或生成内容不算触达。标签说明以方舟已归档信息为准。
- 逾期指有效截止时刻早于当前北京时间且仍待处理；今日到期不含已逾期。未到延后时间不催办，到期后可处理。无截止日期显示待安排。
- 客户、负责人使用名称；原因和建议动作直接显示。复杂配置保持管理员能力；默认研究结果为中文章节、事实与证据，不呈现 JSON。
- 研究质量审核与开发资格是两种判断。资格列表按客户和目标作用范围选择最新合格研究；排除当前已决定和未到重评时间的结论，到重评时间重新进入。
- 来源、范围、策略和审核快照由服务端依据当前可见研究生成；审核页面不用业务员手填 ID、JSON。公海脱敏内容不能作为审核依据，资格通过也不授予归属。
- 客户详情保留列表位置，支持就地处理行动。机会更新使用可见证据选择器，保持原有状态流转与证据校验。
- 完成行动可选择安排后续，必须填写具体动作及未来北京时间；负责人继承原行动，界面明确显示。原记录完成、销售活动、下一次行动在同一事务内落库，重复提交不生成重复待办。
- 复用 CustomerAction、CustomerOpportunity、CustomerQualificationReview 和事实/时间线，不创建另一套客户或待办表。

## 实施顺序

1. 为工作台统计、权限、资格队列、后续行动和证据选择建立有区分力的隔离库回归测试。
2. 实现面向人的查询与事务服务及 API；扩展现有返回字段，不改 Agent 接口。
3. 实现工作台、审核页签、研究展示、复用行动操作与证据选择，完成真实页面交互验证。
4. 更新 API/模块文档与交接，独立审查状态流转、权限、逻辑客户归属及幂等，修复后执行收尾检查。

## 验收证据

- 隔离测试：统计不受分页影响；本人/协作/无权限范围；客户逻辑归属；历史沟通与内部动作；延后和完成状态；北京时间零点及非东八区服务器；资格去重、暂缓重评、冲突；后续行动事务性、幂等和非法输入；证据不越权。
- 前端测试：请求与表单契约、有效状态和条件字段、请求竞争与重复点击。
- 前端构建及浏览器验证：工作台筛选→客户详情→登记结果/下次日期→新待办；研究摘要→资格决定；机会证据选择；空态/错误反馈；桌面和窄屏。
- 运行约定检查与 Git 巡检；独立审查有效发现已处理。生产部署、合并和 push 不包含在本次授权内。

## 验收结果（2026-09-06）

实现位于 `codex/customer-operations-phase1`，基于 `59b2ff1f`。复用现有表和权限，无数据库迁移、无新增 Agent 工具。API 与模块说明已同步；后续集成入口和发布状态见 `docs/handoff.md`。

| 调整前 | 调整后 |
| --- | --- |
| 雷达按建议记录逐条查看，缺少今天的工作顺序 | 今日工作台前置，完整范围统计和本人/可见协作、截止时间、客户搜索、分页共同工作 |
| 研究执行、材料质量、客户开发价值混在同一入口 | 质量审核保留，开发资格另设待审页签，按客户和目标范围选取最新合格研究 |
| 研究结果以结构化原始数据为主 | 中文章节、结论、缺口、逐条依据及原始来源链接 |
| 机会推进需要人工填写证据编号 | 按权限选择事实和事件；不符合当前机会或目标阶段的记录禁用并说明原因 |
| 登记下一步只留下文字 | 可选未来北京时间，保存时一并完成原待办、记录活动并创建同负责人的后续待办 |
| 完成后刷新导致浏览位置丢失 | 客户详情内就地操作，外层搜索和分页保留 |
