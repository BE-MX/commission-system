# 拍摄页「原照片生成 / 美颜生成」完整设计

日期：2026-09-12　版本：V2.1 实施基准（增加美颜提示词管理）

本稿包含需求评估、UI、交互、处理链路、接口与数据设计、异常恢复及验收要求，并作为当前分支的实施基准。用户已提供「强美颜·焕颜级」提示词，原文归档于第 12 节；真实模型效果仍需授权样图验证。本地代码、迁移与测试已完成，尚未迁移共享数据库、推送或部署。


## 评审摘要

**可行性：可实现，建议采用独立美颜预处理 + 统一最终生成的两阶段方案。**

用户确认按 V2.1 实施后，当前分支已落地前后台代码、146 迁移与自动化测试。真实 AI 调用、共享数据库迁移、推送和部署不在本次本地实施范围。

| 用户要求 | 最终设计 |
|---|---|
| 上传页右下角两个选项 | 原照片生成 / 美颜生成，默认原片，互斥选择 |
| 强美颜 | 使用用户提供的完整强美颜提示词，先精修一次 |
| 取消甄选页出图风格 | 移除整个区域；发色、场景及生成按钮保留 |
| 不采用后台面部与皮肤处理 | 原片和美颜路线均排除 finish，不删除历史记录 |
| 继续使用其余后台提示词 | 后台默认版本的其余配置用于最终试戴/场景生成 |
| 避免重复美颜 | 一个会话成功精修一次，后续换款复用 |

评估重点：

- 前端改动范围小，但必须移除旧风格组件对生成按钮可用性的依赖，不能只隐藏 UI。
- 后台默认配置目前已有解析路径，可以保留现有版本管理；默认缺失时明确提示配置不可用。
- 强美颜新增一次图片编辑调用；模型未确定前不承诺具体耗时、费用或强度数值。
- 「明显瘦脸、放大双眼」可能影响身份辨识，因此以用户原文中的人物保真要求优先，实际效果以授权样图验收。
- 现有配额是在生成时扣减，新增前置任务失败如何释放占额需在实施前明确；建议先预留最终图片额度，未进入合成时按批次幂等释放，美颜成本单独记录。不能在前置失败后直接重扣整批额度。
- 当前 420 秒生成看门狗不能机械覆盖新增美颜时长；拟改为分阶段租约/心跳，超时收尾必须阻止旧任务覆盖新状态。

V2 UI 顶部的三个切换按钮只用于设计评审，不会添加到正式客户页面。场景缩略图采用占位示意；正式页面沿用已有场景图片。甄选页的模式摘要是只读提示，不恢复出图风格选择。

## 1. 结论与范围

可实现，前端控件较小，主要工作在后端输入分流与生成提示词约束。建议采用「先选择照片处理方式，确认照片后锁定本会话并立即启动一次美颜，甄选与美颜并行，最终生成等待美颜资产就绪」的方案。

两项互斥，默认原照片生成。拍摄、相册、系统相机、扫码上传统一生效；同时覆盖 AI 换发试戴（tryon）和佩戴实拍场景生成（scene）。同一会话换发型、发色、场景时沿用选定模式；新客户恢复原照片生成。

| 模式 | 输入处理 | 后续生成 |
|---|---|---|
| 原照片生成 | 不执行额外美颜，使用未美颜的上传照片 | 保留原有面部特征与皮肤质感，完成已选择的发型/场景变化 |
| 美颜生成 | 按经确认的参数和提示词执行一次独立美颜 | 将美颜输出作为人物输入继续生成，不叠加第二次美颜 |

「原照片」指上传照片已有的外观。如果用户从手机上传的照片本身经过美颜，系统不会自动还原。现有尺寸压缩、方向规范化属于传输处理，不属于美颜。当前客户端和服务端会缩图，因此本方案不承诺保留原始文件的逐字节数据。

生成模型可能改变局部纹理，提示词约束不能保证面部像素完全不变。验收目标是无主动美颜指令且外观保真。如果要求面部像素完全一致，需要另行设计面部保护蒙版与局部合成，并评估与新发型、光照的融合。

## 3. UI 设计

### 3.1 布局

延续截图的暖米白页面、深棕文字、灰褐取景区和椭圆辅助框。不改标题和中央上传入口。模式组件位于取景区域右下角，底部拍摄提示上方，占用原有空白区，避开人脸框与右下角装饰线。

桌面/平板宽屏采用约 340–380px 宽的不透明米白小面板，距右边 24px、距底部提示栏上缘 20px。标题「生成方式」，下方两项横排，每项至少 48px 点击高度；面板下部显示一行对应说明。这里的 px 均为 CSS 像素，不直接套用截图物理像素。

组件应放在 viewport 内的底部独立布局行并右对齐，而非绝对叠在人像上。为该行预留高度，再放底部拍摄提示栏。照片预览态也保留这行，不因提示栏隐藏而跳动。

宽度不足 600px 时，该行改为撑满宽度，左右边距 16px；两项保持横排，说明可以换行。短屏允许页面纵向滚动。保留原有快门中心位置及「重拍 / 就用这张」按钮的位置关系。

### 3.2 视觉与文案

| 元素 | 设计 |
|---|---|
| 模式组标题 | 生成方式 |
| 选项一 | 原照片生成 |
| 原片说明 | 不额外美颜，按上传照片生成 |
| 选项二 | 美颜生成 |
| 美颜说明 | 强美颜·焕颜级，含肤质、脸型与五官修饰；先精修一次，再生成效果图 |
| 已选 | 深棕实底、米白文字、明确单选标记 |
| 未选 | 米白底、深棕字、浅棕边线 |
| 预览态 | 显示「已选：原照片生成」或「已选：美颜生成」，预览仍是上传照片 |
| 美颜阶段 | 正在美颜处理… / 完成后将继续生成效果图 |
| 生成阶段 | 正在生成效果图… |
| 美颜失败 | 美颜处理未完成，可重试，或改用原照片生成 |

沿用 `tokens.css` 的 `--xk-ink`、`--xk-ink-2`、`--xk-paper`、`--xk-gold-line`、`--xk-mut`。标题延续现有衬线字体，控制项沿用现有正文。客户页面不暴露提示词、模型名、参数值或版本编号。

使用原生 radio + label + fieldset/legend，支持 Tab 与方向键、可见焦点，整项可触摸；选中状态不能仅靠颜色。状态文案使用 aria-live=polite。模式变更立即反馈，无等待动画。

### 3.3 交互规则

1. 首次进入默认原照片生成；未选照片也可切换。
2. 选模式仅更新选择，不触发上传、美颜或计费。
3. 相册/拍照/扫码取得照片后展示上传原片；切换模式不伪造美颜预览。
4. 点击「就用这张」时一次性捕获照片、模式和客户端请求 ID；提交期间禁用模式与重复确认。
5. 建会话成功后模式不可直接修改；返回拍摄页重新确认时创建新会话，旧任务不能污染新会话。
6. 同一客户重拍保留刚才的模式；换客户、回首页或闲置重置清空选择并恢复原片。
7. 已提交会话换发型/场景只复用已有美颜资产。美颜失败时的「改用原照片生成」是明确操作，创建关联的新原片会话并复用原片，不覆盖旧会话历史。
8. 扫码手机页面只负责传照片，最终模式由展位端确认；二维码打开/关闭不改变模式。

## 4. 处理链路

### 原照片生成

上传未美颜照片 → 确认并建会话 → tryon 使用原片分析与匹配 / scene 直接选场景 → 点击生成 → 原片作为人物输入 + 原片保真约束 → 结果。

### 美颜生成

上传未美颜照片 → 确认并保存模式及美颜配置快照 → 立即启动一次美颜 → tryon 同时使用原片分析与匹配 / scene 直接进入选场景 → 点击生成 → 等待或复用已完成的美颜资产 → 以该图片为人物输入生成 → 结果。

美颜在照片确认后立即异步开始，用甄选时间遮盖一部分处理延迟。分析继续用原片，避免修饰改变肤色或脸型判断。点击最终生成时只检查资产状态，不重复发起；若尚未完成，进入明确的等待阶段。美颜是会话共享前置任务，多发型、多场景不能各自重复美颜。该方案会为“已确认美颜但随后退出”的会话产生一次美颜调用，成本换取更短的最终等待；这是本稿建议的明确取舍。

所有业务图片调用统一经 `app.ai.service.edit_image`，模型和默认参数经现有配置体系管理。首期复用已配置的 `expo_wig_composite` 图片编辑 preset，并在会话中冻结 provider、模型和配置指纹；后续可无损切换为独立美颜 preset。

## 5. 数据与接口设计

### 5.1 会话字段

| 字段 | 类型/取值 | 用途 |
|---|---|---|
| photo_processing_mode | original / beautify，默认 original | 与 mode=tryon/scene 正交 |
| photo_path | 现有路径 | 永远保持未额外美颜的基础照片 |
| beautified_photo_path | nullable 路径 | 成功后发布的美颜资产，不覆盖 photo_path |
| beautify_status | skipped/pending/processing/ready/failed | 美颜任务状态 |
| beautify_snapshot | nullable JSON | 模型 preset、提示词、参数及版本的不可变快照 |
| beautify_snapshot.source_hash | nullable 字符串 | 基础照片内容哈希 |
| beautify_error_code | nullable 字符串 | 面向业务的失败分类 |
| beautify_attempt / beautify_queued_at / started_at | 计数 / 北京时间 | 重试、启动丢失与任务超时恢复 |
| client_request_id | 唯一请求标识（按调用主体限定） | 上传请求结果不明时幂等找回 |

生成结果快照同时记录实际输入路径/哈希、处理模式、美颜版本、最终展开提示词。不得只保存可变配置 ID。历史会话回填 original/skipped，不重新生成历史结果，也不将历史结果声称为已满足新保真规则。

可按现有任务组织方式拆出独立美颜任务表；最终迁移以实施时实际任务模型为准，禁止提前编造 Alembic revision。所有新时间字段遵循项目北京时间规范。

### 5.2 建会话

扩展现有 POST `/sessions`，保留 customer_id、mode 和 photo/pending_photo 二选一；新增 Form 字段 `photo_processing_mode` 与 `client_request_id`。缺省模式为 original；非法枚举返回 422；美颜配置未就绪返回 409，不能静默降级。服务端选择已发布配置并冻结快照，不接受普通客户端任意提示词。

重复同一请求 ID 返回已有会话；同 ID 携带不同图片/模式返回 409。即使网络中断，重按确认也不能多建会话。

### 5.3 会话查询

扩展 GET `/sessions/{id}` 的 data：`photo_processing_mode`、`beautify_status`、`processing_stage`（beautifying/generating 等）、面向用户的重试能力。返回图片 URL 继续遵循现有权限与客户边界，不向客户发送模型参数或内部错误堆栈。

保留现有顶层 status 语义，额外由 `processing_stage=beautifying` 驱动「正在美颜」文案；美颜状态与面容分析并行且彼此独立。stale 恢复按 queued/start 时间和任务令牌做条件更新，不覆盖刚完成的结果。

### 5.4 重试与原片继续

已新增 POST `/sessions/{id}/beautify/retry`：仅失败可重试，已处理完成直接返回当前状态，进行中返回在途状态。服务端校验模式、配置快照与任务租约。

“改用原片”通过返回拍摄页重新确认并创建原片会话完成；首期不增加 `/continue-original` 快捷接口，避免在失败会话上静默改变已冻结的处理方式。

正式路径前缀、权限与信封复用 expo 路由规范；以上契约已在本分支实现。

## 6. 提示词与参数边界

将面部控制分为美颜预处理配置和最终生成保真配置。两条路线均不读取或拼接后台「面部与皮肤处理」finish 段。原片路线注入保留输入面部几何、年龄特征、肤色及皮肤纹理的规则；美颜路线最终生成只要求保持已处理照片的面部，不再次磨皮或重塑。保真规则是独立执行约束，不复用被停用的 finish 配置。

不能只在结尾追加一句「不要美颜」来抵消前面矛盾指令。需要结构化拆分所有影响面部的段落，对可编辑的发型/场景提示词提供发布前冲突检查和人工样图验收；简单关键词检查只能辅助，不能证明无冲突。

配置清单（提示词与修饰范围已收到，详见第 12 节；数值参数、模型及验收样图待补充）：

| 项目 | 所需信息 |
|---|---|
| 美颜提示词 | 正向提示词；负向提示词如模型支持 |
| 参数 | 参数名、数值、单位/范围、对应模型或工具 |
| 允许修改范围 | 肤质、肤色、瑕疵、眼部、脸型、年龄感分别是否可改 |
| 必须保留 | 身份、发型/发际线、佩戴产品细节、背景、服装等 |
| 效果验收 | 理想示例及不可接受的变化，确认有使用授权的测试照片 |

未收到参数前不假设强度 0–100，也不承诺任何数值到视觉效果的对应关系。不同模型可能不支持负向提示词或部分参数，适配时要明确拒绝未知字段。美颜提示词与最终生成提示词分别版本化；配置更新只影响新会话，失败重试仍用原快照。

## 7. 幂等、失败及资源管理

成功的美颜资产按「会话 + 输入哈希 + 配置快照哈希」复用，不跨客户共享。抢占任务使用数据库条件更新和租约，不能仅用进程内布尔锁。美颜写临时文件，验证可解码及有效尺寸后再原子发布路径；晚到的旧 attempt 不得覆盖新 attempt。

| 情况 | 行为 |
|---|---|
| 美颜未配置/停用 | 原片可用；美颜选项禁用并显示暂不可用，后端再次校验 |
| 上传失败 | 保留照片和模式，可重试；未开始美颜 |
| 美颜失败 | 不进入最终生成；显示重试或明确改用原片 |
| 美颜请求超时但结果未知 | 优先查供应商任务状态；支持幂等键则复用，不能盲目并发重发 |
| 美颜仍在处理时点击生成 | 进入“正在美颜精修”阶段，完成后自动开始最终生成；不创建第二个美颜任务 |
| 美颜成功、最终生成失败 | 重试最终生成复用已有美颜图 |
| 换发型/多场景 | 全部使用同一美颜资产 |
| 刷新/断网 | 查询已有会话和阶段，不靠前端重新执行美颜 |
| 换客户/返回重拍后旧响应到达 | 通过会话 ID 与代际检查丢弃，不更新当前屏幕 |
| 任务取消/会话删除 | 旧任务落盘前重新确认归属与存在性；清理临时资产 |

「一次」指一个有效美颜产物供后续复用，不是承诺故障情况下供应商永远只收到一个请求。供应商缺少任务查询与幂等能力时，需要记录未知状态并由明确重试解决潜在重复计费。

基础照片、美颜图、最终结果分开存储；删除客户/会话时同步清理新增文件，沿用现有留存策略，不擅自延长保存期限。日志记录任务 ID、耗时和错误码，避免记录人像内容、凭据及完整敏感请求。

## 8. 成本、配额与可行性

原片路线不新增图片模型调用。美颜路线对首次成功生成新增一次美颜调用和一个图片文件；后续同会话生成复用。额外时延约为美颜排队、处理和存储耗时之和，不能在模型未知时承诺秒数。

记录美颜及最终合成的耗时、成功率、重试次数与调用成本。界面使用阶段文案，不展示假百分比。门店现有生成额度扣减必须在实施时核对 quota_service 与调用路径；建议美颜不额外消耗一张「最终结果」额度，但供应商成本独立记录，此项为产品建议而非已实现计费事实。最终生成失败时沿用明确的占额/释放规则，不因重试重复扣减。

工程评估：UI 复杂度低，跨流程与提示词改造中等，故障恢复和真实效果验证是主要风险。准确工期与成本应在参数、模型及实际部署任务机制明确后给出。

### 12.2 评估与冲突处理

该配置可作为独立图片编辑阶段的完整文字指令，包含明显皮肤修饰、局部脸型调整和自然妆效。它超出了单纯磨皮；UI 应明确提示存在脸型与五官修饰。文字中的「较强」「适度」是效果要求，不是可直接传给模型的数值参数。

「明显收窄脸颊」「放大双眼」与人物保真存在张力。建议追加以下执行优先级（设计补充，非用户原文）：

```text
当美颜强度与人物辨识度发生冲突时，以人物辨识度、主要五官特征和成熟气质为优先，降低局部修饰幅度。保持眼距及主要五官的相对位置，不改变表情。不得通过改变发际线、头发体积、饰品形状或背景线条来实现瘦脸。保留具有辨识度的个人特征，不把人物重塑为统一模板脸。
```

验收需检查强磨皮是否仍有微纹理、脸颈是否自然一致、眼型及成熟气质是否保留，以及瘦脸是否扭曲头发边缘、眼镜或背景。无法仅凭提示词保证每张照片都达标，须用实际客户授权样图验证。

### 12.3 两阶段边界

- 预处理阶段：上述完整提示词 + 保真优先补充，只输入本次基础照片，输出一张美颜照片；保持发型、服装、饰品与背景。
- 最终生成阶段：以美颜照片为人物参考，执行用户选择的试戴/场景任务；保持已精修面部，不再次瘦脸、放大双眼、磨皮或美白。
- 不将预处理的「保持原发型和背景」整段复制到最终换发/换场景提示词，否则会与业务目标冲突。
- 原片模式：不应用本节美颜提示词或美颜资产，继续使用基础照片与原片保真规则。
- 预处理不添加水印。最终结果现有水印属于另一阶段；本次提示词不自动修改该阶段的既有品牌处理。

| POST `/api/expo/beautify-prompt-versions/{id}/preview` | `expo:admin` | 使用测试照片预览，不发布、不进入客户会话 |
| POST `/api/expo/beautify-prompt-versions/{id}/publish` | `expo:admin` | 原子发布并归档旧当前版本 |
| POST `/api/expo/beautify-prompt-versions/{id}/archive` | `expo:admin` | 归档非当前版本；当前版本须先发布替代版本 |
| GET `/api/expo/beautify-prompt/status` | `expo:write` | 上传页只读取 available、version_label，不返回完整提示词 |

统一使用项目 `{code,message,data}` 信封。创建/更新请求只接受名称、提示词正文和 expected_revision 等业务字段；模型、Provider、密钥及任意执行参数不由浏览器提交，继续由 AI preset 管理，避免越权改变调用目标。

预览接口属于真实图片编辑调用，应明确标注会产生供应商调用成本。预览文件使用独立临时目录与较短留存期限，不写入客户会话、客户照片库或正式结果；失败返回业务错误码，不在响应中泄露供应商密钥、完整堆栈或内部网络地址。

### 14.5 数据设计

实现采用独立的美颜提示词版本表，没有在普通生图版本表中增加特殊类型：

| 字段 | 含义 |
|---|---|
| id / name | 版本标识与名称 |
| prompt_text | 完整美颜提示词 |
| status | draft / published / archived |
| revision | 乐观锁修订号 |
| published_slot | 当前版本唯一槽位，沿用普通提示词默认版本的唯一约束思路 |
| updated_by / published_by | 操作人 |
| created_at / updated_at / published_at | 北京时间审计字段 |

提示词正文属于业务配置，不写入代码或环境变量。AI 调用日志仍按既有规则保存必要快照；客户查询接口不返回提示词全文。

### 14.6 异常与验收

1. 保存草稿不影响当前已发布版本；发布后仅新确认照片的美颜会话使用新版本。
2. 两名管理员同时编辑时，后提交的旧 revision 被 409 拦截。
3. 无已发布版本、当前版本停用或图片编辑预设不可用时，美颜选项不可选；原片流程正常。
4. 预览不会创建 ExpoSession、扣减正式结果额度或覆盖当前发布版本。
5. 美颜会话快照能够证明实际使用的版本与文本；配置更新后重试不漂移。
6. 客户和普通展位账号无法读取、修改、预览或发布完整美颜提示词。
7. 最终生成提示词仍排除后台「面部与皮肤处理」字段，也不自动拼接美颜提示词。
8. 管理界面在窄屏下表单单列、操作按钮换行，长提示词可滚动编辑且不产生页面横向溢出。
