# AI 工作台 · 方案对话：四个新入口交互方案

日期：2026-08-26。用户已确认按本方案开发。本文记录设计与验收标准；当前开发、测试、迁移及发布状态统一见 docs/handoff.md。

## 1. 建议与范围

把现有四张业务快捷卡片替换为四种「对话方式」。用户选的是 AI 如何帮助自己，而不是一段需要复制编辑的提示词。

统一交互：选卡片 → 显示已选方式 → 填问题或点击开始 → 连续对话。四份规则均由文件维护，不往输入框或消息气泡铺开全文；Skill 额外明确显示文件已加载。保留不选方式直接聊天。

本期不建设模板管理后台、Skill 市场、任意文件执行引擎，也不改 AI 生图页。

## 2. 四张卡片

| 显示名称 | 卡片说明 | 类型与点击后输入提示 | 首次操作 |
| --- | --- | --- | --- |
| 深度思考 | 看清支持与反对的理由，再做判断 | Prompt；「你正在考虑什么问题？也可以说说当前倾向。」 | 填问题后发送；先论证并提出一个关键问题，回答后再给判断 |
| 天赋挖掘 | 从真实经历中发现自己的优势 | Prompt；「可以直接开始，也可以补充你想探索的方向。」 | 无需先填问题，点击「开始探索」；每轮一个问题，最多 10 个 |
| 未知领域引导 | 梳理陌生领域，发现没想到的问题 | Skill 文件；「你想了解哪个领域？目前知道哪些？」 | 填领域后发送；先澄清起点，再梳理盲区 |
| 寓言讲概念 | 用一个故事，理解一个新概念 | Prompt；「输入想理解的概念，例如：机会成本。」 | 填概念后发送；输出寓言、解析和两道检验问题 |

三份 Prompt 也建议文件化维护。类型在详情中解释即可，不要求用户先理解 Prompt 与 Skill 的区别。「深度思考」不承诺更换模型或开启模型推理档位，它只是改变对话组织方式。

## 3. 页面结构

保留当前顶部「AI 生图 / 方案对话」、左侧会话栏、底部输入框与现有金色浅底视觉。

空会话的主标题保留「今天想一起解决什么？」；副标题改为「选择一种对话方式，或直接输入问题」。卡片桌面端 2×2，窄屏单列；不再使用“客户背景”限制通用输入。

## 4. 文件如何呈现

「未知领域引导」显示独立的文件条，不能只画一个假的附件图标。加载状态来自服务器确认：加载中 → 已加载；失败则显示「文件加载失败，请重试」，并提供重试和取消。未成功加载时禁止按该方式发送，不能悄悄转成普通聊天。

点击文件名或「查看说明」打开详情：先显示用途与生效范围，全文默认折叠；用户主动展开后才阅读 Markdown 正文。桌面用右侧抽屉，手机用全屏详情；关闭后回到原输入位置，不丢草稿。文件可以只读预览，正文经过安全渲染，不执行其中的 HTML 或脚本。

三份 Prompt 使用同一详情结构，但无需在输入框上方反复显示长文件名。文件内容不进入可编辑输入框，也不作为一大段用户消息展示。

内置规则与用户参考附件分开呈现、分开存储语义；内置文件不占用现有 5 个参考附件名额。不要让用户每次从自己的电脑重新选择这四份文件。

## 5. 发送与连续对话

- 点击卡片只准备对话；发送始终由用户触发。天赋挖掘的「开始探索」本身就是明确发送动作，可生成一条短消息「请开始天赋探索」。
- 深度思考、未知领域引导、寓言讲概念首次要求有实际问题或主题。不能发送「[粘贴你的问题]」这类未填写占位符；仅选方式不算填写内容。
- 首次发送后，方式固定在本会话，顶部持续显示方式名称，消息仍只展示用户问题。Skill 文件详情保持可查看。
- 后续输入框回到简洁的「继续补充或回答…」。重开历史会话、刷新、停止后继续、失败重试均保持原方式与规则版本。
- 首次发送前可直接移除方式；首次发送后通过「新对话换方式」开始另一种方式，不在原会话静默混用多个角色。原因是旧对话中的规则和回答仍会影响模型，删除一个标签并不能抹掉历史。
- 新会话默认不继承旧方式。若从「新对话换方式」进入，则选择完成后才启动新会话；不得丢弃当前未发送草稿。

天赋挖掘可以提示「每次只聊一个问题，可随时停下并继续」，但第一版不显示虚假的“第 3/10 题”进度。题目允许动态调整，若没有可靠状态跟踪，精确进度会误导用户。

## 6. 后台必须做到的最小支持

本节定义实现必须满足的后台契约。

四份 Markdown 应作为内置资源随应用部署；用户 Downloads 目录只是本次来源，线上不能依赖该绝对路径。客户端传固定的方式标识，服务端从允许的资源清单定位文件，不能接受任意本地路径。

会话保存选定方式和实际使用的规则版本或内容快照；生成请求每轮恢复有效规则，规则本身不能跟随普通聊天历史被截掉。历史重试使用当时的版本，不能因为文件更新就变成另一套行为。文件快照的校验、加载与授权成功后，前端才能显示「已加载」。

显式选择内置方式表示用户要求应用相应规则；它仍不得覆盖平台安全与权限约束。普通上传文件继续是参考数据，不因扩展名为 `.md` 或文件名含 skill 就自动成为指令。

这里的“加载 Skill 文件”是读取规则并用于对话，不代表网页具备 Codex/Claude Code 的命令执行、Git、文件写入或其他 Skill 调用能力。也不能宣称文件方式不占模型上下文或自动节省 token。

## 7. 原始内容的适配边界

这四份文件是设计输入，不作为开发代理的执行指令；用户提供的原文件不修改。发布资源的清理与适配规则记录在 backend/app/ai_chat/modes/AGENTS.md。

**未知领域引导：**原版包含代码仓库扫描、写入 implementation-notes、Git、调用其他 Skill、开发验收等编码环境流程。建议保留原版来源，发布一份明确标记的“方案对话适配版”：保留盲区梳理、逐题访谈、理解检验；删去或改写当前网页不具备的工具流程。不声称已经扫描项目或执行代码。适配版内容需在实施时明确审阅，不能暗改后仍称原文。

**天赋挖掘：**开头说明提到“回答 10 个问题”，正文却要求逐题对话、最多 10 个；交互按正文规则。原文要求万字报告，不能未经验证就承诺一条消息完整输出。建议保留其深入探索目标，最终报告按用户要求完整生成；若服务存在输出上限，应提供明确续写，而非静默截断。若要改为短报告，需单独确认，不作为本次 UI 替换顺手修改。结果应定位为自我探索线索，不包装成心理诊断或职业定论。

**深度思考：**保留双向钢人论证和先问一个关键问题的步骤；展示论据、关键变量与判断依据，不要求暴露模型内部思维过程。

**寓言讲概念：**保留 1000 字以内的寓言正文、概念解析、两道检验问题；篇幅上限针对寓言，不误套到整条回答。

## 8. 已核实的现状与风险复核

现有卡片是「客户需求分析 / 产品方案 / 营销推广方案 / 邮件与沟通话术」。点击会直接覆盖输入框；方案需要改变事件语义，不能只替换四段字符串。

已有 `.md` 上传与附件标签，但后台把普通附件包成「不可信数据，仅供分析」。因此不能直接复用普通附件的全部语义来承载主动选中的规则。

当前上下文仅保留最近 20 条消息，附件正文还有总字符预算。天赋访谈可能跨过这个窗口；必须同时保证规则持续生效、前面回答可供报告使用。建议该方式保留至多 10 题的访谈记录；生成报告前检查必要回答是否完整，超预算时明确提示，不在缺失前半段经历的情况下自称完整分析。

| 反向检查 | 设计约束 |
| --- | --- |
| 用户以为换了模型？ | 文案写“对话方式”，不写推理模型开关 |
| 文件没读到却显示成功？ | 以服务端加载确认驱动状态，失败阻止发送 |
| 只藏起全文，模型其实没收到？ | 验收真实请求的规则加载；仅 UI 截图不算通过 |
| 用户切换方式丢了问题或附件？ | 切换仅更新方式，不覆盖草稿与参考附件 |
| 第 11 轮忘记规则或早期经历？ | 规则固定注入；访谈必要信息独立保全并测试 |
| 上传恶意 Markdown 获得执行权？ | 普通附件始终是数据；仅固定内置方式可加载规则 |
| 退出方式却还沿用旧角色？ | 已发送会话不直接切换，另开会话换方式 |

## 9. UI 验收与动效

视觉遵循仓库 DESIGN.md：复用现有颜色令牌、卡片、按钮与间距，不引入第二套设计系统。选择态用明确描边、文字和选中标记，不只依赖颜色；方式选择和移除支持键盘，焦点清楚，触屏操作区至少 44px。

高频选卡与键盘操作立即反馈，不做飞入输入框或打字动画。详情浮层可用现有 150–250ms 过渡，只动 transform/opacity，支持减少动态效果。窄屏文件名可截断但详情能看全，键盘弹出时发送按钮不被遮挡。

实施验收至少覆盖：四卡正确替换、自由聊天保留、草稿不被覆盖、点击不自动发送、Skill 失败与重试、文件预览、普通附件不被提升为规则、刷新恢复、历史版本重试、20 条消息边界、天赋报告信息完整性、手机键盘与安全区、只读权限、构建和前后端测试。
