# 半成品订单及半成品库存管理规格

> 状态：开发基线
> 日期：2026-08-25
> 领域：`semifinished`
> 关联模块：备货管理、生产订单、订单发票

## 1. 目标与范围

系统现有生产订单以产成品 SKU 为对象、以“件”为单位。新模块把尺寸与颜色抽象为可跨产品复用的半成品，以“g”为库存和下单单位，支持提前备货、订单收货自动入库，以及生产单同步 OKKI 成功后的自动出库。

本期范围：

1. 半成品列表及产品关联自动抽取、人工审核。
2. 半成品订单、部分入库、终止和审计台账。
3. 半成品库存余额、流水、人工调整。
4. 安全库存页生产下单时同步创建半成品订单。
5. 发票生产单按产品行选择半成品，保存计划；同步 OKKI 成功才正式出库，失败释放预占。

不在本期：半成品工序报工、库位/批次先进先出、成本核算、供应商采购。

## 2. 业务定义

半成品唯一键为 `标准化尺寸 + 标准化半成品颜色`，不包含系列、档次、型号和成品克重。所有命中同一尺寸和颜色的产品共享库存。

库存单位统一为 `DECIMAL(14,3) g`：

```text
在制 = 半成品订单量 - 已入库量
实存 = 入库 - 出库 + 调整
占用 = 已为同步操作预留、尚未转正式出库的数量
可用 = 实存 - 占用
```

创建半成品订单只增加在制数量；录入实际完成/收货数量时自动生成入库流水。禁止“下单即增加可用库存”。

## 3. 产品解析规则

仅处理名称满足 `描述/尺寸/颜色表达式/克重` 的启用头发产品。尺寸必须为数字，克重必须为 `g`。名称为主要解析源，结构化 `color/size/unit` 为异常回退源。

| 成品表达式 | 半成品结果 |
|---|---|
| `16/#1` | `16/#1` |
| `16/#P8/24` | `16/#8`、`16/#24` |
| `16/#5ATP8A/24` | `16/#5AT/8A`、`16/#5AT/24` |
| `18/#4T60` | `18/#4T/60` |
| `22/#2TP8/60` | `22/#2T/8`、`22/#2T/60` |
| `20/Cookies Cream` | `20/COOKIES CREAM`，色型 `named_t` |
| `20/Salt & Pepper` | `20/SALT & PEPPER`，英文命名色整体视为一个 `named_t` |
| `18/#1006&#9ATP9A/613` | `18/#1006`、`18/#9AT/9A`、`18/#9AT/613` |

解析结果保存 `parser_version` 和源字段快照。纯色单组件自动确认；P/TP/`&` 多组件按均分生成草稿，状态为 `needs_review`，配比确认前不得自动下单或出库。配比总和必须为 1。

建议克数：

```text
产成品件数 × 单件净重(g) × 半成品配比 × (1 + 损耗率)
```

本期损耗率默认 0；订单行允许覆盖建议克数，但不反写标准配比。

## 4. 状态机

### 半成品订单

```text
submitted -> partial -> completed
    |           |
    +--------> terminated
```

- `submitted`：已提交，尚未入库。
- `partial`：至少一条已部分入库。
- `completed`：全部明细已足量入库。
- `terminated`：停止后续入库；已有入库流水保留，禁止删除。

### 发票库存分配

```text
allocated --(新同步产生正差额)--> pending --OKKI成功--> allocated
                                      |--OKKI失败--> allocated
```

`allocated_qty` 表示该发票已正式出库的当前数量；`pending_delta` 表示本次同步与上次成功结果的差额。正差额先预占，负差额在 OKKI 成功后冲销入库。

## 5. 关键流程

### 5.1 产品同步

1. 管理员调用同步预览。
2. 后端读取启用 OKKI 产品并解析，返回新增、变化、异常和需审核数量。
3. 管理员应用预览；系统 UPSERT 半成品、产品映射和组件。
4. 自动确认映射可立即用于报价；需审核映射只展示，不参与自动库存动作。
5. 人工修改结果优先，增量同步不得覆盖 `manual` 映射。

### 5.2 半成品订单与入库

1. 从半成品列表/订单页选择多个半成品，输入克数并提交。
2. 订单进入 `submitted`，数量计入在制。
3. 每次收货提交增量克数和客户端幂等键。
4. 服务端锁订单行和库存余额，累加入库量并写正向库存流水。
5. 重放相同幂等键直接返回原结果，不重复入库。

### 5.3 生产购物车同步下单

1. 安全库存页生产弹框勾选“同步下单半成品熟料”。
2. 后端按产品和产成品件数返回半成品建议克数、可用和在制。
3. 用户确认后，半成品计划与产成品购物车项一起保存。
4. 生成订单时由编排服务在同一事务创建产成品订单和半成品订单并清购物车。
5. 任一步失败整体回滚；产成品工序初始化在事务成功后执行。

### 5.4 发票生产单自动出库

1. 仅 `production + hair` 行可勾选自动使用半成品。
2. 保存草稿只保存半成品计划快照，不变更库存。
3. 同步前服务端重新校验映射、计划和可用库存；正差额锁行预占。
4. OKKI 成功：正差额转出库，负差额冲销入库；写唯一幂等流水。
5. OKKI 明确未受理：释放本次正差额预占，原成功分配不变。
6. OKKI 已受理但响应缺行，或本地正式出库失败：保持整批 pending，禁止编辑/删除；管理员核对后按同一 `operation_key` 的成功日志执行正式出库或释放。
7. 再次同步按发票+半成品聚合计算差额，避免产品行 ID 重建造成重复出库。

库存不足默认阻止同步，不允许自动形成负库存。

## 6. 数据与接口

领域表见 `docs/database.md`；HTTP 前缀 `/api/semifinished`。所有响应使用统一 `ok()` 信封。

核心接口：

- `POST /materials/sync-preview`
- `POST /materials/sync-apply`
- `GET /materials`
- `PUT /mappings/{id}`
- `POST /quote`
- `GET|POST /orders`
- `GET /orders/{id}`
- `POST /order-items/{id}/receive`
- `PUT /orders/{id}/status`
- `GET /inventory`
- `GET /inventory/{material_id}/ledger`
- `POST /inventory/{material_id}/adjust`

权限：`semifinished:read`、`semifinished:write`、`semifinished:admin`。

## 7. 并发与幂等约束

1. 库存余额行所有变更必须 `SELECT ... FOR UPDATE`。
2. `on_hand - reserved` 不得小于 0。
3. 库存流水 `idempotency_key` 全局唯一。
4. 同一发票存在 `pending_delta` 时禁止发起第二次同步。
5. 生产订单和半成品订单必须单事务创建。
6. 入库不得超过订单量；终止订单不得继续入库。
7. 已产生库存流水的业务单据不得物理删除，只能冲销。

## 8. 验收标准

1. 三个菜单页面按权限显示并可完成列表、建单、入库和查流水。
2. 示例纯色/P色/T色/英文色/复合色解析结果准确。
3. 多组件映射未审核时，安全库存页和发票页均明确阻断。
4. 产成品订单与半成品订单原子创建。
5. 半成品部分入库准确更新订单状态、余额和流水；重复请求不重复入库。
6. 发票草稿不扣库存；同步成功出库；失败释放；修改后只处理差额。
7. 两张发票并发争抢库存时最多一张成功预占，不出现负库存。
8. 迁移可升级/降级，约定检查、后端测试和前端构建全部通过。
