# 待出库保留、自由可用与补货同步

本次按亮哥确认的范围开发；Git 交付范围为提交、合并 main 并推送。未部署，未对真实小满单据执行写入；最终交付版本以 Git 远端回读为准。

## 业务规则

- 发票产品只显示「自由可用」，不增加保留、缺货、未发货等数量列。自由可用 = max(0, 小满目标仓库可用 - 所有有效本地待出库任务尚未由小满承接的整单 SKU 数量)。普通订单仍可缺货下单，缺口不能占用前单保留。
- 仓库沿用原整单出库目标 `8193514242746`，按 product_id + sku_id 汇总全部明细，包括非缺货行和重复 SKU；不把其他仓库库存汇入。前序按出库任务 ID 分配。编辑本单的缺货判断使用内部可分配量，保留记录不等于物理库存。
- 缺货任务新增「补货同步」。立即查目标库存，配齐后走原受管创建及详情回读；仍缺货则更新缺口。并发忙碌、正在处理和结果待核对分别反馈，不把重新排队或 HTTP 超时说成占库成功。
- 小满已生成并严格核验的整单不再次扣减；镜像未追上时读实时原生可用。发现既有部分出库时保留未承接余量，并记录实时关联数量。存量既有出库若没有可核实占库事实，相关数量显示待核对，不猜测为可销售库存。
- 已生成出库单的订单再次增加数量时，新增且尚未由原生出库承接的数量继续保留。原单补齐或减量只有严格回读核验后才更新原生占库快照；发送中或结果不明时待核对。历史已完成任务只有完成时间覆盖成功订单代次时才能作为整单交接证明，后续新代次缺少原生基线则待核对。
- 已确认取消、删除或跳过未建品非标任务不保留；取消处理中、编辑未同步、同步失败与原提交不确定时保留最后成功代次，不能用当前草稿释放旧需求。

## 实现边界

2026-10-23 本地修复：自动生成、补货核验及增加出库数量的执行路径，允许为缺少原生基线的历史完成任务做只读实时核验。仅对影响当前 SKU 的保留量核验；镜像 ID 不直接作为占用依据，必须有匹配的实时详情和有效列表成员证明。只抵扣已验证的待出库数量，多张单汇总、部分覆盖保留差额；先核验原生占用，再读取实时库存。没有发现的单据不释放，查询失败阻断，未决修改不采用新证据。核验不永久覆写历史记录，普通库存列表保持保守显示，不增加页面扫描。

复用 `ark_okki_outbound_tasks`、成功 `InvoiceSyncLog` 和 `ark_shipping_operation_events`，无新增表或迁移。成功代次的整单快照使用 scope `outbound-stock-reservation`，既有原生出库数量观察使用 `outbound-stock-native`；均只保存产品身份、数量和原订单绑定，不写业务镜像。历史完整成功摘要可供只读回退；没有可信快照的未同步历史单返回待核对。

同步订单确认、自动创建、手动补货、已有出库增量同步及预售实际发送共用 `ark-okki-outbound-poller` 命名锁。订单确认与库存发送串行，避免前序保留在发送窗口增加。其他仓库继续沿用原语义。原 legacy 循环改为每轮释放锁，睡眠不持锁；其认领及 creator 都拒绝接管未结束的 Python 原始发送事实。

手动补货不安装后台模式，不借用后台账号权限。每个本地授权阶段重新核实点击人的 invoice:sync、shipping_inspection:write、发票和出库可见范围；原操作人写入 START，崩溃恢复沿原事实核对。库存查询使用独立 product scope，保留共享 invoice token。保持原小满待出库状态，不自动办理真实发货或更改资金。

## 验收

- 两单同 SKU 分别保留 8、7，原生可用 20，新单显示 5；重复 SKU 合计后扣减，其他仓库不可销售。
- 本单保留 10、物理可用 6 时仍缺货；补到 10 后自由可用仍为 0，但本单可出库，不误报缺货。
- 小满成功占用后镜像仍旧、已有部分原生出库、查询失败、未同步编辑及取消待核对均不虚增自由可用。
- 原生已占 10，订单成功改成 15、实时可用 20 时，新单只能用 15；原单核验补齐到 15 后实时可用 15，不再次扣旧差额。
- 补货立即执行；两人点击只发送一次；订单重新同步无法在出库发送窗口改变保留代次；legacy 模式不被手动操作切换。
- 桌面 1440px、手机 390px 的真实 Vue 组件以合成 API 检查按钮权限、加载禁用、缺货反馈、超时反馈、成功刷新和单列显示。真实小满的占库与人员操作属于发布后的固定对象业务验收。
