# 预售：定金、预付货款与当批明细

状态：业务规则已由亮哥确认；金额模型、迁移、API、页面及出库资金引用已实现并进行隔离回归。**尚未合并、推送或部署本规则调整。** 已完成一次专用小满联测并清理；未实测路径见下文，不能把本文件当作已上线说明。

## 已确认的规则

1. 全部是先付款后发货的预售，不提供赊销或欠款放行。订单名称中的“赊销”不能改变资金规则。
2. 实际付款必须明确用途：**定金**只抵最后一批，**预付货款**可以从第一批开始抵扣商品、包装、手续费和运费；可以收多笔、部分或全部货款。付款不必绑定尚未确定的发货明细。
3. 每次填写当前实际发货明细。业务员人工确认“最后一批”，不能因为当前填写的数量全部发完就自动判断末批。
4. 出库时引用原真实回款，记录本批占用及实际核销；不把扣余额当作又收一笔钱。不足额则显示需要补付的金额，款项生效且足额后才派发。
5. 已发批次的产品、数量、价格、金额、原收款及远端出库 ID 保留。改当批明细不改历史出库，也不把旧的小满产品行 ID 复用到新商品。
6. 末批优先使用定金，再用预付货款。定金超过本批商品及相关费用时，只抵应付范围；超出部分继续列为客户余额，不隐式退款、作废或转到其他订单。定金不抵独立运费，预付货款可以。
7. 收款金额、原银行手续费、日期、凭证是已发生的付款事实，修改产品不重算它们。原银行手续费只能核销手续费部分，不能作为商品或运费现金；剩余现金本金可支付本批全部应付费用。

## 接入实现约束

- 初始自动回款意图增加付款用途和原手续费事实；收款页面支持订单级预付，不强制选择发货结算。首款、后续补款走同一资金分类。
- 页面分别显示已生效预付、末批保留定金、已占用、已核销、剩余本金/手续费和本批补付。待同步/失败/待核对的收款占登记额度，不计可发货资金。
- 编辑器仅编辑当批产品；后台保留历史产品行和不可变结算快照。远端主单保留历史关联行，追加当批行。历史行的总额与未发数量如何投影，必须与外部回读一致，不能用虚拟销售项目凑金额。
- 报价包含人工末批标记、明细版本、资金用途、原回款版本与全部非释放分配的摘要。创建时按订单、回款、分配固定锁序重新核验；两批不能重复消费同一余额。离线模型只产出建议，不代替这些锁、当前授权或远端取证。
- 每笔收款的累计 reserved/applied 原额及手续费分别受上限约束。取消未出库结算释放占用，保留真实到账；未知远端结果先查原单，禁止重复创建。已经实际出库的分配不得通过普通取消释放。
- 运费继续是独立销售应收目标，但预付抵扣以原付款来源核验。显示“方舟预付抵扣”，不伪称“小满运费回款已登记”。商品、运费、历史出库、确认实际出库和定期复核统一按真实 Receipt 的目标取证；不得仅删除旧保护检查。
- 重新分类只允许无活动/已核销分配的款，当前 `receipt:write` 与订单数据范围必须实时复核，保留理由与前后用途。已有 shipped 分配的改类需专门受审计纠错，不提供任意编辑。

## 尚未验证的小满契约与专用验证方案

[官方订单编辑接口](https://open.xiaoman.cn/api-3478252)支持传原产品行 `unique_id`、追加行及明确删除行；[官方回款接口](https://open.xiaoman.cn/api-3478278)支持关联订单。两份文档都未明确证明“已有回款时降低订单总额至已收款以下”的租户实际行为。仓库既往联调也未覆盖此情形，不能据此放开生产金额守卫。

由于项目已有集成规则确认小满没有独立沙箱，验证会产生正式租户中的测试业务单据，需要亮哥覆盖该动作的授权。拟定范围如下，全部使用唯一 `ARK-PRESALE-ROLLING-<timestamp>` 标识，不使用真实客户或 `981`：

1. 创建一名专用测试客户、一张 USD 0.03 商品订单、一张 USD 0.03 测试回款，回读客户、币种、金额、状态及精确 ID；无真实银行转账。
2. 编辑测试主单，将明细金额改为 USD 0.01，保留原产品行 ID；验证订单实际金额降低、回款 ID/金额/日期仍原样。
3. 创建一张状态 1 的 USD 0.01 **待出库**单；只测试待出库关联，不确认实际出库。待出库仍可能预占库存，必须回读创建前后的库存/占用，限定专用测试产品及仓库，清理后验证占用恢复。
4. 保留关联旧行，追加新当批产品行，使订单总额 USD 0.02；回读旧行 ID、新行独立 ID、原待出库关联及回款总数/金额。
5. 全部写前落盘意图，成功后保存精确 ID；结果不确定只查原标识。按精确 ID 依次清理测试回款、待出库单、订单及客户，并通过活动列表验证。若当前 API 不支持删除测试回款，需亮哥在小满清理该**测试回款**；不得自动改零或挪到真实订单来掩盖残留。

本次范围已获授权并实际执行，标识 `ARK-PRESALE-ROLLING-20261009-155340`。主单0.03降为0.01后原回款仍0.03、日期和ID未改；旧产品UID保留、同SKU新行取得独立UID，关联待出库仍在。删除待出库后可用库存从9922恢复9923，实际库存全程9999。亮哥删除测试回款后，通过两次完整活动列表确认已移除，再删除订单及测试客户，日志最终为 `cleanup_complete`。软删除回款详情仍可查询，不能以详情404作为唯一删除证据。

官方订单文档明确允许无 `product_list`，但本租户零产品首推、新建回款直接超过当期明细金额、实际出库之后缩减历史原行数量尚未实测。保留旧超额回款不能证明新建超额回款可接受，待出库通过也不能证明实际出库路径。不得用虚拟商品、改写真实手续费或零净额回款绕过接口限制。

亮哥明确选择“暂不补测，保留未验证限制”；本轮不再创建新的小满测试客户、订单或回款。继续完成已授权合并、推送及统一部署，供应商拒绝或证据不足时保留原单与错误，不推定同步成功。
