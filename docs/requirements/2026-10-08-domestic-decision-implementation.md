# 内贸经营决策台实施与验收

依据：已确认的功能设计和七页签原型。目标交付 P0-A、P0-B 的真实数据功能；P1 的预测与历史时点能力按证据门槛保持不可用，不编造历史。

1. 分析内核：当前客户归属权限、有效业务订单、同明细多条件、不可重复的金额/件数、账本桥接、画像和规则。隔离 SQLite 回归覆盖主表/明细、资金符号、日期、缺失维度及越权。
2. 持久闭环：分析快照、证据版本、个人视图、行动状态与结果、按需简报、私有导出、人工分析映射。原订单/客户/账本变更同事务记录必要事件。
3. 真实页面：沿用高仿原型组织七页签，接入服务端口径、筛选、下钻、画像、质量抽屉、行动与简报；资金能力随权限裁剪。
4. 集成验收：迁移在隔离库验证，关联内贸回归、前端构建、关键 UI 路径、独立风险审查、项目约定检查与本地 Git 巡检；更新接口、数据库和交接文档。

分工：分析内核由独立实现代理负责；主代理负责模型、事件、迁移、持久状态、路由及集成；内核契约稳定后实现前端。每段实现核对设计范围，再按资金、权限、并发与前后端契约审查质量。

本次追加授权为提交、合并和推送；生产部署、迁移和角色授权不在本次执行范围，仍走统一部署流程。

## 实际交付与验证

P0-A/P0-B 功能已在独立分支落地。页面入口 `/domestic/decision`，后端模块 `backend/app/domestic_decision`，前端模块 `frontend/src/views/domestic_decision`。分析只使用授权客户的有效业务订单与历史明细快照；资金单独核验权限和截止时点，不继承产品条件造成错误资金圈。

持久状态包括分析运行、映射、配置、变更事件、视图、行动、后台任务。行动用业务信号与幂等请求防重，客户转交重新校验归属，条件变化暂停旧建议；完成必须记录实际结果。自然语言先生成受约束的查询计划，由用户核对后应用。AI 无权新增数字、事实、客户或自由文本结论。

## 发布前边界

本次交付覆盖合并推送，不包含部署。发布需统一入口执行174迁移、配置真实历史覆盖起点和分析标准、按职责授予新权限；AI preset未配置时规则仍可用。迁移拒绝删除已产生的事件、行动和报告，后续修复使用前向迁移。

真实数据库质量体检、十万订单/五十万明细/百万账本和二十并发性能目标尚未验证；现阶段不能据此承诺生产P95。尤其需核验大范围分析证据JSON体积、数据库包大小、全历史读取和MySQL锁竞争。P1可靠预测、历史时点重建、订阅通知和跨团队模型未启用。后台任务中断十分钟后显式失败，用户可重新生成，尚不支持跨进程自动续跑。
