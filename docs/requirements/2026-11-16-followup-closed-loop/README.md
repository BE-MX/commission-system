## 一、要解决的问题

现在的跟进只有「录结果」这一步：联系前全凭业务员自己准备；录入是一张通用表单，不管什么情况都填同样几项；AI 只把原文整理成摘要，下一步得业务员自己想、自己填日期，而且一条记录只能生成一张待办。

本需求把跟进做成闭环：

```
待办到期 / 客户卡片
      │ 准备
      ▼
① 准备卡：选场景 → 背调（自动带出上次已知）→ AI 给策略、开场白、3 个关键问题
      │ 沟通完了，记结果
      ▼
② 引导录入：准备的问题逐个标「问到了 / 没问到 / 客户没回」，按场景只提示该记的几项
      │ AI 整理
      ▼
③ 核对：客户说的 / 业务事实 / 我的判断 / 待确认 分开，每条可看出处；
        下一步清单（谁、做什么、何时或何事后、依据），勾选采纳
      │ 提交
      ▼
④ 待办：主下一步 = 约定跟进；其余 = 行动待办（可手动完成）──► 到期回到 ①
```

**成功标准**：
- 业务员打开准备卡，一分钟内知道这次找客户为什么、第一句怎么说、先问什么。
- 录完一条记录，下一步自动变成待办，不用再手抄。
- AI 的猜测不会冒充客户说过的话，也不会悄悄变成任务。

**不做**：AI 联网背调、长期客户画像库、自动对外发消息、回改历史记录、改跟进频率 / 公海 / 绩效统计口径、给业务员排名。

## 二、决策（2026-11-16 亮哥均已确认）

| # | 决策 | 对用户的影响 |
|---|---|---|
| D1 | 背调存在准备卡里，下一张卡自动带出上一张的事实，暂不建长期画像库。外贸那套 `customer/fact_service` 锚定统一客户档案、只收官网来源，不直接套用到内贸门店 | 背调一张卡一张卡往下传；超过 90 天的事实标「可能过期」 |
| D2 | AI 只用业务员填的内容和系统已有数据，不联网 | 公开账号上看到的信息由业务员贴进背调，并写上观察日期 |
| D3 | 下一步必须业务员勾选才生成待办。默认勾选的只有一种：原文里能找到出处、而且有日期的客户约定。截图来源的、事件型的、我方承诺、我方计划和 AI 建议都默认不勾；其中原文里有出处的我方承诺会提示「你已向客户承诺，建议采纳」 | 常见情况一键提交；AI 的猜测不会变成任务；对客户做过的承诺不容易漏掉 |
| D4 | 模板（T01–T10）由管理员在后台维护，带版本；首批随迁移预置 | 改模板立即生效；历史记录按当时的版本展示 |
| D5 | 主下一步沿用约定跟进 `plan`，其余生成新类型「行动待办」`action`。只要采纳了任何一条下一步，就必须有一条主下一步 | 编辑行为和「约定兑现」「留下一步」统计口径都不变 |
| D6 | 行动待办只能手动完成，必须写一句完成说明；取消也要写理由。新的跟进记录不会自动关闭它，录入时可以「顺便完成」 | 「寄样」这类事做完就能关，并且有记录 |
| D7 | 分期：地基 → 下一步转待办 → 准备卡 → 引导录入 | 最先上线的是「录完自动出待办」 |
| D8 | 客户当前负责人（托管客户取当前主要跟进人，未托管客户取归属销售）可以只读查看该客户的全部准备卡（含前任的背调、策略、话术和草稿），并能「基于此卡新建」；只有作者能修改。作者失去该客户的可见范围后，也看不到自己写的卡 | 交接后不用重新背调，也不会重复问客户、重复承诺；客户转走后资料不会跟着人走 |

## 三、分期

| 期 | 交付 | 业务员能感知到的变化 |
|---|---|---|
| 一 地基 | 模板表与后台、修复洞见漏读 | 暂无（管理员可以开始调模板） |
| 二 下一步转待办 | AI 给出多条下一步，勾选后生成约定跟进和行动待办；行动待办可以完成、改期、取消 | 录完自动出待办 |
| 三 准备卡 | 选场景、背调、策略与话术、历史卡只读 | 联系前有准备、有开场白 |
| 四 引导录入 | 问题回填、场景字段、四类事实与出处、缺口追问 | 录入更快，记录更清楚 |

各期改哪些文件、测试什么，见 [implementation.md](implementation.md)。

## 四、验收（摘要，完整用例见各期测试清单）

- **A 策略**：
  - 最新记录是客户拒绝时只给停止建议；拒绝是同事记的、调用人看不到原文时也一样。
  - 有未处理完的紧急售后时，先处理售后。
  - 编造的记录 ID 被删除；编造的数字标黄，原始金额表达保留。
  - 前任的卡新负责人只能看不能改；第三人打不开。
- **B 整理**：规范 `agent-rules.md` 第 7 节的 22 个用例，例如：
  - 只写「未回复」时不推断原因。
  - 说话人不明的标为待确认。
  - 截图转写的内容标「待核」。
  - 补录原话里的「下周三」按跟进日换算。
- **C 待办**：
  - 3 条下一步生成 1 张约定跟进加 2 张行动待办，重复提交不重复生成。
  - 编辑记录不影响行动待办；统计口径前后一致。
  - 补录和只有待办权限时提交下一步被拒。
  - 释放到公海时行动待办关闭（托管和未托管客户都覆盖）。
  - 新的跟进记录不能关闭行动待办。

| 规范位置 | 建议 |
|---|---|

| `record-templates.md` 6「提交前自检」 | 模板字段只做提示、不拦截提交，与系统设计一致；明确「下一步处置（等待客户 / 暂停 / 关闭）」在没有下一步时选填 |
