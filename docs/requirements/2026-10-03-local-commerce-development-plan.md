# 方舟交易主系统开发与切换验收计划

目标：在独立分支实现 2026-09-30 设计中的全部相关业务，在隔离本地环境创建数据结构并完成端到端闭环；最终交付可承接小满交易业务的切换候选分支。只保留小满客户维护及必要客户同步。

基点：main d9266945（2026-10-03 核对）。分支：codex/ark-local-commerce。原设计归档于 [分析设计](2026-09-30-ark-crm-only-analysis.md)。本计划不以开发阶段完成代替整个目标完成；当前执行进度只维护在 docs/handoff.md。

## 固定约束

- 现有订单/回款/预售/半成品/检验及内贸能力保留，通过本地主数据和账本衔接。不得另建平行销售订单主账。
- 使用现有 FastAPI 模块化单体、SQLAlchemy、Alembic、Vue 和权限框架。新增业务在领域模块。
- 不连接生产库运行迁移/写测试，不读取或复制主目录 .env；本工作树使用独立本地库。禁止真实小满交易、邮件、钉钉和物流外发。
- 远端 push、合并 main、生产发布不在本次授权内。新迁移查所有分支编号、单 head、创建后精确暂存。
- 稳定本地 ID、币种/单位、金额来源、业务时间、历史状态不得猜测回填。缺失身份或不确定远端动作进入人工核验队列。
- 历史归档/期初承接/新业务分开导入；不重放历史库存和资金过账。已付提成不重复计提。
- 切换模式须覆盖所有交易写入口和后台任务，不能只隐藏按钮或把远端失败伪装成功；本地模式不向小满交易接口回退。

## 测试与发布候选判据

1. 快速测试以现有 pytest SQLite fixture 为基础，重要新行为先写能失败的回归；不修改既有断言掩盖问题。
2. SQLite 不能证明 MySQL 锁和 DDL 正确，必须另跑隔离 MySQL 多连接并发、迁移、完整链路。
3. 禁止从生产导入敏感原始资料；使用覆盖真实形态的合成历史数据。生产数据覆盖率/切换期初仍需实际切换前对账，不用合成测试冒充。
4. 前端复用 navigation、clients、tokens、现有列表模式；实际 UI 开发前读取 DESIGN 和指定设计 skill。
5. 最终生成逐项证据报告，记录命令、基点、数据库版本、结果、限制；约定检查覆盖整个分支改动，不用空 diff 报通过；运行 git_sweep --no-fetch。
6. 独立审查覆盖库存并发、资金、迁移、权限和跨模块契约，修复后重验。目标未满足时保持 active，不因计划/分支/局部测试完成而标记 complete。

## 资金实施约束（独立设计审查补充）

- 复用 `ReceiptBatch → Receipt → Receivable`：付款主记录允许没有分配；分配有独立命令身份，登记不等于确认到账。Batch补独立确认状态/操作者/时间/生效日、账户和银行流水身份、实际银行费用/净到账及冻结折算口径。纯预收访问按客户/财务权限判断，不再依赖子Receipt存在。
- 历史 `Receipt.bank_charge/ReceiptBatch.bank_charge_total` 来源于客户附加费分摊，必须保留原口径；真实银行费另字段。公司承担费用时“付款1000、银行费20、实际到账980、核销1000”必须通过。客户附加费和实际银行成本不能重复扣减提成。
- 取消 `(batch_id,receivable_id)` 唯一分配限制，改操作级唯一身份，允许撤销后再次分配到同一应收。撤销用关联原分配的事实累计，不覆盖原金额；退款与分配释放分开，退款不自动减少应收。贷项/应收调整同样保存不可变业务依据和金额。
- 银行经济身份以账户+真实流水号唯一，请求键只防重放；没有真实流水号不能伪造。确认、分配、撤销、退款和应收调整保存付款级审计（原ReceiptLog不能记录空预收），锁定后验证付款/应收/退款守恒。
- 使用统一应收获取口径：商品键 `invoice:{id}:goods`，普通订单运费 `invoice:{id}:freight`，分批运费 `settlement:{id}:freight`。本地商品应收已剔除独立运费；旧获取函数不得再生成第二份整单应收。
- 全资金与履约入口统一锁序：资金账簿→订单ID升序→付款ID升序→应收ID升序→发货结算ID升序→分配/占用ID升序→附件。资金采用单账簿串行事务，保障跨表银行流水身份与期间关闭一致；库存事务不申请资金账簿锁。先取得完整集合再读取当前余额，不能依赖权限查询建立的旧RR快照；无分配的预收也必须锁付款头。
- 历史来源映射保留旧提成消费身份；新本地分配使用独立稳定事件ID并冻结USD折算和费用口径。退款通过关联原事件的调整进入提成，不删除已确认提成或将历史付款重新导入为可计提ID。
- 必须同步 `receipt/batch_service.py` 的空预收权限、附件路由、`settlement_schemas.py` 的全额分配限制、`receipt/service.py` 和 `invoice_link.py` 的无Batch创建路径、余额/资金放行及提成消费者。外部客户同步继续保留。
