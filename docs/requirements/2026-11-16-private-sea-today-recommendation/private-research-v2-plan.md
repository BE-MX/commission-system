## 三、总体结构

```
私海助理「重新背调」按钮 ─┐
管理员批量补齐 ───────────┼─→ 方舟研究任务队列
                          │
北京 OpenClaw 背调 Agent ─┘  每次领一个任务
  ├─ 自带网页搜索 / 打开网页 ──→ 新加坡出口代理 ──→ 境外网站
  ├─ ark_monid_run（新）──→ 方舟后端 ──→ Monid（白名单接口、预算记账、结果自动入库为事实）
  ├─ ark_username_scan（新）──→ 方舟后端 ──→ Maigret（经新加坡出口）
  ├─ ark_append_research_facts（扩事实类型）
  └─ ark_complete_research_task（新结果格式：完整报告 + 结论 + 引用）
                          │
方舟后端校验报告 ─→ 对不上入库事实的精确信息标「待核实」
                          │
私海助理背调页 ─→ 渲染完整报告，未审核加标记
```

关键设计：**Monid 和 Maigret 由方舟后端调用，不让 Agent 直连。**

- 密钥只在后端配置，Agent 拿不到。
- 预算在数据库里记账，调用前预占额度，不依赖 Agent 自觉或本地文件。
- 只开放白名单里的只读查询接口。Monid 目录里有打电话、开邮箱、生成视频等接口，Agent 直连就能自己发现并调用。
- 调用结果由后端保存原文，Agent 无法篡改。

**调用顺序（A7）：**

| 线索类型 | 顺序 |
|---|---|
| 明确公司实体（公司名、官网、企业邮箱） | 网页搜索与官网 → 用户名扫描（发现社媒号时）→ 结束。不调 Monid |
| 弱线索（人名、个人邮箱、社媒号、平台昵称） | 网页搜索 → 用户名扫描（从邮箱前缀、社媒号、人名变体提取用户名）→ 仍缺主体、职业身份、联系方式、社媒活跃度时才调 Monid |

Maigret 只给出「这个用户名在哪些平台存在」的候选账号，不返回主页内容；需要粉丝数、简介、近期帖子等内容时，先用打开网页获取，拿不到再由 Monid 补。

**结果先存为「待绑定证据」，不直接记到客户名下。** Agent 可能传错 LinkedIn 链接或社媒账号；后端先存原始结果并返回证据编号，Agent 确认主体一致后，再经现有的事实写入流程转成本次任务的事实，引用照现有规则绑定本次运行。主体对不上的证据不进客户档案。

**Monid 与用户名扫描是异步调用。** 侧车请求最长 120 秒，Monid 单次可能等 3 分钟，Maigret 默认 3 分钟，同步调用必然超时，重试会重复扣费。改为「提交调用 → 返回调用编号 → 查询状态」，带幂等键，同一调用不会扣两次费。

**代理只用于外呼客户端。** 新加坡出口只给 Monid 网关、用户名扫描服务和 Agent 的打开网页工具使用；模型调用和方舟接口不走代理。

## 四、分阶段实施

### P0 基础设施（需亮哥或运维操作）

| 事项 | 说明 |
|---|---|
| Monid 公司账号 | 现有 Accio 用的是个人账号。方舟需要公司工作区的服务端密钥，并在 Monid 后台设置月度预算上限和单次调用上限 |
| 新加坡出口代理 | 在新加坡机器部署只监听内网/隧道地址、带认证的正向代理；北京背调 Agent 进程和后端的 Monid、Maigret 调用经它出网。在 `deploy/platforms.json` 登记为出口设施，不登记为服务 |
| 连通性验证 | 北京经代理访问 monid.ai、Instagram、Google、LinkedIn；OpenClaw 当前搜索服务（parallel-free）是否可用 |

新加坡只做出口代理，不运行任何已迁到北京的服务，不违反 Agent 单活规则。跨境出口对境内服务器仍有合规与云厂商条款风险，本方案按亮哥决策执行，风险由业务侧承担。

### P1 后端

1. **事实类型与来源登记**：在现有 4 种官网事实之外，增加社媒主页、地图商家、评论、LinkedIn 公司与个人档案、个人职业身份、个人联系方式、海关记录、工商登记、域名注册等可入库类型。来源登记表新增 Monid（按上游供应商区分）和用户名扫描两类来源，否则新事实会被一律判为最高密级。事实输入校验里写死的「只接受公开公司页面」要放开。「已核验平台」级别已在用，需新登记的是「次级公开来源」。
2. **任务输入带上个人联系人**：私海任务现在只把公开与内部级别的联系人发给 Agent，个人邮箱和联系人姓名根本传不过去。改为包含个人联系级联系人，并改写任务书里「不猜邮箱、不调查私人关系」等条款。
3. **新结果格式**：完整报告正文（Markdown，Client Scout 骨架）+ 结构化结论 + 引用 + 缺口清单。缺口不再走单独的「资料不足」提交路径：那条路径要求本次运行零事实，只要调过一次 Monid 就走不通。策略版本号目前在三处写死，统一成一个常量。
4. **报告校验**：后端检查报告中的邮箱、电话、链接、人名和数字，能对上本次入库事实的保留，对不上的自动标「待核实」，不拒收整份报告。
5. **私海助理读取口径**：现在只放行「已审核/免审」且只认旧结果格式，并把「已审核」写死为真。改为同时读新格式、未审核也可读并如实标注。数据级别不用改：业务员对本人客户本来就能读个人联系级数据；改权限层会波及客户档案、MCP 网关等所有读取方，不要动。
6. **用户名扫描服务（先做）**：Maigret 作为北京独立服务部署并登记到 `deploy/platforms.json`，不放进后端公共依赖（办公室那台 Windows 后端不装）。经新加坡出口访问，没有出口时 80～90% 的站点会连接失败。结果入库为「待核验候选」级事实，保留新版 agent 的假阴性判据：命中为零且连接失败率不低于 50% 时只能写「用户名扫描不可用」，不能写「未发现账号」。
7. **Monid 网关服务（后做，规模缩小）**：只对弱线索任务开放。白名单接口：Instagram / TikTok / Facebook 主页、LinkedIn 个人档案、Hunter 域名邮箱。地图商家、评论、腾道海关等偏公司实体的接口不进初版白名单。按接口设单次预算上限，调用前预占、完成后结算；异步调用与幂等键；待绑定证据存储。需要数据库迁移。

8. **任务调度**：
   - 重新背调时，把该客户未审核的旧任务标为已被取代。现在会直接复用旧任务，按钮会长期无效。
   - 研究任务加优先级，业务员点的重新背调排在批量任务前面。现在是先进先出。
   - 批量创建入口新增「有订单、未背调」筛选，现在没有。
9. **运行档案**：背调运行档案的工具白名单加上 Monid 与用户名扫描两个工具，技能清单升版本。
10. **配置与权限**：Monid 密钥、代理地址、预算上限进 Settings 与 `.env.example`；新增 Monid 花费查看的权限点（按「新增权限三步」）。
11. **触发入口**：私海助理客户详情的「重新背调」接口（本人客户、`client_desk:write`、同一客户冷却期）。

### P2 Agent

1. 新技能 `ark-private-research`，从 Client Scout 移植：明确公司 / 弱线索双轨、来源地图、发制品客户分类、五级证据分级、停止条件、报告骨架、Monid 使用规则（URL 优先、搜索类接口需理由）、Maigret 假阴性规则、个人检索流程。
2. 删除：AiReach 基线、OKKI 回填、TeamLeader 路由、日记记忆、话术成品。
3. 方舟 MCP 侧车增加 Monid 与用户名扫描两个异步工具（提交、查状态、确认绑定）；侧车把当前任务租约带给后端。
4. 引导脚本安装新技能；侧车与自动化策略的验证脚本和测试同步更新。
5. 并发：侧车同一时间只持有一个任务、每轮只领一条、心跳当前未开启。批量补齐前需开启心跳，并用多个 Agent 身份并行；实施前给出产能估算（单客耗时 × 客户数 ÷ 并行数）。
6. 改写 Agent 模板与心跳说明里与新规则冲突的条款（「禁止拼接个人姓名与邮箱检索」「个人邮箱只是线索」等）。
7. 私海任务的任务书从 4 项扩到完整报告的全部章节。

### P3 前端

1. 私海助理背调页渲染完整报告，「待核实」内容有明显标记；未审核报告显示「未审核」标签。
2. 客户详情加「重新背调」按钮，显示进行中、上次背调时间、冷却剩余。
3. 管理员侧显示 Monid 花费（按客户、按日）。

### P4 试点与批量

1. 选 Rina 的 20 位客户，其中 10 位为此前空结果。Accio 对同一批客户各出一份报告作对照。
2. 及格线（由亮哥和 Rina 评判）：
   - 原空结果客户中，至少 6/10 能确认主体并出报告
   - 报告中「待核实」的精确信息不超过 20%
   - Rina 逐份评分，至少 15/20 认为「不差于 Accio」
   - 单客户平均花费（Monid + 模型）不超过 $0.20，平均耗时不超过 15 分钟
   - 用户名扫描的连接失败率中位数低于 30%（验证新加坡出口可用）
   - 弱线索客户中调用 Monid 的比例与花费单独统计，用来判断是否需要扩白名单
3. 达标后对全部私海按业务员分批补齐，每批设花费上限。

## 七、风险与未核实

- 北京经新加坡出口的稳定性、速度未测。
- OpenClaw 当前用的是 parallel-free 搜索服务，结果质量是否接近 Accio 的 Exa 未测；如不够，可在 Monid 白名单里加搜索接口。
- 北京 OpenClaw 当前主模型为 mimo-v2.6-flash，长报告写作能力未验证；可能需要换更强的模型，成本会上升。
- 个人信息采集不设限：若客户投诉或当地监管问询，方舟没有删除与查询个人数据的流程。建议至少保留「按客户删除背调数据」的管理入口。
- Monid 是两层第三方（Monid 和上游供应商），社媒抓取类接口的稳定性取决于上游。
- 批量补齐的总花费取决于私海规模和弱线索占比：只有弱线索客户会用 Monid，按单客上限 $0.15 估，每 1000 家弱线索客户约 $150，另有模型费用。
- A7 的代价：明确公司实体的客户拿不到 Monid 的地图、评论、海关数据，只能靠网页搜索和官网。试点后如发现这类客户报告仍薄，再评估是否对公司实体开放部分接口。
- Maigret 完全依赖新加坡出口：出口不稳时，用户名扫描大面积假阴性，弱线索会被迫更多地落到 Monid，花费上升。
- 吞吐：一次一个任务的结构下，几千家客户可能要跑数周，需在实施前实测单客耗时再定并行数。
