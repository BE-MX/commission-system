## 构建与代码组织

客户站建议使用现有 Vue 3 + Vite 依赖体系，独立 `frontend-portal/`，避免把员工路由、私有权限和整套后台 bundle 暴露到客户入口；不复刻参考站的 React/Cloudflare D1 存储作为第二业务真相源。先验证现有锁文件与 Node 支持版本，再固定依赖，不为样式额外引入大型动效库。

客户 API 统一在本应用 `src/api/client` 使用同源 fetch、credentials、CSRF 和统一错误转换，不引用主站员工 token 注入逻辑。主站门户管理页必须从现有 `frontend/src/api/clients.js` 登记 portalAdminClient，路由与菜单仍通过 navigation.js，按钮使用 v-permission/v-any-permission。不得在 `/m/` 增加新领域。

组件按职责组织：PortalLayout、ProductCard、VariantPicker、OrderSummary、DeliveryForm、ProposalDiff、OrderTimeline、InvoicePanel；composables 管理 catalog/cart/session/order request。购物车存客户端选择，不保存可信金额或员工身份。未登录时清除私密缓存；多标签页通过 BroadcastChannel 或 storage 登出信号清空，不能只刷新当前页。

## 品牌和素材

从原型提取品牌黄、方舟金、暖白、深墨色、文本/边框/状态语义变量到客户站 `styles/tokens.css`，所有组件只引用变量。主站管理端继续使用既有 tokens 与 DESIGN.md；二者共享品牌含义但不强制共用布局或动效组件。

Logo 使用用户原始文件，保持比例；生产应准备经确认的透明/横向品牌版本，不能重绘改变字标。色卡原图包含标准色号时，展示别名可能产生冲突；正式资产采用无内嵌旧标签的品牌源图。客户自定义名称不嵌入图片，使用文本渲染。图片必须有明确商品关联与访问级别，不能因为知道图片 URL 就取得未公开的客户配置。

英文标题采用清晰、克制的品牌字体，正文保证可读；优先自托管已获授权字体和子集，网络字体失败时布局不跳动。高频筛选和数量操作不延迟显示；低频 Hero、弹层可使用有意图的短动效。hover 动效仅精细指针启用，遵循 reduced-motion，禁用大面积持续模糊动画。

## 浏览器状态与恢复

报价缓存键包含账号、access 版本、目录版本、映射版本、购物车 hash；注销立即清空。GET 请求可有限重试，POST 必须依据该动作幂等契约，不由通用 axios 重试器盲重试。

提交后冻结的 operation 保留 `key, payload, customer_scope_marker, submitted_at`；可存 sessionStorage 仅用于当前会话恢复，不含邮箱验证码、Cookie 或不必要个人资料。跨账号后不能恢复上一账号操作；服务端以 auth scope 保证真正隔离。地址含个人资料，优先仅留内存；若刷新恢复，客户端只存 key，重新登录后回查已接受请求。

前端初始化以 `/session` 成功且 me 已加载为判据，不能以“本地有一个 token 标记”判登录成功。切换账号中止旧 fetch/轮询；晚返回响应带 scope 标记，不匹配则丢弃。BFF 不在服务端全局变量中缓存“当前客户”。

## PDF 下载续体的身份边界（I18）

接受/拒绝提案和PI、取消的客户端响应必须核原request_id、规范原/当前row_version（精确整数且current>=original）及受控current_state。提案另核冻结revision_id/content_hash和原接受ready_for_review/拒绝submitted；取消原cancelled。PI原回执无status，另核revision/hash/invoice_document_version匹配冻结bound_invoice_document_version及当前amendment_state=current/withdrawn/pending_customer/accepted。原回执version不能强制大于发送If-Match，成功回放优先于新命令版本校验；当前已发布/撤回或后续提案不抹除原成功。拒绝过期提案仍允许。

不完整/错对象/错修订/hash/文档版本/非法版本的POST响应保持uncertain，不允许新动作；仅核对当前原request_id。GET本身永不作为命令成功回执，异对象及非法状态/版本不进入latest展示，GET期间换身份保持已发送命令uncertain且清迟到数据。组件仅验证现有可见字段，不独立证明未返回的actor/动作/原因摘要；真实性仍由当前服务端授权、自然键/完整载荷冲突及原子保存保障。此版未新建端点、表或响应字段，没有把本地字段校验扩写为完整交易证明。

operation冻结数据仅内存；刷新/关tab/清存储后不能重建原reason或POST，本版不提供耐久恢复保证，不因GET状态相似自动宣称成功。端到端真实接口和当前权限联调仍须单独完成；T49–T50/T64不因105前端测试或合成API浏览器局部通过整体关闭。
