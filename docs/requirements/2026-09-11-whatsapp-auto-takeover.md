# WhatsApp 自动接管 v1.6.0

2026-09-11，用户明确授权新增当前聊天自动生成并发送；本轮实现与合成测试，不向真实客户试发、不部署。本版本包含未合并的1.5.1能力修复、1.5.2历史复用和1.5.3标签页布局。

## 使用

话术旁新增「自动接管」按钮，默认关闭。先处理输入框原稿，可在话术的「调整生成要求」填写本次目标；点击后只对当前一对一前台聊天生效。按钮变为「停止接管」，下方显示状态。约3秒没有新客户消息后开始生成；当前尾部已有卖方回复则等待客户。

自动沿用当前聊天历史缓存和后台 generator 系统提示词。后台预设本就由 app.ai.call_service 前置加入，仍是品牌口吻和业务方向的配置入口。AUTO_RULES补充先回应客户、基于历史逻辑推进一个目标、不重复问已知事项、自然简短、适度语气词/表情；模型返回 reply/wait/handoff 三种动作。reply为1–3段，每段最多400字符，通常1–2句；首段准备等待1.5秒，后续段间隔2.5秒，按语义拆分。不通过文字关键词再次拒绝整条草稿；仅自动协议和长度不合格时停止自动发送。

waiting不发送，handoff显示简短内部理由并停止；无法核实的报价、库存、付款动作等由提示词要求交人工。聊天中的草稿或卖方自述不代表已完成业务动作。真实模型的语气、引导质量未在本轮实测。

## 停止与边界

- 点击停止、人工输入/原生发送、切手动话术、修改目标或语言、切换聊天、刷新或将页面切到后台，关闭接管。回到前台不会自行恢复。
- 客户在生成/分段间追加消息，废弃旧回复剩余段，等待消息稳定后重新判断。不会重复对同一已处理客户末条生成。
- 必须确认最新边界。未知消息结构、未读取的最新媒体、采集容量超限、无法确认当前聊天等停止。短聊天仅已识别消息容器可见且无溢出时确认最新；网页完整历史仍不等于手机全部历史。
- 发送前核对聊天身份、客户消息、卖方尾部、草稿与按钮。每段只点击一次；新卖方气泡和输入框清空仅证明本地提交，不能当作送达/已读。结果不确定立即停止，不因后续新消息自动重发。
- Web Locks限制同一浏览器同一WhatsApp站点只有一个接管实例。不会跨浏览器或不同设备全局协调；同一业务对话应只在一个实例接管。
- 当前页面内状态与去重键不持久化，不保存WhatsApp标识。自动模式根据聊天历史生成，不自动关联询盘记录；后台仍只记录模型调用元数据。

## 配套后端与测试

必须配套更新后端：capabilities.reply.auto_reply_enabled=true。沿用话术启用开关、权限、配对和生成预设。未支持的后端不能启用接管。无迁移、无生产配置或预设写入；现有调用配额保持不变，限流/模型错误会停止，需人工查看状态。

请求增加 mode=draft|auto（默认draft）；响应增加 auto_action=reply|wait|handoff 和 reply_segments。普通话术依旧预览/填入，由用户发送。
