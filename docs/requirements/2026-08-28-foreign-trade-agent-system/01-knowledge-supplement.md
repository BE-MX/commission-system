# 外贸询盘到复购｜证据驱动的全链路销售方法

> 拟发布位置：KB-03｜销售打法与客户策略
> 状态：知识库补充草案，需销售负责人审核后发布
> 编制依据：2026-08-27 李宝库老师培训纪要、参训人员心得、方舟企业知识库已发布版本（读取于 2026-08-28）
> 适用范围：Hair Extensions B2B 新询盘、沉睡客户激活、样品验证、报价谈判、订单交付与复购

## 一、核心判断

外贸销售不是“把产品和价格发出去”，而是帮助客户低风险地完成一次采购决策。

完整价值由三部分组成：

1. 真实连接：客户确认对面是一个可信、负责、能持续沟通的人。
2. 决策证据：画像、需求、产品、库存、交期、质量和政策均有来源，不靠销售猜测。
3. 持续兑现：从样品、报价、交付到售后，每一步都有明确负责人、时间点和下一步。

因此，销售链路应从“介绍公司 → 报价 → 催单”改为：

线索进入 → 资格预检 → 背调与画像 → 建立真实连接 → 需求诊断 → 价值呈现 → 报价准备 → 透明报价 → 价值型跟进 → 谈判与验证 → 样品/PI → 交付 → 售后 → 复购与复盘。

培训中“陌生—认识—熟悉—信任—成交”是关系进程；方舟知识库中的 ProcurementStage 是采购进程。两者必须并行记录，不能混成一个状态。

## 二、事实分层与使用规则

每条对客内容都要区分四类信息：

| 类型 | 定义 | 是否可直接对客 |
|---|---|---|
| 已确认事实 | 来自已发布知识、当前系统记录、客户原话或经授权公开来源 | 可以，保留来源 |
| 合理推断 | Agent 根据多个事实形成的解释 | 必须写明“推断”，优先用问题向客户确认 |
| 信息缺口 | 会改变判断但尚未得到的信息 | 不补写；形成最小追问 |
| 动态承诺 | 价格、库存、交期、折扣、独家、赔付、样品费、付款条件等 | 只能在当前查询和对应权限审批后给出 |

宏观趋势、行业预测、培训案例中的百分比和收益数字不作为企业事实。没有可追溯证据的“最快”“最好”“增长 2.7 倍”“使用一年以上”等内容不得对客。

## 三、阶段 0：业务员账号与可信身份

### 3.1 账号基础

客户在阅读完整消息前，先看到头像、姓名、职位、签名和最近一条消息。账号设置必须做到：

- 使用真实姓名或经公司批准的稳定英文名，不使用 sales01 等机器编号。
- 职位如实填写，不用虚高职级换取信任。
- 头像保留本人可识别特征，真实、自然、生活化，但达到清晰、整洁、专业的基本线。
- 邮箱、WhatsApp、Alibaba 等渠道使用一致的姓名、头像、公司名和签名。
- 签名只放已确认的公司信息和有效联系方式，不堆叠未经批准的证书、客户名或夸张口号。
- 个人生活元素只用于自然表达，不以家人、孩子或客户隐私作为固定销售素材。

### 3.2 头像标准

合格头像应同时满足：

- 真人可识别：不是产品图、Logo、AI 虚构人物或过度美颜。
- 小尺寸可读：缩小到 40×40 像素或圆形裁切后，脸部仍清楚。
- 亲和但不随意：自然表情、眼神清晰、背景简洁，没有杂物和其他人抢占视觉中心。
- 与本人一致：不能改变年龄、脸型、肤色、发型长度等关键身份特征。
- 多渠道适配：输出 1:1 主图，并预留圆形裁切安全区。

### 3.3 介绍视频标准

优先准备两个版本：

- 15 秒版：姓名与角色 → 一项与目标客户相关、可验证的公司价值 → 一个低门槛邀请。
- 3 分钟版：个人与公司定位 → 客户常见风险 → LeShine 的证据与合作路径 → 下一步。

15 秒版本通常控制在 28–35 个英文词。视频目标是让客户确认“这是一个真实、专业、愿意负责的人”，不是把公司资料念完。

拍摄要求：

- 真人出镜，正视镜头，语速自然，宁可简单清楚，不追求播音腔。
- 使用真实办公、展厅、样品或工作场景，但不展示客户隐私、订单敏感信息和未公开工艺。
- 不使用无法核验的数字、客户名、承诺和比较结果。
- 字幕与口播一致；背景音乐不得盖过人声。
- 结尾只给一个行动，例如“告诉我你主要使用哪种接发方式，我帮你先确认适合的测试方案。”

## 四、阶段 1：线索接入与资格预检

### 4.1 原始信息先保存

任何标准化询盘都可能来自高潜客户。系统先保存原始询盘、来源、时间、页面/SKU、账户标识和客户原话，再进行分类，不能因为邮箱、模板化表达或个人账号直接判低价值。

### 4.2 排除预检

先按照现有 ExclusionStatus 规则判断目标产品范围：

- 明确只采购 wigs、closures、hair bundles、frontals：进入 Excluded。
- 同时经营目标接发和排除品类，或关键词语境不清：ReviewRequired。
- 明确采购目标接发产品：继续画像。
- 信息不足：UnknownExclusion，提出最小确认问题。

不得根据国家、姓名、肤色、头像或种族判断产品方向。

### 4.3 首轮最小字段

首轮只采集会改变下一步的字段：

- 客户是谁：Account、Contact、国家/地区、语言与可追溯来源。
- 当前要什么：产品方法、使用场景、关键规格。
- 为谁采购：自用、沙龙安装、自有品牌、分销或教育。
- 处于哪一阶段：首次跨境、供应商探索、测试、稳定采购、扩张或沉睡。
- 下一步是什么：一个具体动作和时间，不写“继续跟进”。

## 五、阶段 2：背调、画像与客户生意诊断

### 5.1 背调目标

背调不是为了堆积信息，而是回答：

1. 这个主体是否真实，身份是否与询盘一致？
2. 客户靠什么业务赚钱，服务什么终端客群？
3. 当前采购处于哪个阶段，最可能的风险是什么？
4. 哪一项 LeShine 价值与客户当前问题直接相关？
5. 还缺什么信息才能安全地推进下一步？

### 5.2 证据等级

沿用现有企业知识：

- E1：客户原话、正式询盘、订单/合同字段、销售确认。
- E2：官网服务页、产品页、批发页、课程页、门店页等强公开证据。
- E3：社媒简介、单篇内容、名称关键词等弱公开信号。
- E4：Agent 对零散信号的推断。

High 置信度至少需要一条 E1，或两条相互独立且一致的 E2。只有 E3/E4、来源冲突或信息过时时，置信度为 Low。

### 5.3 画像与评级分开

画像回答“客户是谁、怎么经营、处于什么阶段”；S/A/B/C 评级回答“当前值得投入多少资源”。评级不能反向篡改画像，也不等于折扣、免费样品、账期或承诺权限。

画像至少包含：

- BusinessModelPrimary 与 Secondary。
- ProcurementStage。
- ProductType、UsageScenario、ProductDirection。
- CurrentSupplierPain 与 PriorityNeed。
- DecisionRole 与 BuyingCommittee。
- Evidence、Confidence、Unknowns。
- StoreRoute、NextAction、NextActionAt。

### 5.4 客户的客户

业务员不只分析直接买家，还要理解其下游：

- 沙龙：预约频率、常用方法/色号、断货损失、投诉与返工成本。
- 品牌商：目标客群、渠道、价格带、产品差异、包装和补货节奏。
- 分销商：区域、下游客户、库存方式、毛利结构和渠道责任。
- 教育型客户：课程/学员使用场景、教学套装和技术内容需求。

只有公开证据或客户确认才能写成事实。市场空间、利润和销量预测必须说明数据来源、假设和区间，不能伪装成确定结论。

## 六、阶段 3：第一次触达与三次有理由的出现

### 6.1 第一条消息的五个部件

第一条消息不追求把信息说完，只要推动对方愿意开口：

1. 正确称呼客户姓名。
2. 一句真实身份：“我是 [Name]，来自 LeShine Hair。”
3. 一条与客户公开业务或询盘直接相关的信息。
4. 一项与其风险相关的价值，不列完整能力清单。
5. 一个容易回答的问题或低门槛下一步。

不要只发 Hi、Welcome、目录和查户口式问题。第一条消息中的个性化必须来自真实证据，不能制造“我很了解你”的假熟悉。

### 6.2 联系时机

- 使用有来源的国家/地区解析 IANA 时区。
- 优先在客户当地工作时间联系；多时区国家需要州/省等更细位置。
- 不依据“清晨看手机”“如厕时间”等私人场景制定触达策略。
- 客户明确偏好的渠道和时段优先于地区经验。

### 6.3 三次触达的定义

“三次触达”不是三遍问“有更新吗”，而是三次不同价值：

- 触达 1：回应询盘 + 一个相关价值 + 一个最小问题。
- 触达 2：若未读，在合适工作时间换成更短表达，说明能帮其完成的具体判断。
- 触达 3：提供新的证据、测试建议、对比维度、可验证案例或视频邀请。

触达次数、间隔和渠道服从客户同意、平台规则和退订状态。已拒绝、退订或拉黑后停止自动触达。

## 七、阶段 4：需求诊断与关系推进

### 7.1 从陌生到熟悉

关系阶段不能由消息条数自动判断：

- 陌生：身份与用途未确认。
- 认识：双方知道对方是谁，已确认一个业务事实。
- 熟悉：客户愿意分享真实场景、痛点或决策信息。
- 信任：客户接受低风险验证步骤，并相信承诺会被兑现。
成交不是关系阶段。付款/成交只更新 `ProcurementStage = Ordered` 和对应编排状态；它不能自动把关系从 Familiar 推到 Trusted，也不能新增一个 Transacted 关系值。

### 7.2 渐进式提问

一次只问会改变下一步的 1–2 个问题，按以下顺序推进：

1. 产品与使用场景。
2. 客户业务类型和目标客群。
3. 当前供应商或经营痛点。
4. 理想结果与验收标准。
5. 数量、预算、时间和决策流程。

问完必须改变推荐内容。若答案不会改变下一步，就不应提问。

### 7.3 需求校正

客户的初始说法不等于最终目标。业务员可以基于场景提供：

- 更适合的产品方法、颜色、长度或测试组合。
- 现货、生产、替代 SKU 或分批发货的可选路径。
- 局部测试、标准安装、完整效果等不同预算方案。

校正的目标是帮助客户做正确决策，不是把单件需求强行放大为大单。

## 八、阶段 5：三分钟价值呈现

在确认客户类型、痛点和当前目标后，再进行三分钟价值介绍。标准结构：

1. 客户处境：用一句话复述客户目标和风险，邀请其纠正。
2. 相关价值：只选 1–2 个最相关的 LeShine 能力。
3. 证据：给出已发布事实、批次机制、样品验证或当前查询结果。
4. 合作路径：说明如何从低风险测试走向补货、定制或放大。
5. 下一步：提出一个可执行动作。

可使用的稳定价值主线：

- 原创与开发：从 Genius Weft 源头、研发与市场适配出发。
- 批次证明：慢染、TET 每批检测、批次追溯，把“质量好”变成证据。
- 品牌保护：配色、规格、包装、Logo、NDA 等必须按已批准项目和权限表达。
- 稳定扩张：从小批验证到持续补货和规模化生产，动态库存与交期必须实时确认。
- 市场适配：围绕客户目标市场开发产品组合，而不是让客户将就目录。

## 九、阶段 6：报价准备与透明报价

### 9.1 报价门

以下字段不足时，不得输出“最终报价”：

- 产品、等级、颜色、长度、数量、克重/包装。
- 客户用途与效果要求。
- 当前库存查询时间；若生产，当前排产和质检/出库时间。
- 目的地、物流方式、运费与可能税费边界。
- 付款方式、报价币种、有效期和审批条件。

字段不全时可以给“预算区间/报价所需信息”，但必须清楚标注不是最终承诺。

### 9.2 报价内容

报价至少分开呈现：

- Product / Grade / Color / Length / Quantity。
- Unit Price / Product Subtotal。
- Shipping；税费是否包含。
- Stock or Production。
- Lead Time 与查询时间。
- Payment 条件。
- 报价有效期、适用条件、审批项。
- 推荐的下一步，例如样品、确认规格或 PI。

报价前“先讲价值”不等于拖延报价。客户信息已足够时，应快速给出透明报价，同时解释价格对应的证据和风险控制。

## 十、阶段 7：报价后跟进

### 10.1 先识别沉默类型

报价后无回复可能是：

- 未读或联系时机不合适。
- 已读但信息太多，不知道如何回复。
- 价格/总预算超出预期。
- 正在比较供应商。
- 对质量、交期、付款或售后缺少安全感。
- 内部决策、财务审批或项目时间变化。
- 当前没有需求、已选择别人或明确拒绝。

不得把“无回复”直接等同于“嫌贵”或“失单”。

### 10.2 每次跟进提供新价值

可选价值包括：

- 按同规格整理的可比维度。
- 与客户场景匹配的样品测试方法。
- 当前库存/交期的更新，但必须重新查询。
- 已授权、已脱敏且可查证的质量/交付证据。
- 产品小计、运费、税费和毛利假设的透明拆分。
- 视频或电话邀请，用于快速回答复杂问题。
- 一个更低风险的替代方案。

禁止使用虚构竞争者、虚假库存紧张、伪造监控/发货记录或冒犯性文案制造紧迫感。

### 10.3 电话与视频

电话和视频适合解决多轮文字说不清的问题，不是强制施压工具：

- 先说明通话目的和预计时长。
- 准备客户背景、已确认事实、待确认问题和允许承诺边界。
- 听不清时礼貌请求重复或改为书面确认，不假装听懂。
- 通话后用书面纪要确认决定、未知项、负责人和下一步。

## 十一、阶段 8：价格异议与谈判

标准顺序：

1. 承接：“理解你在比较供应商和预算。”
2. 校准：“我们是否在比较同等级、规格、批次一致性、交付和售后边界？”
3. 取证：请客户提供可分享、可脱敏的规格与条款，不索取其无权披露的发票或商业秘密。
4. 解释：把原料、工艺、检测和售后投入翻译成投诉、返工、断货和客户流失风险。
5. 选择：提供经批准的等级、数量、样品或合作方式，不擅自让利。
6. 下一步：确认样品、修订报价、内部审批或结束本轮。

不攻击竞品，不放大未经证实的 1% 缺点，不用客户隐私或假资料进行“核价”。折扣、返利、年度合同、价格保护和区域政策均需按已批准规则执行。

## 十二、阶段 9：样品、接待与 PI

### 12.1 样品

样品是验证项目，不是赠品：

- 寄样前确认客户类型、预期价值、规格、签收人和测试方式。
- 让样品与未来大货使用相同的等级、颜色、长度、批次记录与验收方法。
- 状态按 Planned → Shipped → Delivered → Test Started → Result Captured → Validated / Issue / No Response → First Order / Lost 记录。
- 签收后 24 小时内确认收货并预约测试回访。
- 免费样品只能申请，不得由业务员或 Agent 自行承诺。

### 12.2 接待

现场或视频接待应让客户高效完成供应商评估，不以拖住客户、阻止比价或占用时间为目标。会前明确议程，会后输出事实、问题、决定和下一步。

### 12.3 意向金边界

培训中提到的“可退意向金/诚意金”不进入现行标准流程。若未来启用，必须先由财务、法务和销售管理共同确认：

- 收款主体、用途、退款条件、退款时限和会计处理。
- 客户显著知情且自愿，不利用沉没成本或客户不好意思退款。
- 与定金、预付款、样品费的法律和业务含义清晰分开。

### 12.4 PI

PI 与配套邮件必须：

- 主体、产品、数量、金额、币种、付款信息和交期口径一致。
- 明确客户要执行的付款步骤和需要确认的字段。
- 感谢客户投入，但不使用虚假情绪、虚高承诺或未审批保障。
- 发出前由商业规则检查和人工复核通过。

## 十三、阶段 10：付款、交付、售后与复购

### 13.1 付款后持续出现

付款后是客户风险感最高的阶段之一。按订单节点主动更新：

- 收款确认。
- 生产/备货与关键质检节点。
- 包装、发货和物流单据。
- 异常、影响、解决方案与下一次更新时间。

不能收款后失联，也不能用无实质内容的每日消息制造“服务感”。

### 13.2 售后

先共情和建单，再收集订单号、批次、数量、照片/视频、使用时间、安装和护理条件。联查留样、生产与质检记录，完成证据和审批后再提出返工、补发、更换、退款、教育或升级方案。证据不足时不预判责任。

### 13.3 成交反馈与复购

在客户完成一次真实使用或交付体验后，记录：

- 为什么选择 LeShine。
- 通过什么关键词、渠道或推荐找到我们。
- 哪个证据或服务降低了决策风险。
- 哪个环节仍有摩擦。
- 正常补货周期和下一次业务事件。

沉睡激活不只看“多久没下单”，还要比较客户历史下单周期中位数与当前超期天数，再结合库存、季节、上新、门店或渠道变化选择触发点。

## 十五、团队复盘与指标

复盘不接受“客户没反馈”作为完整结论。每个重点客户至少写：

- 背景与证据。
- 当前关系阶段和采购阶段。
- 已确认需求、未知项和阻断点。
- 最近一次动作提供了什么新价值。
- 下一步、时间、负责人和成功标准。

优先观察过程质量，而不是只统计消息量：

- 首次合格响应时间，而非机器人首响速度。
- 背调证据完整率与画像复核通过率。
- 三轮内获得有效业务事实的比例。
- 报价前关键字段完整率。
- 含“新价值”的跟进占比。
- 样品测试结果回收率。
- 报价、样品、PI、首单和复购阶段转化率。
- Unsupported claim、错误承诺和人工退回率。
- 售后首响、证据齐全和闭环时长。

## 十七、明确不采纳的培训做法

以下内容不得进入标准话术或自动化：

- 虚构“同事收到同类定制需求”“其他客户正在抢”等竞争与稀缺信息。
- 为达到高频而持续骚扰，或把被拉黑视为努力证明。
- 通过拖住客户、阻止客户比较或刻意占用一至两小时制造压力。
- 利用“客户不好意思退款”设计意向金。
- 索取客户无权披露的竞品发票、客户资料或商业秘密。
- 伪造或不当展示监控、集装箱号、订单、客户聊天和发货记录。
- 按私人作息场景、刻板文化印象或敏感身份信息定向触达。
- 把培训案例数字、行业预测、未经核验的业绩结果写成公司证据。

真正可长期复制的优势不是更强的压迫感，而是更准确的判断、更透明的证据、更低风险的下一步和持续兑现。
