# 自动接管发送按钮与完整回复（v1.6.3）

## 已确认原因

用户配合输入一个字符后，只读检查当前聊天 footer 控件属性：真实按钮为 `button[aria-label="发送"]`，子图标 `data-icon="wds-ic-send-filled"`，没有旧选择器依赖的 testid 或 send 图标。旧规则匹配 0 个，新规则匹配 1 个。没有读取聊天正文、保存真实页面截图或点击发送。

自动接管逐段填入、发送；第一段找不到按钮即停止。因此只看到长度澄清这一段，不能确定模型没有在后续段落回答其他问题。

## 修改

- 发送识别限定当前聊天 footer，支持原生 button 和 role=button 的精确 Send/发送标签及已确认图标。排除隐藏/禁用祖先，嵌套控件去重；多独立可见候选仍停止。保持聊天、最新消息、草稿内容核对和只点击一次，不重试结果不确定的发送。
- 面板保留本轮所有生成段落、各段提交状态及输入资料标题；停止后自动展开尚未完成的回复。提交仅指本地新出站消息和输入框清空，不表示对端送达。数据仅在当前页面内存。
- 生成提示明确多问题覆盖优先于简短偏好，先答资料支持的事实，再澄清未知规格。不新增语义拦截、关键词校验或额外模型调用。

## 验证与边界

构建打包、282 项单元测试通过；后端生成契约 22 项通过，三段完整返回且仅一次模型调用。27 项完整浏览器回归通过，使用合成消息，覆盖语义发送控件、多段顺序及失败后完整预览。独立审查未发现阻断项，补充了嵌套控件、禁用祖先回归和预览高度限制。

实际模型是否完整回答尚未做真实调用验证；办公室后端 SSH 连接被拒绝，未核验运行时知识绑定与预设。资料标题表示本轮输入来源，不代表模型逐条引用。原 FAQ 配置仍须正确应用，代码更新不会自动加载 config JSON。

约定检查剩余素材库 AssetTagEditor small 按钮、AssetLibrary 行数基线两项既有失败，本任务未修改相关文件。git diff --check 通过；git_sweep --no-fetch 已完成，仅代表本地远端快照。

## 使用

安装 1.6.3 扩展后重新加载扩展并刷新 WhatsApp 页面，发送按钮识别和完整预览立即生效。后端提示优化需发布本次后端代码，无数据库迁移。用户已授权合并推送；本轮不部署生产。
