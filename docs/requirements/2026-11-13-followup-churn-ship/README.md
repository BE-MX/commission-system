# 客户流失实时图（方舟甲板）设计方案

> 2026-11-13 · 状态：R1（规则预演，含认领）与 P1（态势图）已在本地实现并验证，未提交、未部署；新规则生效日默认未配置，只预演不释放。实现偏离与待定事项见文末「实施记录」。
> 原型：[prototype/index.html](prototype/index.html)（单文件，双击打开，需联网加载 three.js；全部为演示数据）。顶部深色条是原型专用的视角与海面开关，真实页面没有。原型不含 2D 降级图和看板内卡片。
> 归属：内贸订单 → 客户跟进 → 统计看板（`/domestic/followups` 第 6 个页签，[11-12 看板设计](../2026-11-12-followup-stats-board/README.md)）
> 事实依据：当前工作区源码。**未查询生产数据**，客户数量级、省份填充率、跟进记录覆盖率都是未知数（第十节）。
> v1 经独立 Agent 对照源码审查一轮，采纳情况见第十二节；**v2 未再送审**。

## 结论先行

1. **这件事现在是两个需求：一条新的业务规则 + 一张图。** 「1 个月未跟进入公海」会真的把客户从业务员名下拿走，它必须先于图、单独设计、单独上线。图只是把规则的结果画出来。
2. **新规则不能直接开闸。** 跟进模块上线不久，大量客户很可能没有任何跟进记录。规则生效当天按历史数据执行，会一次性释放一大批客户。必须有起算日和宽限期（Q1）。
3. **建议让图先上线、规则后生效**：宽限期内图按新规则「预演」——谁会掉一目了然，但不真释放。一个月后规则生效。这样图本身就是规则的宣导工具，业务员有一个月把箱子拉回来。
4. **新规则下隐喻变简单也变真了**：货箱离船舷多远 = 距释放还剩几天（两个倒计时取近的）；记一条跟进或下一单，箱子就真的被拉回去。v1 里「跟进拉不回箱子」的别扭没有了。
5. **「不断滑落」现在有真实数据了**：每天都会有客户因 30 天未跟进落海。图上放「近 7 天真实落海」回放 + 「未来 7 / 14 天」推演，都不是装饰动画。
6. **3D 不常驻看板**：看板里只占一张 2D 小卡，点开进全屏才加载 three.js；无 WebGL 或开了「减少动态」时用同一份数据的 2D 甲板图。
7. 先做单文件原型验证观感再投入。3D 的成本不在技术，在做得好不好看。

## 一、现行规则（已核实源码）

| 事实 | 位置 |
|---|---|
| 释放条件：有效日期早于「今天往前 3 个自然月」。是自然月不是 90 天，实际 89~92 天 | `domestic/customer_service.py` `_months_ago`、`PUBLIC_SEA_MONTHS = 3` |
| 有效日期 = 下列四者取最晚：已生效正式订单的最大下单日、档案里的「最近下单日期」、「首次联系日期」、建档日 | 同文件 `release_stale_private_customers` |
| 订单只算正式业务单、未删除、已过审。**待审核的订单不算** | 同上 |
| 档案里的「最近下单日期」「首次联系日期」归属人自己能改，改了同样重置倒计时 | `CUSTOMER_PROFILE_FIELDS` |
| 没有任何豁免：暂缓、S 级、新客、停用客户都照常释放 | 同上，无相关分支 |
| 触发时机：每天定时任务，**以及任何人打开客户列表时** | `schedulers/registry.py`、`domestic/router.py` |
| 释放 = 把归属清空。**有独立跟进责任的客户，释放后责任和待办都保留**（11-09 决策 D07，列表显示「公海 · 某某跟进中」） | `domestic_followup/event_hooks.py` |
| 归属变更有流水：每次变更的前后值、时间、操作人都记在分析事件表里 | `domestic_decision/event_hooks.py` |
| **没有认领流程**。公海客户只有客户管理员能改派；改派不重置倒计时，日期仍超期的会在下次任务中再次被释放 | `domestic/router.py`、前端 `views/domestic` 无认领入口 |

## 二、新规则：3 个月未下单或 1 个月未跟进

**已定**：两个条件满足任一即释放；下单本身算一次跟进。

落到代码上，每个有归属客户有两个钟，取先到的那个：

| 钟 | 重置条件 | 期限 |
|---|---|---|
| 订单钟 | 现行有效日期口径（不改） | 3 个自然月 |
| 跟进钟 | 最近一条已确认跟进记录的跟进日期，或最近一笔已生效正式订单的下单日，取较晚者 | 1 个自然月 |

两个钟的计算抽成一个共享函数，返回「释放日」和「是哪个钟到期」。释放任务、图、看板都调它。否则图上显示还剩 5 天的客户可能今天就没了。

### 落地的 6 项决策（2026-11-13 亮哥确认：全部按建议执行）

| 编号 | 问题 | 结论 | 为什么 |
|---|---|---|---|
| Q1 | 历史客户从哪天起算 | **所有客户的跟进钟从规则生效日起算，满 1 个自然月后才开始释放**；生效前图按新规则预演 | 按历史数据直接执行，没有跟进记录的客户会在第一天全部落海 |
| Q2 | 什么算一次跟进 | **任何已确认的跟进记录都算**（含未接通、未回复），不限是谁写的；订单与订单钟同口径（已过审的正式单） | 「有效沟通才算」更严格，但结果字段是 11-09 才加的，旧记录是空的。代价是可以靠随手记一条保住客户——看板的「有效沟通率」能照出这种情况，先观察再决定收不收紧 |
| Q3 | C 级客户的跟进频率是 60 天，和 1 个月规则冲突 | **把 C 级默认频率改为 30 天**（跟进设置里的配置项） | 否则 C 级客户按频率「没超期」却被释放，看板的「应跟未跟」和释放规则互相打架 |
| Q4 | 暂缓客户（约了未来日期再联系）要不要豁免 | **跟进钟暂停到约定日**，订单钟照走 | 客户说「下个月再联系」，业务员照做却被释放，不合理。不设上限的话可被滥用，订单钟兜底 |
| Q5 | 因未跟进被释放的客户，跟进责任还保留吗 | **同时结束跟进责任并取消待办** | 11-09 的 D07 是「释放保留责任」，那时释放只看订单。因为不跟进被释放却仍挂着跟进责任，自相矛盾。这一条会修改 D07，仅限「跟进钟到期」的释放 |
| Q6 | 业务员怎么把公海客户捞回来 | **补一个认领流程**：业务员可认领公海客户。~~认领当天两个钟都重置~~ → 2026-11-13 修订：**认领只重置跟进钟，订单钟不变** | 现在只有管理员能改派，且改派后会立刻再掉。新规则下每天都有客户落海，没有认领入口公海只进不出 |

另外两点不需要你定，但要知道：

- 新规则同样没有新客保护期：新建的客户 1 个月内不跟进就释放。我认为这是对的（建了不跟不如放出来），如不同意请说。
- 停用客户现在也会被释放。新规则沿用，图上不画停用客户。

## 三、隐喻映射

每个视觉元素对应一个真实字段。

| 画面 | 含义 | 数据来源 |
|---|---|---|
| 货轮 | 私海：有归属、启用中的客户 | 归属非空且启用 |
| 一个货箱 | 一个客户 | 一客户一箱 |
| 货箱大小 | 客户等级：S/A 长箱，B/C 短箱，未定级小箱 | 客户等级 |
| 甲板分区 | 市场。船身从船头到船尾按大区分段 | 省份 → 大区 |
| **货箱离船舷的距离** | **距释放还剩几天**（两个钟取近的）。中线 = 刚跟进或刚下单；舷边 = 3 天内 | 共享函数的释放日 |
| 货箱颜色（三档） | 与距离同一件事的重复表达，不另编码 | 同上 |
| 箱面标记 | 哪个钟在逼近：「跟」= 跟进钟，「单」= 订单钟。只在预警和临界箱上显示 | 共享函数 |
| 绑带 | 按等级频率的「应跟未跟」。绑紧 = 按频率跟上；松开 = 已超频率；**无绑带 = 未定级或没有跟进安排** | 看板现有覆盖口径 |
| 落水 | 被释放入公海 | 归属被清空 |
| 海面漂浮的箱子 | **近 30 天落海**的客户，漂在所属市场的海域 | 归属变更流水 |
| 海面浮标 | 该市场名称 + 公海总数（含更早的） | 聚合 |

三档（颜色 + 位置 + 形态三重表达，不只靠颜色）：

| 档 | 条件 | 画面 |
|---|---|---|
| 稳固 | 剩余 > 14 天 | 中性色，靠中线 |
| 预警 | 剩余 4~14 天 | 琥珀色，外侧车道，显示箱面标记 |
| 临界 | 剩余 ≤ 3 天 | 红色，贴舷边，箱体探出舷外一截，描边缓慢呼吸 |

绑带和距离是两回事，不合并：S 级客户频率是 7 天，第 10 天绑带已松（该跟了），但离释放还有 20 天，仍在中线附近。绑带是早提醒，距离是最后期限。

「滑落的位置和市场有关」：**每个市场有固定的一段船舷和一片海域**，华东的客户只从华东那段掉进华东海域。哪片海近期漂的箱子多，哪个市场流失重。

### 市场怎么分

内贸客户只有省份、城市两个地域字段，且省份是自由文本。按 7 大区分段（华东、华南、华北、华中、西南、西北、东北）+「未填地区」。后端做省份归一（「广东」「广东省」算同一个）和大区映射。分段长度按客户数自适应，有保底宽度。**上线前查省份填充率：未填超过三成，先补数据再上线**，否则「未填地区」是最长的一段，按市场看没有意义。

### 客户多了、少了怎么摆

- 稳固的 B/C 级和未定级客户不逐个画，按区堆成箱垛，悬停显示「华东 · 稳固 182 家」。
- **S/A 级客户始终一箱一画**，哪怕是稳固的。它们从稳固滑向预警是最值得看到的一步。
- 预警和临界客户全部一箱一画。
- 海里只逐个画近 30 天落海的。更早的公海客户只进浮标数字，否则多年累积的公海会让画面变成「空船满海」，读成全流失了。
- 业务员名下只有十几家时，船按比例缩短，不留大片空甲板。

## 四、三种看法

| 模式 | 看到什么 |
|---|---|
| **现在**（默认） | 今天的真实摆位，右上角显示数据时间。进入时自动播一次「昨天至今落海的客户」（没有就不播） |
| **回放** | 时间条往左拖，看近 7 / 30 天真实落海与被认领的。来自现有归属变更流水，不建新表 |
| **推演** | 时间条往右拖到 +7 / +14 天：期间不跟进不下单，哪些会掉。顶部同步「14 天内将落海 N 家，其中 S/A 级 M 家」 |

- 推演最多到 +14 天。新规则下拉到 +30 天所有箱子都会掉，数字没有意义。
- 推演和回放全程带水印（「推演：若期间不跟进不下单」/「回放：11 月 6 日」），有醒目的「回到今天」。
- 画面打开期间数据可能变化（别人记了跟进、任务跑了释放）。重新进入沉浸模式时刷新，不做轮询。

## 五、交互

固定 3/4 俯视机位，不给自由视角，不需要学怎么转镜头。

| 操作 | 结果 |
|---|---|
| 悬停货箱 | 描边 + 浮签：店名、等级、距释放 N 天、哪个钟、上次跟进日、上次下单日 |
| 点击货箱 | 侧边客户卡：上述信息 + 最近一条跟进摘要 +「记一条跟进」「看时间线」（复用看板现有抽屉） |
| 记完跟进回到画面 | 该箱滑回中线、绑带收紧。这是整张图里最重要的一次反馈 |
| 点击市场分区或浮标 | 镜头推近该段，其余变淡；侧栏列出该市场的临界与预警清单 |
| 点击海里的箱子 | 客户卡 +「认领」（依赖 Q6；没有认领权限或流程未上线时不显示按钮） |
| 顶部筛选 | 归属人（仅管理者）、客户等级、只看临界 |
| Esc / 关闭 | 退出沉浸模式，停止渲染 |

- 侧栏清单是真正的列表，Tab 可走、回车开客户卡。3D 画面是它的视觉呈现，不是唯一入口。
- 归属人筛选项取**客户表里实际出现的归属人**，不用看板的统计名单。离职或不在名单的人名下的客户恰恰最该看，用名单会漏掉。
- 归属与跟进责任可能是两个人（交接后）。客户卡上两个都显示；业务员能看到的范围是「我归属的 + 我负责跟进的」。

## 六、动效规格

管理者大约每天看一次，属于「偶尔」档，可以有表现力，但每个动效都要有用途。

| 动效 | 用途 | 规格 |
|---|---|---|
| 进入沉浸模式 | 交代空间关系 | 镜头拉到全景，500ms，强 ease-out；键盘进入不播 |
| 落海（回放 / 推演） | 核心表达 | 单箱：滑向舷边 → 翻出 → 水花 → 浮起漂开，约 1.2 秒。下落段按重力加速（物理运动，不套界面缓动）；多箱错开 80ms；同时在途不超过 8 箱，其余直接到终态并在浮标累加 |
| 拉回中线 | 记跟进后的反馈 | 400ms，ease-out |
| 临界箱描边呼吸 | 指出最急的 | 2.4 秒周期，只动透明度 |
| 悬停描边、浮签 | 反馈 | 描边即时，浮签 150ms 淡入 |
| 海面缓慢起伏 | **纯氛围，没有数据含义** | 只在沉浸模式内；帧率上限 30；不可见即停 |

- v1 的船体摇摆和倾斜都去掉了：摇摆是纯装饰；倾斜会读成「哪个区客户多」而不是「哪个区问题重」。
- 海面起伏是唯一的装饰动效，需要在 DESIGN.md 登记例外（见第七节）。原型阶段对比有无两版，不明显加分就删。
- 不用物理引擎，落水轨迹是解析抛物线，结果确定、可重复。
- 减少动态模式：海面静止、无呼吸、落海改为箱子直接出现在海里并闪一次描边。

## 七、技术方案

### 前端

| 项 | 做法 | 为什么 |
|---|---|---|
| 渲染 | three.js，动态 import，只在进入沉浸模式时加载 | 主站目前只有 echarts，没有 3D 依赖；不能进首屏包 |
| 看板内卡片 | **2D 甲板缩略图（SVG）+ 三个数字**，不加载 three | 卡片要反映真实数据，又不能为它加载 3D 库 |
| 沉浸层 | teleport 到 body 的全屏层；层内的客户卡、浮签、侧栏一律实色底，不用毛玻璃 | 主布局内做不到全屏；动态画面上叠毛玻璃会逐帧重采样（DESIGN.md 性能约束） |
| 模型 | 船和箱子用基础几何体程序化生成，低多边形、平涂材质，无外部模型和贴图 | 没有美术资源依赖，颜色可直接取 token |
| 货箱 | `InstancedMesh`；射线拾取只对单独绘制的箱子 | 上千箱也是一次绘制 |
| 颜色 | 先在 `tokens.css` 新增一组图表用实色（现在没有实色的 warning，且多个语义色带透明度，3D 材质用不了），运行时读变量传给材质 | 红线 13，先改 token 再用 |
| 降级 | 无 WebGL / 减少动态 / 窄屏 → 2D 甲板图，与卡片缩略图同一套布局代码 | 功能不依赖 3D |
| 生命周期 | 该页被路由级 KeepAlive 缓存，切走不卸载。`onDeactivated` 和路由切换时关闭沉浸层并停止渲染；标签页不可见时暂停；关闭时释放几何体、材质、渲染器 | 否则切到别的页面后渲染循环还在跑 |
| 文件 | `views/domestic_followup/components/stats/churn/`：`ChurnShipCard.vue`、`ChurnShipStage.vue`、`shipScene.js`（场景构建）、`shipLayout.js`（数据 → 坐标的纯函数，可单测）、`ChurnDeck2d.vue`、`composables/useChurnShip.js` | 红线 12；布局与渲染分离，布局不依赖 WebGL 就能测 |

评估过的替代：ECharts-GL（做不了箱体滑落，同样要加依赖）；纯 2D 等距画法（约八成观感、无新依赖，已作为降级和卡片方案保留）。选 three.js 的理由只有「一眼被抓住」，成立与否由原型验。

**文档先行**：动手前在 DESIGN.md 登记本功能的例外——业务页内的沉浸展示层、新增 three.js 依赖、海面起伏这一项装饰动效——并写明范围只限沉浸层。

### 后端

| 项 | 做法 |
|---|---|
| 释放口径 | 抽共享函数：输入客户，输出两个钟的释放日、先到的是哪个。按自然月逆推释放日，不做「加 90 天 / 30 天」。释放任务与图共用 |
| 规则变更 | 改 `release_stale_private_customers`：加跟进钟、起算日（Q1）、暂缓处理（Q4）、责任结束（Q5）。规则生效日放后台配置，生效前只算不放 |
| 图的接口 | `GET /api/domestic-followup/stats/churn-map`，挂现有 `stats_router.py`，`require_permission` + 统一信封，不新增权限 code |

## 十一、不做什么

- 不做一人一条船的并排对比，不做「谁掉得最多」的榜。
- 不做随机掉箱子的装饰动画，画面上每一次落海都对应一条真实记录或明确标注的推演。
- 不做自由旋转 / 缩放的 3D 漫游，不做船体摇摆和倾斜。
- 不做外贸客户。
- 不做声音、昼夜、天气。

## 十二、验收要点

- 图上任一客户的释放日与释放任务的判定逐日一致，覆盖月末（如 11 月 29 日和 30 日的有效日期）和两个钟分别先到的情况。
- 规则生效日之前，没有任何客户因跟进钟被释放。
- 待审核订单不重置任何一个钟；过审后重置。
- 业务员账号带别人的筛选条件请求，拿不到别人的客户明细和姓名。
- 北京时间 00:00 跨日、服务器非东八区时剩余天数正确（红线 23）。
- 关闭 WebGL、减少动态、窄屏三种情况功能完整。
- 切到别的路由页后渲染循环已停；进出沉浸模式 20 次，显存与监听器不增长。
- 不进沉浸模式时，看板加载体积不包含 three.js。
