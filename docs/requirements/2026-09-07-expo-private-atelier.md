# 展会 AI 试戴 A 方案：奶油白 · 私享沙龙

## 设计决定

用户在 A 私享沙龙、B 高定秀场、C 未来魔镜三组高保真稿中选择 A，并授权实现。只调整 UI、动效、交互；不遵守后台对动画克制的限制，尽可能保持既有功能逻辑。

顾客端改成暖奶油白背景、深咖文字/按钮、香槟棕细节、衬线标题与自然人物主视觉。首页面向顾客表达“天生是您，美得更从容”；首发合作入口继续保留。全套主题限定 `.xk-root`，后台及其他模块的主题不变。

## 页面与功能

- 迎宾：人物摄影主视觉、两个体验入口、合作弹窗；退出登录、门店额度、品牌进入顾问模式保持原样。
- 登记：原称呼/手机/微信、需求/风格、授权字段及提交校验；改为清晰浅色表单、可键盘选择的卡片和真实复选框。
- 拍摄：统一取景、快门、反转镜头、相册、扫码传照片、示范和重拍界面。任意相机画面上的提示均有独立深色衬底，避免浅色主题导致不可读。
- 分析：自然人像与柔光，真实返回的正面标签；等待区改成体验引导，不使用没有真实素材的占位客户证言。
- 发型：三列摄影画廊、选中描边、原系列/评分/推荐理由、换一批及发型库，保留发色和分类场景滑选。
- 场景大片：图片化场景卡，保持最多三选；没有场景图片时显示编号和名称，不伪造素材。
- 出图风格：沿用最新主线后台配置的版本列表、默认项、刷新、失败阻断与 `prompt_version_id`。不按旧原型写死三档。
- 结果：更大对比图、触摸指针捕获和键盘范围控件、成图缩略图、心动/再看看、二维码及分享链接、打印、换款/换景、顾问。平板竖屏使用紧凑的双列操作区。
- 异常：保留额度/重试/联系管理员/结束本次确认。展示版图片失败先回退原图，两者均失败显示明确重试入口，不把原照片误当成佩戴后效果。
- 顾问、合作方案等子屏同步浅色视觉，原数据、文案条款和提交行为保持。

`useTryOnFlow`、相机/扫码 composables、API、鉴权路由和后台未修改。静态截图是合成测试数据的界面验证，不代表线上客户或真实 AI 生图结果。

## 动效

- 迎宾：摄影主视觉 1200ms 柔和展开，暖光扫入；文字/按钮 70ms 错峰进入，按钮无等待锁。
- 页面切换：480ms 轻移与淡入；选款照片 480ms 舒展，按压反馈 180–240ms。
- 分析/生成：外围柔光及不确定进度条，不伪造完成百分比或承诺固定生成耗时。
- 结果：图片实际加载成功后才触发 900ms 镜面光带与淡入；拖动对比一比一跟手。切换结果按 id 重新揭晓，旧图加载事件不能污染新图。
- 动画不改变请求次数、状态推进或触发生成时机。减少动态效果模式关闭循环、位移和等待；场景平滑滚动同时降级。

## 验证方式

先启动独立本地前端：

```sh
npm run dev --prefix frontend -- --host 127.0.0.1 --port 3017
node --test frontend/tests/expo*.test.mjs
npm run build --prefix frontend
python3 scripts/check_conventions.py
```

浏览器测试使用可用的 Playwright 安装；若没有项目本地安装，通过 `PLAYWRIGHT_MODULE` 指定包路径，`EXPO_BROWSER` 可指向本地 Chrome 可执行文件：

```sh
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright EXPO_BROWSER=/path/to/chrome node frontend/tests/expoAtelier.browser.mjs
```

该测试只访问本地 Vite，所有业务 API 均用合成 fixture 拦截，无真实用户资料和付费生成。输出到 `tmp/expo-atelier/`（可用 `EXPO_UI_OUTPUT` 指定），包括关键页截图及 `verification.json`。

本机没有仓库引用的 Emil skill / review-animations 标准文件，已搜索本地技能目录。本次按同级原则检查 transform/opacity 动画、输入即时响应、退出清理、减少动态效果、滚动与触区，并进行独立 agent 对抗性审查。

物理 Android/iPad 的相机、打印机以及展位网络最终体验需要对应设备验收；本地浏览器通过模拟摄像头与 Android 打印桥验证调用和交互，不冒充硬件实测。
