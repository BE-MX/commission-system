# P2 实施范围与验收计划

2026-11-05，实现基点 `3d05c413`，工作区 `commission-system-codex-alibaba-feed-p2` / `codex/alibaba-feed-p2`。本轮仅本地开发、隔离验证，无生产配置、凭据发放、真实模型调用、消息发送或 Git 发布。

当前文件缺稳定消息身份和活动覆盖。亮哥明确选择「同时实现 v1.1 接入与规则闸门，但保持自动能力关闭」。本轮同时完成 v1 人工闭环、v1.1 严格接收/规范消息/修订与撤回、独立活动覆盖水位和自动规则资格闸门；不存在真实采集证据的能力仍拒绝放行，不新增自动消费任务。

## 开发边界

1. 来源管理补精确负责人映射、独立 CRM / AI / 私海资料许可及版本。管理员配置权不授予消息正文范围，采集凭据仍只能接收与查询回执。
2. 新增个人记录关联，按来源、采集代次、记录类型和 ID 匹配当前版本；仅关联本人仍有效的私海客户。关联不修改客户归属，不按姓名猜合并。
3. TM 资料页按当前有效映射与授权展示快照和质量，提供本人客户检索、人工关联和撤销。正文纯文本，历史消息顺序不冒充精确时序。
4. 单客户重新分析必须显式传入所选 item ID，沿用每日每客户三次手动额度；排队、调用前与落结果前复核全部来源依赖。AF 引用绑定快照及消息位置。
5. 持久保存 `manual_only_v1` 策略。含该策略的摘要、前版摘要及建议不得流入例行分析、自动规则、自动完成或早报。转出、撤权、重新映射、取消关联或版本不可用后，正文与派生结果即时隐藏。

## 责任划分

- 业务数据：`alibaba_feed` 的模型、映射、关联、受控读与隔离测试，迁移包含必要手动选择持久字段。
- 私海分析：`client_desk` 的显式选择、队列幂等/配额、来源与 AF 证据、策略闭包和派生结果读取。
- 界面：沿用现有设计体系的 TM 资料及来源管理、API client/navigation 与前端回归。
- 集成：独立业务开关、路由注册、接口与表文档、集成测试、独立审查及必要浏览器验收。

## 验收证据

所有写入型测试只使用隔离 SQLite 或独立回环 MySQL，显式哨兵配置，绝不复制 `.env`。模型与消息发送只 mock。依次验证：有效关联与读包最小闭环 → 跨用户/来源和撤权隐藏 → 手动幂等与额度 → 历史策略跨轮次闭包 → 真实路由和前端构建 → 迁移/并发与独立复审。源与私海助理开关默认 false，证明关闭状态没有注册新增自动外发任务。
