## 架构判断与保留事项

1. **继续模块化单体。** 已有领域 service、中央 client、唯一导航入口、独立协议连接器可满足当前协作方式。必要改动集中在正确性与共享层，未引入新队列、ORM、数据库或服务拆分。
2. **保留实际安全边界。** PM 独立身份、机器凭证、公开库存和邀请门户不强制套同一 JWT；生产调度单活、共享 MySQL 与文件归属仍由既有部署流程管理。
3. **查询优化依据计数证据。** 本轮只修改确认的路线 N+1；不凭源文件大小泛化为性能故障。客户列表已有批量标签查询，本轮修正过时测试，没有虚报减少一次查询。
4. **后续清理候选**：未注册的旧 `views/sales_automation/` 页面和旧 API 测试链仍有 18 个静态未匹配候选，需整体退役，不要恢复已淘汰的后端接口。当前现役客户经营入口不依赖它们。
5. **大包与全平台历史样式**：ECharts/vendor 大包、部分页面内联裸色仍存在。本轮没有真实性能采样证明必须全局拆包，保持为后续指标驱动优化。
6. **尚未验证的环境能力**：真实 MySQL 外键并发锁等待、大数据量查询耗时、生产角色/客户数据下的完整业务流、实际 OKKI/钉钉/WhatsApp/OCR/AI 服务、微信真机相机扫码、Linux 发布文件系统流程和真实部署均未验。不能用 SQLite、模拟接口或源码审查替代这些验收。

生产上线前需在授权的候选发布环境核对 Connector 密钥非空与实际连接地址，执行既有部署入口的预检；如要求跨主机连接，显式设置监听 host。此项是本轮启动收紧带来的具体配置影响，不是本次已部署的声明。
