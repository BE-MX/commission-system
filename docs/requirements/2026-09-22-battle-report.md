# 临时战报：实现与验收说明

日期：2026-09-22。用户确认按功能设计开发，实现在 `codex/battle-report`。用户随后授权合并 main 并推送；实际集成状态见交接，未部署或执行生产迁移。

## 业务流程

入口为「订单管理 → 临时战报」，路径 `/invoice/battle-reports`。

1. 管理员创建草稿：名称、开始与结束日期、填报截止时间、参与业务员、活动小组、组长及汇总可见范围。
2. 发布后，参与业务员在截止前填写自己的周期 USD 目标。小组和活动目标自动求和；管理员可以代录。
3. 战报总览展示累计 GMV、目标完成率、时间进度、订单数、组卡、个人排行和逐日柱图。
4. 每日复盘展示最近七天的业务员成交矩阵，可前后翻周；点金额或姓名筛选下方订单，支持日期、人员、订单号/客户搜索、金额排序和分页。点击订单号查看本战报计入金额与原因。
5. 目标、配置和发布/归档操作留存修改前后值、操作人、原因及北京时间。截止后更正目标、进行中或已结束战报更正设置，管理员必须填写原因。
6. 已结束战报可归档与恢复。归档禁止修改目标与配置，但不会冻结上游订单金额。

首版允许最多 366 天、200 位参与人。个人目标为正数，最多两位小数、14 位整数。目标未填为 null，不作为零目标计算完成率。

## 已采用的统计口径

| 项目 | 实现 |
| --- | --- |
| 日期 | 订单 `account_date`，北京时间自然日，开始与结束日均包含；当前累计最多计到今天，未来订单不提前计入 |
| 金额 | 业务镜像 `okki_orders.amount_usd`，Decimal 按分累计；不读取回款作为成交额，不在看板另设汇率 |
| 有效订单 | 复用 `gmv_daily_service.VALID_ORDER_SQL` 的状态与非个人订单限制 |
| 归属 | 订单 `user_id` 匹配参与人 OKKI ID，再归入活动名单内的小组快照；不按订单部门比例拆分 |
| 去重 | 按稳定 `order_id` 去重；同 ID 内容冲突排除并提示异常 |
| 汇总 | 同一订单集合生成组、个人、日期、明细；订单列表合计覆盖完整筛选集合，不受分页影响 |
| 完成率 | GMV / 完整周期目标；显示一位小数、允许超过 100%；条形封顶但实际比例保留 |
| 缺目标 | 展示已填合计及覆盖人数，组/活动目标未填全则不计算完成率；无完成率者不参与该指标排名 |
| 异常 | 可授权参与人的空金额、负金额、非法日期、缺失日期、重复主键冲突不伪装成零；受影响范围不授完整排名 |
| 更新 | 首次进入、切换筛选与点击刷新时读取镜像；展示计算时间及「源同步时间未知」，不声称实时同步或财务结算 |

无订单且查询成功显示 0；未来日显示「未到」。源镜像取消或金额更正会重算原核算日；没有额外扣减退款流水。未参与人、无法归属到名单的订单不进入本战报，首版不提供全公司排除订单审计界面。异常日期不能可靠分配到某一天时，会保守提示该成员的日期数据待核对。

组织变更不会自动修改历史战报名单。现有参与人的姓名和 OKKI 身份保留快照；管理员调整周期/名单会整体重算并使旧目标表单版本失效。目标写入和审计同事务，批量目标任一冲突全部回滚，返回 409，不覆盖他人修改。

## 权限

| 权限 / 身份 | 范围 |
| --- | --- |
| `battle_report:read` | 页面、战报列表及查询；必须是该活动参与人；草稿仅管理员可见 |
| `battle_report:write` | 截止前修改本人目标；业务员应同时授予 read 和 write |
| `battle_report:admin` | 创建/设置/发布/归档/恢复、全活动明细、代录目标、修改记录；包含本模块读写能力 |
| 活动内组长 | 无需额外全局管理权限，可看活动本组订单；不能修改组员目标 |

汇总可见范围可设活动、本组、本人；订单和客户明细另行限定为本人、组长本组、管理员全部。前端筛选不能扩大服务端权限。普通参与人读取或填报时再次验证当前账号仍有效绑定活动快照中的 OKKI 身份，失效时提示配置路径，防止转绑后读取旧身份明细。

## 数据与接口

- 独立模块：`backend/app/battle_report`，只写方舟的战报配置、目标、审计，不写业务订单镜像。
- 迁移：`162_battle_reports`，父节点 `161_invoice_lifecycle`；新增 `ark_battle_reports`、`ark_battle_report_members`、`ark_battle_report_audits`，不回填历史订单。
- 迁移 downgrade 明确拒绝删除已填目标及审计。发生应用回滚时保留新表，修复后前滚。
- `/api/battle-reports` 接口与字段说明见 [API 参考](../api-reference.md)，表约束见 [数据库参考](../database.md)。
- 前端复用统一 API client、导航配置、权限指令、列表分页和详情抽屉。宽表仅在表格内滚动。

## 启用与边界

上线需按项目统一部署入口执行迁移 162 并发布前后端，重启后端播种三项权限，再在角色管理分配。普通业务员授 read/write；负责配置活动的角色授 admin，组长在活动名单内指定。上线前需将真实业务员的 OKKI 主账号绑定配置完整。

用户已授权合并与推送；本次不发布，也不调用生产写接口。全量约定检查中既有九个 UI 行数基线问题单独记录，不因本功能放宽门禁。生产数据质量、真实 MySQL 并发行为及正式环境访问由上线验收确认；本地测试不替代这些结论。
