## 1. P0 的输入与交付

先做一份可追溯的取样清单。除 U6 已有局部代码证据、U8 已知 SSO 占位外，下表中的业务数量、试点人选、终端表现均须在试点阶段获得。U3 已撤销。

| 项 | 取证与判读 | 不满足时的动作 |
|---|---|---|
| U1、D6 | 对候选业务员只读统计 WA active/CRM/AI 三道闸门、近 30 天有效消息数和活跃单聊数、其中可导入数、首次手工关联量。结合 U5 选 1 人，目标私海约 50～200 | 无有效授权不采原文；覆盖不足换人，待关联过多则安排首次集中关联 |
| U2 | 以全私海为分母，按唯一强身份、逻辑归属、审核、可见性逐层记剩余数 | 低覆盖折叠背调卡；缺失不能被 Agent 补写 |
| U4、U5 | 统计 S～E 及空值，另算有订单或近 30 天沟通客户的分级覆盖；让业务员解释等级。统计各人私海规模和每日候选分布 | 统一等级含义，按规模复算 40 名额和成本，记录超额原因 |
| U6 | 选普通周末、调休工作日、节假日、跨年四个偏移样例；检验样品跟进 +10 个工作日、R7/R6 阈值与沟通率窗口用同一日历 | 补确切年度配置，缺年度时明确提示与告警 |
| U7 | 逐个旧菜单/隐藏路由/定时任务取近 30 天访问与写入量，列实际使用者与调用关系 | 仍被使用的入口列入通知与交接；共享来源任务保留 |
| U8 | 用指定试点人的实际钉钉客户端检验工作通知、短链预取、免登兑换、系统浏览器回退、WA 草稿落点及返回 | 保留实际客户端、环境与结果；身份/归属无法验证走登录，失败不自动发送 |

**每天怎样评。** 对 1 位试点人的全部私海先保存候选，再按名额分析，每天取前 10，少于 10 按实际数，连续 5 个工作日。使用历史有效绑定和业务员填写的临时对照表；不为 P0 在业务表新建关联。按既有授权和供应商范围构包。逐条记录 useful / useless / 未评价及一句原因，当天另问“还有谁今天该联系但不在单上”。把补报名单与同日**截断前**全候选匹配，区分未命中、命中未入额、已分析未入前十及留出。

**数据保存。** 建议在办公室开发机的隔离目录保存去标识化快照，客户、联系人、电话与会话换为代号。受限映射与分析结果分开，限制到试点执行人，30 天后清除评测资料；指标仅留聚合。冻结 pack/protocol/规则版本、日历与模型标识，报告留版本、token、错误码和截止时间。P0 临时对照不进入仓库、生产日志或 P1 永久表。

**库存对照。** 同一客户、同日、同协议与模型，以同一资料包复制两份，仅改变是否含备货模块的已核实库存；打乱草稿顺序供业务员评价。并列记录有用率、核对项错误、额外成本和偏好理由。原设计未给“明显提升”的数值门槛，P0 报告列样本数和差异，由评审决定是否加入。没有对照结论前，P1 不默认接库存。

**退出。** 有用率 ≥50%、召回率 ≥70%、失败率 ≤5%。若未达标，按漏项或失败原因调整规则、协议或资料包，保留各轮版本和同一口径，最多两轮调整，仍不达标回到产品设计。原型通过评审不能替代这个门槛。

## 2. P1 指标字典

按 user_id、北京业务日、company_id 去重后输出日明细和两周合计（总分子÷总分母）。例行建议作为实验主样本；手动重跑的展示/反馈归并到该客户日，保留各轮原值；同日先评有用后来主动纠正，以最后一次明确的人工质量评价计。样本发生归属/关联变化时冻结入组条件，按可审计排除理由另报。分母为 0 显示 N/A 与数量，不能以 0% 或 100% 代替。

| 指标 | 分子 / 分母 | 目标与读数限制 |
|---|---|---|
| 有用率 | 已展示且受评 useful 的客户日 / 已展示客户日。出现于被钉钉受理的早报，或业务员实际打开了含该建议的详情，以最早一次为准 | ≥50%；没评价仍在分母，自动完成不计有用。列表预取、规则计数、仅看客户名不计曝光 |
| 反馈率 | 已展示且有任何人工反馈或有效自动完成的客户日 / 已展示客户日 | ≥60%；先评价后行动仍算 1 |
| 补报召回率 | 当日补报「名单外该跟」且命中当日全候选的客户数 / 当日所有有效补报客户数 | ≥70%；按补报子集测，不能称为全体真实召回；无补报日保留 N/A |
| 建议后沟通率增量 | 仅限入组时已关联 WA、适合 R5/R6 留出的客户日。以稳定分配的建议组和 15% 留出组分别计算：两工作日窗口内有本人 WA 出站或手工跟进的客户日 / 该组所有合格客户日 | 主判据为分配组差值 >0（ITT）；建议组未曝光仍在分母，入组后有更高优先级信号可正常提醒且保留原组、单列交叉。另报产品关心的实际展示与留出两组沟通率，分层列两组分子、分母和实际曝光量。起点为当日计划早报时间，至第 2 个后续工作日末，仅纳入完整窗口 |
| 早报打开率 | 已受理的推送日中，业务员有效打开任一报告入口的日数 / 实际被受理的推送日数 | ≥70%；系统预取、同日重复打开、普通菜单进入不算。多用户按人日相加，另报发送状态不明数 |
| 分级覆盖率 | 分级非空的重点候选数 / 试点私海中有订单或近 30 天沟通的客户数 | ≥80%；这里的「A 类候选」是活跃子集，不等于发票等级 A |
| 失败率 | 最终校验失败或执行失败（含 ambiguous）的分析轮数 / 实际启动的分析轮数 | ≤5%；申领未执行、超额、留出、skip 不算失败；skip 若已调用属于总分析。确定性纠正调用在本轮内另计调用次数/成本 |

**两周判定。** 1～2 人试点，报告按个人和合计展示上述七项、实际天数、名单外补报与实验可比性。打开率按有实际推送的人日计算。留出或补报分母不足时，标“证据不足”并继续采样，不以别的指标代替。另做计时走查：从钉钉开始，3 分钟内能说明先找谁、为何、第一句说什么；从任一详情开始，30 秒能说出客户背景、最近沟通和下次行动。计时属于可用性验收。

## 3. 可执行验收场景

以下为建成后的验收清单。后端写入和迁移只用隔离 MySQL；客户端用演示账号/可控对话。原型的演示数据手动操作单列，不据此判定线上权限和投递正确。

| 编号 | 准备 / 操作 | 通过条件 |
|---|---|---|
| T01 归属 | 用户未绑定 OKKI、镜像滞后有新 overlay、转出及远程超时分别开列表/详情/子资源 | 未绑定得到引导；合并后再分页；转出 404；实时核验失败可重试且不泄露上次详情；发票选择器结果不变 |
| T02 共同归属 | 两人共有公司，一人有出站，两人有不同备注，再测试都无出站 | 按设计选收件人，未授权必要信号缺失时各自独立评估并记录降级；各人只见自己资料；一个人手动改级另一个可见 |
| T03 来源闸门 | 账号仅 CRM、有 AI、撤权、重绑、撤回单条、群聊、已改绑各一例 | 展示/入模分别按权限；不从 preview、上一画像、旧建议、深链、报表或缓存泄露；撤回正文不能定位 |
| T04 规则 | 构造 R1 最后入站、R7 各级恰好 N 与 N+1 工作日、R2/R3 到期前后、R8 建档 30/31 日、R5 两/三笔、样品和在途、R6 未关联、R4 唯一命中 | 每项命中/不命中与开发说明一致；R4 不占提醒优先名额。节日降权不改变其他命中项 |
| T05 时间与冷却 | 主机非东八区、北京零点前后、节日/补班、稍后到期、done +7 / useless +14、连续两次无新活动复查 | 所有消费者使用同一业务日和工作日，边界既不早发也不漏发，第二次无新活动后停止复查 |
| T06 快照与留出 | 55 名候选、含同分、纯 R4 和混合 R1/R5；同版本重复扫 | ≤40 个例行模型名额，超额仍可解释，留出无建议曝光，前后排名和组别稳定；补报第 45 名能命中当日候选 |
| T07 构包与校验 | 假围栏、伪造系统指令、陌生链接/账号、伪引用、四种语言金额/交期、超长原文、skip 无复查、超过 30 天 | 围栏转义、裁剪后引用闭合、拒绝或标记与协议相符；未经确认的数据不会成为确定承诺，metadata 日志无正文 |
| T08 队列崩溃 | 两 worker 同时领取；分别在调用意图落库前/后中断；模拟租约到期迟回、超时和格式失败 | 只领取一次；无出站意图可回队，可能出站转 ambiguous；迟到不能写；仅明确格式错最多纠正一次 |
| T09 人工写竞争 | 自动完成与评有用并发、编辑备注时新画像回写；两位归属人同时从相同旧值改为不同等级、并发重复「记一笔」和第 3/4 次重分析 | 共享改级仅一人成功，另一人收到 409；两类反馈均保留，个人与 AI 字段互不覆盖，重复请求仅一条，最多 3 个手动轮次，历史计分可复算 |
| T10 会话关联 | 导入有效历史绑定；联系人同名不自动配；忽略/恢复、改绑 A→B、同时尝试两目标 | 每会话最多一条活跃关联；新会话待回复置顶；A 移除、B 加入；旧画像/跳转失效，导入重跑不复活已撤销项 |
| T11 客户详情 | 点引用展开原事件；同一秒有跨源多事件，翻页并换过滤；电话/寄样记一笔 | 无漏重，WA 按会话和北京日聚合；发生时间、作者、可选下次日期正确；最近接触显示可见渠道与同步时间 |
| T12 早报重验 | 06:30 待回，08:00 已回，同日重复调度；无建议、超额、整体模型不可用各一组 | 08:40 单独最多一条，每项最多两行、≤10 人；已回不再提示原问题；模型坏用规则，无建议不推，未知发送不重试 |
| T13 票据/WA | 预取、串用用户、重放、并发兑换、已过期、联系人无有效号、转出或撤权后打开 | 预取不消费；正确用途仅可兑换一次；拒绝越权；不可用跳转提示登录或查档案；草稿正确 URL 编码，跳转不自动发送或标 done |
| T14 UI | 桌面与钉钉窄屏完成筛选、切客户、编辑、稍后、复制、查看已授权证据；模拟慢请求/权限变更 | 3 分钟/30 秒任务可完成；窄屏返回保留位置，无横向溢出；失败保留人工输入，失权清空派生内容，只读无写控件 |
| T15 指标与运行 | 同建议先入报再打开再反馈并自动完成，手动重跑一次；另加留出、未展示、受理未知与零分母 | 客户日只计一次曝光/反馈，useful 不因 done 改写；组间可比，零分母单列；开关关闭后无新推送/外呼 |

## 4. 投入试点与回退顺序

1. 实现阶段在所属 worktree 开发。先查所有分支的迁移编号，验证隔离 MySQL 迁移前后、单 head、队列锁和生成列唯一性。按影响跑定向 pytest、前端构建与 UI 验收；交付时同步数据库/API 文档与 handoff。
2. 默认 `CLIENT_DESK_ENABLED=false`，试点名单为空。部署需单独授权；上线后先核 scheduler 单活、时区、日历、额度、允许的模型 preset 与供应商，以及收件人映射。seed 新增 read/write/admin，read_all 为二期数据范围保留；仅对试点授所需权限。
3. 每日读取运行数、等待/超租约、ambiguous、rule_only 原因、调用成本、合格资料覆盖、入报/受理/打开人日。租约过期检查不能导致不确定任务再次出站。发生串客、撤权泄露或重复推送立即关停外呼和投递；保留已完成业务记录，清查后恢复。
4. 全员切换前先审七项指标并取得切换授权。试点仅增新入口；验收通过且全员开通后才下架客户工作台、跟进日历、客户机会、隐藏雷达和作战卡，保留旧路由提示与重定向。获客任务、背调中心、邮件触达队列照常。逐项核实 pcw_daily_evaluation、customer_delegation_enqueue、customer_source_reconcile 的共享依赖再决定停用。
5. 回退先停扫描/领取/推送并拒绝在途迟写，隐藏新入口，恢复必要旧导航。早报票据失效，保存四表审计与历史；不删除或迁移旧数据。全员切换满四周才单独评估清理。即时报送、邮件/TM 采集、主管视图、DSH 工具化各自立项。
