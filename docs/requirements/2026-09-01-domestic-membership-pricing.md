# 内贸客户会员与优惠价机制设计开发文档

> 日期：2026-09-01
> 状态：业务规则已确认，可进入开发
> 适用范围：方舟平台内贸客户、内贸产品、内贸订单
> 关联模块：`backend/app/domestic/`、`frontend/src/views/domestic/`
> 价格来源：本需求附带的 4 张价格截图；业务已于 2026-09-01 确认截图价格继续有效，但不自动继承其中未被本需求明确提出的限购、期限等规则。

## 1. 结论

本需求在现有内贸域内完成，不新建第二套客户、订单或余额系统：

1. 客户会员等级由**最近一笔成功充值的单笔金额**自动决定，与累计充值、历史最高充值和当前余额都无关。
2. 原始价格按真正影响价格的维度维护：发片按“工艺 + 尺寸 + 发长”，头套按“工艺 + 发长”。产品 SKU 清单显示对应原始价格，但不在每个包含网底色、发量等完整 SKU 上重复存一份价格。
3. 下单时由后端根据客户当前会员等级、SKU 原始价格和会员规则计算优惠价。前端只展示报价和提交用户确认过的预期价格，不能自行计算或篡改最终价格。
4. 订单明细保存原始价格、优惠价格、优惠金额、会员等级和规则类型快照。以后充值、会员降级或后台改原价，都不反向改动历史订单。
5. 余额扣款继续复用现有原子账本逻辑，但金额口径从当前手填 `unit_price` 改为后端算出的优惠价。
6. 会员价海报中的“有效期”和“限量专供 3/8/20 个”不属于本次用户请求，V1 不实现；如果后续需要，应单独增加促销有效期和额度账本，不能只在前端做提示。

## 2. 目标与验收结果

### 2.1 用户目标

- 充值人员完成一笔充值后，客户会员等级立即自动更新，不再人工填写。
- 下单人员选择客户和产品属性后，系统自动显示原始价格与优惠价格，不需要查海报或心算。
- 提交订单时，客户余额按“优惠价格 × 数量”扣减。
- 管理员能在产品 SKU 清单中看到并维护当前原始价格，缺价 SKU 一眼可见。
- 财务或售后查看历史订单时，能说明“当时为什么是这个价格”。

### 2.2 成功标准

- 会员等级边界金额 9999.99、10000、29999.99、30000、99999.99、100000 计算无误。
- 后续较小充值会降级，后续较大充值会升级；订单扣款、退款不改变会员等级。
- 同一价格维度下，不同网底色、头围、发量的 SKU 显示同一个原始价格。
- 固定会员价优先于金额扣减；所有其他已有原始价格的会员 SKU 统一立减，非会员使用原始价格。
- 任何缺失原始价格的明细都不能以 0 元提交或保存成订单。
- 前端展示的原价、优惠价、等级和规则与后台落库、余额扣款完全一致；任一报价要素在提交前变化时，系统要求重新确认，不静默多扣或少扣。
- 历史订单不受后续会员和原始价格变化影响。

## 3. 现状与差距

| 领域 | 当前实现 | 与目标的差距 |
|---|---|---|
| 客户 | `ark_domestic_customers.membership_level` 是任意文本，新增/编辑客户时人工填写 | 会员等级没有和充值绑定，可能填成“金卡”等任意值 |
| 充值 | `ark_domestic_customer_ledger` 记录充值、扣款、差额、退款；充值支持 `request_id` 幂等 | 充值成功后没有刷新会员等级 |
| 产品 | 完整 SKU 身份是 `type|craft|net_color|size|length|density`，下单选择后自动沉淀 | 没有原始价格，也没有缺价管理 |
| 订单明细 | `unit_price` 由前端手填，后端直接信任并落库 | 无原始价、会员快照、优惠规则快照；存在误填和改包风险 |
| 结算 | 草稿不扣款，提交扣款；改单结算差额；终止/删除退款 | 事务能力可复用，但金额来源必须改为服务端优惠价 |

## 4. 业务口径

### 4.1 会员等级

会员等级只读取最近一笔 `transaction_type = recharge` 的成功账本记录。订单扣款、差额补扣、退款和当前余额都不参与判断。

| 最近一笔充值金额 | 内部代码 | 展示名称 |
|---:|---|---|
| `< 10000` 或从未充值 | `NULL` | 非会员 |
| `>= 10000` 且 `< 30000` | `silver` | 银卡会员 |
| `>= 30000` 且 `< 100000` | `black` | 黑卡会员 |
| `>= 100000` | `supreme` | 至尊会员 |

明确示例：

- 先充值 100000，再充值 5000：最近一笔是 5000，降为非会员，即使余额仍大于 100000。
- 先充值 5000，再充值 30000：升级为黑卡。
- 充值后发生订单扣款或退款：会员等级不变。
- 同一个 `request_id` 的弱网重放：不产生第二笔充值，也不能再次改会员等级。
- 旧充值请求在新充值完成后再次重放：必须保持新充值决定的等级，不能被旧请求降级。

### 4.2 优惠优先级

按以下顺序匹配，命中即停止：

1. 非会员：优惠价 = 原始价格。
2. 命中“头套固定会员价”：优惠价 = `min(原始价格, 对应会员固定价)`。
3. 其余已有原始价格的会员 SKU：优惠价 = 原始价格 - 会员立减额。
4. 缺失原始价格：报价失败并阻止订单提交。

会员立减额：

| 等级 | 单件立减 |
|---|---:|
| 银卡会员 | 70 元 |
| 黑卡会员 | 120 元 |
| 至尊会员 | 130 元 |

金额统一使用 `Decimal` / `NUMERIC(14,2)`，人民币保留两位小数。会员永远不能比非会员更贵：如果管理员后来把原始价格调到固定会员价以下，直接按更低的原始价格成交，规则码为 `member_fixed_capped`，展示“命中固定会员价，但原价更低，已按原价”。系统不允许出现负优惠价；若立减配置导致结果小于 0，报价失败并提示管理员修正原始价格，而不是自动截断为 0。

### 4.3 头套固定会员价

根据会员价截图，固定价必须匹配“工艺 + 发长”，不能只按发长匹配。原因是 20 厘米递针旋原价为 1498，若错误套用 20 厘米固定银卡价 1698，会员反而比原价贵。

| 系统工艺（推荐映射） | 发长 | 银卡 | 黑卡 | 至尊 |
|---|---:|---:|---:|---:|
| `递针旋全头套`、`递针旋九分头` | 15厘米 | 1048 | 998 | 960 |
| `递针顶` | 20厘米 | 1698 | 1598 | 1548 |
| `递针顶` | 25厘米 | 2098 | 1998 | 1948 |

业务已确认 `递针旋九分头` 与海报“递针旋”属于同一价格产品，因此它与 `递针旋全头套` 共用 15 厘米固定会员价。

### 4.4 会员立减适用范围

业务已确认：除第 4.3 节固定会员价组合外，**所有已维护原始价格的头套和发片 SKU** 都按会员等级立减 70/120/130 元，不再限制海报上列出的工艺、尺寸或发长。

- 头套：任何工艺、任何发长，只要不命中固定会员价，就按原始价格立减。
- 发片：任何工艺、尺寸、发长组合，只要有原始价格，就按原始价格立减。
- 缺失原始价格仍按缺价阻断，不能因为会员立减而推导或猜测原价。

### 4.5 不从附件自动继承的规则

以下内容出现在截图，但没有出现在本次用户请求中，因此不进入 V1：

- 银卡/黑卡/至尊“限量专供 3/8/20 个”。
- 海报会员价格有效期 2026/03/01—2026/06/30。
- 普通价格表有效期 2026/03/01—2026/06/01。
- 任何按月重置、累计购买数量或跨订单额度规则。

虽然当前日期已晚于截图标注的原有效期，业务已于 2026-09-01 确认截图中的价格数值继续有效，应按本文第 5 节直接初始化。V1 不实现自动到期；以后价格变化由管理员维护原始价格，会员政策变化则提升 `PRICING_VERSION`。

## 6. 关键设计判断

### 6.1 原始价格不直接重复存到完整 SKU

现有 SKU 身份还包含网底色、头围尺寸和发量，但需求已明确这些维度不影响价格。如果每个完整 SKU 各存一份原始价格，同一个“递顶 + 35厘米”会因为头围、网底色和发量产生大量重复价格，维护时很容易只改一部分。当前发片产品已按已上线属性契约把“工艺 + 尺寸”合并存入 `craft`（例如 `全递针13*15`），不能再假设产品上还有独立 `size` 值。

因此新增独立的原始价格表：

- 发片唯一键：`piece + craft_size_code + length`，其中 `craft_size_code` 就是产品 `craft` 的精确业务值。
- 头套唯一键：`cap + craft + length`。
- 产品 SKU 列表通过上述维度解析并显示原始价格。
- 从任一 SKU 编辑价格，实际更新共享的原始价格行，并明确提示“同价格维度的其他 SKU 会同步生效”。

这既满足“每个 SKU 清单显示和维护原始价格”，又保证相同价格维度永远只有一个真相源。

### 6.2 会员规则先固化为代码策略，不做通用促销引擎

V1 只有 3 个等级、3 行固定价规则和一条“其余已有原始价 SKU 统一立减”规则。为此建设可配置条件表达式、优先级和额度引擎会明显过度设计。

实现方式：

- 等级阈值、立减额、固定会员价和适用范围集中放在 `pricing_service.py` 的结构化常量中。
- 每次规则变更同步提升 `PRICING_VERSION`，订单明细保存版本号。
- 原始价格是高频业务数据，按需求提供后台维护。
- 当会员政策发生第 3 次重复调整，或确实需要生效期/限购时，再把策略升级为后台可配置政策表。

### 6.3 后端是价格唯一裁决者

前端自动报价只负责减少操作，不是可信价格源。创建订单、追加明细时，后端必须重新执行完整报价：

1. 锁定并读取客户当前会员快照。
2. 按产品属性解析原始价格。
3. 计算优惠价格与优惠类型。
4. 与前端提交的 `expected_quote` 逐项比较。该快照包含原始价、原始价格行版本、优惠价、会员等级、规则类型和规则版本。
5. 全部一致才落订单快照并扣款；任一项不一致都返回 409，前端展示新旧金额和规则并要求重新确认。

只比较优惠价是不够的：固定会员价可能不变，但原始价变化会改变订单的原价与优惠金额快照。比较完整报价既能防请求篡改，也能避免管理员恰好改价时用户看到的依据与落库依据不同。

### 6.4 正式订单价格提交后冻结，草稿允许重新报价

- 直接创建正式订单或向已提交订单追加明细时，按当时客户等级报价并存快照。
- 正式订单后续遇到充值升级/降级或原始价格调整，都不改已有明细。
- 草稿价格是待确认报价：提交草稿时按客户当前会员等级和当前原始价格重新报价；金额有变化则返回 409，展示新旧金额，由用户确认后再提交，不能静默重算后直接扣款。
- 现有“新客户先存草稿，再到客户管理充值”的流程因此可以获得充值后的会员价，不会把新客户永久锁在非会员价。
- 草稿更换客户时同样整单重新报价并由用户确认。
- 已提交订单沿用现有规则，禁止更换客户。
- 数量修改只按已冻结优惠价结算差额；V1 移除人工改单价入口。

正式扣款前，用户一定会看到并确认最终金额；一旦正式提交，价格即冻结。

## 7. 数据设计

### 7.1 `ark_domestic_customers` 扩展

| 字段 | 类型 | 说明 |
|---|---|---|
| `membership_level` | `VARCHAR(16) NULL` | 只允许 `silver/black/supreme`；`NULL` 为非会员，替换当前自由文本语义 |
| `last_recharge_amount` | `NUMERIC(14,2) NULL` | 最近一笔成功充值金额快照 |
| `last_recharged_at` | `DATETIME NULL` | 最近一笔成功充值的北京时间 |

账本仍是审计真相源，上述字段只是查询快照。充值事务中新建账本成功后同步更新；幂等重放不更新。

### 7.2 新表 `ark_domestic_base_prices`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | `INT` | 主键 |
| `product_type` | `VARCHAR(16)` | `cap/piece` |
| `craft` | `VARCHAR(64)` | 头套为工艺 code；发片为当前产品使用的“工艺+尺寸”合并 code |
| `length` | `VARCHAR(32)` | 发长 |
| `original_price` | `NUMERIC(14,2)` | `> 0` |
| `version` | `INT` | 从 1 开始，每次更新原始价格加 1，便于审计和诊断陈旧报价 |
| `updated_by` | 与 `ark_users.id` 一致 | 最后维护人 |
| `created_at/updated_at` | `DATETIME` | 北京时间 |

唯一约束：`(product_type, craft, length)`。

应用校验：

- 头套工艺和发长必须能对应当前产品属性值；发片必须使用精确的合并工艺尺寸 code，不做前缀、后缀或正则猜测。
- 系统初始化第 5 节全部已确认价格组合；其中暂未出现在当前标准字典中的组合可以保留为待用价格，只有产品使用完全相同的 code 时才会命中。
- 特单自定义工艺或海报未覆盖的新组合也使用同一个精确三维价格键；默认没有价格，管理员必须先从产品清单维护原始价格，之后才能报价和下单。海报未覆盖只表示“不自动猜价”，不表示该 SKU 永久禁止维护价格。
- 允许管理员删除原始价格行以纠正错误配置。删除前前端二次确认并展示受影响 SKU 数；已有订单不受影响，相关 SKU 的新报价立即进入缺价阻断。

### 7.3 `ark_domestic_order_items` 扩展

| 字段 | 类型 | 说明 |
|---|---|---|
| `original_price` | `NUMERIC(14,2)` | 下单时原始单价快照 |
| `unit_price` | `NUMERIC(14,2)` | 保留现有列，语义明确为最终优惠/成交单价 |
| `discount_amount` | `NUMERIC(14,2)` | `original_price - unit_price`，非负快照 |
| `membership_level_snapshot` | `VARCHAR(16) NULL` | 本明细报价时的会员等级 |
| `pricing_rule` | `VARCHAR(24)` | `base_price/member_fixed/member_fixed_capped/member_reduction/legacy_manual` |
| `pricing_version` | `VARCHAR(32)` | 例如 `domestic-member-v1` |
| `base_price_version_snapshot` | `INT` | 本次使用的原始价格行版本；历史旧单为 0 |

不保存完整规则 JSON。`attrs_snapshot + original_price + unit_price + membership_level_snapshot + pricing_rule + pricing_version + base_price_version_snapshot` 已足够解释历史价格，避免重复存储可推导信息。最终约束为：`original_price/unit_price/discount_amount/pricing_rule/pricing_version/base_price_version_snapshot` 全部非空，`unit_price >= 0`、`discount_amount >= 0`、`unit_price <= original_price`；新规则订单必须 `original_price > 0`，只有 `pricing_rule = legacy_manual` 的历史旧单允许原价为 0。只有 `membership_level_snapshot` 允许为空，表示非会员或历史旧单。

### 7.4 新表 `ark_domestic_order_pricing_requests`

用于草稿提交和草稿换客户这两类价格确认操作的持久幂等：

| 字段 | 说明 |
|---|---|
| `order_id` | 草稿订单 |
| `request_id` | 客户端操作请求号，和 `order_id` 组成唯一键 |
| `operation` | `submit` 或 `reprice_customer` |
| `request_hash` | 目标客户、完整 `expected_quotes` 等请求内容的 SHA-256 |
| `result_json` | 首次成功结果的最小快照，供弱网重放返回 |
| `created_at` | 北京时间 |

同请求号、同指纹返回首次成功结果；同请求号、不同指纹明确拒绝。直接建单继续复用 `ark_domestic_orders.request_id/request_hash`，追加明细继续复用 `ark_domestic_item_append_requests`，不再复制第三套逻辑。

### 7.5 历史数据处理

- 旧客户：按充值账本中 ID 最大的 `recharge` 记录回填最近充值金额、时间和会员等级；没有充值记录则清空旧自由文本会员等级。
- 旧订单明细：`original_price = unit_price`、`discount_amount = 0`、`pricing_rule = legacy_manual`、`membership_level_snapshot = NULL`、`pricing_version = legacy`、`base_price_version_snapshot = 0`。
- 不用当前客户会员等级回填历史订单，避免制造并不存在的历史事实。
- 原始价格表按第 5 节已确认数据初始化：1040 原样使用；`递针旋九分头` 复用头套“递针旋”矩阵；发片 `递针旋` 复用 `全递针` 矩阵。截图没有给出价格的组合仍保持缺价，不猜值。

## 9. API 设计

### 9.1 客户与充值

| 方法 | 路径 | 变化 |
|---|---|---|
| `GET` | `/customers` | 返回 `membership_level/label`、`last_recharge_amount/at` |
| `POST/PUT` | `/customers` | 请求中删除 `membership_level`，禁止人工维护 |
| `POST` | `/customers/{id}/recharges` | `request_id` 改为必填；成功后返回账本余额快照、当前余额、当前会员和本次等级变化 |

```json

  "replayed": false
```

重放语义必须明确：`ledger_balance_after` 永远是原充值当时的账本快照，`current_balance` 和 `membership_level` 是当前客户状态；`membership_change` 在重放时为 `null`，因为本次请求没有再次改变等级。这样旧充值请求在更新充值之后重放，也不会伪装成又一次升级/降级。前端遇到 `replayed=true` 显示“该充值已处理，当前会员为 X”，不重复播放升级提示。

### 9.4 统一价格变化 409 契约

直接创建订单、追加明细、草稿提交和草稿换客户统一返回以下结构。创建/追加用 `client_key` 定位，存量草稿用 `item_id` 定位：

```json
{
  "detail": {
    "error_code": "DOMESTIC_QUOTE_CHANGED",
    "message": "价格已更新，请确认后重新提交",
    "changes": [
      {
        "client_key": "line-1",
        "item_id": null,
        "reasons": ["base_price_changed"],
        "previous_quote": {
          "original_price": 2650.00,
          "base_price_version": 3,
          "discount_price": 2530.00,
          "membership_level": "black",
          "pricing_rule": "member_reduction",
          "pricing_version": "domestic-member-v1"
        },
        "current_quote": {
          "original_price": 2700.00,
          "base_price_version": 4,
          "discount_price": 2580.00,
          "membership_level": "black",
          "pricing_rule": "member_reduction",
          "pricing_version": "domestic-member-v1"
        }
      }
    ],
    "current_expected_quotes": [
      {"client_key": "line-1", "item_id": null, "original_price": 2700.00, "base_price_version": 4, "discount_price": 2580.00, "membership_level": "black", "pricing_rule": "member_reduction", "pricing_version": "domestic-member-v1"}
    ],
    "retry_requires_new_request_id": true
  }
}
```

`reasons` 值域固定为 `base_price_changed/membership_changed/rule_changed/price_missing`。普通变价时，前端直接用 `current_expected_quotes` 更新表单，展示 changes 后由用户确认；再次调用同一端点时必须生成新 `request_id`。

如果报价后原始价格被删除，缺价行使用联合类型：`current_quote = null`、`current_status = missing_base_price`，并且该行不进入 `current_expected_quotes`。前端保留用户表单，但禁用确认提交，提示具体 SKU“原始价格已被删除，请维护后重新报价”；管理员补价后必须重新调用 `/pricing/quote`，不能沿用旧价或用 `null` 确认。所有 409 都不落订单、不改草稿、不扣余额，也不写成功幂等记录。

## 10. 后端事务与并发

### 10.1 充值事务

1. schema 先拒绝缺失或空白 `request_id`，所有充值都必须有持久幂等键。
2. 按现有顺序锁客户行。
3. 按 `business_key` 检查幂等记录。
4. 如果是重放，返回原账本余额快照和客户当前状态，**不写会员快照**。
5. 如果是新充值，写账本并更新余额。
6. 根据本次金额计算并更新 `membership_level/last_recharge_amount/last_recharged_at`。
7. 同一事务提交。

这一步必须专门测试“旧请求在新充值后重放”，否则旧账本金额可能覆盖最新等级，或接口可能把历史余额错报成当前余额。

### 10.2 建单与扣款事务

1. 锁订单请求幂等键和客户行。
2. 批量解析或创建产品 SKU。
3. 按 `ark_domestic_base_prices.id` 升序，用 `SELECT ... FOR UPDATE` 锁住本单命中的全部原始价格行；任一缺价则整单失败。
4. 在价格锁内重新读取原价与 `version`，再读取客户会员快照并计算所有优惠价。
5. 与前端完整预期报价逐行比较；任一变化则返回 409，整单不落库、不扣款。
6. 写订单和价格快照。
7. 草稿只保存待确认报价；直接创建正式订单时调用现有 `sync_order_finance` 一次性扣减优惠价总额。
8. 提交事务后才释放价格行锁。

订单请求哈希必须纳入完整 `expected_quote`，确保同一个 `request_id` 不能重放成另一组原价、优惠价或规则。

建单、追加明细、草稿提交、草稿换客户都使用同一锁顺序：订单/客户 → 价格行（按 ID 升序）。原始价格 PUT/DELETE 也必须先 `FOR UPDATE` 锁目标价格行并在提交时递增 `version`。因此：

- 管理员先改价并提交：订单随后读到新版本，返回 409。
- 订单先锁价并提交：管理员改价等待订单完成，已提交订单合法使用旧价。
- 当前缺价时订单直接失败，不锁不存在的间隙；并发管理员 upsert 依赖唯一键落一行，订单由用户重试后读取新价。

禁止价格维护端绕过 service 直接批量 UPDATE/DELETE，否则会破坏上述并发保证。

### 10.3 改单

- 改数量：沿用该明细已冻结的 `unit_price` 结算差额。
- 追加明细：按追加时客户等级重新报价，因此同一订单不同行可能有不同会员快照；这是充值发生在两次操作之间的真实结果。
- 草稿换客户或充值后提交：锁订单后按当前客户等级整单重新报价，全部价格变化一次性返回前端确认。
- 已提交订单：继续禁止换客户。
- 后台改原始价格：只影响之后新报价，不更新存量订单。

## 14. 测试与验收用例

### 14.1 会员

1. 9999.99 → 非会员。
2. 10000 → 银卡；29999.99 → 银卡。
3. 30000 → 黑卡；99999.99 → 黑卡。
4. 100000 → 至尊。
5. 100000 后再充 5000 → 非会员。
6. 5000 后再充 30000 → 黑卡。
7. 扣款、退款、差额调整不改变等级。
8. 同充值请求重放不重复加余额、不重复改等级。
9. 较旧充值请求在新充值后重放，不覆盖新等级。
10. 两笔并发充值按实际账本落库顺序决定最近一笔，余额和会员快照一致。
11. 缺失或空白 `request_id` 的充值在写账本前被拒绝。
12. 旧请求重放同时返回原 `ledger_balance_after` 和当前 `current_balance/membership_level`，两种口径不混淆。

### 14.2 原始价格

1. 同一头套工艺和发长，不同尺寸/网底色/发量解析同一价格行。
2. 同一发片工艺/尺寸/发长，不同发量解析同一价格行。
3. 修改共享价格后，所有相关 SKU 列表立即显示新价，历史订单不变。
4. 缺价 SKU 报价返回可行动提示，订单不产生 0 元明细。
5. 禁止为停用或不存在的字典值维护新价格。
6. 删除共享原始价格后，相关 SKU 全部变为缺价，历史订单金额不变。
7. 建单持有价格行锁时，并发 PUT/DELETE 必须等待；管理员先提交时，建单读到新版本并返回 409。
8. 缺价报价与并发 upsert 不产生重复价格键；用户重试后能读取唯一新价格行。

### 14.3 优惠计算

1. 三行固定头套组合逐等级价格正确，其中 15 厘米同时覆盖 `递针旋全头套` 和 `递针旋九分头`。
2. 参数化验证 `递针旋九分头` 在 15/20/25/30/35/40 厘米六档原始价格逐项等于 `递针旋全头套`；15 厘米走固定会员价，其余五档分别按银卡/黑卡/至尊立减 70/120/130。
3. 固定价优先于立减，不能固定价后再减一次。
4. 固定价组合外的头套和发片 SKU 各抽取不同工艺、尺寸、发长，全部验证 70/120/130 立减。
5. 参数化验证发片 `递针旋` 与 `全递针` 所有已配置尺寸、发长的原始价格逐项相等，并正常参与会员立减。
6. 非会员全部使用原始价。
7. 分界 13*15 / 35cm 按确认值 1040 初始化，银卡/黑卡/至尊分别得到 970/920/910。
8. 原始价格低于固定会员价时按原始价成交，`pricing_rule = member_fixed_capped`、优惠金额为 0、标签正确，绝不出现会员价高于原价或负优惠金额。

### 14.4 订单与资金

1. 前端报价、订单快照、订单总额和余额扣款完全一致。
2. 篡改 `expected_quote` 的任一字段都被拒绝且不扣款。
3. 报价后管理员只改原价、固定优惠价不变，提交仍返回 409，防止原价和优惠金额快照静默变化。
4. 正式订单余额不足时整单回滚，产品、订单、账本不留半成品。（2026-09-02 起新增例外：`settle_mode='credit'` 的「先下单后付款」客户不受余额校验限制，余额可扣成负数记欠款，充值后自动冲抵；prepay 客户行为不变。）
5. 草稿不扣款；新客户存草稿后充值，提交时能更新为新会员价，并在扣款前要求用户确认变化。
6. 改数量正确补扣/退款；终止订单按优惠价退款。
7. 后续充值或改原价不改变历史订单价格。
8. 建单和追加明细弱网重试不重复建单、不重复扣款。
9. 历史订单迁移前后 `total_amount/charged_amount` 和客户余额总额完全不变。
10. 草稿更换客户时，客户和全部价格快照在同一事务更新；报价变化未确认时两者都不改变。
11. 直接创建正式订单按本次完整报价校验；草稿转正式则按提交时当前会员/原价重新报价，二者边界明确。
12. 四个写入口的 409 都按统一 schema 返回逐行 old/new quote、固定 error code 和可直接回传的 `current_expected_quotes`。
13. 草稿提交/换客户同请求号同指纹返回首次结果，同请求号不同指纹拒绝；409 后新请求号可成功确认。
14. 两阶段迁移后必填列、条件 CHECK 全部生效；B→A downgrade 冒烟验证旧应用只在列恢复可空后才能写入。
15. 草稿报价后管理员删除原始价格，409 对该行返回 `current_quote=null/current_status=missing_base_price`，不生成可确认快照；前端保留表单并阻止重提，补价并重新报价后才能提交。

### 14.5 前端

1. 选择客户后会员、最近充值和余额反馈清晰。
2. 切客户、工艺、尺寸、发长会使旧报价失效并自动重算。
3. 报价未完成或缺价时不能提交。
4. 价格变化 409 保留用户已填的所有图文要求。
5. 产品页缺价筛选、价格维护和共享影响提示可用。

## 15. 开发拆分

### Phase 1：数据与定价内核

- Alembic 迁移、ORM、schema。
- `pricing_service.py` 与会员计算。
- 历史回填和基准价格导入脚本/迁移数据。
- 会员、报价、边界、并发、幂等和金额测试。

### Phase 2：后端订单闭环

- 充值自动更新会员。
- 批量报价接口。
- 建单/追加明细改为服务端定价。
- 订单价格快照、余额扣款、改数量和退款回归测试。

### Phase 3：前端体验

- 客户会员展示和充值预览。
- 产品原始价格维护与缺价筛选。
- 下单自动报价、陈旧价格确认、缺价引导。
- 订单详情与导出双价展示。

### Phase 4：上线校验

- `cd backend && pytest`。
- `cd frontend && npm run build`。
- `python scripts/check_conventions.py`。
- 管钱功能独立 agent 对抗性审查：边界、并发、幂等、价格篡改、账本守恒、前后端契约。
- 停写迁移、数据核对、恢复流量。

## 16. 已确认的业务决策

以下 5 项已由业务于 2026-09-01 确认，是开发和验收的最终口径：

1. **价格继续有效**：忽略截图原有效期，按截图数值上线；系统不实现自动到期。
2. **分界价格**：发片“分界 13*15 / 35cm”就是 1040。
3. **头套工艺映射**：`递针旋九分头` 与截图“递针旋”同原始价，并享受 15cm 固定会员价。
4. **优惠范围**：除固定会员价组合外，所有已有原始价格的 SKU 都按会员等级立减 70/120/130 元。
5. **发片工艺映射**：发片 `递针旋 = 全递针`，两者相同尺寸、发长的原始价格相同。

上述事项不再作为开发阻塞项；截图没有提供任何原始价格的其他组合仍按缺价处理。
