# 外部站点订单发票接入需求

日期：2026-08-26
范围：Phase 1 REST 接口、Phase 2 Codex 站点接入包

## 1. 要解决的问题

用户用 Codex 搭建的站点已经能保存订单并导出发票 Excel，但 Excel 是给人查看的结果，不是可靠的系统间协议。样本中就存在公式与缓存值不一致：如果方舟直接相信工作簿总额，可能生成金额错误的业务单据。

本功能把每个站点的订单源数据转换成统一 JSON，由站点服务端直接提交给方舟。方舟负责确认客户和产品、重算金额、幂等创建订单发票，并返回可恢复的确定结果。

对用户的影响：生成发票后不再二次录入方舟；网络超时不会因换单号重试而生成重复发票；客户、SKU 或金额有问题时，用户会在站点看到明确的修正动作。

## 2. 核心边界

- 主协议是版本化 REST，Base URL 为 `https://leshine.work/api/integrations/v1`。
- 每个站点使用一个 Integration App，长期 Token 仅能保存在站点服务端。
- 站点提交订单源 JSON，不上传 Excel，也不依赖 Excel 公式缓存。
- 方舟只创建本地订单发票，创建动作不自动同步 OKKI。
- 方舟绑定用户决定订单归属；请求不能指定业务员或方舟发票号。
- 第一版只创建，不提供覆盖或更新已创建发票的接口。

## 3. 对外能力

| 能力 | 目的 |
|---|---|
| 客户解析 | 把方舟客户 ID、唯一邮箱、电话或精确公司名解析为一个主数据客户 |
| 产品解析 | 把产品/SKU ID 或结构化规格解析为唯一、启用的目录项 |
| 发票预检 | 只读返回标准化快照、服务端重算金额、警告和可执行错误 |
| 发票创建 | 使用同一份请求幂等创建方舟发票 |
| 结果查询 | 在创建响应丢失或超时后按外部订单号恢复结果 |

具体端点、字段和响应见 [外部订单发票 API](../integrations/invoice-api.md)。

## 4. 数据契约

### 4.1 业务主键

`external_order_id` 是站点订单中稳定、不可复用的主键，不是每次请求生成的追踪号。幂等范围是 `Integration App + external_order_id`：

- 首次成功创建返回 HTTP 201。
- 相同 external_order_id、相同标准化内容重放返回原发票，HTTP 200。
- 相同 external_order_id、不同内容在发票创建后返回 HTTP 409，不覆盖原单。
- 校验失败的订单可修正后继续使用同一个 external_order_id。

### 4.2 金额

所有输入金额必须使用 JSON 十进制字符串，例如 `"19.6700"`，不能使用 JSON number。明细、数量和费用是输入；方舟服务端重算行金额、产品金额和总额。`declared_totals` 只是可选对账值，不是最终金额来源。声明值与重算值的绝对差额 <= 0.01 时通过；> 0.01 时返回 HTTP 422，issue code 为 `DECLARED_TOTAL_MISMATCH`。

用户影响：站点显示金额与方舟计算不一致时，创建会被拦截，不会静默落下一张金额不同的发票。

### 4.3 主数据

- 客户只接受唯一精确结果；零命中或多命中返回 422，不自动猜测或新建客户。
- 产品优先使用 `product_id + sku_id`；结构化规格必须唯一命中。
- 主数据命中后，客户公司名和产品描述以方舟快照为准；订单联系人、地址和成交价仍作为本单数据保存。
- 成交 `unit_price` 用于发票计算；当前标准价/客户价只形成快照和 warning，不替换成交价。

## 5. 安全与权限

- `Authorization: Bearer ark_live_...` 只能由站点服务端发送。
- Token 不得进入浏览器包、HTML、Git、URL、日志或错误消息。
- Integration App 被停用、过期、轮换或吊销后立即失效。
- App scope 与绑定用户当前 `invoice:write` 权限实时取交集；任一方不足都返回 403。
- 不把 Integration App Token 扩展为 MCP 个人凭证，也不授予 OKKI 同步能力。

## 6. 失败与恢复

- 400/422 类错误由站点按 `field + code + message` 指引用户修正。
- 401/403 由管理员处理凭证或权限，站点不得盲目重试。
- 409 `EXTERNAL_ORDER_CHANGED` 表示已创建内容不可覆盖；409 `INVOICE_PROCESSING` 表示稍后查询同一订单号。
- 429、500、503、网络失败或超时都不能换 external_order_id。站点先查询原 external_order_id；仍未创建时，才用完全相同的订单内容和订单号重试。

## 7. 验收标准

1. 五个 REST 端点可从 FastAPI OpenAPI 查到，请求/响应模型与本文档一致。
2. 金额字段传 JSON number 会被拒绝；合法字符串按方舟规则重算。
3. 同一 App 并发提交同一订单只能生成一张发票。
4. 首次创建为 201，相同内容重放为 200，不同内容为 409。
5. 创建响应丢失后，可用同一 external_order_id 查到原发票。
6. Token 吊销、绑定用户停用或权限撤销后不能继续创建。
7. 创建结果为 `sync_status=not_synced`，且不产生 OKKI 推送。
8. TypeScript helper 不生成业务订单号、不读取浏览器存储、不记录 Token。
9. Codex 改造任务书能让站点从订单源数据完成 resolve、validate、create 和异常恢复。

## 8. 非目标

- 不提供 Excel 导入或公式解析。
- 不自动新建客户、模糊选择客户或 SKU。
- 不同步 OKKI，不在本接口提供同步开关。
- 外部 REST API 不提供发票更新、删除、作废或提成字段。方舟人员仍可在“订单发票”页面删除尚未同步 OKKI、且没有未恢复库存的站点接入发票；删除会同时释放该 App + external_order_id，允许独立站重新同步。
- 本阶段不要求站点运行时使用 MCP；后续 MCP 如建设，必须复用同一业务服务与权限规则。
