# AI 接入管理重设计：订阅管理 + 预设可视化（需求）

> 版本：v0.3 · 2026-11-27 · 状态：**已确认**（第 6 节 Q1–Q6 已全部拍板，见各条决策记录）
> 对应设计：[design.md](design.md) · 原型：[prototype/index.html](prototype/index.html)
> 现有实现：`backend/app/ai/`、`frontend/src/views/system/AIManager.vue`（菜单：系统管理 → AI 接入管理，需 `ai:admin`）

---

## 1. 背景与目标

现在「AI 接入管理」页面有 5 个 Tab：提供商管理、预设管理、调用日志、聊天运行、站点应用。问题有三点：

1. **看不出“我们订了什么”**：提供商是一张技术配置表（API Base、协议、超时），没有订阅日期、续费、余额、消费。要回答“还剩多少钱、什么时候到期、这个月花了多少”，只能去各中转站后台逐个登录查。
2. **预设看不出“用在哪”**：预设（如 `waybill_ocr`、`expo_wig_composite`）只有名称、模型、提供商，业务人员无法知道它服务哪个功能导航；想找“某个提供商下的所有功能用量”要逐行翻表。
3. **费用只有 token，没有统一总账**：调用日志只记录了 token，部分单价分散在聊天配置（`chat.pricing`）与生图费率卡（`rate_card`），缺乏全平台统一的提供商维度本月消费、上线后累计消费与固定订阅支出视图。

**目标**：管理员打开页面，一眼看清当前订阅了哪些 AI 服务、每个服务还剩多少钱/多少天、本月调用消费与固定订阅支出以及上线后累计花了多少；预设按功能归类，可按提供商和模型快速筛选。

**非目标（本期不做）**：
- 不做支付、充值下单、自动扣款。
- 不替代各中转站后台的账单明细；页面展示的是方舟内估算与手工登记值，不是财务账。
- 不改变预设的调用协议、参数和鉴权方式；不改变 API Key 的加密与“只显示掩码”规则。

## 2. 用户与场景

| 角色 | 权限 | 典型场景 |
|---|---|---|
| 平台管理员（亮哥/IT） | `ai:admin` | 每周看一眼“哪家快没钱了 / 快到期了”；月底核对本月 AI 调用估算与固定订阅支出；新增一家中转站并录入订阅与单价信息 |
| 业务模块开发者 | `ai:admin` | 新增业务功能时，给预设选择所属功能，避免“孤儿预设” |

消费数据属于经营信息，只开放给持有 `ai:admin` 的账号。普通业务用户不可见。

## 3. 现状事实（设计依据）

以下来自代码，设计时以此为准：

- 提供商表 `ark_ai_providers`：有 `name`、`provider_type`（`direct` / `accio_work`，调用链强依赖此枚举不可改）、`api_base`、`api_key`（加密）、`api_type`（`openai` / `anthropic`）、`extra_headers`、`runtime_config`、`timeout_sec`、`remark`、`deleted_at`。**没有**直连/中转站区分、余额、续费、价格、LOGO、控制台地址、文档地址。
- 预设表 `ark_ai_presets`：有 `preset_name`、`provider_id`、`model`、`system_prompt`、`parameters`、`description`。**没有**“所属功能”字段。启动种子（`seed_ai.py`、`seed_fx_settlement.py`、`seed_whatsapp_reply.py`）会自动创建 20+ 预设，全仓约 40 个预设、50 个调用来源，含部分无对应侧边栏菜单的预设（如站点网关、Agent Runtime、内部测试）。
- 调用日志 `ark_ai_call_logs`：写入入口共 **5 条主链路 + 3 条外部兜底链路**（同步 `call_service.chat`、`call_service.delegate`、流式 `stream_service.chat_stream`、生图 `image_service.generate_image/edit_image`、Agent 网关 `agent_service.prepare_agent_chat`，以及 `ai_chat`、`customer_image`、`design_image` 的超期 pending 清理）。目前没有 `provider_id`、`finished_at` 和费用字段。
- 现有两处局部定价：AI 工作台已在 `preset.parameters.chat.pricing` 维护 token 单价（最多 6 位小数）并用于「聊天运行」Tab；生图任务已在 `preset.parameters.rate_card` 维护文本/图片分项 token 费率。新单价表须作为全平台单一真相源收编这两套口径，避免多套账本打架。
- 页面 `AIManager.vue` 顶部已有 4 张全局统计卡（其中调用数和 Token 未按今日/本月过滤），采用 Liquid Glass 材质；提供商/预设编辑为弹窗，支持连通性测试、预设复制、多模态双图测试。

## 4. 需求

### 4.1 订阅管理（新 Tab，默认打开）

**定义**：一张卡片 = 一个订阅源（一个提供商账号/中转站，下挂若干模型）。

**F1 卡片展示**（每张卡片）
- 名称、LOGO（无 LOGO 时显示名称首字的彩色字标）、接入类型（**直连 / 中转站 / ACCIO WORK**）、协议（OpenAI / Anthropic）。
- 下挂模型：该提供商下启用预设所用的模型名，以标签列出（超过 4 个折叠为“+N”）。
- 订阅主状态与次要告警：主状态按优先级显示 1 个（正常 / 即将到期 / 待确认续费 / 余额偏低 / 余额不足 / 已停用）；若同时命中另一维度告警（例如“待确认续费”且“余额不足”），以副标签一并展示，不隐瞒风险。
- 周期/续费段（正交可选，填了续费/到期日即展示，不限制计费方式）：订阅日期、下次续费/到期日期、距到期天数、**本周期已过进度条**（已过越多条越长；剩 > 7 天绿色、≤ 7 天琥珀色、过续费日待确认 100% 满格琥珀色）、套餐名与周期金额。
- 余额段（正交可选，登记过余额即展示，按量默认随调用扣减，纯包月默认不扣减）：余额（估算）、**较上次登记余额剩余进度条**（以上次登记值为 100% 基准，标注预警线）、余额来源与登记距今天数（超 14 天提示“建议核对”）、在途调用提示。
- 本月调用消费、上线后累计消费（金额，按原币种展示）；未定价的调用不计为 0，单独标注“含 N 次未定价调用”。累计只统计上线后已计费的调用，存量日志不计入。
- 内部不计费通道（如 ACCIO WORK）以紧凑摘要块展示绑定预设数与近 30 天调用量，不留大片空白。
- 控制台链接、API 文档链接（新窗口打开，仅 https）。
- 操作：待确认续费时提供「已续费」快捷确认；常规操作含「登记余额」「编辑」及「更多（测试连通性、查看该提供商调用日志、停用/启用、删除）」。

**F2 状态颜色与进度**（统一规则，见设计文档 §4.3）
- 续费/周期：剩余天数 > 7 天绿色；0–7 天琥珀色（即将到期）；过续费日未确认琥珀色（待确认续费，人工确认后顺延一期，不自动顺延）。
- 余额：余额 ≥ 预警线绿色；低于预警线琥珀色（余额偏低）；≤ 0 红色（余额不足）。
- 颜色之外必须有文字，不能只靠颜色表达状态（色盲可读）。

**F3 页面顶部汇总条**（取代原 `AIManager.vue` 顶部旧 4 卡，避免叠罗汉）
- **本月调用估算**（按币种分列，不换算）+ 副行并列展示 **在用固定周期订阅合计（当期/折合月费）**，两者不混算但一眼看全公司真实 AI 开支。
- **上线后累计调用**（按币种分列；附注未定价调用次数）。
- **在用订阅数**（已启用且非待确认续费的提供商数）。
- **续费提醒数**（可点击筛选，独立维度计数：所有已启用且即将到期或待确认续费的提供商；再次点击取消筛选）。
- **余额预警数**（可点击筛选，独立维度计数：所有已启用且余额偏低或不足的提供商，**不被续费主状态遮蔽**；再次点击取消筛选）。
- **总账守恒**：已停用及已软删提供商的历史日志，均保留并继续计入全平台本月/上线后累计总消费。

**F4 筛选与排序**
- 筛选：状态（全部 / 续费提醒 / 余额预警 / 已停用）、接入类型（直连 / 中转站 / ACCIO WORK）、协议（OpenAI / Anthropic）、可选“隐藏已停用”。搜索：名称、模型名。
- 排序：按到期日（默认，无到期日置后）、按余额剩余占比、按本月消费（不同币种分币种或显式标注原币比较，不静默混排）。
- 卡片/表格切换：表格视图保留现有全部技术列与操作，供批量核对使用。

**F5 订阅信息录入与余额流水**
- 必填：名称、API Base、接入类型、协议、Key（可空，ACCIO WORK 除外）。
- 订阅信息（可选，缺失时卡片显示“未登记”或隐藏不适用可选段，不显示 0）：套餐名、计费方式（包月 / 包季 / 包年 / 按量充值）、是否按调用扣减余额开关、订阅金额与币种、订阅日期、下次续费/到期日期、控制台链接、API 文档链接、LOGO（上传到本站并走对象存储同步，禁外链热加载、禁 SVG）、低余额预警线。
- 余额登记（保留流水）：填写当前余额、币种、类型（余额核对 / 充值入账）、备注、截点时刻（默认精确到秒的“此刻”北京时间，防止当天早些时候的调用被重复扣减）；保存时同步记录系统原估算值快照以便复盘漂移误差。之后余额 = 最新登记值 − 该时刻之后的按量已计费消费。

**F6 与现有提供商管理的关系**
- 现有“提供商管理”表格的全部能力（新增、编辑、启停、删除、测试连接、API Key 掩码查看、`runtime_config` / `extra_headers` 结构化配置）全部保留，并入“订阅管理”。
- 卡片视图和表格视图共享同一份数据，操作入口一致。首次进入显示可关闭的一行迁移提示“提供商管理已并入订阅管理”。

### 4.2 预设管理（改造）

**P1 按功能归类展示**
- 预设按“所属功能”分组，主体沿用系统导航（`frontend/src/config/navigation.js` 分组与子项，如物流跟踪、展会营销、内贸订单、客户经营、方舟洞见、企业知识库、设计中心等），并补充平台内置非导航分类（外部站点网关、Agent 引擎、系统测试）。
- 每条预设显示面包屑：`功能 › 预设名`，并标出提供商与模型（窄屏/移动端也必须完整展示模型名，不可隐藏）。

**P2 面包屑标签快速筛选**
- 顶部标签行：功能 → 提供商 → 模型，三层标签可多选，选中即过滤。
- 标签上显示交集数量（如 `DeepSeek · 6`）。
- 已选标签可一键清除；筛选条件保留在 URL 中，刷新与分享后不丢失。

**P3 归属字段与种子一致**
- 每个预设必须有一个“所属功能”（`feature_key`）。新建预设时 API 层必填；存量预设由迁移按写死的映射快照回填，回填不了的归入“未归属”并醒目提示。
- 后端启动自动种子（`seed_ai.py`、`seed_fx_settlement.py`、`seed_whatsapp_reply.py`）同步写入 `feature_key`，防止重启或新环境持续产生新的未归属预设。
- “未归属”预设不影响调用，页面顶部给出数量提示和一键筛选处理入口。

**P4 预设详情、用量与旧能力保留**
- 点击预设打开右侧详情抽屉（复用 `DetailDrawer`）：调用模块、近 30 天调用次数、成功率、平均耗时、本月估算消费。
- 抽屉与列表行内保留现有的全部能力：测试调用（含多模态双图测试）、编辑（含 `AiPresetImageFields`、`AiPresetChatFields`、`AiConfigFields`）、**复制预设（继承 `feature_key`）**、启停、删除。

**P5 反向定位**
- 从订阅卡片“查看该提供商的调用日志”跳转调用日志 Tab，并带上 `provider_id` 筛选。
- 从预设面包屑点击“功能”，跳转到该功能对应的业务页（仅在存在对应路由页面时显示）。

### 4.3 费用口径（全平台单一真相源）

- **统一单价表**：按“提供商 + 模型”在 `ark_ai_model_prices` 登记单价与币种（支持 `token` 每百万输入/输出单价最多 6 位小数、`per_call` 按次固定价、`image_rate_card` 复用生图分项费率卡）。**收编现有 `parameters.chat.pricing`**，消除同一页面多处维护单价的冲突；未登记单价的模型调用记为 `unpriced`，不计入金额。
- **全链路调用结束时计算**：覆盖全部 5 条主调用链（`chat`、`delegate`、`chat_stream`、`generate_image/edit_image`、`prepare_agent_chat`）与 3 条外部 pending 兜底链；调用完成时按单价与实际用量计算费用快照写入日志，单价调整不回溯历史。计费代码与业务结果严格隔离，计费异常绝不改变调用成功状态。
- **币种**：按原币种（`CNY` / `USD`）存储与展示；汇总时只在同一币种内相加，跨币种不换算，分别展示。
- **估算声明**：页面明确标注“调用费用由方舟按单价估算，以供应商账单为准”。

### 4.4 数据与安全

- API Key 仍只显示掩码；卡片、日志、导出中均不出现明文。
- 控制台与文档链接只接受 `https://`，保存前前后端双重校验。
- LOGO 仅允许上传真实图片（后端校验 magic bytes，限 PNG/JPEG/WEBP ≤ 512KB，**严禁 SVG 防 XSS**），通过平台对象存储体系保存与同步，不做外链热加载。
- 费用与余额数据仅 `ai:admin` 可读；接口和页面都要校验，不能只隐藏按钮。
- 时间统一北京时间：“本月”按 `beijing_today()` 的自然月计算，余额截点按 `beijing_now()`；前端按 `frontend/src/utils/datetime.js`。

## 5. 验收标准

| 编号 | 验收项 | 通过判据 |
|---|---|---|
| A1 | 卡片信息完整 | 每个订阅源卡片按正交规则展示 F1 字段；未登记字段显示“未登记”而非 0 或空白；不适用可选段不占位 |
| A2 | 状态、副标签与独立计数 | 构造即将到期、待确认续费、余额偏低、余额为 0、以及“待确认续费+余额不足”叠加数据，卡片主/副标签正确，顶部“续费提醒”与“余额预警”各自独立计数不互相遮蔽 |
| A3 | 汇总与总账守恒 | 本月/上线后累计消费覆盖同步/流式/生图/Agent 全链路（不含 legacy/test/failed/预扣 reservation），与数据库 SQL SUM 一致；停用或软删提供商后历史消费不丢失；固定订阅合计单列不混算 |
| A4 | 预设归属与种子 | 存量预设全部有归属或进入“未归属”；新建预设不选功能无法保存；启动种子创建的预设自带 `feature_key` |
| A5 | 多维筛选 | 选“功能 + 提供商”后列表只剩交集；清除标签后恢复；刷新 URL 后筛选保持；窄屏下模型名完整可见不错位 |
| A6 | 旧功能不回归 | 提供商新增/编辑/启停/删除/连通性测试/JSON 运行配置、预设复制与多模态双图测试、调用日志、聊天运行、站点应用 Tab 均可用 |
| A7 | 权限 | 无 `ai:admin` 用户访问全部新接口返回 403，且看不到费用与余额字段 |
| A8 | 安全 | API Key 不出现在响应、页面、日志中；非 https 链接保存失败；非白名单图片或伪装 SVG 的 LOGO 上传被拒绝 |
| A9 | 费用与余额口径 | 单价调整后新调用按新单价（同步对多 worker 生效），历史日志不变；当天下午登记余额不重复扣减当日上午消费，且历史登记流水可查 |
| A10 | 移动与桌面适配 | 1280px 与 390px 宽度下 Tab 栏与汇总条横向可滚动不折行、卡片不溢出、预设行不错位 |

## 6. 需求决策记录（Q1–Q6 已全部确认）

| # | 问题 | 确认结论（2026-11-27 亮哥拍板） |
|---|---|---|
| Q1 | 中转站余额能否通过接口自动同步？ | **一期全部手工登记并保留核对/充值流水**（可复盘估算漂移）；第三期按提供商适配器逐家接入自动查询。 |
| Q2 | 单价从哪里来？如何处理已有定价？ | **人工在统一单价表 `ark_ai_model_prices` 维护，并收编现有 `chat.pricing`**（过渡期兼容回退、不保留双处录入）；生图支持按次价或复用现有 `rate_card`。 |
| Q3 | 一个提供商是否可能有多个套餐/账号？ | **一期 1 个提供商 = 1 张卡片（1:1）**；多套餐用多条提供商记录区分。 |
| Q4 | “功能归属”以哪套分类为准？ | **以 `frontend/src/config/navigation.js` 分组与子项为主体，补充平台内置非导航分类**（外部站点网关、Agent 引擎、系统测试）。 |
| Q5 | 费用与卡片如何区分“包月”与“按量”？ | **续费/到期与余额正交可选（不互斥）**，通过“是否按调用扣减余额”开关控制扣减；**顶部汇总并列展示「调用估算消费」与「在用固定周期订阅合计（月折算）」**，两者不混算。 |
| Q6 | 停用/删除的提供商如何处理？ | **停用卡片默认保留置灰**（可筛选隐藏），不计入在用订阅数；**已停用及已软删提供商的历史日志继续计入平台总消费**，保证总账守恒。 |
