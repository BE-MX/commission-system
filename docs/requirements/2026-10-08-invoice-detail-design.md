# 订单发票关联详情：功能设计与高仿真原型

日期：2026-10-08。设计依据：本地 main `7d9e42ea` 的前后端代码、`DESIGN.md`，以及用户提供的 OKKI 截图。原始阶段交付功能设计与静态交互原型；后续按用户授权基于 main `fbb63182` 实现真实页面与 API，详见[实现及验收](2026-10-08-invoice-detail-implementation.md)。候选 `ddc4a5a5` 已统一发布，见[发布记录](../reports/2026-10-08-invoice-detail-release.md)；生产权限体验与预售开关未逐账号核验。

## 核心问题与设计选择

业务员在订单发票列表看到一张发票后，需要直接判断订单内容、哪些商品已出库、哪些款项已生效，以及剩余事项对应哪些单据。当前发票号是普通文本，编辑入口承担录入职责，回款和出库分散在其他页面。

把发票号改为只读详情入口，打开一个宽弹窗，保留列表筛选、排序和滚动位置。借鉴 OKKI 的「进度概览 + 标签页 + 关联单据」信息层次，视觉沿用方舟的暖金、青碧与中性色。

顶部用**回款进度、出库进度两条独立进度条**。方舟允许预售分批交付，回款和出库可以并行或分次推进；不能把它们画成「确认 → 结清 → 备货 → 出运 → 出库 → 完成」的线性流程。当前也没有足够证据支持复用 OKKI 的“全部备妥、已出运、待完成”等节点。

## 当前功能与数据依据

| 已有能力 | 代码依据 | 对详情的影响 |
| --- | --- | --- |
| 库存单、生产单、预售单；订单商品、配件、折扣、包装、运费及附加费 | `backend/app/invoice/models.py`、`schemas.py`；`frontend/src/views/invoice/InvoiceManage.vue` | 统一只读入口；按订单实际明细展示，不重算保存金额 |
| 同步状态与取消状态 | `useInvoiceManagePage.js`、`InvoiceLifecycle.vue` | 订单同步/取消标签独立于资金和履约进度 |
| 回款关联 `invoice_id`；方舟编号、远端 ID、财务状态、凭证、批次及用途 | `backend/app/receipt/models.py`、`service.py` | 展示每笔回款；同步结果不等于财务生效 |
| 原币资金汇总、远端去重、含费恢复、余额占用 | `backend/app/receipt/balance.py`、`service.invoice_summary` | 直接复用领域口径，不从列表页可见行自行汇总 |
| 预售结算、商品应收、独立运费应收、资金应用、出库派发 | `backend/app/invoice/settlement_models.py`、`settlement_service.py`、`settlement_pricing.py` | 主单运费为零，运费单独统计；预付款只在末批抵扣，抵扣不新增回款 |
| 预售能力开关 | `backend/app/invoice/settlement_policy.py` | 不默认宣称生产已启用；历史只读详情与创建动作分开 |
| 出库列表、生成队列、缺货、检验状态、打印数据 | `shipping_inspection/outbound_service.py`、`outbound_queue_service.py`、`frontend/src/views/shipping/OutboundRecords.vue` | 保留生成状态、检验状态；缺货/待生成仅是计划，不能计入已出库 |
| 出库单的精确订单关联 | `outbound_service.order_ids_for_records`、`list_outbound_items` | 通过出库明细订单 ID 和桥接键关联，不能根据单号、客户或日期猜测 |

后续用户确认：出库进度按当前有效的 `ShippingInspection.status=submitted` 计入对应订单行数量，不再以小满状态 2 或预售本地 `shipped` 为前提。撤回检验、同步未确认或待补验的单据不计入；数量镜像落后于已核验修改、映射缺失、重复或超量时隐藏汇总。仍按订单 ID、远端行 ID、产品 ID、SKU 精确关联，混合订单仅取本订单行，预售冻结数量须一致。该只读口径不改变原单或结算状态。静态原型保留初版场景，当前实现以此后续口径为准。

## 入口与公共区域

- 发票号使用原生可聚焦按钮，保持现有列表颜色与固定列；点击打开详情，默认激活「订单详情」。编辑仍从已有编辑入口进入。
- 弹窗桌面建议宽 1200px，上限为视口减 24px，最大高度为视口减 32px。页头、概览、标签页和页尾保留，仅标签页正文滚动。小屏两条进度并排，字段改两列，表格内部横向滚动。
- 页头：发票号、订单类型、订单同步/取消状态、宽屏与关闭。
- 概览：客户、客户等级、业务员、发票日期、原币订单总额、商品数量、回款/出库进度。点击进度卡直接切换对应标签页。
- 页尾：各数据源最近成功核验时间及状态、打印订单预览、关闭。各源时间不同则分别显示，不制造统一“实时”时间。原型的固定时间与场景切换器仅用于设计演示。
- 三个标签始终可辨识：**订单详情 / 出库单详情 / 回款单详情**。出库计数为实际关联出库单数，待生成发货批次另列；回款计数为合并去重后的实际单据数。无权限时不显示计数。

## 异常标识与导航角标（2026-10-08 补充）

- 列表发票号与详情标题发票号的右上方增加红色荧光描边框。订单异常显示“订单异常”，出库异常显示“出库单异常”，回款异常显示“回款异常”；多个域同时异常时并列显示全部相关提示。
- 提示来源为明确的业务异常状态：订单 `sync_failed` / `sync_uncertain`；出库生成/派发 `failed` / `uncertain` / `outbound_uncertain` / `review_required`；活动回款 `failed` / `uncertain`。正式实现以各域实际状态字典与任务状态核验，不能只根据颜色或错误文案猜测。
- 普通未同步、待生成、等待回款、财务未生效、未检验及权限不足不标为业务异常。作废或已核实远端删除的回款不进入活动异常汇总。单纯网络读取失败作为“核验失败”反馈，不能据此推断三类业务单据均异常。
- 荧光效果用静态红色边框、浅红底、深红文字与外发光实现，不闪烁、不呼吸。移动端允许换行，不覆盖发票号或关闭按钮。详情中的每类异常文字可以点击，直达对应标签页；悬停提示关联异常单据及状态。
- 左侧“订单发票管理 / 出库单 / 回款单”名称右上显示黄色 `!` 角标，只标记出现异常的相应域。正常等待不会误报；多个域异常则多个对应导航显示角标。
- 导航角标是当前用户有权查看的单据范围内的异常概览，不随当前打开订单、标签页或列表分页/筛选改变；只有该域已确认无未解决异常时移除。获取异常概要失败不能当作“无异常”，需保留并标注上一核验状态或显示待核验，避免误清除提示。
- 后端须分别校验各域功能权限、数据归属与任务访问范围；既不返回无权查看的异常数量，也不通过角标或 tooltip 暴露单号。聚合范围应覆盖可见单据的完整范围，不能仅扫描当前页；详情接口与导航只读异常概要应复用同一状态判据。
- 静态原型以三张演示订单作为完整模拟单据集合，切换异常演示会替换第一张示例。打开其中一张正常订单仍保留集合内的导航异常提示。正式的全域异常概要接口尚未实现。

## 三个标签页

### 订单详情

订单信息：客户与联系人、业务员与跟单员、发票日期、订单类型、小满订单 ID/编号、收货地址、联系方式、付款条款、发货方式、来源与备注。同步和取消状态沿用现有状态字典。

商品明细保留 hair/accessory 的实际类别、规格、订单数量、已确认出库数量、成交单价、行折扣和保存的小计。配件不伪装成头发规格。金额来自发票快照；商品净额已经包含行折扣，订单级不再重复减一次折扣。底部展示商品净额、包装费、主单运费、附加费和发票总额。

### 出库单详情

数量汇总：订单数量、已确认出库、待生成批次数量、未安排数量。普通订单不强制展示预售批次概念；如已生成但未实际出库，单独列出待出库数量。统计单位不兼容的商品分组展示，不合并成同一种件数。

关联出库单与待生成批次分组展示。每张单据显示单号、日期、制单人、本订单关联数量、生成/出库状态与检验状态；展开显示商品规格和该单实际数量。预售批次展示结算编号、状态、计划数量、独立运费和冻结快照，未生成时使用「第 N 批 · 待生成出库单」，不能编造出库单号。

一张出库单若包含多个订单，只统计当前订单的明细数量；详情明确展示本订单关联范围。原始整单打印能力复用已有权限与可打印判断，正文查看不依赖打印前置条件。

### 回款单详情

先展示已生效、待生效、未结清和主单余额，再展示关联回款明细。普通订单显示可登记余额；预售订单显示主单未登记金额，并单列当前活动批次的可登记余额，不能将两个额度混用。预售运费应收与回款另列汇总，不进入商品主单分母。

表格：方舟/小满回款号、回款日期、用途及关联对象、原币回款金额、手续费、同步状态、财务状态、凭证。可以按用途及单号筛选。点击回款号或凭证，在本标签页展开回款资料、净额、批次、备注、凭证与核验状态。共享批次凭证保留批次关联，不暗示一张截图等于一笔独立收款。

方舟创建的回款与仅在小满创建的回款合并展示：有映射时只保留一条；远端独有单据标注来源，缺少本地凭证显示“未关联凭证”，不生成本地编号或虚构附件。作废、核实远端删除记录归入历史记录，退出当前进度；待核对记录仍保留可恢复入口。

首版定位只读查看与现有查看/打印能力。不在详情原型增加生成回款、同步、作废、删除、取消订单等写动作。

## 进度与金额口径

| 指标 | 规则 |
| --- | --- |
| 订单金额 T | 发票总额，订单原币；预售主单不含独立运费应收 |
| 已登记金额 R | 复用 `registered_amount`，含活动回款及已占用自动回款意图；失败/待同步仍占用 |
| 已生效金额 E | 复用 `effective_amount`，核验到远端 `collect_status=1` 才计入；匹配方舟回款时恢复手续费，使其与订单含费口径一致 |
| 待生效 P | `R − E`；涵盖未同步、失败、未生效和可确认的占用，不能称作“银行已到账” |
| 未结清 | `max(T − E, 0)`；超收另外明确显示 `max(E − T, 0)` |
| 主单余额 | `max(T − R, 0)`；普通单称可登记余额，预售称主单未登记金额；超登记另显示异常，不以截零隐藏差异 |
| 预售本批可登记余额 | 复用 `order_balance` 的活动批次 `funding_balance`，商品及运费分别限制，再展示合计；不是主单的 `T − R` |
| 回款进度 | `E / T`。视觉进度上限 100%，超收另标金额；百分比保留实际精度，不把 99.6% 四舍五入成“已结清”；状态按精确金额判定 |
| 出库进度 | 本订单各商品行有效检验已提交数量 / 对应订单数量；数量必须按明细身份、单位及当前检验状态核验 |
| 出库明细去重 | 本地派发记录与远端记录按 `remote_id` / 出库明细身份去重；同 SKU 多行通过订单行身份映射，不能直接累计全单或按产品名称匹配 |
| 待出库 | 总数量 − 已确认数量；预售计划/预约数量另列，不作为已出库；负数/超量为异常 |
| 数据异常 | 遇到远端金额/身份变化、删除、币种不一致、明细无法关联或核验失败，相应指标显示“待核验”，不显示 0 或过期百分比 |
| 零金额 / 零数量 | 无分母不显示百分比；“无需回款 / 无可出库商品”需有实际业务依据，不能把缺失值视为零 |

回款不使用 `internal_received` 等旧录入快照作为真实生效金额，不使用“已同步小满”代替财务确认。实际净额、银行手续费与用于清偿订单的含费金额分别标注。预付款末批抵扣和资金应用不能再累计到 E 或 R。

## 权限、异常与实现边界

- 订单读取沿用 invoice 权限及订单访问规则；出库读取沿用 shipping inspection 权限与归属；预售批次沿用 shipment 权限；回款读取沿用 receipt 权限及业务员归属/`receipt:read_all`。拥有订单读取、代创建或 `invoice:read_all` 不自动获得另外三种访问范围。
- 三标签可保留，但无相应访问范围时只显示权限提示。汇总金额、数量、计数与凭证也受保护；禁止先取全量数据再在前端隐藏。拥有某一相关域的权限但不具备另一域权限时，分别返回可见数据，不让整个订单详情失败。
- 未同步订单依然能查看发票快照；空关联记录显示原因。取消/取消处理中保留历史单据，明确取消状态，不包装成履约完成。
- 数据源按独立区块加载，区分加载中、真空数据、核验异常、无权限；单个源失败不清空订单快照。核验异常仅阻断相关进度和动作，保留已有单据及恢复线索。
- 关闭支持按钮及 Escape；原生模态隔离背景焦点；标签支持方向键/Home/End；关闭恢复触发发票号焦点。高频切换不加位移与表格入场动画，正文无延迟显示。

## API 复用与需要补齐的能力（设计提案，尚未实现）

已有发票详情、`GET /api/receipts/invoice-summary/{invoice_id}`、回款详情/私有凭证、预售 `GET /api/shipments/order/{invoice_id}`、出库列表及 print-data 可作为数据来源。现有列表分页数据不适合直接作为完整汇总。

建议增加 invoice 领域的只读聚合接口 `GET /api/invoice/invoices/{invoice_id}/related-detail`（拟定路径，注册前核对已有 client prefix）。服务层按域权限、归属及能力分别返回订单、资金汇总、出库汇总、单据分页与状态信息，保持统一响应信封。关联均以数据库 ID/远端 ID为准。扩展适当的只读出库详情能力，不能只借用 print-data 的打印许可。

需补齐：普通订单实际出库事实来源；完整分页、明细身份及多订单拆分；本地/远端回款合并清单；预售运费按 receivable 核验的汇总；批次明细读取；资金汇总对领域异常的统一处理；独立源权限及核验时间。现有 `service.invoice_summary` 调用普通 `balance.calculate`，预售需要复用 `goods_balance` 的未分配远端资金检查并另取运费目标，不能不加核验直接当作最终预售看板。

正式实现的回归验证必须覆盖：普通订单含费去重、预售末批抵扣、运费不串额度、同 SKU 多行、混合订单出库、部分/全部出库、远端修改/删除、作废历史、失败占用、零分母、超收/超出库、权限及归属泄漏、生产开关关闭。此次静态原型的检查只证明界面交互和样例自洽，不能替代以上 API 和数据库验证。

## 原型与样例

入口：[高仿真交互原型](2026-10-08-invoice-detail-prototype/index.html)。默认预售示例：24 件、商品净额 USD 1,800.00、包装费 USD 40.00、订单 USD 1,840.00；已生效商品款 USD 1,104.00 = 预付款 184.00 + 第一批商品款 920.00；待生效商品款 368.00；主单未登记金额 368.00；未结清 736.00。当前第 2 批可登记余额 245.33（商品款 245.33，运费 0.00）；不能直接用主单未登记金额作为本批可登记额。

第一批 12 件净额 900.00 + 包装费 20.00，商品款 920.00 已生效，不在非末批抵扣预付款。第二批计划 8 件，冻结商品净额 600.00 + 包装费 13.33，部分款项已登记但未齐备，尚无出库单；后续 4 件待安排。已确认出库 12/24 = 50%。独立运费应收 120.00，其中 80.00 已生效、40.00 待生效，不进入主单 60% 回款进度。

原型提供预售部分履约、库存结清、已生成待实际出库、生产草稿、核验异常、权限受限以及订单失败、出库待核对、回款失败、多项异常十个场景。支持发票入口、三标签、进度跳转、关联出库单展开、回款用途与单号筛选、回款资料/模拟凭证展开、宽屏、复制、关闭和订单打印预览。生产草稿额外展示四位成交单价与负行折扣，行金额使用保存小计。全部客户、金额和单号都是演示资料，不连接任何真实业务系统。
