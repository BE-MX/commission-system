# WhatsApp 长历史直接生成（v1.5.0）

2026-09-11，分支 `codex/whatsapp-full-history`，基于 main `915837f6`。用户授权修改、优化与测试；本轮未合并、推送、部署或调用付费模型。无数据库迁移。

## 行为

默认「加载历史并生成」主动滚动当前聊天，先向下纳入最新内容，再向上分批采集，最后尽量恢复滚动位置。用户无需预先手动滚动；这已在合成页面验证，真实 WhatsApp 的历史加载仍待实测。范围显示采集数量与时间，以及网页边界未核实、仅已加载、步数限制等状态，不宣称已获取手机全部历史。也可选择仅已加载或最近 20/40 条。

消息 JSON 保留 customer/salesperson、正文、日期时间、引用、媒体占位及可读标题。电话和邮箱沿用脱敏；不包含联系人标题或 WhatsApp ID。稳定 DOM ID 仅在内存匹配重叠窗口，重复文字保留，节点重建且无法可靠对齐时停止。未知方向消息跳过并提示，群组和未知聊天结构不支持。只读当前页面 DOM，不访问内部数据库/网络拦截。

JSON 通过现有请求传给生成服务，同一采集内容可由用户点击下载为 JSON 文件，不增加附件存储或自动保存完整聊天。最多 2,000 条，正文与引用合计 120,000 字符；服务端可下调。触及容量明确停止生成，可下载已采集部分或主动选择较小范围，不默默丢弃早期内容。

## 生成与可靠性

普通上下文直接调用 generator Agent；移除 planner 前置步骤及旧语义拒绝模块，不再因数字、价格、日期、链接、引用或承诺字样拒绝草稿。知识用途和不编造承诺由提示词引导，业务员仍预览、核对再使用。无知识时仍生成并提示；JSON 基本解析、权限、知识发布/撤权检查、限流、幂等、错聊天和旧草稿保护保留。

超过 32,000 字符时，所有消息先按约 16,000 字符块摘要（保留原消息索引；超长单条按片段覆盖），再结合摘要与最近最多 8,000 字符原文生成；返回 `context_processing=summarized`，界面明确告知。原始完整消息参与摘要，但摘要可能丢失细节，不能将模拟覆盖视为模型质量保证。所有调用共享服务端总期限，不自动计费重试。

可选记忆结构/证据错误和保存冲突仅显示记忆错误，不抑制有效草稿。询盘保存的归属、实例标识、CAS 和人工修正规则继续生效。草稿展示先于保存完成；采集期间禁止重入、暂停因历史节点加载而触发的翻译，取消/切换聊天后不回填。没有自动发送行为。

## 启用配置

需要配套新版后端：capabilities 的 `reply.history_enabled=true`，否则扩展提示更新。现有权限、知识来源绑定、启用开关继续使用。默认 `WHATSAPP_REPLY_MAX_CONTEXT_CHARS=120000`、`WHATSAPP_REPLY_TIMEOUT_SECONDS=120`（上限 180，扩展 185 秒）。若生产 .env 显式保留旧 12000/30 值，需要在获准部署时更新，否则旧容量/期限仍有效。

只依赖 `WHATSAPP_REPLY_GENERATOR_PRESET`；bootstrap 新建预设 max_tokens 3200，默认禁用，不覆盖管理员已有预设。已有生成预设需要核对输出预算及 JSON response_format。删除代码中的 planner 配置依赖，旧数据库预设不删除。本轮不修改生产 .env 或预设。
