## 部署程序已落地的行为

- 默认统一处理办公室 NSSM 后端、Connector、主站/PM 内外网构建、北京后端及已登记的云静态目标。
- 构建、依赖安装和校验在候选目录完成；停止服务后才切换办公室代码与目录；不会在运行中的 PM `dist-lan` 内直接构建。
- 本地构建按内容及运行时版本缓存；云端按 SHA-256 清单只传变化文件，避免逐文件建立 SSH。准备好的候选可跨重试复用。
- 默认 fetch 后保留尚未推送的本地已审查提交，只接收可快进的远端更新；分支分叉时阻断，不要求先 push main 才能部署。
- 首次用 Linux 原子目录交换接入已有 Nginx 路径，此后切换 current 指针；保留旧浏览器仍需的 assets。摘要或真实 HTTPS 返回不符时回退。
- 共用数据库只通过统一迁移子进程升级一次；停机前验证 writer 清单和独立 DBA 权限。迁移与服务激活共同遵守 MySQL 发布锁。
- 未知／领先／分叉 schema 阻断；数据库变化后不会自动启动不兼容的旧代码。当前 writer 清单尚未完整核实，DDL 开关保持关闭，不能绕过。
- 云端单独发布时，依赖办公室后端且有变化的新加坡前端会列为 deferred。已成功目标、失败阶段和待办写入 `.deploy_state/publish-current.json`。
- 旧 `rollback.bat` 已阻断，避免用历史快照覆盖受管静态版本；失败激活在 schema 不变时自动恢复。已经完成发布的跨版本人工回退仍须核对 schema。

操作入口、目录规则与恢复边界见 [部署说明](../../deploy/README.md)。
