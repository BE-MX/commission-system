# 预售单、分批出库与多订单回款设计 V1

日期：2026-09-23。状态：设计交付，未实施、未迁移、未发布。

> 已被 [V2 开发规格](2026-09-23-presale-settlement-development.md) 取代。后续确认了“每批款到发货、预付款只抵末批、一笔客户付款包含商品与运费”。下文保留历史推导，不再作为实施依据，尤其不能沿用其无资金门槛出库及旧批次唯一约束。另见 [对抗性审查](../reports/2026-09-23-presale-settlement-adversarial-review.md)。

## 1. 目标与已确认范围

在现有订单发票体系增加预售单；预售单首次只按实际预收款生成回款，不自动出库。业务员按实际发货批次选择产品和数量生成出库单，系统推送小满。回款页面支持一次登记到账、分配给多张订单，并逐订单生成小满回款单。

用户已确认：一张汇总回款只关联同一客户、同一币种的订单；回款金额沿用含手续费口径。

本版交付业务规则、页面交互、数据及同步边界和验收场景。退款、跨币种换汇、跨客户收款、自动按比例分配回款、预售库存预占均不在本次范围。

## 2. 当前代码核对结论

| 当前能力 | 本次设计影响 |
| --- | --- |
| `invoice/schemas.py` 只允许 stock / production | 新增 presale；搜索、导入、编辑、导出和标签均显式识别，不能继续用“非生产即库存”的二选一显示 |
| `InvoiceReceiptFields.vue` 默认按订单总额填回款；`receipt/invoice_link.py` 只接库存单，但服务端已经允许小于订单总额 | 预售单增加明确的预收款输入，复用意图转换；不是另造一套回款算法 |
| `receipt/service.py` 已支持单订单创建，余额版本校验、幂等、权限和订单锁 | 增加汇总单事务编排，保留现有每订单回款账本与同步执行器 |
| `receipt/balance.py` 合并远端回款、本地占额及自动回款意图 | 继续沿用，避免遗漏失败单或把本地/小满同一笔重复计算 |
| `outbound_task_service.py` 和 `OkkiOutboundTask` 按小满 order_id 唯一建自动任务 | 不适合一个订单多批发货；预售使用按批次持久化的出库单与任务 |
| `shipping_inspection/outbound_queue_service.py` 将本地任务预览与只读小满镜像合并，部分去重依据为 order_id | 必须升级为按具体出库单映射去重，否则第一批镜像到达会隐藏后续批次 |
| `receipt/attachments.py` 的附件只能绑定一个订单/回款 | 增加汇总单附件关联及授权读取，不能把同一个附件反复绑定到不同子单 |
| 回款小满同步发送扣费后金额，附件当前仅方舟留存 | 沿用当前金额映射；不把“推送回款成功”描述为“凭证已同步小满” |

依据为本次工作区代码读取，包含已有未提交修改；未读取生产业务数据，未核验小满在线契约。后文接口/表名为拟定设计，外部能力见第 8 节实施前验证项。

## 3. 预售单

### 3.1 行为矩阵

| 行为 | 库存单 | 预售单 | 生产单 |
| --- | --- | --- | --- |
| 产品、价格、费用、客户、发票导出 | 保持现状 | 复用库存单规则，不允许库存单原本不支持的定制行 | 保持现状 |
| 首次回款 | 保持现状 | 仅按本次实际预收款生成 | 保持现状 |
| 首次完整同步小满订单后 | 保持现有自动出库规则 | 只触发预收回款；不建自动出库任务或本地出库预览 | 保持现状 |
| 后续出库 | 保持现状 | 列表操作“生成出库单”，支持多批 | 保持现状 |
| 后续回款 | 可从回款页登记 | 可从回款页登记 | 可从回款页登记 |

新建入口增加“新建预售单”，筛选和详情增加“预售单”。订单发票号沿用库存单现有编号分配器，使用同一前缀时共享序列防重，不额外引入用户未要求的编号体系。

### 3.2 预收款录入与生成

- 结算区显示“本次预收款（含手续费）”、回款日期、付款方式、凭证；旁边实时显示订单总额和本次登记后剩余金额。
- 预收款不默认填满订单总额，不随总额修改被静默覆盖。金额大于零且不超过可登记余额，金额统一两位小数。
- 允许无预收款资料保存草稿；本版建议首次同步要求正数预收款、日期、有效付款方式及凭证齐全，沿用库存单先有实际到账凭证再同步的规则。若以后支持零预收发售，应另行明确，而不是创建零元回款。
- 唯一录入来源为 `receipt_draft.amount`；“已收金额”作为账本汇总展示，不用 `internal_received` 再独立驱动自动建款。预收款是首次实际收款，不是计划收款，也不是订单总额。
- 订单完整同步成功后，自动回款意图转成一张回款，唯一业务键仍为“订单 + 首笔”。重复同步、修改订单均不重复生成首笔。
- 已提交的预收资料冻结，后续到账走回款页面。存在回款或出库占用后不允许改客户、币种、订单类型；订单金额不得低于已登记及占用金额。
- 预售在首推、补偿扫描、重试、恢复等所有自动出库入口统一排除；不能只隐藏前端按钮或只拦首推钩子。

## 4. 分批生成出库单

### 4.1 页面与交互

预售单列表展示“出库进度”和“回款进度”两个独立状态。操作菜单增加“生成出库单”；订单未完整同步、取消中/已取消、正在关联同步、数量待核验时禁用并说明原因。全部数量已分配出库后显示“已全部安排出库”，不再新增。

点击后打开“生成出库单”弹框：

| 信息区域 | 内容 |
| --- | --- |
| 单头 | 订单发票号、客户、收货信息、本次出库日期、出库单号预览 |
| 明细 | 勾选、产品/规格/SKU、订单数量、已建单占用数量、剩余可出库数量、本次出库数量 |
| 底部 | 本次选中产品行数、数量合计；取消 / 创建并推送小满 |

默认不勾选、不自动出全单；勾选行后可默认填该行剩余量，用户再调整。至少一行，本次数量必须大于零、符合该产品单位精度、不超过剩余量。余量为零不可选。提交前展示最终明细供核对，不增加独立重复确认步骤。

创建完成关闭弹框，反馈“出库单 XXX-01 已创建，正在推送小满”，提供查看入口；不能把排队当作小满已创建。出库列表立即展示本地单，之后更新为同一条对应的小满单。详情只显示本批次明细，打印、验货、扫码均不能误用整单数量。沿用现有正式出库单的打印/扫码资格，远端身份未取得前不伪造正式二维码。

### 4.2 数量口径

逐订单明细计算：

`剩余可出库量 = 订单行数量 - 有效出库占用量`

有效占用包括：本地已提交待推送、推送中、缺货等待、明确失败待处理、结果待核对，以及远端待出库/已出库的有效单据。按小满出库 ID 去重已映射的本地与远端记录；本地镜像和实时远端查询也不能重复累计。

“已建单占用”不等于“已实际出库”：列表区分未安排/部分安排/全部安排，详情另示小满执行状态。订单行 ID 是分配主键，不能仅按 SKU：同 SKU 多行可能有不同价格、备注。需要保存方舟行、小满订单行、出库行映射；远端只有 SKU 且不能唯一归属时，先核对映射，禁止猜测分配。

查询须包含小满直接创建的出库单，分页完整、状态明确；读取失败或映射不清时冻结受影响订单的新增出库。已出库后的退货不自动恢复可出库额度；补发/退款另按原业务流程处理，避免本次新增隐式退货逻辑。

### 4.3 编号、并发和编辑保护

- 默认编号为 `订单发票号-01`、`-02`，超过 99 后自然为 `-100`；V1 自动分配、不可任意改号。
- 弹框单号仅预览；提交时锁订单并分配最终序号，唯一约束覆盖 `(invoice_id, sequence)` 和出库单号。作废不回收序号。
- 提交带请求幂等键和数量快照版本；后端重新核对权限、订单状态、行归属及可出库量。并发争用时一方成功，另一方收到具体变化行，保留输入后刷新校验。
- 提交事务同时保存出库单、明细、占用、同步任务。远端调用在事务提交后执行；任务崩溃可恢复。
- 有出库占用后禁止删除/替换关联订单行、修改其 SKU；减量不能低于占用数量。现有编辑重建全部明细 ID 的路径必须改为稳定行身份或显式禁止相关编辑，不能留下悬空映射。
- 关联同步核对必须识别预售的合法部分出库：累计出库小于订单数量是正常待履约，不能继续用“出库必须等于整单数量”阻断完成；只将超量、错行、未知状态列为异常。取消流程仍核对全部批次及回款，不因预售允许分批就绕过原保护。
- 未外发的单允许审计作废；明确拒绝且确认无远端效果后可作废释放数量。已同步、执行中和结果不确定不能直接释放；远端删除需核实成功并保留审计。不可简单以“接口报错”判定未创建。

## 5. 多订单回款

### 5.1 单据组织

用户操作的是一张“汇总回款单”；内部关联 N 张“订单回款单”。汇总单记录一次到账、总额和凭证，子单承载各订单分配及小满同步。汇总单不另推一笔小满回款，避免总额被记两次。

回款页面“新建回款单”改为可多选订单的宽抽屉；选择一张订单也走相同流程。现有列表继续展示按订单的子单，增加可点击“汇总单号”，详情可查看本次到账及各子单状态。汇总金额仅用于核对，统计回款总额仍只累计有效子单。

### 5.2 录入流程

1. 选择客户和币种，添加订单。也可先搜索并选择第一张订单，自动确定客户/币种，之后只允许选择相同组合。
2. 候选显示发票号、类型、总额、已生效回款、待处理占用、剩余可登记金额；支持搜索和分页多选，已选订单不可重复添加。默认只展示余额大于零且可登记的订单；数据未核验时显示状态，不当作零余额或可提交。
3. 填写本次回款总额、日期、付款方式、附件、备注。上传沿用现有 1～5 张 PNG/JPEG/WebP、单张不超过 10MB；原始文件只上传一次。
4. 分配表逐订单填“本次回款金额”，同时展示“手续费”和“扣费后金额”。可使用每行“填满剩余”操作，不默认自动分配整笔资金。
5. 底部固定展示“本次总额 / 已分配 / 未分配”。差额为零且各行通过校验后，按钮为“创建 N 张订单回款单并推送”。

| 订单 | 总额 | 已登记及占用 | 剩余 | 本次分配 |
| --- | ---: | ---: | ---: | ---: |
| A（预售） | 10,000.00 | 3,000.00 | 7,000.00 | 4,000.00 |
| B（库存） | 5,000.00 | 3,000.00 | 2,000.00 | 2,000.00 |
| 合计（USD） | | | | 6,000.00 |

本次总额 6,000.00，生成 A 的 4,000.00 和 B 的 2,000.00 两张子单；A 剩余 3,000.00，B 可登记余额为零。只有财务生效后才显示回款完成，不能用“已经登记满额”冒充到账审核完成。

### 5.3 金额、手续费与附件

- `总额 > 0`；每个选中订单 `0 < 本次分配 <= 最新剩余可登记金额`；`Σ本次分配 = 汇总总额`。零金额行提示移除，不静默生成零元单。
- 订单类型不限于预售，允许库存/生产/预售混选，但须为当前方舟可关联、完整同步小满、业务有效且用户有权限的订单。仅小满存在、尚未关联方舟的订单不暗中导入。
- 全部金额使用 Decimal / 十进制定点，统一两位小数，不使用浮点容差放过不等额。
- 已提交自动预收意图和待处理子单均占用余额，复用当前余额核验服务；匹配远端 ID 后只计一次。余额变化提示具体订单和最新上限，保留已填金额与凭证，不自动修改用户分配。
- 按订单既有手续费分摊规则预填本次费用，尾笔处理舍入余数；无订单手续费时默认零，可沿用现有手工费用输入规则。每行费用必须非负且不大于该行金额。
- 汇总显示含费总额、手续费合计、扣费后合计。小满仍逐单传扣费后金额，远端手续费字段按现有约定置零；方舟保留完整原额及费用。例：分配 1,000、手续费 30，小满本笔金额 970，方舟占额 1,000。
- 共用凭证通过汇总单附件关联引用，不能复制绑定为多个互相独立的到账。子单能访问本次凭证，但不能因此访问无权限的其他订单金额；汇总详情也按订单数据权限处理，不泄露整批数据。
- 附件状态继续明确显示“仅方舟留存”。本需求的自动推送指子回款业务数据，附件上传到小满不在已验证能力内。

### 5.4 事务与同步反馈

一次提交先核验全部远端余额和费用证据，再按订单 ID 固定顺序加锁并重检本地状态/版本；锁内不调用会自行 commit 的单订单 create 方法。任一订单不满足时整批不建单，避免用户以为一笔资金已全额分配。

同一事务创建汇总单、全部分配及子回款单、附件关联和待同步状态。汇总请求幂等键与内容摘要唯一；重试返回原批次，不重新分拆。子单唯一 `(batch_id, invoice_id)`，同步仍使用原子单 ID 和固定请求内容。

本地事务成功后分别推送小满，各子单独立成功/失败；小满跨多订单不具备本地原子性，不能承诺远端全成全败。界面反馈“已创建 3 张，已同步 2 张，1 张待处理”，汇总状态由子单计算，不把任一失败说成整批未创建。

明确拒绝可重试原子单；超时/断网等结果未知进入待核对，先查远端并绑定已有单，不盲重试。已成功子单绝不再次推送。

本地订单锁不能拦截在小满直接登记的回款。子单推送前再次核验远端余额，校验时排除正在发送的本子单占额，保留其他本地占额；发现冲突转待处理，不强推或静默缩减分配。实施时验证小满自身的超收约束及可用并发保护；若不能原子保证，则须约束同订单跨系统同时写入或转人工核验，并如实显示此限制。

汇总提交后冻结分配及附件；子单不可通过原有编辑/作废接口单独破坏汇总等式。V1 允许整批在所有子单均确认未产生远端效果、且无执行租约时审计作废后重建；只要有一单已同步或结果未知，就保持原分配，通过原单核对及受审计纠错流程处理，不自动冲销已成功款项。作废批次保留原始分配，总额统计排除已作废子单。

## 6. 数据与接口建议

| 改动 | 最小结构 |
| --- | --- |
| 订单类型/首款 | 扩展 presale，复用 ReceiptIntent；更新枚举、导入、模板和订单生命周期校验 |
| 分批出库主表/明细 | commission_db 新建出库表：订单 ID、序号、唯一单号、单据/同步状态、幂等键、版本、远端 ID、审计；明细存稳定订单行、远端行映射、数量及打印快照 |
| 分批出库任务 | 一批一持久任务，复用现有执行器可用能力；不删除现有“整单自动任务按订单唯一”的防重约束 |
| 汇总回款 | 新增 `ark_receipt_batches`；现有 `ark_receipts` 增加可空 batch_id，子单本身即分配明细，无需重复建金额账本 |
| 附件关系 | 增加批次附件关联；历史单单绑定继续保留真实归属，新批次显式使用关联授权 |

拟新增接口：

- `GET /api/invoices/{id}/outbound-options`：可出库明细、版本、单号预览、不可操作原因。
- `POST /api/invoices/{id}/outbounds`：本次行数量、快照版本、幂等键，返回本地出库单及同步状态。
- `POST /api/receipts/batches`：总额、日期、方式、附件、各订单金额/费用/余额版本、幂等键。
- `GET /api/receipts/batches/{id}`：权限过滤后的汇总详情与子单结果；扩展订单候选查询为同客户/同币种/可登记余额筛选。

回款写入复用 `receipt:write`，每张订单继续做数据范围鉴权；出库新增独立写权限（建议 `shipping_inspection:write`，正式编码前核查其既有用途），不可仅凭查看订单权限出库。前端用权限指令，后端强制校验，重试/作废/凭证读取同样鉴权。

不写只读 `lsordertest` 镜像，不提前创建镜像行；新表走 Alembic，关联列类型匹配，历史订单不重分类、不自动补首款或补出库。新批次和旧单据共同参与余额/数量核对。发布时协调 API、后台补偿器、出库执行器，旧执行器不得消费不认识的分批任务。

## 7. 验收场景

1. 预售总额 10,000、预收 3,000：首次同步仅生成 3,000 回款，不生成出库任务；重推及补偿扫描结果相同。
2. 第一批 A 产品 4/10、B 产品 2/5：生成 `-01`；下次上限 A=6、B=3。第二批只选 A，B 不出现在该批单据中。
3. 同 SKU 不同行分别占用；远端行无法唯一映射时阻断，不任意扣某行。
4. 双击提交、两个用户并发、服务崩溃恢复：不重复建单、不超量，序号唯一，允许合法空号。
5. 第一批镜像到达后第二批本地单仍可见；单头先到、明细后到不重复计量，不误认整单已完成。
6. 小满直接建出库、删单或改量后重核验；分页/状态不完整时拒绝新增；只读镜像不产生业务写入。
7. 两订单分配 4,000+2,000，总额 6,000 成功；5,999.99、超余额、重复订单、异客户/异币种均拒绝。
8. 预收意图转换与批量回款并发时不超收、不重复占额；远端财务未生效的已登记款仍占余额。
9. 三张子回款第二张推送失败：其余两张保留成功，只能处理原失败单；超时先核对，不重复建款。
10. 一份附件可被本批子单合法读取，其他客户/无权限用户不可读取；直接子单编辑与作废不能破坏批次总额。
11. 1,000 含费金额与 30 手续费：方舟占 1,000，小满传 970；后续余额不因镜像净额少扣 30。
12. 已安排出库后减订单行低于占用、替换 SKU、切换订单类型均拒绝；已收款后减总额低于登记额同样拒绝。
13. 原库存/生产单、旧回款、打印和手机扫码验货回归；跨北京时间零点日期一致；批次部分成功的汇总显示真实状态。

## 8. 实施顺序与当前限制

1. 先核验小满分批出库契约：同订单多单、行标识、自定义单号及长度、外部查重标识、库存不足响应、删除/完成状态和镜像身份映射。验证失败时保留本地设计，不伪造远端支持。外部直接操作与方舟无法共享数据库锁，推送前必须重核远端余量；确认小满自身超量约束，无法保证时显示待人工核验，不能声称本地锁解决了外部竞争。
2. 完成数据迁移、数量账本和汇总回款事务，先用隔离数据做金额/数量/幂等测试；编号长度校验须覆盖发票号后缀增长，不静默截断。
3. 接预售首款、自动出库各入口排除、分批出库执行和多订单回款页面；复用现有设计系统及上传组件。
4. 联调镜像去重、部分同步成功、未知结果核对、打印验货、附件权限和旧单据回归；同步 API/数据库/模块说明。

设计建议：首次同步需正数预收款，附件格式沿用现有图片能力；不新增按收款比例限制发货的规则。以上未改变用户已经确认的同客户、同币种及含手续费金额口径。
