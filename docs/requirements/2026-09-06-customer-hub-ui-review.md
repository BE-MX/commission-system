# 客户经营 UI 检查与修复

范围：今日工作台、客户档案、获客任务、背调中心、客户机会，以及其配置、结果、待办、证据、开发资格和公海规则界面。本轮只改前端呈现，不改 API、权限、业务状态或数据。

## 发现与处理

| Before | After | Why |
|---|---|---|
| 获客页装饰背景向上溢出 24px，覆盖顶部按钮下部 12px | 背景从内容区顶部开始，并隔离页面内部层级 | 顶部配置与创建按钮完整可见 |
| 失败任务的两个操作在约 150px 列内换行；固定列透明 | 操作列最小 224px、单行间距 12px；表头、正文和悬停使用不透明主题背景 | 操作排列稳定，横向滚动不与下层文字重叠 |
| 研究详情按钮的 110px 列宽略小于按钮与内边距 | 最小宽度 128px | 消除按钮旁的裁切省略号 |
| 固定操作列占去手机大半宽度 | 768px 及以下取消固定定位，与表格一起滚动 | 优先看清客户和任务，仍可横向滚到操作列 |
| 工作台标题 22px、正文继承 16px，原生统计按钮字体与其他页面不一致 | 页面标题 17px、正文 14px、表格 13px、章节 15px；使用 Outfit / DM Sans 字体变量 | 遵循 DESIGN.md 的信息层级 |
| 表格链接按钮带圆角阴影，部分查询与刷新按钮缺少图标 | 域内链接按钮无阴影圆角，补充图标及可见键盘焦点，移动按钮最小 44px | 区分行操作与主要操作，改善可访问性 |
| 配置及待办等长表单直接撑高弹窗，保存按钮低于屏幕底部 | 弹窗受视口限高，表单独立滚动，页头与操作区不收缩 | 长表单和大量证据下仍能取消、保存 |
| 研究复核按钮位于正文末尾 | 移至抽屉 footer，保留全部复核可用性判据 | 阅读长研究内容时操作区仍可见 |
| 客户抽屉可能被页面隔离层约束 | 详情抽屉 append-to-body，样式使用专属类 | 遮罩和抽屉覆盖应用导航，嵌套待办弹窗层级正确 |
| 长客户名、资格队列表格和结果表格呈现不一致 | 列表长名称省略并保留原文提示，详情允许换行；表格使用 table-card 容器 | 长内容不会挤出操作，表格边界保持一致 |

共享样式位于 `frontend/src/views/customer_hub/customerHub.css`，全部选择器限制在客户经营页面或其弹窗/抽屉专属类内。没有修改 App.vue、GlassButton 或其他业务模块的全局样式。

## 浏览器验收

使用真实 Vue 页面连接本地合成 API 数据，覆盖长英文客户名、失败获客任务、长配置、待办后续跟进字段和多条证据；不使用生产数据。这里验证的是 UI 呈现和交互可达性，不代表真实后端持久化联调。

| 场景 | 实测结果 |
|---|---|
| 1280×720 获客顶部按钮 | 按钮底部 y=161；装饰背景顶部 y=173，无交叠 |
| 1280×720 获客双操作 | 两按钮同为 y=380.5–401.5，x=1033–1120 / 1132–1219；固定列背景 rgb(255,255,255) |
| 1280×720 长配置 | 修复前 footer y=837–905，超出视口；修复后 y=612–680 |
| 1280×720 机会证据表单 | 内容滚动高度 1714px，正文可见高度约 512px；footer 保持 y=612–680 |
| 1280×720 研究 / 资格 / 公海规则 | footer 均在 y=654–720；客户档案抽屉从 y=0 开始且在页面隔离层外 |
| 390×844 手机工作台 / 客户档案 | 页面宽度 390px；客户抽屉正文 scrollWidth=clientWidth=385px，长标题换行 |
| 390×844 配置 / 待办 / 机会弹窗 | footer y=744–816，弹窗左右均在视口内，正文无横向溢出 |
| 390×844 公海规则 / 资格审核 | 公海 footer y=720–844，三个按钮自动分两行；资格 footer y=774–844 |
| 768×600 短屏平板机会表单 | footer y=500–572，正文 scrollWidth=clientWidth=583px |

浏览器临时视口已恢复。独立审查发现的抽屉层级问题已修复，最后增量复核无阻断项；修改的 Vue 模板编译无错误。
