# 工厂到货 P2 接口核验

## 已证实的接口契约

- 采购入库使用 `POST /v1/invoices/purchaseInbound/push`。OpenAPI 将 `serial_id` 描述为采购入库列表返回的编号，本轮关联试单已确认新建时可保留自定义编号。[小满 OpenAPI](https://open.xiaoman.cn/api-3484333.md)
- 同一个接口支持编辑。请求字段 `inbound_id` 取既有采购入库的 ID，响应和详情使用 `inbound_invoice_id`。请求状态 `1` 表示草稿，`2` 表示完成。本轮已验证草稿按原 ID 转完成及库存增量。[小满 OpenAPI](https://open.xiaoman.cn/api-3484333.md)
- 详情支持按 `serial_id` 或 `inbound_invoice_id` 查询。正式租户对本次预留编号只读查询返回 HTTP 200、业务码 404、无有效单据。空列表仅供人工核查。一次未命中不足以证明先前未知结果的请求永远不会落库。[详情](https://open.xiaoman.cn/api-3484298.md) [列表](https://open.xiaoman.cn/api-3484297.md)
- 小满把 `api-sandbox.xiaoman.cn` 标为正式域名。联调前按实际企业及仓库确认数据影响。文档有删除接口，已完成单据能否删除以及实存、可用数量和成本的恢复效果仍需另行确认。[快速开始](https://open.xiaoman.cn/doc-338269) [删除](https://open.xiaoman.cn/api-3484312.md)

## 防重与回写边界

- 接通发送时须在发送前持久化批次和发送意图。草稿、超时、结果不明、回读不一致都暂停生产单回写。自动补查可以补证据，重发需要满足经实测的条件。
- 回读核对小满内部 ID、编号、状态、仓库、供应商、备注、币种及明细 SKU、数量和单价。完成凭据属于唯一批次。
- 本地候选以同一事务写备货订单增量、明细与订单状态、审计及分配生效。发票对应只记录分配。已验证同一批回写重放只生效一次，以及小满入库内部 ID 不能绑定两批。
- 本地实现了三阶段发送与核对续办，绑定小满租户配置、批次单号、请求内容和远端内部 ID。每阶段领取一次发送权，事务提交后才发 POST。已经确认且从未领取发送权的意图可以继续发送。
- 在单据内点击「核对并续办」可查原采购单和入库单。原单回读一致才进入下一阶段。已经领取发送权但持续查无原单，或完成请求后仍只能看到草稿时，需小满确认原请求的最终处理结果。单次 404、草稿状态和采购待安排数量均不能用于重发。当前入口不允许人工清除发送标记。
- 完成凭据与生产单回写独立提交，回写失败只补本地事务。手工生产单入口保护未回写预占。已确认跨单行按当时的可用余量重算。遗留未回写批次会拦截本地实物范围分配和全量切换。
