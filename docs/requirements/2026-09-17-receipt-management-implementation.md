# 回款管理实现与交付说明

2026-09-17；来源分支 `codex/receipt-management`。用户已授权合并 main 并推送 origin，本轮不部署。设计依据：[功能设计](2026-09-17-receipt-management.md)。

## 已实现的行为

1. 库存单创建、编辑增加回款截图、金额、回款日期、回款方式和备注。草稿允许不完整；同步前后端强制校验截图，先校验再执行库存/小满写操作。图片限定 JPEG、PNG、WebP，单张 10MiB、最多 5 张，服务端解码校验。
2. 新库存单第一次完整同步订单并完成库存收尾后，将回款意图转为 `ready`。后台每 30 秒生成一张方舟回款单；库存收尾失败不会提前生成。历史库存单需要补凭证才能同步，但不会自动补建历史回款。
3. 回款列表位于「订单管理 → 回款单」，支持关键词、来源、同步状态、业务状态和日期筛选。详情显示凭证、原币金额、小满编号、财务状态与操作记录。
4. 手工创建选择已完整同步的小满订单发票，自动带出币种及剩余可登记金额；金额可修改，必须大于零且不超过最新余额。必须填写回款方式、日期及截图。允许多次部分回款。
5. 本地待同步或明确失败的单据可修正、作废；明确失败在原单重试。网络超时、失去租约、成功但缺少回款 ID 均进入「待核对」，禁止盲目重发。管理员可核验并绑定已生成的远端单，或在无匹配候选时确认未创建并重新排队，操作必须填写理由。

## 金额与一致性

- 金额使用 Decimal/NUMERIC(14,2)，以订单原币计算，不做本次回款的跨币种兑换。手续费默认零且不得超过回款金额；金额包含手续费，手续费不重复扣减额度。
- 可登记余额 = 小满订单原币总额 − 已生效小满回款 − 尚未被同一远端 ID 覆盖的方舟有效回款 − 已占用的自动回款意图。远端 ID 去重；待同步、失败和待核对单持续占额度，作废的本地单释放额度。
- 同一远端 ID 的金额不一致、远端订单身份变化，或已知远端 ID 的待核对记录，冻结新增登记，要求先核验。
- 创建使用请求幂等键、内容摘要、订单行锁、余额版本和唯一自动业务键。相同请求返回原单；更换内容复用幂等键会拒绝。后台领取使用执行令牌和租约，发送前再次检查令牌，旧任务不得覆盖新任务结果。
- 远端查询与部分前台修正/核对操作仍可能持有订单锁；不要将其理解为所有网络调用都在锁外。租约保证过期任务不再发送，但不能消除外部服务收到请求后断网的不确定性，因此采用待核对流程。

## 小满接口与启用边界

使用现有 OKKI 客户端读取回款方式、字段配置、订单、完整回款分页及回款详情，并调用回款创建接口。金额与汇率以十进制字符串发送，避免浮点精度损失；汇率沿用现有接口单位。必填自定义字段没有可用值时明确失败，不填造假值。

成功取得回款 ID 后先保存，再读取详情核验订单、日期、金额、币种和财务状态。读回失败保留已接收结果，允许刷新核验，绝不重新创建。已同步与财务生效为两个独立状态；财务状态未知显示未核验。

官方资料出现 `file_list`，但当前没有已验证的附件上传与关联协议，因此本期**仅在方舟保存截图，不向小满传附件**。这不是断言小满不支持附件。真实租户的金额字符串接受方式、自定义必填字段和附件协议尚未联调。

`RECEIPT_SYNC_ENABLED` 默认 `False`：仍生成方舟回款和恢复本地任务，但不发送小满回款。页面显示同步未启用。启用时会处理既有 pending 单，请先核对待发列表。

生产启用前需明确回款创建是否使用当前实现的 `collect_status=0`（未生效）及自动回款默认金额规则。当前按设计采用可编辑金额、新订单默认订单金额，手工默认剩余金额；这些不代表已批准生产财务口径。既有提成回款镜像并非处处明确过滤 `collect_status`，本次未修改提成算法，须在真实租户验证未生效回款对现有统计的影响后启用。

## 双实例凭证存储

办公室与北京后端共享数据库但不共享本地文件。本期提供固定存储入口代理：

| 实例 | 配置 | 行为 |
| --- | --- | --- |
| 办公室凭证主存储 | `RECEIPT_STORAGE_PROXY_URL` 留空 | 在仓库 `backend/data/receipt-proofs` 保存私有文件 |
| 北京后端 | `RECEIPT_STORAGE_PROXY_URL=https://leshine.work` | 仅上传/读取凭证转发到办公室；无本地 fallback |

两端均验证用户权限；转发保留当前用户 Authorization，只允许配置中的 HTTPS origin、固定 API 路径，不跟随重定向，hop 标记阻止循环。读取先检查本地对象范围，再转发。代理实例绑定凭证信任主存储已经校验并提交的共享数据库记录；办公室文件后来丢失会在读取时暴露，不能通过数据库备份恢复图片。

部署时必须同时确认：两实例 JWT 密钥/算法互认；新加坡和北京入口允许 10MiB 加 multipart 开销（建议对应 API 的 `client_max_body_size 12m`）；办公室凭证目录持久保存且纳入备份；北京到办公室入口可达。配置无效或入口失败返回错误，不悄悄改存另一节点。本次未修改生产配置。

## 数据结构与权限

迁移 `156_receipt_management` 父节点为 `155_announcements`，新增 `ark_receipts`、`ark_receipt_intents`、`ark_receipt_attachments`、`ark_receipt_logs`。回款行同时作为持久待发送记录，未另建设计草案中的 tasks 表；操作日志采用 logs 表。迁移可重入并检查已有结构，不导入历史数据，禁止删除账本式 downgrade。

集成最新主线后已串联 `154 → 155 → 156`，Alembic ScriptDirectory 检查唯一 head 为 `156_receipt_management`；未连接或升级生产数据库。

`receipt:read` 查看，`receipt:write` 创建/修改/重试/本地作废，`receipt:admin` 处理未知结果，`receipt:read_all` 扩大数据范围。普通用户沿用订单归属及有效代理授权。首次权限种子给已有 invoice:sync 角色补查看权限；手工写权限单独分配。截图不挂静态目录，不提供公开 URL；只有订单权限的用户只能读库存单自身意图中的凭证，不能读取手工回款截图。
