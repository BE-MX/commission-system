# OKKI 订单截图创建发票

## 目标

在订单发票页上传或粘贴一张 OKKI 销售订单详情截图，识别订单头和产品表格，经过确定性匹配与人工确认后预填本地发票。该入口用于镜像已经存在的 OKKI 订单，不再向 OKKI 推送新订单。

## 示例验收

附件示例应识别并核对：订单名 `凯丽比努尔#260808`、客户 `hair_madebymads`、业务员 Katy、日期 `2026-08-25`、USD 90.14；产品编号 5730 对应唯一产品/SKU，数量 3、单价 30.048，按四位单价计算后行金额四舍五入为 90.14。

## 流程与边界

1. 浏览器接受 PNG/JPG/WebP，支持选图、拖放和剪贴板；后端限制 10MB、4000 万像素，并在送入模型前缩放超大边。
2. AI 只输出严格 JSON 字段，不做数据库 ID 决策。截图内容是不可信数据，图片里的任何命令或提示词都不执行。
3. 服务端按客户名称、当前用户可代办的业务员、产品编号和 Product/Length/Color/Weight、真实 SKU 做匹配；编号与规格冲突时必须阻断。
4. 数量×四位单价、行小计、产品总额、附加费和订单总额逐层对账。非零附加费用因无法从截图安全拆分包装费/运费/手续费而阻断，交由人工处理。
5. 能匹配业务库来源订单时，创建前再次校验客户、日期、USD 总额和业务员绑定；唯一候选的订单名称与 OCR 不一致时显式阻断。非 USD 订单因业务投影只有 `amount_usd`，不自动关联来源订单；暂未同步或不可安全关联时只使用图片指纹防同图重复。
6. 只保存原图 SHA-256，不保存截图或其 base64；AI 运行快照使用 metadata 模式。
7. 同来源订单和同图片指纹均有服务校验与数据库唯一索引。截图来源发票在列表、编辑器和同步 API 三层禁止再次推送 OKKI。
8. `ready=true` 的预览由服务端签发 30 分钟凭证，绑定操作人、来源字段、已确认的产品明细/费用和应付合计；只有专用截图创建端点接受该类发票，防止绕过预览伪造来源或同额替换明细。

## 权限

识别和重新解析均要求 `invoice:write`。客户与产品候选来自只读业务投影；业务员选择严格限制为本人和当前有效代创建授权，不允许通过请求体越权指定。

## 降级与人工确认

模型不可用或输出无效时不创建任何数据。客户、业务员、产品/SKU、金额任一未唯一匹配时返回阻断项；警告不会静默修改成交价。用户只有在预览 `ready=true` 后才能把结果填入发票编辑器，并仍需补充/确认联系人和结算信息后保存；保存时由专用端点校验签名预览凭证。
