# 订单同步后的出库资料同步

入口一：「订单发票」的「保存并同步」或列表「同步」。订单成功推送小满后，同一次操作继续核对关联出库：首推新单由原自动任务生成；缺货任务即时读取目标仓库可用库存并刷新缺货状态，齐货时重新排队，由执行端复查后生成；唯一关联且仍待出库的现有单直接同步发制品、配件及备注。订单成功而出库不能安全更新时，返回独立的出库处理结果，不把订单成功误报为整体失败。

入口二：「出库单打印」列表 → 对应行「同步订单」，保留差异预览与人工确认，供单独补同步和核对使用。两入口共用同一出库同步计划、状态锁、回读验证及打印快照。配件按发票真实产品/SKU 明细同步，包含更换品种、数量和销售单价；同步成功后进入打印及 Word 的配件明细。手动入口的同步源仍是关联方舟发票的最新已推送版本。

## 范围和保护

- 手动入口及产品、数量、价格、备注修改需要 `shipping_inspection:write` 和 `invoice:sync`，并通过出库镜像与发票双重归属核验。订单发票号变化时，若出库内容和备注无需修改，持有 `invoice:sync` 的订单操作者可只更新唯一关联待出库单的 `serial_id`；目标号先查重，编辑使用原 `outbound_invoice_id` 并回读验证。没有出库修改权限且资料也变化时订单仍可成功，出库结果提示由有权限的仓库人员处理。不新增权限码。
- 支持唯一关联一张方舟发票且该订单只有这一张有效出库单的待出库单。多订单、分批出库、关联缺失/重复、未建品合并行、取消/同步中订单仍拒绝覆盖。验货草稿无媒体时自动同步并递增编辑版本；只有价格变化时，即使验货已提交也可自动同步，不改变验货证据。已有照片/视频且产品、规格、数量、配件或单头备注变化时，先持久标记 `recheck_required`，停用打印、上传和提交；出库单页预览差异，仓库明确点击「同步并重验」。已提交验货单必须先撤回。
- 按 `order_record_id` 对应订单明细；修改保留 `outbound_record_id`，新增不传原明细 ID，删除显式传 `remove:1`，同时保留原行数量、销售单价、产品和 SKU 等可写字段（小满在删除前仍校验必填字段）。同步产品/SKU、名称型号单位、数量、销售单价，以及方舟发票的单头 `remark`（空值清空出库备注）。保留成本单价；不改客户、仓库、币种、汇率、处理人和状态，不把运费/收款事实写入出库明细。
- 预览哈希覆盖方舟订单内容、小满订单、小满出库单和验货状态/媒体 ID 基线。提交重新核对，旧预览拒绝执行。发票同步入口在订单推送成功后自动使用该计划；待重验出库不自动覆盖，出库单入口需要 `confirm_recheck=true` 的显式确认。出库尚未生成、已出库、分批、镜像滞后或同步结果不确定时不覆盖，也不补发/退货。

## 持久化与恢复

使用现有 `ark_shipping_operation_events`，scope 为 `outbound-invoice-sync`，request_id 为方舟镜像记录 ID；历史请求保存在 `outbound-sync-history`。无新增表或迁移，不写 `lsordertest`。

发送前分别持久化 `sync_pending`（准备完成）与 `sync_sending`（可能已发送），再持有发票和事件行锁执行唯一一次 POST。5 分钟租约内的恢复只返回处理中，不抢占发送者；未发送的过期准备可安全结束。已发送请求超时或回读不一致进入 `sync_uncertain`，再次点击只回读，不重复 POST。`check_only` 请求即使没有原任务也不会发送。真实不确定结果需在小满核对并修正到本次预期状态，再点击核对；不能删审计记录或清锁后重发。

ACTIVE 状态阻止发票修改/取消、出库删除、验货写入、正式打印和 Word 导出。查询守卫使用 MySQL 当前读；准备过程中原单变化或认证明确拒绝时安全结束，保留此前已验证打印快照。

成功必须回读验证明细集合、原行 ID、产品、数量、价格、资料、目标 `serial_id` 及非目标单头字段。只有已验证结果可作为方舟打印快照，在镜像追上前即时显示新单号、产品、数量及备注；镜像版本超过快照或同版本且内容一致后退出快照。关联验货草稿的出库单号随已验证结果更新。镜像尚未追上时暂缓验货写入，防止照片关联到旧明细 ID。已打印旧纸单需要重打。

验货资料版本与出库修改一起提交：同步成功后递增验货 `edit_version`，旧手机页面必须刷新。事件结果保留旧媒体 ID 和待补验规则，不删原件；产品/规格/数量/配件变更时，镜像明细 ID 与小满明细 ID 不保证相同，因此保守地将本单全部旧媒体标记为旧版本证据，并要求为镜像中每条现存明细补拍照片。仅备注变更时要求新的整单照片；删除明细或备注变化也要求整单照片。旧证据仍可在详情查阅，但不得删除或进入正式验货打印/PDF。补验齐全并重新提交前，出库单和验货单打印均暂停；提交在同一事务清除待补验标记。验货资料尚未被方舟镜像刷新时继续阻止写入。

## 已知协议边界

小满公开接口没有已确认的条件更新/版本锁协议。本功能不传 `status`，在发送前后读取并校验，但数据库行锁只能约束方舟写入，不能与小满网页的同时编辑/确认出库构成远端原子事务。应避免仓库同时操作同一张单；检测到状态或资料变化后进入待核对，不自动宣告成功或补偿覆盖。关联完整性检查沿用实时全量扫描，较早订单可能耗时较长。

## 验证

后端回归在隔离 SQLite 中模拟 OKKI，覆盖增改删、22寸规格更新、数量价格备注、权限与归属、陈旧预览、超时恢复、准备窗口重复点击、打印快照及验货保护。前端 Node 测试覆盖预览/确认、防重复、check-only恢复；本地真实 Vue 页面配隔离模拟 API 验证差异弹窗与成功后列表刷新。不以这些测试声称生产写入验收或 MySQL 双连接并发测试已完成。
