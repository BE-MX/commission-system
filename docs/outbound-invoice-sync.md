# 出库单手动同步订单资料

入口：「出库单打印」列表 → 对应行「同步订单」。先展示发制品及配件新增、修改、删除及备注差异，再确认同步。配件按发票真实产品/SKU 明细同步，包含更换品种、数量和销售单价；同步成功后进入打印及 Word 的配件明细。同步源是关联方舟发票的最新已推送版本；方舟发票未完成小满同步时，先到订单发票完成同步。这里只更新出库资料，不发送订单、不处理回款、补发或退货。

## 范围和保护

- 需要 `shipping_inspection:write` 和 `invoice:sync`，并同时通过出库单与方舟发票的数据范围检查。不新增权限码。
- 支持唯一关联一张方舟发票且该订单只有这一张有效出库单的待出库单。多订单、分批出库、关联缺失/重复、未建品合并行、取消/同步中订单、有验货草稿或已提交验货资料时拒绝覆盖。
- 按 `order_record_id` 对应订单明细；修改保留 `outbound_record_id`，新增不传原明细 ID，删除显式传 `remove:1`，同时保留原行数量、销售单价、产品和 SKU 等可写字段（小满在删除前仍校验必填字段）。同步产品/SKU、名称型号单位、数量、销售单价，以及方舟发票的单头 `remark`（空值清空出库备注）。保留成本单价；不改客户、仓库、币种、汇率、处理人和状态，不把运费/收款事实写入出库明细。
- 预览哈希覆盖方舟订单内容、小满订单和小满出库单完整基线。提交重新核对，旧预览拒绝执行。原有自动关联同步仍只核对出库；此入口是用户预览并确认的手动动作。

## 持久化与恢复

使用现有 `ark_shipping_operation_events`，scope 为 `outbound-invoice-sync`，request_id 为方舟镜像记录 ID；历史请求保存在 `outbound-sync-history`。无新增表或迁移，不写 `lsordertest`。

发送前分别持久化 `sync_pending`（准备完成）与 `sync_sending`（可能已发送），再持有发票和事件行锁执行唯一一次 POST。5 分钟租约内的恢复只返回处理中，不抢占发送者；未发送的过期准备可安全结束。已发送请求超时或回读不一致进入 `sync_uncertain`，再次点击只回读，不重复 POST。`check_only` 请求即使没有原任务也不会发送。真实不确定结果需在小满核对并修正到本次预期状态，再点击核对；不能删审计记录或清锁后重发。

ACTIVE 状态阻止发票修改/取消、出库删除、验货写入、正式打印和 Word 导出。查询守卫使用 MySQL 当前读；准备过程中原单变化或认证明确拒绝时安全结束，保留此前已验证打印快照。

成功必须回读验证明细集合、原行 ID、产品、数量、价格、资料及非目标单头字段。只有已验证结果可作为方舟打印快照，在镜像追上前即时显示新产品、数量及备注；镜像版本超过快照或同版本且内容一致后退出快照。镜像尚未追上时暂缓验货写入，防止照片关联到旧明细 ID。已打印旧纸单需要重打。

## 已知协议边界

小满公开接口没有已确认的条件更新/版本锁协议。本功能不传 `status`，在发送前后读取并校验，但数据库行锁只能约束方舟写入，不能与小满网页的同时编辑/确认出库构成远端原子事务。应避免仓库同时操作同一张单；检测到状态或资料变化后进入待核对，不自动宣告成功或补偿覆盖。关联完整性检查沿用实时全量扫描，较早订单可能耗时较长。

## 验证

后端回归在隔离 SQLite 中模拟 OKKI，覆盖增改删、22寸规格更新、数量价格备注、权限与归属、陈旧预览、超时恢复、准备窗口重复点击、打印快照及验货保护。前端 Node 测试覆盖预览/确认、防重复、check-only恢复；本地真实 Vue 页面配隔离模拟 API 验证差异弹窗与成功后列表刷新。不以这些测试声称生产写入验收或 MySQL 双连接并发测试已完成。
