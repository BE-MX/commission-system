# 客户经营（Customer Hub）功能使用说明书

> 适用版本：以 `main` 分支当前代码为准（2026-09 基线）。
> 涉及代码：后端 `backend/app/customer/`（API 前缀 `/api/customer-hub`）、前端 `frontend/src/views/customer_hub/`。

## 1. 模块概览

「客户经营」是围绕统一客户域（Ark Customer Domain）的经营工作台，覆盖 **获客 → 背调 → 资格审核 → 机会跟进 → 日常经营动作** 的完整链路。菜单组位于左侧导航「客户经营」分组，包含 5 个页面：

| 菜单 | 路由 | 主要权限 | 说明 |
|---|---|---|---|
| 客户档案 | `/customer-hub/customers` | `customer:read` | 统一客户主档（只读视图 + 详情抽屉） |
| 获客任务 | `/customer-hub/acquisition` | `sales_automation:read` | 创建 AI 获客搜索任务、查看结果、公海水位 |
| 背调中心 | `/customer-hub/research` | `sales_automation:read` | 背调任务列表、公海批次、结果人工复核 |
| 客户机会 | `/customer-hub/opportunities` | `customer_opportunity:read` | 机会列表与状态推进 |
| 经营雷达 | `/customer-hub/radar` | `customer_radar:read` | 系统建议的每日经营动作 |

整体业务流（自动与人工结合）：

```
配置获客模型 → 创建获客任务 → AI Agent 执行搜索 → 候选客户入档/去重
      → 高分候选自动创建背调任务 → Agent 执行背调 → 人工复核结果
      → （或公海批次定时生成背调任务）→ 资格审核通过 → 自动创建「开发客户」机会
      → 销售跟进机会、推进状态 → 经营雷达按机会生成每日建议动作
```

## 2. 客户档案

**用途**：查看全公司统一客户主档（`ark_customer_accounts`），以及每个客户的画像、联系人、往来时间线、证据与治理信息。

### 2.1 你能看到哪些客户

页面顶部显示「可见客户」总数，可见范围由权限决定：

- `customer:read_all`（或 super_admin）：可见全部活跃客户。
- 普通 `customer:read`：自己为主负责人/协作人的客户 + 公海客户（无主负责人的客户）；若有 `customer:admin` 且绑定 okki 部门，另可见同部门同事名下客户。
- 无权访问的客户一律返回 404（不泄露客户存在性）。

公海客户详情只显示概要信息（`access_scope="public_pool"`），看不到完整画像。

### 2.2 列表使用

- **搜索**：按客户编号或名称模糊搜索（匹配客户编码、显示名、规范公司名）。
- **分页**：每页 20/50/100 条；列表固定按最近更新倒序，无自定义排序。
- **列表列**：客户（名称+编码）、身份状态、行业、关系阶段、归属（公海/已分配）、完整度、最近更新。
- 加载失败时保留上次成功数据，并提示「数据可能已过期」。

### 2.3 客户详情抽屉

点击列表中的客户名打开，共 5 个 Tab：

1. **概览**：关系阶段、主要市场/行业、互动健康度、画像总览、当前需求、下一步行动。
2. **身份与联系人**：身份解析结果、联系人、偏好、行为模式。
3. **往来与订单**：沟通记录 + 时间线（首次切到才加载，最多显示最近 50 条，超出会提示「当前展示最近 50 / N 条记录」）+ 商业摘要。
4. **证据与机会**：证据事实、关联机会、动作、风险、近期变更、待确认问题。
5. **治理信息**：人工批注、档案版本号、契约 schema 版本、编译时间、数据截至时间。

### 2.4 关键状态枚举（看懂标签）

- 身份状态 `identity_status`：`provisional`（临时）→ `identified`（已识别）→ `verified`（已核验）；`disputed`（有争议）。
- 关系阶段 `relationship_stage`：`discovered`（发现）→ `qualified`（已审核）→ `developing`（开发中）→ `active_customer`（成交客户）→ `inactive`（静默）。
- 归属：无有效主负责人即显示「公海」；归属来源含 `public_pool_claim`（公海认领）、`admin_assign`（管理员分配）、`import`、`transfer`、`manual`。

### 2.5 使用注意（重要）

- 本页面是**只读的**：没有新建客户、编辑档案、添加联系人的入口。客户档案由获客/背调/画像编译流程自动产生和更新。
- 档案内容不是人工录入的，是系统从「事实层（facts）」按版本编译出来的（抽屉「治理信息」里能看到版本号）。
- 需要修改客户主数据（合并、拆分、分配主负责人、DNC 等）时，走**变更提案（change-proposals）**流程：创建 → 提交 → 审批（四眼原则，审批人不能是提案人）→ 执行。该流程**目前只有后端 API，无前端页面**，仅限 `customer:admin` 使用，由管理员操作。

## 3. 获客任务

**用途**：让 AI Agent 按公司目标画像在公开渠道搜索新客户，候选客户自动入档、去重，高分候选自动转背调。

### 3.1 第一步：配置获客模型（一次性，管理员）

页面上「配置获客模型」按钮（需 `sales_automation:admin`）：

- 填写：公司名称（必填）、公司网站、产品、竞争优势、目标国家、目标行业、目标角色、排除条件、默认触达语言。
- 策略配置：`policy_version`（策略版本号）+ 策略 JSON（`target_profile_policy_v1`，含 thresholds/weights/research_rules/claim_rules；`research_threshold` 为 0–100 的自动背调分数线）。
- 规则：同一 `policy_version` 下修改画像或策略内容会被拒绝（409），**改动必须升版本号**，保证任务可追溯。
- 未配置模型时无法创建获客任务（409「请先完善获客模型」）。

### 3.2 创建获客任务（业务/管理员）

需 `sales_automation:write` 或 `sales_automation:admin`。表单只有三项：

- 任务名称
- 目标数量（1–500，默认 20）
- 目标国家（逗号分隔）

提交后任务冻结当时的画像快照与策略版本（结果可追溯到具体 `policy_version`）。相同材料的重复提交会幂等返回已有任务，不会重复扣量。

### 3.3 任务状态与跟进

- 状态：`pending`（排队）→ `running`（Agent 执行中，租约 15 分钟自动续）→ `completed` / `failed`；另有 `cancelled`。
- 列表可按状态筛选；有进行中任务时页面每 10 秒自动刷新。
- **查看结果**：每行「查看结果」打开结果明细弹窗，显示每个候选的客户、排名、匹配分、结果状态（待跟进/已忽略/审核通过/已驳回）与入档时间。
- **失败重试**：`failed` 任务显示「重新入队」按钮，点击后回到 `pending` 重新排队。失败原因只显示脱敏文案（如服务商不可用、限流、返回格式错误、执行失败）。
- **空结果告警**：任务 `completed` 但候选数为 0 时，反馈列会红色提示「任务完成但未产出候选客户，请检查执行端或调整后重新创建任务」——这通常意味着执行端异常，不要以为搜到了但页面没显示。
- 列表显示：目标数/结果数、归档客户数（新建入档的客户数）、策略版本、反馈信息（含「已去重 N 条」）。

### 3.4 结果去哪了

- 每个候选先做身份解析：新公司 → 新建客户入档；命中已有客户 → 计入去重；身份冲突 → 隔离待人工核验（不进主档）。
- 每个候选有匹配分数；**分数 ≥ 策略中的 `research_threshold` 时，系统自动创建背调任务**（类型 `high_score_candidate`），流转到背调中心。

### 3.5 公海水位

后端提供公海审计（`GET /public-pool/audit`）：活跃客户总数、公海客户数（无归属）、被抑制名单拦截数。刷新（`POST /public-pool/audit/refresh`）需 `sales_automation:admin`。

## 4. 背调中心

**用途**：查看背调任务（由 AI Agent 执行），人工复核背调结果；也是公海批次的创建入口。

### 4.1 背调任务从哪来

页面**不提供手工创建单个任务**的入口，任务来自三处：

1. 获客任务的高分候选（`high_score_candidate`）。
2. 公海批次（`public_pool`，本页可手动创建）。
3. 每日定时公海批次（服务端定时任务，默认策略 `v3`）。

### 4.2 创建公海批次（管理员）

背调中心页「创建公海批次」对话框（需 `sales_automation:admin`）：填策略版本 + 配额 JSON（`quotas_json`，按 T1/T2/T3 档配置数量上限）。执行逻辑：

- 从公海客户（身份为 identified/verified、无主负责人、未命中 DNC）中按目标客户匹配分打分分档：**T1（≥80）、T2（≥60）、T3**；
- 按配额限量选取，为每个入选客户创建带层级的背调任务；
- 同一天同策略同配额重复创建会幂等，不会重复产生任务。

### 4.3 任务列表与详情

- 列表列：客户（有 `customer:read` 可点开客户抽屉）、背调类型、层级（T1/T2/T3）、执行状态、结果复核状态、数据级别。
- 详情抽屉：选择原因、输入快照、研究结果（六段结构：identity / business_quality / product_fit / supplier_status / risk / strategy，均带引用）、研究摘要、证据事实 ID。
- 权限不足或公海范围时内容会**脱敏**（提示「该任务内容已脱敏，不能作为复核依据」）。

执行状态机：`pending → running → completed / failed`，门控不相关时 `skipped`（复核标记 `not_required`）。

### 4.4 人工复核结果（管理员）

任务执行完成且内容未脱敏时，可三选一（需 `sales_automation:admin`）：

- **通过复核**（accepted）：结果生效，客户进入待资格审核队列。
- **要求修订**（revision_requested）：任务可被 Agent 重新领取执行。
- **驳回结果**（rejected）：结果作废。

### 4.5 资格审核（当前仅 API）

背调通过复核后，客户进入「待资格审核」队列（`qualification-queue`）。资格审核决定客户是否可开发：`approved`（必须配理由 `qualified`）/ `rejected` / `deferred`；理由码含 `not_now / poor_fit / wrong_identity / duplicate / do_not_contact / bad_data` 等。

- 审核通过 → 系统自动创建「开发 {客户}」机会（进入客户机会页）并写时间线事件。
- 理由为 `do_not_contact` → 自动写入抑制名单（DNC）。
- **注意：资格审核目前只有后端 API（`POST /qualification-reviews`），前端页面尚无入口。**

## 5. 客户机会

**用途**：集中跟进所有客户机会（阿里询盘、公海开发等），按证据推进状态。

### 5.1 机会从哪来

机会**只能由系统自动创建**，页面无新建入口：

- 阿里询盘同步（`ali_inquiry`，初始无负责人）；
- 公海资格审核通过（`public_pool`，负责人=客户主负责人，优先级/置信度从审核快照带出）。

列表按最近更新倒序，列为：机会标题、客户（可点开抽屉）、状态、优先级（A/B/C/D）、负责人、截止时间、最近更新。

### 5.2 状态推进（核心操作）

点击「更新」（需 `customer_opportunity:write` 或 `customer:admin`），必填：**目标状态 + 更新原因**。

状态机：`pending → contacted → replied → quoted → won / lost / dismissed`；`lost`/`dismissed` 可重开回 `pending`；`won` 为终态。

**证据要求（重要）**：

- 转 `contacted`：必填证据事件 ID（需为已发送消息或有效销售活动记录）。
- 转 `replied`：必填证据事件 ID（需为收到客户消息）。
- 转 `quoted`：机会需已有报价引用 + 已发送消息证据。
- 转 `won`：
  - 理由 `order_confirmed`：必填有效订单 ID（校验该客户名下有效订单）。
  - 理由 `manual_confirmed`：必填人工说明，且需 `customer_opportunity:confirm_without_order` 特殊权限（页面上无此权限时该选项不可见）。
- 关闭态必填原因码：`lost`（无回应/价格/产品不匹配/时机/竞对/预算/风险拒绝/其他）；`dismissed`（重复/不合格/客户错误/无机会/DNC/其他）。

### 5.3 字段说明

机会含：类型、来源、负责人（空=待分配）、预期金额/币种/预计成交日、赢单概率、预测类别（pipeline/best_case/commit/closed）、优先级 A–D、置信分 0–100、紧急度、推荐策略、英文开场白/跟进草稿（**仅供人工确认，系统不自动外发**）、证据事实 ID 等。

## 6. 经营雷达

**用途**：把高优先级信号转成当天可执行的下一步行动（"每日动作清单"），并回收执行反馈。

### 6.1 动作从哪来

动作由规则引擎按机会自动生成（`customer_radar_v1` 策略），每个客户每天最多 1 条，按指纹幂等去重：

| 机会来源 | 动作组 | 含义 |
|---|---|---|
| 阿里询盘待处理 | 新询盘响应（优先） | 尽快回复真实询盘 |
| 公海开发机会 | 公海验证（顺手） | 内部核验 |
| 老客唤醒机会 | 老客唤醒（重点） | 内部复核触达 |

A 级机会的动作优先级=high，其余 normal；建议话术取机会的英文开场白草稿（**不自动外发**）。

> 说明：动作生成由读取「每日焦点」类接口懒触发；本页的「刷新」只重新拉取列表，不触发生成。

### 6.2 列表

列：建议动作（类型）、客户（可点开抽屉）、状态、优先级、建议完成时间、最近更新。仅分页 + 刷新，无筛选器。

### 6.3 处理动作（需 `customer_radar:write` 或 `customer:admin`，且须为动作负责人）

点「处理」打开对话框，按状态可用：

- **完成**：填结果码（已联系/已回复/无回应/已约会议/联系人错误/其他）、渠道（阿里/邮件/WhatsApp/电话/LinkedIn/线下/内部）、发生时间、摘要、下一步，以及建议质量反馈（有用/无用）。
- **延后**：选新的提醒时间（必须晚于当前时间）。
- **忽略**：选原因（用户忽略/重复/不再相关/客户错误/已在他处完成/策略抑制/其他）+ 备注。
- **仅反馈**：对建议本身标记有用/无用 + 备注（不改动状态）。

状态规则：`pending` 状态四种操作全可用；`snoozed/done/dismissed/cancelled` 只能做反馈。

## 7. 权限速查表

| 操作 | 所需权限 |
|---|---|
| 进入客户档案页、看名下/公海客户 | `customer:read` |
| 看全部客户 | `customer:read_all` |
| 客户数据治理提案（合并/分配/DNC 等，仅 API） | `customer:admin`（DNC 类执行需 `customer:manage_dnc`，重大风险确认需 `customer:confirm_material_risk`） |
| 进获客/背调页、看任务 | `sales_automation:read` |
| 创建获客任务、失败重试、资格审核（API） | `sales_automation:write` 或 `sales_automation:admin` |
| 配置获客模型、创建公海批次、背调结果复核 | `sales_automation:admin` |
| 看机会 | `customer_opportunity:read` |
| 推进机会状态 | `customer_opportunity:write` 或 `customer:admin` |
| 无订单人工确认成交 | `customer_opportunity:confirm_without_order` |
| 看经营雷达 | `customer_radar:read` |
| 处理雷达动作 | `customer_radar:write` 或 `customer:admin` |
| 角色模板参考 | 业务员：机会/雷达 read+write；主管：另加 `:manage` |

数据分级（由严到宽）：`restricted_internal > personal_contact > internal_business > public_business`；公海范围内只能看到 `internal_business` 及以下、`all_authorized` 范围的内容，其余自动脱敏。

## 8. 常见问题与已知边界

1. **为什么不能新建/编辑客户档案？**
   客户主档由系统从获客/背调产生的事实自动编译生成，人工修改一律走变更提案流程（`customer:admin`，目前仅 API，四眼审批）。
2. **背调中心怎么手动加任务？**
   单个任务没有手工入口；可通过「创建公海批次」批量产生，或提高获客任务质量让高分候选自动触发。
3. **资格审核在哪里操作？**
   目前仅有后端 API（`POST /api/customer-hub/qualification-reviews`），前端入口尚未上线。
4. **机会/雷达动作能手工新建吗？**
   不能，均由系统事件（询盘同步、资格审核通过）和规则引擎生成；人只负责推进状态与反馈。
5. **英文开场白会自动发给客户吗？**
   不会。机会与雷达动作里的英文草稿仅供人工确认后自行使用。
6. **列表提示「数据可能已过期」？**
   刷新失败时页面保留上次成功数据并给出提示，稍后点「刷新」即可。
