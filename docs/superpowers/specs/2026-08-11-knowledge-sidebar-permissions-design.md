# 企业知识库侧栏与成员权限优化设计

## 目标

把企业知识库工作台的检索、建库、审批、成员授权和树形浏览收敛到左侧栏，让用户不必在页面顶部与知识库列表之间来回寻找操作，同时增加知识库分类、方舟用户名选人、长名称浮层和可折叠侧栏。

本次只优化现有知识库工作台及其必要的数据契约，不改变文档修订、审批快照、发布搜索、删除和 MCP 读取规则。

## 已确认的界面方向

采用“平衡型”左侧栏：

- 展开宽度为约 310px，最顶部放“搜索已发布知识”。
- 搜索框下方的知识库标题栏中，“新建知识库”和“审批队列”并列。
- 每个知识库名称右侧直接显示“成员权限”按钮；只有具备该库管理能力的用户可见。
- 删除知识库仍是次要危险操作，只在悬浮或键盘聚焦时显示，避免与成员权限混淆。
- 目录标题栏提供“新建目录”和“新建文档”两个入口。新建目录使用蓝色实心文件夹加号，新建文档使用金色纸张加号，通过颜色和轮廓双重区分。
- 左侧栏可收缩为约 54px 的图标轨道。折叠态保留展开按钮、搜索、新建知识库、审批队列和知识库分类图标；鼠标悬浮显示入口或知识库全名。
- 折叠状态保存在当前浏览器，下次进入沿用。侧栏列宽直接切换，不添加宽度动画；仅保留短时颜色、透明度和浮层反馈。
- 键盘可聚焦所有按钮，折叠按钮提供准确的 `aria-label` 和 `aria-expanded`。

## 知识库分类

知识库分类固定为三种：

| 分类值 | 显示名 | 图标颜色 | 用途 |
| --- | --- | --- | --- |
| `company` | 公司级 | 金色语义色 | 公司制度、统一标准和跨部门知识 |
| `department` | 部门级 | 蓝色语义色 | 部门流程、岗位方法和团队共享知识 |
| `personal` | 个人级 | 绿色语义色 | 个人经验与个人维护的知识 |

分类是知识库自身属性，不是当前用户在知识库中的成员角色。成员角色仍为 `viewer / editor / reviewer / admin`，继续决定只读、编辑、审核和管理能力。

`ark_knowledge_libraries` 新增非空 `category` 字段，只接受上述三个值。创建知识库时必须选择分类，默认选中公司级以减少操作。现有知识库在结构变更时统一设为 `company`。接口和前端不增加缺失分类的猜测或兼容回退。

## 长名称展示

知识库、目录和文档名称统一使用单行省略。新增一个小型、无业务状态的 `OverflowTooltip` 组件：

- 组件测量文本节点的 `scrollWidth` 与 `clientWidth`。
- 只有实际溢出时启用 Element Plus 浮层；完整显示时不弹出冗余浮层。
- 浮层内容始终使用完整原始名称。
- 知识库切换、树刷新和侧栏展开后重新判断溢出状态。

## 成员权限交互

成员权限弹框标题为 `成员权限 · {知识库名称}`，让用户始终知道当前配置对象。

成员选择不再输入数字用户 ID：

- 弹框加载时展示当前成员的方舟用户名、姓名和知识库角色。
- “添加成员”使用可远程搜索的下拉框，按方舟 `username` 或 `real_name` 搜索启用账号。
- 选项以 `username` 为主文本，以 `real_name` 为辅助信息；保存的数据仍使用稳定的 `user_id`。
- 已在成员列表中的账号不允许重复添加。
- 失效、已删除或不存在的账号不能保存为知识库成员。
- 保存继续整体替换成员列表；非超级管理员不能通过本操作移除自己的知识库管理员角色，沿用现有服务规则。

## 后端契约

### 知识库接口

- `POST /api/knowledge/libraries` 增加必填 `category`。
- `GET /api/knowledge/libraries` 和 `GET /api/knowledge/libraries/{id}` 返回 `category`。
- `GET /api/knowledge/libraries/{id}/members` 返回 `user_id`、`username`、`real_name` 和 `role`。
- `PUT /api/knowledge/libraries/{id}/members` 仍接收 `user_id` 与 `role`，服务层额外校验所有用户存在、未删除且启用。
- 新增 `GET /api/knowledge/libraries/{id}/member-candidates?q=&limit=20`，返回可被加入的启用方舟用户。

成员候选接口使用平台 `knowledge:admin` 权限并校验目标知识库 `admin` 角色，不要求额外拥有 `user:read`，避免知识库管理员必须进入系统用户管理模块。普通成员和无权访问该知识库的用户不能枚举方舟账号。

### 数据访问

成员列表和候选搜索直接查询既有 `ArkUser`。返回字段严格限制为成员配置所需的 ID、用户名和姓名，不返回邮箱、电话、角色或其他账号信息。

分类、成员替换和成员搜索继续位于 `backend/app/knowledge/` 领域边界内；路由只负责参数、权限依赖和统一响应封装。

## 前端组件边界

- `KnowledgeWorkbench.vue`：持有分类建库表单、成员弹框、成员候选搜索和折叠状态；负责调用 API。
- `KnowledgeSidebar.vue`：渲染搜索、知识库操作、分类图标、树和展开/折叠图标轨；只通过 props 与 emits 通信。
- `OverflowTooltip.vue`：统一处理知识库、目录和文档名称的溢出浮层。
- 纯函数配置模块：维护分类显示元数据、成员行校验和侧栏本地存储键，供前端目标测试直接验证。

不引入新的 UI 或动效依赖，继续使用 Vue 3、Element Plus、现有图标和 Design Token。

## 状态与数据流

1. 页面加载知识库列表，取得每个知识库的 `category` 和当前用户成员角色。
2. 侧栏按分类元数据渲染图标，按成员角色决定是否展示成员权限按钮。
3. 点击成员权限时，以被点击的知识库作为目标，不依赖当前选中文档；加载该库成员后打开弹框。
4. 用户搜索方舟账号，候选接口返回有限字段；选择后加入本地成员草稿。
5. 保存前检查空用户、重复用户和无效角色；后端再次做权威校验并整体替换。
6. 保存成功后关闭弹框并刷新知识库列表；失败时保留弹框、成员草稿和目标知识库，便于直接修正或重试。
7. 折叠操作只更新 UI 状态与浏览器本地存储，不触发知识库或文档重新加载。

## 异常处理

- 成员候选搜索失败：保留当前成员列表和已输入关键词，显示可操作的“搜索失败，请重试”，不清空配置。
- 成员加载失败：不打开空白权限弹框，提示重新点击成员权限。
- 保存时用户已停用或删除：后端返回明确校验错误，弹框保持打开并标出需要移除的账号。
- 重复成员：前端阻止添加，后端按 `user_id` 再次拒绝重复输入。
- 分类非法或缺失：后端返回 422；前端建库表单必须选择有效分类。
- 浏览器本地折叠状态损坏：只接受明确布尔值，其他值恢复为展开态。

## 动效与可访问性

- 高频侧栏开合不做列宽动画，避免布局抖动和等待感。
- 按钮仅对颜色、背景、透明度和按压缩放使用 100–160ms 的短反馈。
- 浮层使用 Element Plus 现有进入与退出行为，名称浮层只在文本溢出时启用。
- 悬浮效果放在精细指针媒体查询内；`prefers-reduced-motion` 下取消位移和缩放，只保留颜色与透明度。
- 分类不只依赖颜色：图标浮层和可访问名称同时写明“公司级 / 部门级 / 个人级”。
- 新建目录和新建文档不只依赖颜色：分别使用文件夹与纸张形状。

## 测试与验收

### 后端

- 创建三种分类知识库并在列表、详情中原样返回。
- 缺失或非法分类被拒绝，现有数据结构变更后统一为公司级。
- 知识库管理员可按用户名和姓名搜索启用方舟用户。
- 非管理员不能调用成员候选接口；响应不泄露邮箱、电话等字段。
- 成员列表返回用户名和姓名；失效、不存在和重复用户不能保存。
- 原有成员角色、自管理员保护、审批和发布搜索测试保持通过。

### 前端

- 搜索框位于左侧栏最顶部。
- 审批队列紧邻新建知识库按钮。
- 成员权限按钮位于对应知识库行内，并把被点击的知识库传给弹框。
- 弹框标题含知识库名称，成员选择使用方舟用户名而非数字 ID 输入框。
- 三种分类映射到不同语义颜色和可访问标签。
- 新建目录与新建文档同时具有不同图标形状和不同颜色。
- 知识库、目录和文档只在文本溢出时显示完整名称浮层。
- 侧栏可折叠、可恢复，并保留搜索、新建、审批和知识库入口。
- 折叠态、键盘聚焦和 reduced-motion 行为可用。

### 完成检查

- 先运行新增前后端目标测试并观察预期失败，再写最小实现使其通过。
- 运行知识库相关后端测试、前端知识库测试、`npm run build` 和 `python scripts/check_conventions.py`。
- 启动真实页面验证展开态、折叠态、三个分类、长名称浮层、方舟用户名搜索与权限保存。
- 按动效审查标准检查变更中所有 transition、hover、按压反馈和 reduced-motion。
- 对涉及的数据、权限和前后端契约执行独立对抗性审查。

## 不在本次范围

- 自定义知识库分类、分类管理后台或更多分类层级。
- 调整 viewer、editor、reviewer、admin 的权限含义。
- 改造文档审批状态机、搜索算法、编辑器、附件或 MCP 契约。
- 拖拽调整侧栏宽度、移动端重做或新增第三方组件库。
