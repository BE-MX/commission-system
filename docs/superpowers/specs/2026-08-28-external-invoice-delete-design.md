# CODEX 独立站发票删除与重新同步设计

日期：2026-08-28

## 目标

允许用户在方舟“订单发票”列表删除由 CODEX 独立站通过外部接入 API 创建的发票。删除后，独立站可以使用原 `external_order_id` 重新同步并生成一张新发票。

## 当前问题

外部接入发票目前被后端明确禁止删除，用于保证接入请求的幂等查询结果一直指向已创建发票。若只移除该限制，数据库外键会把接入请求的 `invoice_id` 置空，但其状态仍是 `created`；之后相同订单的重放或结果查询会遇到“已创建记录指向不存在发票”的错误。

## 方案

在现有发票删除事务中处理外部接入记录：

1. 发票来源为 `external_api` 时，按 `invoice_id` 找到对应的 `InvoiceIngestRequest`。
2. 删除该接入记录，再删除发票及其既有级联数据。
3. 由现有删除路由统一提交事务，任一步失败都不提交，避免只删除其中一侧。
4. 不修改前端入口；继续使用列表已有的“删除”按钮和确认交互。

不采用数据库外键级联删除，避免为一个明确的业务动作增加迁移；不新增“已删除”状态，避免引入当前需求不需要的墓碑与恢复分支。

## 保留的安全限制

本次只取消 `external_api` 来源的绝对删除禁令。以下已有规则保持不变：

- 已存在小满/OKKI 订单 ID 的发票不能删除。
- 同步状态为 `synced` 或 `sync_uncertain` 的发票不能删除。
- 存在待处理、已分配或待恢复半成品库存数量的发票不能删除。
- 删除操作仍要求 `invoice:write` 权限，并遵守现有发票可见范围。

## 删除后的接入行为

删除成功后，原 App 与 `external_order_id` 的唯一接入记录不再存在。独立站再次提交同一 `external_order_id` 时：

- 按首次请求处理并返回 HTTP 201。
- 创建新的接入请求 ID、发票 ID 和发票号。
- 新发票继续保持 `source_type=external_api`、`sync_status=not_synced`，且不会自动同步 OKKI。
- 后续相同内容重放仍返回新发票，幂等行为从新记录开始计算。

## 错误处理与一致性

- 未找到关联接入记录时仍允许删除发票。这兼容历史或人工修复过的数据，不额外制造阻塞。
- 如果接入记录或发票删除失败，路由不提交事务，数据库保持原状态。
- 不改变外部创建、查询接口及其响应契约。

## 测试

用回归测试锁定完整行为：

1. 通过外部 API 创建发票，确认一张发票和一条 `created` 接入记录。
2. 调用发票删除业务逻辑并提交，确认发票和接入记录均消失。
3. 使用相同 App、相同 `external_order_id` 和相同内容再次提交，确认返回 HTTP 201。
4. 确认新的请求 ID、发票 ID 与原记录不同，数据库仍只有一张当前发票和一条当前接入记录。
5. 运行现有发票删除、外部接入幂等、OKKI 同步保护和库存保护测试，确认其他来源与安全限制不受影响。

## 非目标

- 不提供外部 API 删除端点。
- 不允许独立站远程删除方舟发票。
- 不改变已同步 OKKI 发票或库存相关发票的删除规则。
- 不保留已删除外部发票的接入审计墓碑。
- 不修改数据库结构。
