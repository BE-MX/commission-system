# PDA 逐件连续扫码报工设计

## 目标

只有“逐件扫描报工”权限的用户，在内贸报工 APP 前台按 PDA 实体扫描键后，系统自动完成单件报工。用户无需点击确认，可在同一个结果弹框中连续扫描下一件，并能清楚看到每次报工结果。

本设计以减少小屏 PDA 上的操作步骤为核心：每件产品只需要一次实体键扫码，不增加屏幕扫描入口，也不改变按数量报工用户的现有确认流程。

## 适用条件

- 后端扫码结果的 `report_mode` 为 `unit` 时，视为用户只有逐件扫描报工权限，启用自动报工。
- `report_mode` 为 `quantity` 时，继续使用现有数量输入和手工确认流程。
- 自动报工不再区分扫码来源。厂家广播和键盘输入得到的逐件二维码都执行相同行为。
- 删除“单件码自动报工”设置项及本地偏好；逐件模式的自动报工是固定业务规则，不让用户重复配置。

## 交互流程

### 首次扫描

1. 用户按 PDA 实体扫描键。
2. APP 查询并校验二维码。
3. 校验成功且 `report_mode=unit` 时，立即显示逐件报工信息弹框，同时自动提交数量 `1` 的报工请求。
4. 请求进行中时，弹框展示当前扫码信息和明确的“正在报工”状态，关闭按钮暂时禁用，避免用户在结果未知时关闭。
5. 报工成功后，弹框顶部立即显示绿色提示块：`✓ 报工成功`。
6. 成功提示块显示 3 秒后直接隐藏，不使用位移、弹跳或延迟进入动画。
7. 弹框保持打开，用户可关闭，也可直接扫描下一件。

### 连续扫描

1. 上一件已得到明确成功或业务失败结果后，APP 立即允许再次接收实体键扫码。
2. 新二维码查询成功后，复用当前弹框并原位刷新全部报工信息，不关闭后重新弹出，避免闪烁和焦点变化。
3. 新一件开始报工时，清除上一件的成功或失败提示；成功后重新显示绿色提示块并重新计时 3 秒。
4. 提交请求尚未完成时不接受下一次扫码，沿用“上一笔处理中”的保护，避免并发报工和重复提交。

## 弹框内容与视觉层级

逐件报工弹框只保留一个“关闭”按钮，不显示数量输入、取消或确认报工按钮。

- 顶部结果区：成功使用绿色背景、白色 `✓` 和“报工成功”文字；可恢复的业务失败使用红色提示并说明可以重新扫码。
- 关键信息区：产品、客户、订单、单件编号、当前工序五行的字段名和值都加大、加粗；值字号约 `18–19sp`，保证小屏 PDA 上清晰可读。
- 其他辅助信息维持次要层级，不与五个关键字段争夺视觉注意力。
- “关闭”按钮位于弹框底部，宽度占满弹框内容区，最小高度 `56dp`，便于戴手套或单手操作。
- 弹框内容较长时允许纵向滚动，关闭按钮保持容易触达。

## 状态与异常处理

- **扫码查询失败**：若逐件弹框已打开，在顶部显示红色错误提示并允许重新扫码；否则在主页面显示错误。
- **明确业务失败**：例如权限、二维码状态或后端校验返回明确失败时，清除待提交记录，弹框显示红色错误提示，恢复扫码能力。
- **网络结果未知**：网络中断、超时或服务端异常可能发生“后端已成功但客户端未收到结果”。此时保留现有幂等待重试记录并阻止继续扫码，避免同一件重复报工；用户按现有重试流程确认结果后才能继续。
- **关闭弹框**：仅关闭结果展示，不撤销已完成报工；请求进行中时关闭按钮不可用。
- **页面离开**：注销扫描监听并取消 3 秒提示计时，避免 Activity 泄漏或后台接收报工扫码。

## 实现边界

- 复用现有逐件扫码查询、报工提交、待提交幂等和历史刷新逻辑。
- 新增独立的逐件结果弹框组件，避免继续扩大主页面类，并集中管理内容刷新、结果提示和 3 秒计时。
- 数量报工确认弹框保持原样。
- 不修改后端 API、权限模型、二维码格式或厂家广播协议。
- 不增加屏幕扫描按钮，不发送厂家主动出光广播。

## 验收标准

1. 逐件权限用户扫描有效单件码后，不点击屏幕即可完成数量 `1` 的报工。
2. 成功后弹框顶部显示绿色 `✓ 报工成功`，3 秒后隐藏，弹框仍然存在。
3. 弹框打开且上一笔已完成时，按实体键扫描下一件，弹框不重建、不闪烁，五项关键信息刷新为新二维码内容，并再次自动报工。
4. 逐件弹框只有一个全宽大“关闭”按钮；产品、客户、订单、单件编号、当前工序字体明显加大加粗。
5. 数量报工用户仍需输入数量并点击确认，现有行为不变。
6. 明确业务失败后可以重新扫描；网络结果未知时仍阻止连续扫码并提供幂等重试。
7. PDA 模块单元测试、Lint 和 Debug APK 构建通过；APK 包名、版本、签名和 SHA-256 可核验。

## 不在范围内

- 批量排队或离线连续报工。
- 自动关闭结果弹框。
- 成功提示的声音、震动或复杂动效。
- 修改内贸报工后端业务规则。
