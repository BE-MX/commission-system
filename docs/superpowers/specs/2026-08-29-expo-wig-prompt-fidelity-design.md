# 展会 AI 试戴发型细化与人脸稳定设计

日期：2026-08-29

## 目标

根据用户测试反馈，完成四类修正：

1. 将每款发型的造型纠偏要求直接写入对应 `ExpoWig.composite_prompt`。
2. 修复医生等场景中人脸失真、年龄漂移和发型纹理生硬的问题。
3. 修复场景合成中头部过大、脖子过短、头肩比例失调的问题。
4. 修复高铁场景同时改变姿态、表情、光线和背景时造成的人脸及发型变形。

本次不改变发型匹配、图片上传、模型供应商或生成参数，只调整合成提示词及现有发型业务数据。

## 根因

当前问题来自两层约束叠加，而不是单一发型描述不准确：

- 发型层：多数 `composite_prompt` 为空；部分通用 `wig_description` 与实物细节或测试反馈冲突，例如 `6010-B` 的通用描述含“齐碎刘海”，反馈要求却是垂直感斜刘海、不要碎。
- 场景层：共享场景提示词主动要求模型改变头部朝向、视线和表情，医生与高铁场景又进一步要求特定神态、动作和主光。模型为了同时满足这些要求，只能重画整张脸。
- 光影层：当前提示词要求重新塑造颧骨、眉弓、阴影侧和眼神光。图像模型并非真实摄影补光，而是通过重绘面部实现，容易改变脸型、年龄和皮肤特征。
- 构图层：当前“头部约占画面高度三分之一”与“完整发型必须入框”叠加，蓬松发型会被模型解释为放大头部、压缩脖子和肩部。
- 高铁场景：坐姿、电脑、视线、表情、强窗光、疾驰窗景和精确假发同时竞争注意力，是当前约束最密集的场景。

## 方案选择

采用“发型补充提示词 + 全局合成规则”双层修复。

- 仅修改发型提示词无法修复医生、高铁和人体比例等系统性问题。
- 仅修改全局规则无法修正每款发型的长度、刘海、层次和纹理。
- 不恢复 2026-08-27 后被整体回滚的历史提示词，而是基于本轮反馈重新引入范围更小、可验证的身份保护规则。

## 发型补充提示词

只更新当前启用发型的 `composite_prompt`，不修改 `wig_description`。补充提示词位于最终合成提示词末尾；当它与通用描述冲突时，以补充提示词为准。

| 胎毛波波 | 刘海按四六比例侧分；发量较多的一侧由短到长斜向过渡，不能形成齐刘海；胎毛只保留为贴近发际线的短细绒毛，不能延长成刘海。 |

## 面部有限适配规则

不采用“头部、视线和表情完全锁死”，也不继续当前“主动改变以上三项”的自由适配。采用有限适配：

1. 第一张客户照片是脸型、五官比例、自然不对称、年龄特征和稳定皮肤标记的唯一视觉依据，不注入类别化人脸摘要。
2. 默认沿用原图的头部角度、视线方向和表情类型。
3. 优先调整场景构图去适配人物：将电脑、病历、交谈对象等放在原视线方向附近，而不是强迫人物扭头或改变表情。
4. 场景明显不协调时，允许头部、视线和微表情作为一个整体做最小幅度调整。
5. 禁止从正脸切换为侧脸、从侧脸切换为正脸，禁止明显俯仰或大幅转头。
6. 保持表情类别和张嘴状态：中性仍为中性，闭嘴微笑仍为闭嘴微笑，不能突然露齿、大笑或张嘴说话。
7. 有限适配只能改变神态，不能改变面部几何、年龄、皮肤特征或人物身份。

这套规则的用户影响是：场景仍有自然互动感，但不再通过大幅重画脸来获得“抓拍感”。

## 光影范围

保留场景光影效果，但把不同区域的权限分开：

- 头发、发际线边缘、耳后接触区、脖子、衣服、身体和背景允许完整接受场景光线、高光、阴影和色温。
- 面部允许进行低强度、整体性的曝光和色温融合，使脸与场景不割裂。
- 面部不得新增独立主光、重填阴影侧、重新塑造颧骨或眉弓，也不得凭空新增强眼神光；这些局部指令会触发面部重绘。
- 真实版和柔光版保留原图皮肤纹理与年龄特征；美颜版只允许在原有面部轮廓内处理皮肤纹理，仍不得改变脸型、五官、年龄和表情类别。
- 光影效果主要通过头发高光、轮廓光、衣物明暗、背景方向光和整体调色体现。

## 头部、脖子和身体比例

删除容易诱导大头的“头部约占画面高度三分之一”单一比例锚，改成互相校验的关系约束：

- 保留客户原图的头部尺寸和颈部长度，不因发型蓬松而扩大头骨或面部。
- 腰部以上构图必须包含完整肩宽、上胸和锁骨区域，不能退化为头肩特写。
- 下颌到衣领之间保留自然可见的颈部空间；禁止耸肩、缩颈、用高领或头发遮掉全部脖子。
- 假发的轮廓、长度和蓬松度来自假发参考图，但不能反向改变客户的头骨大小、肩宽或颈部长度。
- 完整发型继续保留在画面内，同时留出舒适头顶空间。

## 医生场景

- 保留医生身份、轻薄夏季白大褂和诊室环境。
- 通过身体姿势、手势、病历或设备表达专业状态，不指定新的面部表情。
- 将病历、设备或交谈对象布置在人物原视线方向附近。
- 诊室冷色日光继续作用于头发、白大褂、身体和背景；面部只做整体色温、曝光融合。

## 高铁场景

- 保留高铁商务出行、座椅、车窗和简洁笔记本电脑等核心识别信息。
- 将电脑和身体朝向布置为兼容人物原有头部角度与视线，不强制低头、转头或生成“自信表情”。
- 简化窗外疾驰景物，只保留柔化的速度感和环境背景，不与脸和假发争夺生成权重。
- 车窗光主要落在头发、肩部、衣服和座椅上；面部只接受整体融合，不重新生成局部明暗结构。
- 继续禁止其他乘客以清晰面孔或手部出现。

## 代码与数据范围

- 修改 `backend/app/expo/ai_pipeline.py` 中合成锚、场景适配、构图、面部光影及医生/高铁场景描述。
- 修改 `backend/tests/test_expo_color_scene.py`，为身份来源、有限适配、光影范围、人体比例、医生和高铁场景增加回归测试。
- 更新数据库 `ark_expo_wigs.composite_prompt` 的15款启用发型记录。
- 不修改数据库结构，不新增 Alembic 迁移，不修改前端。

## 验证

自动化验证：

1. 每种提示词版本及场景路径都包含第一张照片作为面部唯一视觉依据，且不出现类别化人脸摘要。
2. 共享场景提示词不再要求主动改变头部、视线和表情，同时保留有限适配条款。
3. 医生和高铁场景不再指定新的表情或强制视线目标。
4. 场景光影仍明确作用于头发、衣服、身体和背景；面部不再要求新主光、重填光、颧骨/眉弓塑形或强眼神光。
5. 构图规则包含完整肩宽、上胸、锁骨和自然颈部空间，不再包含“头占画面三分之一”。
6. 运行展会合成相关测试、完整后端测试和约定检查。
7. 数据库回读验证15款目标提示词准确写入，魅力卷保持不变。

人工效果验收建议使用同一张客户照片、同一发型和同一模型，与当前线上结果做对照：

- 医生：优先检查脸型、年龄和眼睛是否漂移。
- 高铁：优先检查脸、刘海、发际线、头身比例和脖子长度。
- 短发：检查侧区层次、鬓角、刘海和头顶高度。
- 长发：检查最终长度、底边整齐度和发尾方向。

## 非目标

- 不保证仅凭提示词消除所有随机生成波动。
- 不更换图片生成模型或供应商。
- 不增加人脸类别、年龄段或脸型摘要。
- 不改变用户现有的真实、柔光、美颜版本选择。
- 不把发型纠偏逻辑抽象成新的配置系统。
