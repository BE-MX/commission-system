# 客户预约选择器搜索设计

## 目标

提交设计预约时，业务人员可以通过客户名称或客户联系人名称找到客户。客户 ID 只作为内部提交标识，不出现在搜索提示、候选项或辅助说明中。

## 范围

- 修改现有 `CustomerInfoPicker` 的展示文案与候选标签。
- 扩展现有客户素材客户查询，使关键词匹配客户名称或 `customer_contacts.name`。
- 保留现有客户归属权限过滤、返回结构和预约提交的 `customer_id` 契约。
- 不新增接口、不改数据库、不改变预约提交及素材归档流程。

## 方案

客户查询继续以 `customer_info` 为主表。关键词条件使用客户名称匹配，或通过联系人表的相关子查询判断是否存在名称匹配的联系人。相关子查询不会放大客户行，因此同一客户有多个匹配联系人时仍只返回一个候选项，也不会破坏现有销售人员客户归属过滤。

前端候选项显示 `客户名称 · 国家`；未知国家继续显示“未知国家”。输入框提示和字段说明统一改为“客户名称或联系人名称”，不展示或宣传客户 ID 搜索。选中后仍将字符串形式的 `customer_id` 写入表单，提交接口与后端校验保持不变。

## 数据流

1. 用户输入客户名称或联系人名称。
2. 前端沿用现有防抖调用 `/api/customer-media/customers?search=...`。
3. 后端先应用当前用户的客户范围，再按客户名称或联系人名称过滤。
4. 前端展示去重后的客户候选项，用户选择客户。
5. 表单内部保存客户 ID，后端提交时重新校验客户访问权限并读取规范客户名称。

## 边界与错误处理

- 空关键词仍返回空列表。
- 仅输入客户 ID 不再作为搜索条件。
- 联系人名称命中多个客户时，分别返回对应客户。
- 同一客户有多个同名联系人时，客户只出现一次。
- 现有未绑定 OKKI 账号、客户越权及请求失败处理保持不变。

## 验证

- 后端回归测试覆盖：客户名称命中、联系人名称命中、客户 ID 不命中、权限范围不被联系人搜索绕过、结果不重复。
- 前端契约测试覆盖：候选标签不包含客户 ID，文案只提示客户名称或联系人名称。
- 运行相关后端测试、前端契约测试、前端构建和 `scripts/check_conventions.py`。
