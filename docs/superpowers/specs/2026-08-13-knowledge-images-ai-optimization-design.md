# 企业知识库图片与 AI 优化设计

## 目标

在现有企业知识库不可变修订、发布审批和库级 ACL 基础上增加两组能力：

1. 文档可以通过文件选择、拖放和剪贴板粘贴插入私有图片。
2. 编辑者可以对已保存草稿执行“智能排版”或“知识增强”，在差异预览后将结果应用为新的草稿修订。

图片、AI 来源和优化结果都不得绕开现有知识库 ACL、不可变修订与审批发布流程。

## 图片

- 支持 JPEG、PNG、WebP，默认单图上限 10MiB。
- 客户端先在原光标位置插入临时占位，上传完成后替换成正式 `assetId`；存在上传中或失败占位时禁止保存。
- Tiptap 事实源只保存 `knowledgeImage` 节点的 `assetId`、`alt` 和 `caption`，不保存磁盘路径、公开 URL 或 base64。
- 文件存入 `KNOWLEDGE_STORAGE_ROOT` 私有目录，内容只能通过带登录鉴权的 Blob 接口读取。
- 编辑者可读取库内草稿图片；审核者可读取待审修订图片；普通读者只能读取已发布修订图片。无资源权限统一返回 404。
- 修订保存时冻结图片引用。上传后 24 小时仍未被任何修订引用的图片由清理任务删除。
- MCP 不返回图片文件，只把替代文本和说明加入文档纯文本。

## AI 模式

### 智能排版

模型只能调整块类型、标题层级和列表结构，不得修改正文、标题或受保护结构。后端在接受结果前强制比较：

- 全部文本字符流完全一致；
- 代码块、表格、图片和链接签名完全一致；
- 文档标题完全一致。

任一校验不通过，任务失败且结果不可应用。

### 知识增强

- 创建任务时冻结当前草稿修订、配置版本和实际检索到的已发布来源修订。
- 来源范围是“配置允许来源库”与“执行用户实时可读库”的交集。
- 模型必须返回核心观点覆盖矩阵、引用和结构化应用建议；所有核心观点必须标记为已保留。
- 引用只能指向任务冻结的来源修订。配置要求引用时，至少要有一个有效来源引用。
- 后端统一在文末追加“应用建议”，包含可并入知识库、可生成 Skill、可搭建 Agent 和可搭建自动化工作流四部分。
- 原文图片必须保留；AI 结果再次通过受限 Tiptap Schema 和图片 ACL 校验。

## 配置

“企业知识库 → AI 优化配置”由 `knowledge_ai:admin` 控制。每个配置包含：

- 启用的文本 AI Preset；
- 排版提示词和知识增强提示词；
- 来源知识库和适用目标知识库；
- 检索数量、上下文上限、跨库开关、引用要求；
- 单文档长度、单用户并发和每日限额；
- 单调递增的 `config_version`。

管理员自定义提示词只是业务补充。固定安全规则、输出 JSON Schema、权限边界和结果校验由后端控制，不能被配置覆盖。

## 异步任务与并发

1. 前端要求先保存草稿，再创建带幂等键的 AI 任务。
2. 任务入队时记录 `base_revision_id`，Worker 通过租约领取，模型调用期间不持有数据库行锁。
3. 完成后展示基准稿、优化稿、结构变化、核心观点、引用和应用建议。
4. 应用时锁定知识库、文档和任务；若当前草稿已不是 `base_revision_id`，返回 409，绝不覆盖后续编辑。
5. 成功应用会创建新的不可变草稿修订；待审冻结版本不受影响。重复应用返回第一次结果。

## AI 日志安全

知识库正文和来源上下文不得写入通用 `ark_ai_call_logs` 快照。知识优化调用使用 `metadata` 日志策略，只保留消息长度、哈希、模型、Token、耗时和状态。完整结果留在知识库任务表中并继续受知识库 ACL 保护。

## 验收

- 图片选择、拖放、粘贴、失败重试、删除、替代文本提醒和刷新回显可用。
- Viewer、Editor、Reviewer、Admin 对草稿/待审/已发布图片的读取矩阵正确，远程 URL 不会进入事实源。
- 排版模式的原文字符流与受保护结构校验有正反测试。
- 知识增强只读取获准且用户有权访问的已发布修订，引用不能越过冻结来源。
- 创建任务幂等、租约恢复、取消、基准冲突和重复应用均有测试。
- 通用 AI 日志不含知识库正文。
- 新修订仍需提交原审批流程才能发布，MCP 仍只读取已发布内容。
