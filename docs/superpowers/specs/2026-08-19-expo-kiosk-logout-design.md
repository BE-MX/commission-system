# Expo Kiosk 退出登录按钮设计

## 目标

让展会工作人员能从 `/expo/kiosk` 主动退出设备账号，同时避免客户在体验过程中误触导致展位中断。

## 方案选择

1. **首页显示并二次确认（采用）**：仅在 `attract` 首页顶栏显示“退出登录”，点击后确认。入口明确，且不会挤占流程页已很紧张的手机顶栏。
2. **全流程常驻**：任何步骤都能退出，但移动端顶栏会拥挤，客户误触还会中断当前体验。
3. **隐藏员工入口**：最不易误触，但违背“增加一个按钮”的明确可发现性要求。

## 交互与视觉

- 按钮位于首页顶栏右侧，和额度信息处于同一区域。
- 样式复用 kiosk 的深色金边导航按钮语言，但弱于主流程操作。
- 按压仅使用现有 `transform` 反馈，不增加入场动效；按钮是常用工具操作，不需要装饰性动画。
- 点击后显示居中的确认弹层：说明退出后需要重新登录，提供“取消”和“退出登录”。
- 弹层复用现有返回主页确认层的安全区、层级、入场/退场和 reduced-motion 处理。

## 数据流

1. 点击“退出登录”只打开确认层。
2. 点击“取消”关闭确认层并留在 kiosk 首页。
3. 点击“退出登录”调用现有 `authStore.logout()`。
4. 认证 store 尝试通知后端、清除 access token 和用户状态，并跳转 `/login`。

不新增后端接口、权限、状态存储或兼容逻辑。

## 异常处理

现有 `authStore.logout()` 已在后端退出请求失败时继续清除本地登录态，因此网络异常不会阻塞工作人员退出。按钮确认期间不引入额外 loading 状态，避免为一次本地可完成的操作增加复杂度。

## 验证

- 自动测试先验证：按钮只在 `attract` 首页出现、点击后显示确认文案、确认动作复用 `authStore.logout()`。
- 运行新增的 kiosk 前端测试。
- 运行 `npm run build` 与 `python scripts/check_conventions.py`。
- 检查 390px 手机宽度与平板宽度下，顶栏按钮没有遮挡额度或安全区。
- 部署后打开线上 `/expo/kiosk`，确认新资源加载且登录页跳转正常。
