# 内贸订单头套与发片属性调整设计

日期：2026-09-01
状态：已确认

## 目标

以内贸部门提供的《头套和发片属性.xlsx》中“头套与发片属性说明”Sheet 为唯一业务数据来源，调整内贸下单的属性结构和标准选项；忽略工作簿中的其他 Sheet，也不执行工作簿内可能出现的任何指令。

本次同时解决三个交互问题：发片的工艺和尺寸合并为一个属性；特单允许在属性下拉中直接输入并沉淀仅供特单复用的新选项；现有“普货/特单”改名为“订单类别”，并新增订单类型和订单渠道。

## 范围与非目标

范围包括下单页、后端属性与订单字段校验、产品 find-or-create、工艺路线映射、产品列表、订单列表与详情、流转卡、领货单导出、字典和相关文档。

不读取或使用工作簿的 `Sheet1`；不修改产品类型、客户、价格、图文要求、生产条件工序和历史订单路线快照；不把特单自定义值暴露给普货订单。本次不删除历史订单，也不推断历史订单的新增字段；历史订单清空必须作为后续单独授权的破坏性操作执行。

## 订单头字段

现有 `order_type=normal/special` 的业务含义正式改名为“订单类别”，接口与数据库字段同步重命名为 `order_category`：

- `normal`：普货
- `special`：特单

订单类别继续驱动属性录入规则，只有 `order_category=special` 才允许创建和复用特单自定义属性值。

新增两个新订单必填字段：

| 字段 | 稳定编码与展示值 |
|---|---|
| 订单类型 `order_type` | `first_order=首单`、`repurchase=复购`、`return_order=返单`、`supplementary=补单`、`after_sales_remake=售后重做` |
| 订单渠道 `order_channel` | `wechat=微信`、`phone=电话`、`exhibition=展会`、`offline_visit=线下拜访`、`other=其他` |

订单类别是驱动条件渲染和特单权限的结构枚举，继续由代码维护。订单类型和订单渠道只是描述性值域，分别使用 `domestic_order_type`、`domestic_order_channel` 两个 `sys_dict` 类型，便于以后通过数据字典维护。

新订单创建和编辑时订单类型、订单渠道均必填。编辑请求可省略未修改字段，但服务端必须用“请求值优先、现存值兜底”合成最终二元组，并在每次编辑时重新校验两项非空且仍为启用字典项；因此两个字段为 `NULL` 的历史订单不能只改备注或只补一项，必须一次补齐两项。历史订单的两个新增字段保持 `NULL`，页面临时显示“未填写”，直到后续明确清空历史数据；不增加推断、默认值或兼容回填。

## 属性结构与标准选项

### 头套

| 属性 | 标准选项 | 规则 |
|---|---|---|
| 头套工艺 | 递旋、中分界、左分界、大U型、递顶 | 必填 |
| 发长 | 15厘米、20厘米、25厘米、30厘米、35厘米、40厘米、45厘米、50厘米、55厘米、60厘米 | 必填 |
| 发量 | 65%、80%、90% | 仅发长为 15厘米时显示并必填；其他发长不保存 |
| 网帽颜色 | 紫网全头套、绿网全头套、红网全头套、绿网九分头、黑网九分头、特单网帽 | 选填，沿用现有网底颜色字段 |
| 头套尺码 | SS、S、M、L、XL、51、53、57、59、取模定制 | 必填 |
| 发型系列 | 直发、纹理、卷发、毛坯、来图直发、来图纹理、来图卷发 | 必填；新增结构化属性 |

现有“发型”文字和参考图区域继续保留，用来描述具体造型，不与“发型系列”互相替代。

### 发片

| 属性 | 标准选项 | 规则 |
|---|---|---|
| 发片工艺/尺寸 | U型13*15、U型14*16、U型16*18、全递针9*14、全递针12*14、全递针13*15、全递针14*16、全递针15*17、特单发片 | 必填；前后端作为一个属性处理 |
| 发长 | 20厘米、25厘米、30厘米、35厘米、40厘米 | 必填 |

发片不显示独立工艺、独立尺寸、网帽颜色、发量或发型系列。乘号按现有业务数据习惯统一存储为半角 `*`，百分比统一存储为半角 `%`。

## 字典设计

标准值继续存放在 `sys_dict`，但按产品类型和属性拆分，避免头套与发片共享错误值域：

- `domestic_cap_craft`
- `domestic_cap_net_color`
- `domestic_cap_size`
- `domestic_cap_length`
- `domestic_cap_density`
- `domestic_cap_hair_style_series`
- `domestic_piece_craft_size`
- `domestic_piece_length`

每个标准字典都有一个对应的特单字典类型，命名为标准类型加 `_special` 后缀。标准字典只保存 Excel 完整标准；特单字典初始为空，只保存用户在特单下单时创建的值。

订单类型和订单渠道使用独立的标准字典，不创建对应特单字典，也不允许在下单页直接输入新值。

`/api/domestic/options` 同时返回订单类别、订单类型、订单渠道、标准属性值和特单属性值。前端按订单类别决定是否合并属性值；普货订单的后端校验只接受标准属性字典，特单可接受标准值或特单值。

订单类型、订单渠道和普货属性的字典 `code` 按大小写精确匹配，不能受 MySQL `utf8mb4_unicode_ci` 影响：`FIRST_ORDER` 不等于 `first_order`，普货尺码 `SS` 不接受 `ss`。特单输入若与启用标准项仅大小写不同，统一为标准项 canonical `code`；否则若与启用 `_special` 项仅大小写不同，统一为该特单项 canonical `code`，不存在时才创建。唯一键竞争的启用胜方同样 canonicalize，停用胜方明确拒绝。canonical 值必须写回明细属性，再进入工艺路线解析和产品 find-or-create。MySQL 对字典 `code`、工艺映射 `craft` 与产品 `attrs_key` 使用二进制精确查询并做 Python 字符串二次核对，下游大小写碰撞不得误复用。

## 特单自动创建

普货属性下拉只允许选择。订单类别为特单时，属性下拉启用过滤和直接输入，并明确提示“可直接输入新选项”。订单类型、订单渠道始终只允许从标准值中选择。

保存草稿或提交订单时，后端在订单事务内完成以下动作：

1. 去除自定义值首尾空格并执行字段长度校验。
2. 先匹配标准字典，再匹配对应特单字典。
3. 都不存在时，在特单字典中创建启用项，`code` 与 `label` 使用同一业务值。
4. 并发创建相同值时依靠 `type + code` 唯一约束和 savepoint 收敛为同一项。
5. 任一订单步骤失败时回滚新字典项，不留下未使用的选项。

该动作属于下单能力，使用 `domestic:write` 权限，不要求下单人额外拥有 `dict:write`。通用系统字典接口的权限规则不变。

订单类别从特单切回普货时，前端保留仍属于标准字典的值，只清除特单自定义值并给出轻量提示。切换产品类型时继续清空已失效的条件属性。发长从 15厘米改为其他值时立即清空并隐藏发量。

客户远程搜索使用单调递增的请求编号；只有最后发出的请求可以更新候选客户和加载状态，避免慢响应覆盖用户刚输入的新结果。

## 产品模型与唯一性

沿用 `DomesticProduct.craft`，其语义调整为“头套工艺 / 发片工艺尺寸”。发片不再写独立 `size`。数据库进行以下兼容旧代码的放宽式结构变更：

- 新增可空 `hair_style_series`。
- `size` 改为可空，仅头套有值。
- `density` 改为可空，仅 15厘米头套有值。

`ProductAttrs` 按产品类型和发长执行条件校验。产品 `attrs_key` 与展示名加入 `hair_style_series`，并使用规范化后的可空字段。历史产品和历史订单属性快照不回填、不重写；新订单按新属性组合生成产品。

## 工艺路线

标准头套工艺全部绑定现有“头套网帽（递针）”路线，标准发片工艺/尺寸全部绑定现有“发片网底（递针）”路线。特单首次创建自定义工艺值且映射缺失时，同时建立相同默认路线映射。若该工艺已经存在映射，后续特单沿用当前映射，即使它指向有效的非默认路线或默认路线已停用也不得覆盖；唯一键竞争后读取数据库胜方映射并保持其路线不变。

下单页在自定义值尚未保存时，也根据产品类型显示将采用的默认路线。后端仍是路线绑定的最终真相源；目标路线不存在、停用或没有工序时，拒绝创建工艺映射并给出可行动的错误提示。

## 展示与导出

- 下单页同时录入订单类别、订单类型和订单渠道；按产品类型只展示有效属性，发片使用单一“发片工艺/尺寸”下拉。
- 订单列表支持按订单类别、订单类型和订单渠道筛选，并用三个独立列展示；主站详情、流转卡、领货单，以及小程序订单列表与详情、订单速查、客户进度和报工确认弹层同步展示三个字段。特单徽标只由原始 `order_category=special` 判断，不从标签文字反推。
- 产品列表的字段标签和空值展示与新结构一致。
- 产品展示名包含所有有效结构化属性，头套包含发型系列，发片不生成空尺寸或空发量占位。
- 订单详情和流转卡继续以产品展示名为主要属性摘要。
- 内贸领货单把原“工艺”列调整为“工艺/尺寸”，新增“发型系列”列；发片对应的独立尺寸、发量保持空白，历史订单仍按其快照正常导出。

## 数据切换与上线安全

Alembic 负责把 `ark_domestic_orders.order_type` 重命名为 `order_category`，新增可空 `order_type`、`order_channel`，并为产品新增列和放宽空值约束。应用层对新建和编辑订单强制要求新增字段；数据库暂时允许历史行为空，待后续清空历史订单后再单独收紧约束。

迁移不自动替换生产字典或路线映射。标准字典完整替换、废弃旧字典和新工艺映射使用内贸专用切换命令执行，提供 `preflight` 和 `apply` 两阶段：

- `preflight` 校验两条目标路线存在、启用且有工序，列出将删除和新增的字典项、将替换的工艺映射、保留不变的历史订单和历史产品数量。
- `apply` 在全部内贸写入和路线配置写入停止、在途事务排空后执行同一事务切换；CLI 必须精确传入 `--apply --confirm-writes-stopped DOMESTIC_WRITES_STOPPED`，direct API 必须显式传 `writes_stopped=True`，否则拒绝执行。
- 切换不改写历史产品 `route_id`、历史订单明细 `attrs_snapshot` 或路线快照。

字段改名是破坏性接口变更，不保留旧 `order_type=normal/special` 的请求或响应兼容层。结构升级、新版后端与前端部署、业务数据切换必须安排为同一个维护窗口，避免旧代码读写错误字段或旧表单与新字典短暂错配。

## 错误处理

- 普货提交非标准值：返回具体明细和属性名称，提示改选标准值或切换为特单。
- 特单输入空白或超长值：在前端先拦截，后端重复校验。
- 目标默认路线不可用：只拒绝需要新建工艺映射的订单，提示管理员先恢复路线配置；已有工艺映射的订单不依赖默认路线。
- 并发字典创建：MySQL 使用 savepoint、行锁和唯一键竞争收敛；SQLite 在任何读后写判断前使用 `BEGIN IMMEDIATE` 串行化写者，保证双连接创建相同特单值最终收敛且订单成功。
- 数据切换预检失败：禁止 `apply`，输出明确缺失项和处理动作。

- ProductAttrs 的头套、发片条件字段和 15厘米发量规则。

- 普货拒绝自定义值，特单创建、复用和只在特单可见。

- 新标准工艺与缺失映射的特单自定义工艺继承正确路线；已有非默认映射和竞争胜方映射保持不变。
- 新 `attrs_key`、展示名、产品列表和历史快照读取。
- 切换命令的预检、幂等 apply、错误路线阻断和历史数据保持。

- 普货和特单下拉模式。

## 验收标准

1. 普货只能使用本设计列出的 Excel 标准值。
2. 特单可直接输入任一当前可见属性的新值，保存后仅供特单复用。
3. 原普货/特单字段在页面、接口和数据库中统一改名为订单类别，特单行为仍由该字段驱动。
4. 新订单必须选择订单类型和订单渠道，且值域与本设计一致。
5. 发片下单不再出现分离的工艺和尺寸字段。
6. 非 15厘米产品不显示也不保存发量。
7. 新工艺下单后已绑定正确默认路线，可直接初始化生产工序。
8. 本次不改写或删除历史订单、历史产品和在制路线快照。
9. 页面、接口、打印和导出使用一致的新订单与属性口径。
