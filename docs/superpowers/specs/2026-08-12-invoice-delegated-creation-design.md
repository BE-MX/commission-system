# 订单发票代创建功能设计

## 目标

允许用户 B 受控地替业务员 A/C/D 创建订单。B 只承担录入动作；客户私海、订单业务归属、业务员资料和 OKKI 业绩归属始终属于被选择的 A/C/D。

## 身份语义

- `sales_user_id`：订单归属业务员。它是客户私海、订单业务可见性、业务员资料和 OKKI 创建人/处理人/业绩/部门的唯一依据。
- `created_by`：实际创建人。它只用于审计，同时允许代办人在授权有效期间继续完成自己创建订单的编辑、校验和推送。
- `updated_by`：最后操作人，只用于审计。

禁止再通过可编辑的 `sales_user_name` 文本推断业务归属。业务员姓名、电话、邮箱必须由后端根据 `sales_user_id` 生成快照。

## 授权模型

新增 `ark_invoice_delegate_grants`：

- `delegate_user_id`：代办人，例如 B。
- `sales_user_id`：被代办业务员，例如 A/C/D。
- `created_by`、`created_at`：授权审计。
- `(delegate_user_id, sales_user_id)` 唯一；删除授权直接删除关系，不保留兼容层或软删除状态。

管理员在“系统管理 → 用户管理 → 编辑用户”中维护“可代创建订单的业务员”。每个有效用户天然可以为自己创建订单，不需要写一条自授权记录。禁止自授权、重复授权、授权给已禁用或已删除用户。

## 后端契约

### 授权管理

- `GET /api/invoice/delegations/users/{delegate_user_id}`：管理员读取某用户的代办范围。
- `PUT /api/invoice/delegations/users/{delegate_user_id}`：管理员整组替换代办范围。
- 两个端点使用 `user:read` / `user:write`，保持与用户管理入口一致。

### 订单录入

- `GET /api/invoice/delegations/assignees`：返回当前用户本人及获授权的有效业务员，包含姓名、用户名、电话、邮箱、OKKI绑定状态和归属部门状态。
- 客户和联系人搜索新增 `sales_user_id`。后端先验证当前用户是否可替该业务员创建，再用该业务员绑定的 OKKI ID 过滤私海。
- `InvoiceCreate` 新增必填 `sales_user_id`。后端验证本人或有效授权，不信任前端。
- 创建时 `created_by=B`、`sales_user_id=A/C/D`，并由后端填充归属业务员资料快照。
- 编辑时不允许修改 `sales_user_id`，避免已选客户、价格和 OKKI 归属被无声切换；需要换归属时删除未推送草稿后重新创建。

### 数据范围

无 `invoice:read_all` 的用户可以访问：

- `sales_user_id == 当前用户`：自己的业务订单，包括他人代建的订单；
- `created_by == 当前用户` 且当前仍获授权替该 `sales_user_id` 代办：自己创建并仍有代办权的订单。

`invoice:read_all` 和 `super_admin` 保持全量可见。详情、编辑、删除、校验、同步、日志和导出统一复用同一个可见性守卫。授权被撤销后，B不能继续访问该归属人的订单；归属人A/C/D不受影响。

### OKKI 推送

沿用现有 `invoice.sales_user_id` 映射：`create_user`、`handler`、`users` 和 `departments` 全部取 A/C/D 的 OKKI绑定与部门。推送操作人 B 只写同步审计日志，不进入业绩归属。

## 前端交互

- 新建订单时先展示“订单归属业务员”下拉框，默认当前用户。
- 选择 A/C/D 后，自动更新业务员姓名、电话、邮箱，并清空已选客户、联系人及依赖客户的价格上下文，随后按所选业务员刷新私海客户。
- “业务员信息”改为只读，避免显示值和真实ID分离。
- 编辑现有订单时归属业务员只读。
- 用户管理编辑框增加多选字段“可代创建订单的业务员”，保存时与用户基本信息一起提交对应授权关系；失败时明确提示哪一步未保存。

## 错误处理

- 未授权的 `sales_user_id`：HTTP 403，“无权替该业务员创建或操作订单”。
- 归属业务员无有效 OKKI 绑定：私海返回空列表并标记 `okki_bound=false`；推送前继续按现有规则阻止。
- 归属业务员已禁用/删除：不出现在候选中，新建请求返回 400。
- 管理员替换授权范围时整次事务提交，任何非法用户使整次请求失败，不产生部分更新。

## 验收测试

1. B仅能选择本人和获授权的A/C/D，伪造其他ID被拒绝。
2. B选择A时只能搜索A的私海客户；选择C/D同步切换。
3. 创建结果为 `created_by=B`、`sales_user_id=A`，业务员快照来自A而非请求文本。
4. A能看到和操作该订单；无关用户看不到。
5. B在授权有效时能完成自己代建订单的编辑/推送，但看不到A的其他订单。
6. 撤销授权后B不能再访问或新建A的订单，A仍可访问。
7. OKKI payload 的人员和部门全部属于A，操作审计属于B。
8. 管理员授权配置前后端可回显、保存，非法/重复范围被后端拒绝。
9. 现有本人建单、私海、read_all、同步和导出行为不回归。
