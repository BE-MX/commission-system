# 客户产品效果图门户设计规格

> 日期：2026-08-07  
> 状态：已完成方案评审，待书面规格确认  
> 范围：客户产品效果图门户 V1  
> 参考产品：Pacdora 的“选产品 -> 进入工作区 -> 上传品牌素材 -> 调整选项 -> 输出效果图”交互路径

## 1. 结论

新增独立的“客户产品效果图”业务领域。客户通过业务员创建的专属邀请链接进入，无需方舟账号；先从业务员勾选的产品中选型，再上传一个当前 LOGO、选择该产品的预设参数、填写可选补充要求并生成效果图。

该门户只复用现有 AI 生图基础能力，包括 `app.ai.service`、Provider/Preset、调用日志、私有图片存储模式和可恢复任务机制；不复用内部 AI 生图工作台的会话权限、页面状态或客户身份模型。

核心原则是：**复用底层能力，隔离客户业务状态。**

## 2. 问题与成功标准

### 2.1 要解决的问题

当前 AI 生图工作台面向内部设计师，包含会话、参考图库、自由提示词和历史版本等专业能力。客户真正需要的不是一个缩小版工作台，而是一条低思考成本路径：

```text
打开专属链接 -> 选择产品 -> 上传 LOGO -> 选择业务参数 -> 生成并下载
```

系统承担提示词拼装、模型参数、任务恢复、额度、权限和文件隔离。客户不接触模型名、Provider、技术参数、内部图库和完整提示词。

### 2.2 V1 成功标准

- 业务员可在 1 分钟内选择客户、产品、有效期和额度并复制邀请链接。
- 客户无需登录；单产品邀请打开后直接进入生成页，多产品邀请进入产品页。
- 客户最多经过“产品、LOGO、参数”三个决策阶段即可首次生成。
- 同一邀请有效期内保留当前 LOGO、历史结果和运行中任务；刷新或重新打开不丢失。
- 客户只可访问邀请绑定的已发布产品、该邀请的素材和结果。
- 并发点击或网络重试只创建一个任务、只扣一次额度。
- 业务员可停用自己创建的邀请；停用或过期后客户接口立即拒绝新访问。
- 桌面与手机均可完成真实生成和下载，不出现双滚动、固定按钮遮挡或文字溢出。

## 3. 已确认的产品决策

| 议题 | 决策 | 用户影响 |
|---|---|---|
| 客户身份 | 专属邀请链接 | 无需创建方舟账号 |
| 入口验证 | 链接即凭证，不再输入验证码 | 打开即用，减少流失 |
| 邀请创建者 | 业务员 | 客户与成本天然归属到业务员 |
| 产品范围 | 业务员为每个邀请勾选产品 | 客户只看到本次推荐产品 |
| 历史记录 | 邀请有效期内保留 | 可关闭页面后继续使用和下载 |
| 产品配置 | 每个产品独立参数与提示词 | 选项符合当前产品，结果更稳定 |
| LOGO 范围 | 每个邀请一个当前 LOGO | 切换产品自动复用，可随时替换 |
| 自由输入 | 预设参数 + 可选补充要求 | 保留必要灵活性但不暴露提示词 |
| 系统边界 | 独立客户域，复用底层生图能力 | 客户体验可独立演进，内部数据不暴露 |

## 4. V1 范围

### 4.1 包含

- 管理员维护产品模板、产品图片、分类、参数、默认值、隐藏提示词和发布状态。
- 业务员选择客户、一个或多个产品、有效期和生成额度，创建、复制和停用邀请。
- 客户产品列表、分类筛选、搜索和产品卡片。
- 单产品邀请自动跳过产品列表。
- 每个邀请保存一个当前 LOGO，允许替换并保留任务级版本快照。
- 产品预设参数：单选卡片、颜色、开关。
- 可选补充要求，限制长度并接受内容安全检查。
- 异步生成、状态恢复、历史结果、查看大图和下载。
- 按邀请、客户、业务员、产品、状态和时间查询使用记录。
- 邀请有效期、额度、停用、幂等和客户素材隔离。

### 4.2 不包含

- 客户方舟账号、邮箱验证码或二次验证码。
- 完全公开的匿名生图入口。
- LOGO 拖拽、缩放、旋转或精确贴图定位。
- 3D 模型、尺寸编辑、材质编辑、刀模或视频。
- 客户查看或编辑完整提示词、模型、质量和 Provider。
- 参数条件脚本、任意动态表单或多层级联配置。
- 客户之间共享项目、协作评论或公开分享链接。
- 永久保留客户 LOGO 与效果图。

## 5. 用户与权限

### 5.1 角色

**管理员**

- 维护和发布产品模板。
- 查看全部邀请、用量和异常任务。
- 停用任意邀请，处理计费不确定任务。

**业务员**

- 从其可访问的客户范围中选择客户。
- 创建邀请、勾选产品、设置有效期和额度。
- 查看和停用自己创建的邀请。
- 查看自己邀请产生的用量和结果缩略图；默认不展开客户原始 LOGO。

**客户访客**

- 以邀请令牌作为唯一身份凭证。
- 访问邀请绑定且当前已发布的产品。
- 管理该邀请的当前 LOGO、提交生成、查看和下载该邀请的历史结果。
- 不能访问内部主站 API、内部生图会话、内部参考图库或其他邀请数据。

### 5.2 内部权限

在现有 RBAC 中新增客户效果图领域权限，动作沿用项目允许词汇：

- `customer_image:read`：查看自己创建的邀请及用量。
- `customer_image:write`：创建和停用自己的邀请。
- `customer_image:admin`：产品模板管理、全部邀请和异常处理。

客户接口不使用方舟 JWT 或上述 RBAC 权限，统一走独立邀请令牌依赖。

## 6. 信息架构与交互

### 6.1 内部管理页

主站新增“客户效果图”，包含三个标签页：

1. **产品模板**：管理员维护产品定义与发布状态。
2. **客户邀请**：业务员创建邀请，查看有效期、额度、已用次数和状态。
3. **使用记录**：查看生成状态、耗时、用量和可行动失败原因。

邀请创建采用单个流程表单：

```text
选择客户 -> 勾选产品 -> 设置有效期和生成次数 -> 创建并复制链接
```

有效期和生成次数必须由业务员显式选择，前端不得用隐式默认值直接提交。有效期必须是未来时间，生成次数必须为正整数。

链接完整明文只在创建成功时返回一次。之后列表只显示末尾识别片段，不提供恢复原令牌；遗失时停用旧邀请并创建新邀请。

### 6.2 客户产品页

URL 形态：

```text
https://leshine.work/create/{token}
```

多产品邀请展示品牌标识、搜索、分类和产品卡片。卡片只显示真实产品图、产品名称和“立即设计”。不显示内部编号、提示词、模型或技术标签。

只有一个可用产品时，系统自动进入生成页。没有可用产品时显示“当前没有可设计的产品，请联系您的业务经理”，不暴露产品停用原因。

### 6.3 客户生成页

桌面采用三栏工作区：

```text
┌──────────────┬──────────────────────────┬──────────────────┐
│ 返回产品      │                          │ 生成设置          │
│ 上传/替换LOGO │      产品或效果预览       │ 产品预设参数      │
│ 当前LOGO      │                          │ 补充要求（可选）   │
│ 历史结果      │      最新结果为主焦点      │ 剩余额度          │
│ 缩略图列表    │                          │ 生成效果图        │
└──────────────┴──────────────────────────┴──────────────────┘
```

手机改为单列任务流：产品信息、LOGO、参数、补充要求、结果。生成按钮固定在安全区上方；结果完成后提示并定位到结果区，但不抢夺输入焦点。

客户操作顺序固定：

1. 上传或确认当前 LOGO。
2. 选择产品预设参数。
3. 可选填写补充要求。
4. 点击“生成效果图”。
5. 中央区域显示真实任务状态，完成后展示结果。
6. 下载、查看大图或调整参数再次生成。

### 6.4 Pacdora 的选择性复用

复用：

- 产品列表的分类、搜索和大图卡片选型逻辑。
- 进入产品后把素材、预览和输出设置集中在一个工作区。
- 主要生成动作始终可见。

不复用：

- 3D 编辑、视角、尺寸、材质和布局工具。
- LOGO 的确定性拖拽贴图交互。
- 大量工具栏与导出格式选择。

原因：本系统是 AI 合成，不是确定性 3D 渲染。提供精确编辑器外观会让客户误以为 LOGO 位置和产品结构可像 3D 工具一样严格控制。

### 6.5 状态反馈

| 状态 | 客户反馈 |
|---|---|
| 缺少 LOGO | 禁用生成按钮，在素材区提示“请先上传品牌 LOGO” |
| queued | “已提交，可以关闭页面，结果会保留在这里” |
| running | “正在生成，通常需要几十秒到数分钟” |
| succeeded | 展示结果和下载操作，额度计数刷新 |
| validation failed | 保留选择，指出需要修改的参数或补充要求 |
| moderation blocked | 引导修改 LOGO 或补充要求，不自动原样重试 |
| provider unavailable | “生图服务暂时不可用，本次设置已保留，请稍后重试” |
| quota exhausted | 历史仍可查看下载，隐藏或禁用新生成动作 |
| invite expired/revoked | “此链接已失效，请联系您的业务经理重新获取” |

### 6.6 动效

动效只服务于状态理解：按钮按压反馈、面板切换、结果淡入和小面积生成骨架。仅动画 `transform` 与 `opacity`，不使用 `transition: all`；支持 `prefers-reduced-motion`。不为列表添加装饰性逐项入场，不伪造模型内部生成阶段。

## 7. 产品模板与提示词

### 7.1 产品模板

每个产品独立维护：

- 展示名称、分类、说明和排序。
- 封面产品图与一到多张生成参考图。
- 参数定义、可选值、默认值和排序。
- 产品固定约束、隐藏提示词模板和输出约束。
- 草稿或已发布状态。

产品图不是普通参考图库资产。现有图库可作为后台选图来源，但产品模板必须持有稳定的资产引用或独立快照，避免图库图片删除后破坏已发布产品。

### 7.2 参数类型

V1 仅支持：

- `single_choice`：单选卡片。
- `color`：颜色色块；可引用现有 Pantone 数据，但保存产品值快照。
- `boolean`：开关。

不支持条件显示、任意 JSON Schema 或管理员脚本。需要完全不同参数组合时创建不同产品模板。

### 7.3 提示词组装

最终提示词只在服务端组装：

```text
[产品固定约束]
[产品参考图用途说明]
[选中参数的提示词片段]
[LOGO 保真与合理应用要求]
[客户补充要求]
[输出构图与质量约束]
```

约束优先级固定：

```text
产品与 LOGO 保真 > 管理员预设参数 > 客户补充要求
```

补充要求是业务输入，不是完整提示词编辑器：去除首尾空白、限制长度、执行内容安全检查，并作为独立段落插入。服务端明确补充要求不能覆盖主体、LOGO 保真和已选参数。客户 API 不返回固定约束、提示词片段或最终提示词快照。

每次任务冻结产品版本、LOGO 版本、参数值、补充要求和最终提示词快照，后续模板修改不改变历史任务。

## 8. 领域架构

新增独立后端领域，命名为 `customer_image`：

```text
backend/app/customer_image/
├── __init__.py
├── models.py
├── schemas.py
├── router.py              # 内部 RBAC API
├── public_router.py       # 邀请令牌 API
├── service.py             # 产品、邀请、额度、生成状态
├── token_service.py       # 令牌签发、哈希与校验
├── prompt_service.py      # 参数校验与提示词组装
└── worker_adapter.py      # 对接共享图片任务执行层
```

前端保持同一 Vite 应用，但客户页面使用顶层全屏公开路由，不进入内部导航框架：

```text
frontend/src/views/customer-image/
├── CustomerImagePortal.vue
├── CustomerProductCatalog.vue
├── CustomerProductEditor.vue
├── components/
└── composables/
```

内部管理页放在同领域目录的 `admin/` 子目录。所有 API 继续注册到 `frontend/src/api/clients.js` 的既有客户端体系；客户客户端不注入方舟 JWT，只向本领域公开 API 发送邀请令牌。

### 8.1 共享执行边界

```text
客户 generation
  -> 冻结产品、LOGO、参数和提示词
  -> 创建共享图片执行任务
  -> worker 从 app.ai.service 调用 gpt-image-2
  -> 结果回写客户 generation 与私有资产
  -> 关联 AiCallLog 做用量和审计
```

优先抽取现有设计工作台任务中真正通用的执行组件，而不是让客户记录伪装成内部 `DesignImageSession`。共享组件只负责任务领取、AI 调用、租约、结果落盘和调用日志；所有权、会话和页面消息仍由各业务域负责。

若现有实现无法小范围抽取，共享层可先接受清晰的执行请求 DTO 与完成回调契约；不得复制 Provider HTTP 客户端或 worker 可靠性逻辑。

## 9. 数据模型

表名前缀统一为 `ark_customer_image_`。最终字段与索引在实施计划中按现有 ORM 和 Alembic 约定细化。

### 9.1 `products`

- 产品展示信息、分类、排序和发布状态。
- 封面资产与产品参考资产关系。
- 固定提示词、输出约束和配置版本。
- 创建人、更新人和时间审计。

### 9.2 `product_options`

- 所属产品、参数 key、显示名称、控件类型、必选、默认值和排序。
- key 在单个产品内唯一。

### 9.3 `product_option_values`

- 所属参数、稳定 value、显示文案、提示词片段、色值或 Pantone 快照、排序和启用状态。

### 9.4 `invites`

- 客户引用与创建业务员。
- 令牌哈希、仅供识别的尾部片段。
- 开始时间、过期时间、额度、已消费次数和停用时间。
- 状态从时间和停用字段派生，不维护第二套可漂移状态真相。

### 9.5 `invite_products`

- 邀请与产品关联。
- 创建邀请时冻结业务员选择范围；产品被停用后对客户即时隐藏。

### 9.6 `invite_assets`

- 所属邀请、资产类型、私有存储路径、文件元数据和创建时间。
- `asset_type` V1 为 `logo` 或 `generated`。
- 邀请保存 `current_logo_asset_id`；历史生成记录另外冻结 `logo_asset_id`。

### 9.7 `generations`

- 所属邀请、产品与业务员/客户审计快照。
- 产品版本、LOGO 资产、参数快照、补充要求和最终提示词快照。
- 任务状态、幂等键、共享调用日志、输出资产、错误、计费确定性和时间字段。
- 幂等唯一约束作用于邀请与客户端请求 ID。

是否单独建立共享执行任务表，取决于实施前对现有 `design_image` worker 的抽取评估；业务真相始终以 `generations` 为客户领域入口，不能让公开 API 直接操作内部工作台任务表。

## 10. 邀请令牌与安全

### 10.1 令牌

- 使用密码学安全随机值，至少 256 bit 熵。
- 数据库只保存 SHA-256 哈希和短尾部识别片段。
- 明文只在创建成功响应中返回一次，不写日志、调用快照或错误信息。
- 每次公开请求都回查邀请是否存在、未停用、在有效期内。
- 使用独立领域密钥或随机令牌模型，不复用 `QR_SIGN_SECRET`、普通短链 code 或方舟 JWT。
- 服务端日志与前端埋点必须脱敏 URL 中的令牌。

### 10.2 公开 API 防护

- 所有读取与写入都从令牌解析邀请，不接受客户端传入 owner/invite ID 作为授权依据。
- 产品查询同时校验邀请绑定和产品已发布。
- 素材与结果查询同时校验资产所属邀请。
- 上传限制 MIME、真实图片格式、大小、像素数和解码资源；标准化后落私有目录。
- 公开写接口按邀请和真实客户端 IP 限速，防止令牌泄露后快速消耗额度。
- 错误响应不区分“不存在、已停用、已过期”的内部细节，统一给客户可行动提示。

### 10.3 额度与幂等

创建生成任务时在同一数据库事务内：

1. 锁定邀请行。
2. 校验有效期、停用状态、产品范围和剩余额度。
3. 按 `(invite_id, request_id)` 查幂等记录。
4. 已存在则返回原任务，不再扣额。
5. 不存在则原子增加已消费次数并创建 generation。

失败额度规则：

- Provider 请求前失败：自动退回额度。
- Provider 明确未计费失败：自动退回额度。
- 已调用且是否计费不确定：不自动退回，标记 `billing_certainty=unknown`，管理员处理。
- 任务成功：额度永久消费。

退款同样需要事务锁和一次性标记，防止重复退回。

## 11. 文件与保留策略

- 客户 LOGO 和结果只存私有目录，不进入公开 `/uploads`。
- 图片端点经邀请令牌鉴权流式返回，不暴露磁盘路径。
- 同一邀请替换 LOGO 只更新“当前 LOGO”指针；历史任务引用的 LOGO 版本继续保留。
- 邀请过期或停用后立即禁止客户访问，但文件进入待清理期，不同步物理删除。
- V1 固定在邀请过期后保留 30 天再清理 LOGO 和效果图；管理员可在清理前续期。该数值不是客户或业务员可配置项，后续若业务合规口径变化，先修改本规格和 Settings 再调整实践。
- 清理任务必须跳过仍被未完成任务引用的资产，并保留非敏感审计与用量记录。

## 12. API 边界

内部 API：

```text
/api/customer-image/products
/api/customer-image/invites
/api/customer-image/generations
```

公开 API：

```text
/api/customer-image/public/context
/api/customer-image/public/products
/api/customer-image/public/logo
/api/customer-image/public/generations
/api/customer-image/public/assets/{asset_id}/content
```

邀请令牌可放在 `Authorization: Invite <token>` 请求头，首个页面 URL 读取后存入当前标签页的 `sessionStorage`，随后使用不含令牌的规范 URL，避免令牌持续出现在浏览器历史、截图和 Referer 中。不得放入长期 `localStorage`。

客户入口需设置严格 `Referrer-Policy: no-referrer`、`Cache-Control: no-store`，并避免加载会接收完整 URL 的第三方统计脚本。Nginx 与应用访问日志必须对 `/create/{token}` 路径做令牌脱敏；仅在前端移除 URL 不足以阻止首个 HTML 请求进入服务器日志。

## 13. 错误处理与恢复

- 公开页面只显示客户可行动文案；完整 Provider 错误留在内部日志。
- 客户刷新后从公开 context 和 generation 列表恢复当前 LOGO、剩余额度、历史结果及运行中任务。
- 运行中任务通过轮询恢复；客户离开页面不取消任务。
- worker 重启后按租约恢复任务，不能将失联任务永久留在 running。
- 产品或参数在客户停留期间被管理员修改时，提交接口以当前发布版本重新校验；失效选项返回“产品设置已更新，请重新选择”。

## 14. 测试与验证

### 14.1 后端

- 邀请令牌只存哈希，明文不进入日志和序列化结果。
- 业务员数据范围、管理员权限和客户归属测试。
- 过期、停用、未绑定产品、未发布产品和跨邀请资产全部拒绝。
- 并发幂等、额度原子扣减和一次性退款测试。
- LOGO 替换后历史 generation 仍引用原版本。
- 模板更新后历史提示词与参数快照不变。
- 客户接口不返回隐藏提示词或内部存储路径。
- worker 租约恢复、成功回写、明确失败和计费不确定失败。

### 14.2 前端

- 单产品自动跳转，多产品搜索与分类。
- 无 LOGO、额度用完、邀请失效和运行中恢复。
- 参数默认值、补充要求限长和重复点击防护。
- 刷新后恢复 LOGO、历史和任务状态。
- 桌面三栏与手机单列的文本溢出、滚动和固定按钮安全区。
- `prefers-reduced-motion` 下取消非必要位移。

### 14.3 真实链路

- 使用真实邀请完成：创建邀请 -> 客户打开 -> 选产品 -> 上传 LOGO -> 生成 -> 下载 -> 再次打开查看历史。
- 在生成中刷新页面和重启应用进程，验证任务最终可恢复。
- 并发提交相同 request ID，核对数据库只有一个 generation、一次额度消费和一次 Provider 请求。
- 停用正在浏览的邀请，下一次 API 请求立即失效。
- 生产部署后在真实桌面和手机视口现场验证，不只依赖组件测试页。

## 15. 实施顺序

遵循最小端到端切片：

1. 产品、邀请、令牌和公开产品读取。
2. 单产品客户页、LOGO 上传和一次真实生成。
3. 历史结果、刷新恢复、额度与停用。
4. 多产品目录、搜索分类和内部邀请管理完善。
5. 使用记录、保留清理和生产验证。

第一条可用链路只需要一种参数控件和一个真实产品模板；确认任务、权限和结果质量后再补齐颜色与开关控件。不得先实现完整表单构建器再验证生图链路。

## 16. 风险与应对

| 风险 | 应对 |
|---|---|
| 邀请链接转发给非目标客户 | 可撤销、有效期、额度、限速；V1 明确认领链接持有人为客户身份 |
| AI 无法精确放置 LOGO | 页面不伪装成确定性编辑器；模板明确 LOGO 保真和合理应用，结果允许重试 |
| 补充要求破坏模板约束 | 服务端分段组装并固定优先级，内容安全检查，冲突以预设为准 |
| 产品模板修改导致历史不可复现 | generation 冻结产品版本、参数和提示词快照 |
| 并发超额或双扣 | 邀请行锁 + 幂等唯一约束 + 同事务扣额 |
| 共享 worker 抽取影响内部工作台 | 先定义执行 DTO 与契约测试，小步抽取，不改内部会话语义 |
| 客户素材长期滞留 | 过期即关闭访问，延迟清理，保留非敏感审计 |
| URL 令牌泄露到日志或第三方 | 首次换入 sessionStorage、规范 URL、no-referrer、日志脱敏、无第三方脚本 |

## 17. 实施前必须核实的代码事实

以下不再做产品选择，但必须在实施计划中通过仓库现状核实具体代码落点：

- 客户选择器复用的具体客户数据源与业务员数据范围查询。
- 共享任务执行组件从 `design_image` worker 抽取的最小边界。
- 现有图库资产如何转为产品模板的稳定快照。
- 迁移 revision 编号；创建前必须检查所有分支迁移历史。
- 独立公开路由使用“莱莎产品效果图”品牌和 `/create/:token` 路径时，与现有 Nginx 静态回退规则的接线位置。

这些细节不得由客户提交，也不得演变为首版的通用配置平台。
