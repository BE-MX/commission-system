# MCP Agent 接入凭证管理界面设计

## 目标

在方舟平台内为具备 `mcp:admin` 权限的管理员提供一个独立、可审计的图形化入口，用于向外部 Agent 发放、查看、轮换和吊销 MCP 个人访问凭证。管理员无需调用接口或接触数据库，同时能够在发放前判断绑定账号是否具备知识库读取条件。

## 范围

本期交付：

- 系统管理菜单中的“Agent 接入凭证”页面。
- 固定展示生产 MCP 地址 `https://leshine.work/mcp/`，支持一键复制。
- 按账号名称或用户名搜索可绑定的在职账号。
- 展示账号的 `knowledge:read` 权限、已加入知识库数量和有效 Token 数量。
- 对不具备知识库读取条件的账号禁止从该界面发放，并引导管理员前往角色权限和知识库成员设置。
- Token 发放、列表、筛选、吊销和原子轮换。
- 明文 Token 仅在发放或轮换成功后展示一次，可复制 Token 或完整 Agent 配置。

本期不做：

- 在数据库保存或再次查看明文 Token。
- 为外部 Agent 新建独立身份体系；Token 继续绑定现有方舟账号并继承其权限。
- 在本页面编辑角色权限或知识库成员关系。
- 自定义 MCP 地址或多环境地址配置。

## 用户流程

### 发放

1. 管理员进入“系统管理 → Agent 接入凭证”。
2. 点击“发放凭证”，搜索并选择账号。
3. 页面展示账号的知识库读取权限、知识库成员数量和有效凭证数量。
4. 若账号缺少 `knowledge:read` 或未加入任何知识库，提交按钮不可用，并显示对应设置入口。
5. 管理员填写可识别的 Agent 用途，提交后只展示一次明文 Token。
6. 管理员复制 Token 或完整连接配置；弹窗关闭时前端立即清空明文。

### 轮换

1. 管理员在有效凭证行选择“重新发放”。
2. 二次确认旧 Token 会立即失效。
3. 后端在同一事务内生成新 Token 并吊销旧 Token。
4. 页面只展示一次新 Token；旧 Token 不再可用。

### 吊销

管理员二次确认后吊销凭证。吊销记录仍保留在列表中，便于追溯，不允许恢复。

## 信息架构与界面

页面沿用方舟系统现有管理页的紧凑布局：

- 顶部接入卡：页面标题、MCP 地址、复制按钮和主要操作“发放凭证”。
- 概览区：有效凭证、已吊销凭证、具备知识库访问条件的账号数量。
- 筛选区：账号或用途关键词、状态筛选。
- 表格区：用途、绑定账号、知识库可用性、状态、最近使用、创建时间和行操作。
- 发放弹窗：账号远程搜索、权限条件摘要、Agent 用途。
- 一次性凭证弹窗：安全警告、只读 Token、复制 Token、复制 Agent 配置。

状态反馈使用 Element Plus 现有消息与确认组件。动效仅用于一次性凭证出现和状态反馈，时长控制在 160–200ms，并遵循 `prefers-reduced-motion`。

## 后端接口

所有接口继续挂载在 `/api/mcp`，并强制要求 `mcp:admin`：

- `GET /token-candidates?q=&limit=`：返回有效账号及知识库可用性摘要。
- `GET /tokens`：返回 Token 列表及绑定账号、知识库可用性摘要，不返回明文。
- `POST /tokens`：为有效账号发放 Token，Agent 用途必填。
- `POST /tokens/{token_id}/rotate`：同一事务内创建新 Token 并吊销旧 Token，只返回一次新明文。
- `DELETE /tokens/{token_id}`：软吊销 Token；重复吊销保持幂等。

候选账号和列表返回字段包括：`user_id`、`username`、`real_name`、`user_is_active`、`has_knowledge_read`、`knowledge_library_count`、`active_token_count`。Token 行另外包含 `id`、`label`、`is_active`、`last_used_at`、`created_at`。

## 权限与安全边界

- 页面路由、菜单和全部后端接口均由 `mcp:admin` 控制；前端隐藏不是安全边界。
- Token 绑定现有方舟账号。外部 Agent 最终能读取哪些知识库，仍由该账号的 `knowledge:read` 平台权限与知识库成员关系共同决定。
- 明文 Token 不写入日志、URL、浏览器存储或页面持久状态；关闭一次性弹窗后清空内存引用。
- 轮换必须是原子操作，避免旧 Token 已失效但新 Token 创建失败。
- 禁用或软删除账号不可新发 Token，已有 Token 的运行时鉴权继续拒绝该账号。

## 失败与空状态

- 无候选账号：提示先创建有效账号并分配权限。
- 账号缺权限：明确区分“缺少知识库读取权限”和“未加入知识库”，并给出设置入口。
- 复制失败：保留明文弹窗并提示手动复制，不自动关闭。
- 发放、轮换或吊销失败：保留当前页面状态，展示后端错误，不进行乐观更新。
- 列表为空：展示首个发放入口，不显示无意义的空表格。

## 验收标准

- 只有具备 `mcp:admin` 的管理员能看到菜单并访问接口。
- 可搜索有效账号并准确看到知识库读取条件。
- 不满足知识库条件的账号无法从页面提交发放。
- 发放、轮换只在响应时返回一次明文，关闭弹窗后前端无明文残留。
- 轮换后旧 Token 立即失效，新 Token 可用于 MCP。
- 吊销后 Token 不能访问 MCP，记录仍可筛选查看。
- 后端定向测试、前端行为测试、前端生产构建、项目约定检查和线上页面验证全部通过。
