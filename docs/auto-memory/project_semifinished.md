# 半成品订单与库存领域记忆

- 半成品唯一业务键是标准化后的 `尺寸 + 半成品色号`，所有库存和订单数量统一为 g，精度三位小数。
- 产品名称解析只提供候选主数据：纯色单组成可自动确认；P 色、TP/T 色、`&` 复合色和结构化字段回退都进入 `needs_review`，人工确认配比前禁止自动下单或扣库。
- P 色拆出的 `#8/#24` 是两个 solid 半成品；TP/T 色拆出的 `#5AT/8A/#5AT/24` 是两个 t 半成品；纯英文颜色作为 named_t 半成品。
- 人工确认后的产品映射标记 `source=manual`，后续 OKKI 产品同步不得覆盖；组成比例合计必须为 1。
- 库存真相由 `ark_semifinished_inventory_ledger` 的幂等流水与 `ark_semifinished_inventory_balances` 快照共同构成。余额更新先锁物料行，任何调整都不能让实存低于占用。
- 半成品订单允许分批入库；相同全局幂等键只回放原结果。生产购物车计划与生产订单、关联半成品订单在一个事务创建，避免只生成一边。
- 发票推 OKKI 采用 saga：先预占并持久化 pending，OKKI 成功后正式出库，明确失败才释放；OKKI 已受理但缺行或本地完成失败时保留 pending，禁止并发编辑，由管理员依据与库存 operation_key 精确匹配的成功同步日志执行恢复，绝不自动误释放。
- 预占提交会短暂释放原发票锁；重新加锁后必须核对当前计划与 pending 目标一致，防止并发编辑导致按旧计划占用、按新计划推单。
