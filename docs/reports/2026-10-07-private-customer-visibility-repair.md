# 业务员私海客户可见性修复

用户授权修复业务员的客户工作台读取权限和私海客户回填；共享客户保留现有主负责，没有主负责的先待核对。代码分支 `codex/customer-private-visibility-repair`。

## 根因与修复

Derek 有正常账号、salesperson 角色及有效 OKKI 绑定，但角色缺少 `customer:read`，前端隐藏客户组合；镜像中的 126 个私海客户也未投影到统一客户域，没有有效归属。原有回填入口是手工脚本，未建立 OKKI 自动同步适配器。

已为 salesperson 角色只增加既有 `customer:read`，原 59 项角色权限保留，当前 60 项，不增加 `customer:read_all`。权限审计 ID 71。已有登录令牌需要刷新或重新登录才能包含新增权限。

回填脚本使用冻结范围，再逐客户检查当前镜像 owner、有效绑定及业务员角色；客户与归属通过现有治理服务写入。存在的主负责人绝不自动转移，多业务员但无主负责时待核对。归属失败整客户回滚；档案与列表投影单独核验，失败回执不能计为完成。只处理客户可见性，不回填订单、创建研究任务或调用 AI，不写业务镜像或执行数据库迁移。

首批档案编译暴露既有边界：MySQL 的 `CAST(task.id AS CHAR)` 继承连接排序规则，与 Run 引用字段不一致；改为查询当前事实相关 Run 与任务、按规范引用字符串精确匹配，保留私海研究候选隔离语义。既有客户行业描述超过列表 VARCHAR(128)；仅列表行业摘要截取 127 字加省略号，完整事实与档案不改。另有超长产品偏好无法表示为标准分类；列表产品标签置空，全文保留在档案，限定产品族活动明确判为不匹配，不编造截断标签。128 字以内的产品标签及市场字段不变。
