## 交付判断

`PRESALE_SETTLEMENT_ENABLED` 默认为 false。打开此开关只允许本地预售登记、报价与分配，不代表小满运费单或出库能力已验证。`settlement_policy.capabilities()` 明确返回两项外发能力 false。预售批次回款同步入口也有独立拦截；不能通过改配置绕过。普通订单批量回款沿用既有回款投递链路。

## 已实现

- 新 `presale` 类型，主单运费为零，初始回款按填入预付款生成。预售不走旧版整单自动出库路径；不允许普通订单与预售互相转换。
- 首款提交后冻结商业合同；分批报价按原行 ID、已出库数量计算剩余量。所有明细参与累计分摊，避免折扣、包装、手续费或分币误差丢失。原订单金额保持不变。
- 预付款仅在最终批次记录抵扣占用，不新增一张相同现金回款；非最终批不能消耗应留给尾批的商品额度。
- 同一订单最多一个活动结算。编号使用主单号加序号，取消后不复用序号。报价摘要、请求幂等键、订单行锁与版本共同保护提交。
- 独立商品/运费应收账本；一笔客户付款可在内部拆分，但共享付款批次和附件。货款、运费不能混计主单剩余可回款额。
- 回款页支持同客户、同币种多订单分配，合计必须相等。整批事务落库，任一订单超额或版本失效全部回滚。金额使用 Decimal/整数分。
- 多订单先按 ID 一次锁定所有主单、禁用该次查询的关系加载，再读取余额，避免 MySQL RR 锁间建立旧快照。凭证也先排序加锁再以当前读核验归属。
- 共用凭证只归属一个付款批次，访问必须具有回款权限且能访问整批订单。禁止从旧单笔入口改单/作废批次子记录；仅管理员可对尚无远端效果的整批录入错误作废，并保留记录与凭证。
- 结算取消、暂停、恢复，历史读取；有新增付款的结算不能任意取消。外部未映射回款、未知出库阻断新的登记/安排。
- 前端失败保留输入和凭证，异步响应防过期覆盖；前端限制数量并在后端重新检查，不信任页面计算结果。

## 尚未完成与解锁条件

1. **运费应收的真实小满承载与分类**：没有可用的隔离租户。官方订单 push 文档允许费用列表、产品列表非必填，但这不证明当前租户允许无商品运费单，也不证明原生报表可将其排除 GMV。不得用生产订单验证。
2. **预售批次资金核验 → 自动出库的执行器**：当前仅有状态与 `ark_shipment_outbounds` 持久结构，没有执行 `ready → outbound_pending → shipped` 的投递/核验闭环。不能把本地登记成功当成真实到账或实际出库。需在第 1 项验证后实现经验证的适配器、发送前逐笔核验、未知结果回查、实际出库回读及后续批次解锁。
3. **小满端原子额度/数量保护与异常恢复**：需验证外部同时操作、超额拒绝、重复编号、丢失响应、稳定行 ID；如果小满不能提供等价保护，需明确操作隔离及复核方案后实现，不能假定幂等。
4. **隔离 MySQL 双连接与迁移实跑**：目前是 SQLite 业务测试和 MySQL 方言离线 DDL 编译，尚未实际验证 MySQL 锁等待/死锁重试与迁移执行。
5. **浏览器端真实联调**：前端单元测试和生产构建已过，尚未进行本地鉴权+接口+图片上传的真实浏览器端到端验证。

继续完成需要一个允许创建/回查订单、回款和出库的隔离小满租户及隔离 MySQL 环境；使用项目配置/密钥渠道提供，不把密钥写入文档。文档名为 sandbox 的小满域名不能作为隔离证据：官方说明它仍指向正式环境。[官方环境说明](https://open.xiaoman.cn/doc-338269)、[订单写入契约](https://open.xiaoman.cn/api-3478252)。

## 实现与 V2 设计的差异

- 用锁定原订单行 + 结算序号唯一约束实现单活动批次；未在原订单新增 active_settlement_id/next_sequence 字段。
- `ReceiptBatch` 在接口上称汇总回款，返回 `items`（实际子回款）与共享 `attachment_ids`。预售含运费时按应收目标生成商品、运费子回款，因此可能不止“每订单一条”；前端仍是一行订单分配。
- 原单自动首款和普通回款继续使用既有 ReceiptIntent/Receipt；新批次只增加关联和 purpose，历史 purpose 迁移为 ordinary，不回填推测预售数据。
- 发货结算创建不立即意味着出库。当前未开放远端链路，状态最多停在 awaiting_payment/awaiting_verification/paused/cancelled，不伪造 ready/shipped。
- P0 未通过之前，本分支不应以功能开关打开作为生产上线方案。
