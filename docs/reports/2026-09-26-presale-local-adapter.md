# 预售分批出库与运费：本地契约模拟

日期：2026-09-26。范围：本地载荷适配与模拟验证；没有连接小满、没有执行 MySQL 迁移或发布。

## 现状与本次改动

- “新建预售单”被 `PRESALE_SETTLEMENT_ENABLED=false` 禁用，后端创建接口也执行相同门禁。这是此前为未完成外部闭环设置的发布保护，不是按钮事件失效。本地 `backend/.env` 没有覆盖该开关。
- 订单发票页隐藏“AI 识别 OKKI 截图”入口；已有截图组件与服务保留，没有从页面打开它的交互。
- `backend/app/invoice/settlement_contract.py` 提供纯函数，用已冻结的结算明细与远端订单快照生成本批出库候选载荷。校验订单、客户、币种、产品行身份、冻结单价、显式传入的已占用数量、仓库与绑定业务员，只包含本批选中的行。fixture 采用[官方订单详情示例](https://open.xiaoman.cn/api-3478251)中的 `users` 和空 `unit` 形状；单位为空时沿用现有出库执行器的 `Piece` 回退。
- 预售结算报价现在提前拒绝没有独立 OKKI 产品/SKU 映射、或多个方舟明细共享一条 OKKI 明细的订单。此类通用产品合并行的本地数量不能安全对应远端单行数量；待隔离联调确认映射规则后再支持，不让它产生无法安全发货的结算。
- 同一模块准备独立运费订单候选：复制主单的客户与归属、将产品行清空，仅保留本批运费费用行；不改预售主单金额。返回值固定 `sendable=false`，未接入任何发送路径。小满是否接受无商品订单、怎样准确归类以及其原生报表口径仍待隔离租户证实。
- 页面禁用提示改为明确的“预售建单暂未开放”。**预售发布开关和外发能力仍关闭**。

## 模拟结果与边界

模拟覆盖两批 4 件、6 件的出库载荷；首款 3000，第一批商品 4000 + 运费 200，末批商品 6000 + 运费 150 - 首款 3000，实际新收分别 4200/3150，总实收 10350。还覆盖错单/错客户、冻结价格变化、累计占用后超量、远端已占数量漏计、共享行和运费无效金额的拒绝。测试均为本地 fixture，不是小满租户返回样本，也不能证明并行超出/超收保护。真实发送前仍须从完整远端出库与本地待处理任务重建占用快照；仅用小满订单详情里的计数字段不构成完整证据。

本地验证：后端预售/出库影响范围回归 120 项通过；前端相关测试 9 项通过，`npm run build` 通过。`python scripts/check_conventions.py` 报 13 项既有 UI 债务；在 main 与本分支分别运行，项目和数量一致，本次未改这些问题。`git diff --check` 通过。独立审查发现的订单详情形状、累计占用、冻结价格、通用合并行和运费错单风险已按上述规则修正并回归。

后续需先取得隔离 OKKI 租户与隔离 MySQL；在该租户验证无商品运费订单及统计分类、同单多批出库与编号、远端资金/数量限制、未知结果回查和读取字段。确认后再实现有持久提交意图、回读核验与恢复路径的发送器，完成迁移实跑和浏览器联调，最后才考虑启用预售建单。具体发布门槛见[开发规格第 10 节](../requirements/2026-09-23-presale-settlement-development.md#10-外部能力门槛及发布顺序)。

官方文档：[正式 API 域名](https://open.xiaoman.cn/)、[订单新建/编辑](https://open.xiaoman.cn/api-3478252)、[销售出库单新建/编辑](https://open.xiaoman.cn/api-3478296)。文档所列 `api-sandbox.xiaoman.cn` 是正式接口地址，不能当作隔离环境。
