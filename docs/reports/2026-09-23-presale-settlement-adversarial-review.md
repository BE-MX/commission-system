# 预售发货结算对抗性审查

日期：2026-09-23。范围：需求、工作区代码契约、开发规格；未连接生产业务库，未创建小满测试订单/回款/出库，未实施业务代码。

## 结论

原 V1 不能直接实施：后续已确认的“运费独立、款到发货、预付款只抵末批、一笔客户合计付款”改变了应收、资金应用和出库生成条件。经业务账务与系统集成两路独立审查，采用 [V2 开发规格](../requirements/2026-09-23-presale-settlement-development.md) 修正。

修订后的本地设计可进入开发；小满运费承载、分类统计、跨系统并发和精确查重能力尚未验证，是集成启用门槛。此结论不等于“小满全链路已验证”或“已可生产发布”。

## 独立审查组织

- 业务账务审查：末批保留、金额守恒、手续费、收款有效性、取消与多单入口。
- 系统契约审查：Receipt 目标、附件、JS/poller 出库身份、整单覆盖入口、小满镜像统计。
- 主代理负责合并修正，并让两路审查回看开发规格；不把代理启动或原设计可行意见当作完成证据。

主要当前代码依据：`backend/app/invoice/models.py`、`service.py`、`outbound_task_service.py`；`backend/app/receipt/{models,balance,fees,remote,sync_service,attachments}.py`；`backend/app/shipping_inspection/{outbound_sync_plan,outbound_sync_service,outbound_queue_service}.py`；`deploy/okki_outbound_creator.mjs`、`okki_outbound_poller.js`；`backend/app/dingtalk/gmv_daily_service.py`、`battle_report/statistics.py`、`festival/service.py`。这些均为工作区读取，不代表线上版本已经一致。

## 必须在实施阶段解决的外部验证

1. 独立运费目标是否可建、可回款、无库存动作，并可从方舟及所需小满原生报表剔除；不假设原生费用单API存在。
2. 自定义业务标识、编号、镜像分类字段是否保留，未知创建结果能否可靠核对。
3. 同订单明细跨多出库的实际接口行为、剩余数量约束及远端执行状态含义。
4. 跨系统同时写入下的余额/数量保护；确认本地锁之外的真正约束。

失败时阻止相关自动集成启用，保留本地开发和隔离测试进度，不写“联调通过”。不通过修改商品主单金额、误用商品SKU或放开余额上限规避这些问题。
