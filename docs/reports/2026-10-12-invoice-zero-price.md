# 订单发票零价明细

2026-10-12，分支 `codex/invoice-zero-price`。本地验证完成，用户已授权合并推送 main；未部署。

## 结论与证据

原 0.01 下限来自方舟：发制品与配件输入框 `min=0.01`，`InvoiceItemPayload.price_per_piece` 要求 `gt=0`，同步前 `validate_invoice` 拒绝 `<=0`；Excel 粘贴和截图提取也要求正价。数据库成交价格列无需迁移。

[OKKI 官方销售订单新建/编辑文档](https://open.xiaoman.cn/api-3478252)将 `unit_price` 定义为必填数字，未声明正价下限；`cost_amount` 由调用者传入，不自动计算。文档没有声明限制不等于真实写入已经验证。

本次仅只读查询现有业务记录：

- `lsordertest.okki_order_items` 中 `unit_price=0 AND quantity>0` 共 401 行、271 张订单，401 行小计均为 0。
- `GET /v1/invoices/order/info?order_id=105839228404511` 实时返回 HTTP 200、业务 code 200。明细 `unique_id=105839228402889` 数量 2、`unique_id=105839228402901` 数量 8，均 `unit_price=0,cost_amount=0`。
- 上述证明当前 OKKI 能保存和返回零价明细；本次没有用生产新建、编辑或出库写入进行试验。

## 行为

- 产品和配件可输入 0，空值仍表示未填、不能同步，负价仍拒绝。数量保持正整数，零价行不可再使用负折扣。
- Excel 粘贴与截图提取接受显式 0；保存、重载、推单载荷保留原价与数量。HTML 与 PDF 导出使用 `None` 判断空值，零价和零小计正常显示。
- OKKI 继续按现有产品/SKU 和行号机制发送真实零价明细。非标产品仍按现有通用产品合并规则推送，不新增供应商兼容模式。
- 配件标准参考价配置仍须正数，本次仅放开每张发票上的成交单价。

## 后续失败处理与边界

现有同步机制足够处理供应商明确拒绝：保留本地单价 0，记录 `sync_failed`、供应商错误和请求审计，停止该次同步。不得自动补成 0.01、丢弃零价行或扣减其他行补平金额，这些动作会改变账务事实。超时或连接中断沿用 `sync_uncertain`，先查原单，避免重复创建。相关拒绝回归验证只发送一次且审计保留零价。

如果将来企业规则开始拒绝零价，先依据具体错误确认是单价规则还是整单金额/审批规则。只有确认存在硬限制且实际需要替代时，另行评估赠品/售后单据或经确认的行费用表达方式，并同时验证订单、出库、回款和金额对账；本次不自动实施未经实证的替代机制。

预售单夹带零价产品且当前商品总额大于 0，不新增限制；全零商品合计批次仍被 `settlement_pricing.quote_current` 拦截，且现有发货结算要求首款资金池。它涉及免费发货的资金机制，不能由放开输入框推导为已支持全零预售发货。
