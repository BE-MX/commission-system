# 导航默认图标及任务按钮动效回归修复

用户反馈导航管理改造后图标统一、任务按钮悬停动效丢失；确认只保存过导航草稿，没有发布。本轮修代码与草稿恢复入口，不读写生产数据，不执行部署。

## 原因与修复

1. 构建阶段分别通过 Vite SSR 加载 navigation.js 和图标包，两份导出的组件对象并非同一引用。引用比较全部不命中，165个节点统一回退为Document。改为优先引用匹配、再用组件稳定name / __name在注册表中匹配；无法识别时阻断构建，不再静默替换。
2. 分类菜单移至递归子组件后，原SidebarNavigation的scoped按钮样式无法作用于子组件。提取navigationQuickTask.css，由两组件分别以scoped src加载，恢复原120ms显隐/轻微位移、焦点环、触屏隐藏与减少动态模式。
3. 浏览器实测还发现hover的transform:none特异性高于旧active缩放，改成匹配菜单上下文的active选择器，按下缩放0.94；减少动态模式下保持无位移。

重新生成的默认目录含40种图标，17个实际文档类入口仍使用Document。默认菜单读新目录后恢复，自定义配置仍优先于默认。

## 已保存草稿

旧草稿里可能已经存入错误的Document。系统无法区分默认错误与管理员主动选择同值Document，因此不直接改写草稿或已发布历史。新增管理员显式操作“恢复默认图标”：说明受影响数量，确认后只修改当前编辑内容中的内置节点图标；名称、分类、角标、顺序、显隐与自建分类图标保留。管理员预览后另行保存/发布。

本轮没有把用户现有草稿保存或发布，也没有为了修图标恢复整个V0版本，避免覆盖其他导航调整。

## 验证

- 新增真实Vite SSR回归，修复前失败（Shop被替换Document），修复后逐节点与源码组件名一致；同时校验提交的catalog逐节点图标一致，不再只测相同对象的假样本。
- 未注册图标明确失败；显式恢复图标保持其他字段及自建图标，不产生保存/发布API调用。
- 本地真实Vue浏览器：User、OfficeBuilding、Document、Van的SVG路径分别与图标包输出逐一匹配；任务按钮hover显示/移出隐藏、Tab聚焦可见、折叠后无任务按钮；实际鼠标按住缩放0.94，减少动态偏好下transform/transition均none。
- 旧草稿恢复实测：取消时图标/已保存状态不变；确认后148个错误图标恢复，首项变Shop、原名称及NEW角标保留，状态为未保存，侧栏仍为线上默认，没有点击保存或发布。
- 按Emil规范自查：高频显隐120ms，轻微按下反馈，无循环动画，减少动态模式停用位移。
- 自动测试/构建结果见交接记录。隔离浏览器fixture在frontend/tests/fixtures/navigation-regression，全部请求由本地adapter处理。截图在本机会话navigation-regression目录，构建日志在任务worktree的tmp/nav-regression。

基于main 082cfe15，不修改主目录既有未提交内容。本次不增加数据库迁移。

最终验证：前端38项、后端41项（隔离SQLite）通过，生产构建35.70s成功，严格增量约定检查通过；保留既有大包提示及第三方JWT弃用警告。该修复沿用本导航功能先前合并推送授权交付，不包含生产发布。
