# WhatsApp 未关联客户列表排除本人及平台通知

## 范围与状态

用户要求 Rina 本人会话和 WhatsApp 平台通知不再进入未关联客户列表，保留消息，5 组号码冲突不动，并将机制适用于所有业务员。本地实现分支 `codex/whatsapp-noncustomer-filter`，基点 `c9d899ca`；2026-11-14 已按用户后续明确授权发布生产，实际版本与验收如下。

## 行为

- 连接器从当前绑定凭据 `me.id/me.lid` 提取精确 PN/LID，生成带 `session_generation` 的 `self_identity`，由现有增量同步保存至账号 raw_payload，不涉及 schema 变更或凭据外传。
- 默认未关联列表在搜索、统计和分页之前排除当前账号本人身份与 PSA `0@c.us` / `0@s.whatsapp.net`。精确规范化仅兼容协议域名和设备后缀，不按姓名、手机尾号、客户 contact_phone 或别名猜测。
- 账号、授权与本人身份代次交叉校验；明确旧代或未知代次会话保持显示。退出需重新扫码时不使用旧身份。重新授权后的 republish 沿既有契约生成当前代次投影，则按当前精确身份判定，不修改原消息。
- 已关联和已忽略视图保留；消息存储、会话 ID、客户关联与5组号码冲突保持原样。其他业务员使用相同规则，无个人 ID 白名单。

## 生命周期保护

独立审查发现清除凭据时身份残留、重绑 configure 与清除凭据之间崩溃会复用旧身份两个问题。现在凭据与本人身份同事务撤回；更换绑定代次或明确 fresh_credentials 的 configure 同事务清除旧凭据和身份，活跃租约阻断换代。写入失败整体回滚。当前已绑定账号正常启动不会清除凭据或重跑联系人补全。

## 发布边界

必须同时更新办公室连接器与提供私海接口的后端；原 `--whatsapp-connector-only` 只允许连接器修复，不能用来发布这次后端规则。当前 main 另含客户回收/统计与迁移263，本次排除不需要这些变更；若单独发布，应基于已上线 `5c6e2704` 组合本次修复，保留 schema262，通过受管部署入口预检。发布前后核对实际版本、消息总量、缺失数与5组冲突指纹；不以生产只读模拟冒充实际发布。
