# 2026-11-02 GMV 手续费口径核查

## 结论与处理范围

绩效看板、临时战报、奖项战报、GMV 日报、订单智能分析和采购节大屏的现有来源契约要求使用不含方舟订单手续费的经营金额；当前推单与本地投影已排费，下游不再重复扣。这不代表所有历史记录都已正确，实际数据差异见下文。不能在小满 `amount_usd` 上再次统一扣除当前方舟 `surcharge_amount`，否则会重复扣费，非 USD 订单还会混用原币和美元。

订单发票页此前直接汇总含费 `total_amount`，本任务已在独立工作区修正为 `total_amount - surcharge_amount`，包括平均订单金额与新增订单金额列；本地验证完成后，亮哥已授权本批提交、合并与推送，未授权部署。此次扩展核查未修改其他区域的计算公式，未改生产数据或发送日报/战报。

代码契约不等于所有历史数据都正确。对 815 张可关联的有手续费 USD 发票进行只读核对，784 张与小满镜像净额一致；其余 31 张逐笔 GET 小满订单详情，发现镜像、商品、运费和历史附加费差异。其中一张存在手续费/运费分类冲突，亮哥已明确确认是运费，应保留：小满来源 GMV 无需扣减，方舟当前分项误分类未在生产更正。未把所有差异都当成手续费，也未把当前镜像当成已验证的全部历史净额。

退货仍由 `backend/app/sales_return/gmv.py` 按独立生效日形成有符号调整；不以本次口径核查删除、重新生成或重复扣减退货事实。已有发送快照保持历史记录，未重发。

## 实际数据证据

- 使用主项目现有配置在进程内连接；未复制 `.env`、输出凭据或持久化令牌。
- MySQL 会话执行 `SET SESSION TRANSACTION READ ONLY` 和 `START TRANSACTION READ ONLY`；查询结束 `ROLLBACK`。远端仅 GET `/v1/invoices/order/info`，使用现有缓存令牌，不推单、不修复镜像、不写回款。
- 比较范围：发票日期 2026-01-01 至 2026-11-02，方舟已同步、未删除/取消中/已取消、USD、手续费大于零、可通过小满订单 ID 精确关联，且小满状态为已结束或已结清。此为金额核对集合，不声称等同各看板完整人员、日期、个人单及货物单过滤后的集合。
- 库存单 781 张，其中 751 张净额一致；生产单 34 张，其中 33 张净额一致。合计 815 张，784 张在 0.01 美元容差内一致，31 张存在差异，没有空金额。此集合不覆盖无法关联的纯小满历史单、非 USD 单或全部历史快照。

例：`翟-261104` 应付 230.00，手续费 10.95，订单净额 219.05，小满 GMV 来源已经是 219.05。`露Sylvia-20261102-1101` 的对应值为 568.55、27.07、541.48、541.48。

### 差异分类

| 类别 | 张数 | 说明 |
|---|---:|---|
| 镜像与小满实时金额不同 | 2 | `田雯261012`：镜像 1540.06，实时 1495.15，方舟净额 1495.15；`罗馨瑜浅色库存1030`：镜像 1242.27，实时及方舟净额 1249.37。属于来源同步差异，未刷新生产镜像 |
| 运费/包装分项不同 | 12 | 产品金额基本相同，运费/包装差异解释金额差；不是统一手续费计算错误 |
| 产品或多个分项不同 | 12 | 包含远端零额、商品调整及不同运费；需逐单核实实际业务事实 |
| 费用分类冲突 | 1 | `宋皓月浅色库存 0939`：方舟净额 433.50、手续费 44.17；小满产品 433.50，加名为“运费”的 44.17 后金额 477.67。亮哥已确认 44.17 是运费，应保留，GMV 应为 477.67；方舟将运费记录为手续费的分项错误尚未改生产数据 |
| 远端已有与手续费等额的负附加费 | 4 | `0821`、`0818`、`凯丽比努尔#260806`、`凯丽比努尔#260803` 的实时 `addition_cost_amount` 分别为 -2.25、-6.20、-4.68、-0.60。当前 GMV 已比方舟净额更低，不属于漏扣；原业务依据未核实，未自动加回或继续扣 |

上述分类反映读取时的字段事实，不是对运费或历史折让的财务批准。0939 的运费性质已由亮哥确认；这不自动授权修改生产发票或关联回款。方舟订单金额列按现存字段计算仍会显示 433.50；日期范围包含该单时，修正后的发票顶部 GMV 也会少计 44.17，平均订单金额随之偏低，采购节方舟直读净额路径同样继承误分类。待单独更正费用归类后才能与真实 477.67 一致。其他逐单数据修复需先确认正确分项与修改对象，再取得覆盖具体生产动作的授权。
