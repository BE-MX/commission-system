# 发票明细表 UI 约定修复

## 范围与结果

用户要求修复全项目整理中报告的 17 项发票 UI 检查命中。在独立 `codex/invoice-ui-conventions` 分支修改两张明细表和对应录入体验断言；没有修改计算、保存、权限或后端接口。

| Before | After | Why |
| --- | --- | --- |
| 产品与配件表各 8 个数字/工具列写固定 width | 16 处改为保留原数值的 min-width | 保留最低输入空间，允许表格在可用空间中分配列宽 |
| 价格输入框用额外 deep 选择器撑宽，计数超过既有基线 | 对组件根节点添加类并设置宽度 | 保持输入框满宽，内部覆盖回到原基线 1，无需修改基线数字 |
| 数量、折扣与半成品克重控件默认宽度可超过小单元格 | 同样在控件根节点约束宽度为 100% | 避免数字控件挤出单元格，保留错误类、引用与原事件 |

`max-width` 不是当前 Element Plus 列组件支持的属性，未添加无效参数。原静态固定列配置及 `pinColumns` 保留；现有容器规则继续在手机与窄抽屉中取消 sticky，允许横向滚动。动态匹配列的原行为保持。
