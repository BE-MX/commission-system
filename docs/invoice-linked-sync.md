# 保存并同步关联单据

订单编辑器中，已有小满订单的按钮改为“保存并同步关联单据”；未推送订单沿用首次同步。保存与任务登记在同一事务中完成，前端随后执行任务。重新打开订单时，编辑器顶部显示最新任务：待处理可继续同步，明确失败可重试未完成步骤或保留结果结束，待核对需管理员处理。任务未结束前，保存和保存并同步按钮会停用。

## 处理规则

1. 保存前校验编辑内容哈希（覆盖同秒编辑），生成请求幂等键、修改前后快照、操作者和分步任务。修改后快照从数据库已落盘的金额与明细重读，避免金额小数位格式化导致重新核对误判为新编辑。任务占用订单期间禁止其他编辑、普通同步、回款发送和自动出库认领；已运行或待核对的回款/出库任务会阻止新修改。
2. 小满订单使用原 order_id 更新；方舟订单发票号改变时，同步更新小满订单名称（name），小满原生 order_no 和 order_id 保持不变。保持行映射与删行协议；库存处理沿用既有半成品流程。成功步骤不再重发。租约与运行令牌贯穿鉴权重试前、库存预占前、订单回写和库存收尾。
3. 出库单按订单创建日起查询小满实时列表和详情，显示关联单号、状态、订单行ID、产品和SKU数量差异。分页不完整或数量变化报失败，不推断“不存在”。此查询与回款增量索引相互独立，旧订单可能较慢。唯一关联且仍待出库时，改单号还会以原 outbound_invoice_id 更新小满出库 serial_id；方舟出库镜像刷新或已验证打印快照随之显示新单号，关联验货草稿的单号同步更新。
4. 已登记回款金额、手续费、实到账和凭证不随发票修改。按原有持久增量索引核对小满回款，更新本次任务的有效/待处理/待收/超收摘要。待处理占用超过订单金额与实际已生效超收分开提示。不会创建补收、退款，也不会改写原回款单财务事实。
5. 客户、币种、订单类型禁止通过关联同步更换。回款详细结果仍需回款动作权限和订单归属/receipt:read_all数据范围。

## 当前能力边界

出库单列表另有[手动同步订单资料](outbound-invoice-sync.md)入口。订单推送成功后，发票同步操作者凭 `invoice:sync` 可自动更新该订单唯一关联的待出库单，包括明细增删、数量、价格、产品资料、备注和改单号；系统核对发票归属、原出库 ID、关联订单及状态，发送后回读验证。仓库手动入口仍按仓库权限执行。已有验货草稿和照片时自动更新出库并标记旧照片失效；已提交验货且涉及实物变更时，只有出库更新经小满回读验证后，才在同一事务中自动撤回验货并记审计，随后提示重新拍照提交。出库失败或结果待核对时保持原提交状态，禁止旧资料打印和提交。出库更新成功但待补验时，关联同步显示待处理，不表示旧验货仍有效。已出库、分批、关联不唯一、目标单号被占用或远端结果不确定时停止自动修改并显示处理原因；不新建第二张出库单，也不把订单成功撤销。

| 改动后场景 | 自动处理与操作方式 |
| --- | --- |
| 改数量、删除、增加或更换明细 | 保存并同步后先更新原小满订单，再按最新订单更新唯一待出库单；已有出库明细保留原明细 ID，删行显式删除，新增行由小满生成 ID。 |
| 首次出库任务因缺货等待、修改明细后重同步 | 原任务重新入队，执行端重读新版订单及目标仓库库存；仍缺货则继续等待，库存齐全后自动生成。 |
| 出库任务待执行、执行中或提交前失败且仍可自动重试 | 显示“出库单正在自动生成，请稍后刷新查看。”；失败任务是否可重试以执行端记录的真实上限判断，保存并同步不重置任务或跳过退避。 |
| 出库重试已耗尽，或尚未登记任务 | 提示管理员从订单“取消 / 恢复”选择“恢复漏建 / 未发送出库”，重新核对后处理。缺少可信重试策略记录时提示稍后刷新或管理员核对，不假定仍在生成。 |
| 原出库任务已完成，但实时未查到关联出库单 | 提示人工核对原单，不能自动重建；只有已登记并核实删除的原出库单才进入删除后重建检查。 |
| 出库单已有验货草稿或已提交且有照片 | 待出库单自动更新；已提交验货自动撤回为草稿，旧照片保留并失效。仓库刷新镜像后按新明细补拍、重新提交，打印在此之前受限。 |
| 已有回款，订单金额变化 | 原回款金额、手续费、到账日期和凭证保留；自动重算订单的已收、待收、待处理和超收结果。需要新增收款或退款时走回款流程，超收须核实。 |
| 已出库、分批、多单、非标映射不完整或远端不确定 | 显示独立出库处理结果，按补发/退货、建品、核对远端状态等实际情况处理；不盲目覆盖或重发。 |

小满[出库编辑接口](https://open.xiaoman.cn/api-3478296)未提供已确认的条件更新协议。发送前后读取与状态保护不能消除小满网页同时编辑的竞争；不确定结果只回读，不重复发送。方舟不直接写 `lsordertest` 镜像。方舟和小满回款单号仍保持原编号，按稳定订单 ID 关联；已登记金额、日期和凭证不因订单改名而重写。真实货物和资金变化仍需各自流程登记。

## 改单后的回款处理（2026-10-08）

订单预付款和尾款表示合同结算安排；实际资金按回款单核验。回款仍是草稿时，只有金额为空或仍等于原预付款才跟随新预付款，用户手工填写的独立金额保留，预售不自动跟随。已生成回款的生成意图保持 converted，编辑页显示实际回款当前值，旧意图快照不再阻止后续发票保存。

- **尚未发送或明确失败，且没有小满回款 ID**：订单保存并完成同步后，可在编辑页“修正回款”独立改金额、日期和备注。沿用原回款 ID、版本检查和凭证；自动回款按新金额重新分摊手续费，计算时排除原单，保存后点击“重试同步”。预售定金及批次回款保持原结算规则。
- **已同步小满**：保留已收事实，按新订单金额计算待收或已生效超收。新增实际到账使用“补登记回款”；录入纠错先在小满处理，再由管理员“核实小满变更”回读登记。超收只提示核实退款安排，系统不自动退款。
- **正在发送或结果待核对**：禁止直接改金额和重复发送，使用原核对流程。

“实际回款与待收”单独显示应收、已生效含费金额、待处理金额和待收/超收；待处理登记超额另行提示，不当作实际超收。未保存明细的汇总标为预览，未同步订单仍可查看已保存金额的资金情况，但普通回款写入须等订单同步和关联任务结束。余额因远端删改或未知结果无法核验时停止普通写入，保留原回款及管理员核对入口。权限和订单归属仍独立检查。

回款修正和截图变更各自保存；回款操作期间锁定截图编辑，修正后重新读取截图版本。页面保存订单不包含资金改单；再次同步订单不会生成第二张首笔回款。本次不新增迁移，需前后端一起发布。

## 恢复与权限

已安装客户门户权限协议的数据库，即使 `PORTAL_ENABLED=false`，订单编辑仍使用当前权限和单据锁。编辑已推单订单时，先记录订单与任务版本并结束只读事务，再读取小满回款；取证后重新授权、锁定和核对版本，最终保存复用已验证回款数据，不在全局权限锁内等待远端。查询失败不视为空回款，原提交幂等重放也不要求重新取证。普通保存、关联保存和同步前校验都保留各自权限与订单归属检查。

出现“交易服务繁忙，请先核对原操作结果后再重试”时，表示参与权限事务的数据库行锁等待超时。先查看订单保存版本、原关联任务和小满订单号；已有运行中或待核对任务时继续原任务核对，不能创建新请求来绕过。无任务或推单记录时也不能据此断言页面尚未提交的改动已保存。

- pending：继续同步。failed：仅重试未完成步骤，或保留结果结束任务后编辑新版本。
- running：刷新结果；30分钟租约届满转uncertain，不接管、不盲目重发。
- uncertain：管理员人工核对原单与库存；有半成品pending先通过原库存恢复入口处理。原执行租约未过期不得解除。管理员需填写至少10字核对依据并确认后结束，保留人工记录，**不标记订单同步成功**，不修改原ID。原订单仍为sync_uncertain时还需原订单恢复入口处理。
- manual/done：仅订单步骤已确认成功且内容未变化、仍为最新任务，才能重新核对关联单据；不会重新POST订单。
- 保存需invoice:write+invoice:sync；执行需invoice:sync；人工结束uncertain需invoice:admin；所有接口先检查发票可见范围。

隔离SQLite验证状态机、幂等、旧版本、过期执行令牌、权限、超收和迁移重启；Node验证前端409修正、超时原key恢复、结果刷新和poller锁。真实组件以模拟数据在本地浏览器验证差异展示和重新核对交互。无生产金融POST验收。
