# 保存并同步关联单据

订单编辑器中，已有小满订单的按钮改为“保存并同步关联单据”；未推送订单沿用首次同步。保存与任务登记在同一事务中完成，前端随后执行任务。重新打开订单可恢复查看最新结果。

## 处理规则

1. 保存前校验编辑内容哈希（覆盖同秒编辑），生成请求幂等键、修改前后快照、操作者和分步任务。任务占用订单期间禁止其他编辑、普通同步、回款发送和自动出库认领；已运行或待核对的回款/出库任务会阻止新修改。
2. 小满订单使用原 order_id 更新；方舟订单发票号改变时，同步更新小满订单名称（name），小满原生 order_no 和 order_id 保持不变。保持行映射与删行协议；库存处理沿用既有半成品流程。成功步骤不再重发。租约与运行令牌贯穿鉴权重试前、库存预占前、订单回写和库存收尾。
3. 出库单按订单创建日起查询小满实时列表和详情，显示关联单号、状态、订单行ID、产品和SKU数量差异。分页不完整或数量变化报失败，不推断“不存在”。此查询与回款增量索引相互独立，旧订单可能较慢。唯一关联且仍待出库时，改单号还会以原 outbound_invoice_id 更新小满出库 serial_id；方舟出库镜像刷新或已验证打印快照随之显示新单号，关联验货草稿的单号同步更新。
4. 已登记回款金额、手续费、实到账和凭证不随发票修改。按原有持久增量索引核对小满回款，更新本次任务的有效/待处理/待收/超收摘要。待处理占用超过订单金额与实际已生效超收分开提示。不会创建补收、退款，也不会改写原回款单财务事实。
5. 客户、币种、订单类型禁止通过关联同步更换。回款详细结果仍需回款动作权限和订单归属/receipt:read_all数据范围。

## 当前能力边界

出库单列表另有[手动同步订单资料](outbound-invoice-sync.md)入口。订单推送成功后，出库步骤可自动更新唯一关联的待出库单；改单号时先按目标 serial_id 查询冲突，再以原出库 ID 编辑并回读验证。订单成功而出库不能安全更新时，出库步骤单独显示需要处理；不新建第二张出库单，也不把订单成功撤销。`invoice:sync` 用户只有在产品和备注无需更改时才能执行单号联动；需同步其他出库资料时仍要求 `shipping_inspection:write`。已出库、分批、关联不唯一、验货已提交、已有媒体且需重验、目标单号被占用或远端结果不确定时停止自动修改，留给出库单流程核对。

小满[出库编辑接口](https://open.xiaoman.cn/api-3478296)未提供已确认的条件更新协议。发送前后读取与状态保护不能消除小满网页同时编辑的竞争；不确定结果只回读，不重复发送。方舟不直接写 `lsordertest` 镜像。方舟和小满回款单号仍保持原编号，按稳定订单 ID 关联；已登记金额、日期和凭证不因订单改名而重写。真实货物和资金变化仍需各自流程登记。

## 恢复与权限

- pending：继续同步。failed：仅重试未完成步骤，或保留结果结束任务后编辑新版本。
- running：刷新结果；30分钟租约届满转uncertain，不接管、不盲目重发。
- uncertain：管理员人工核对原单与库存；有半成品pending先通过原库存恢复入口处理。原执行租约未过期不得解除。管理员需填写至少10字核对依据并确认后结束，保留人工记录，**不标记订单同步成功**，不修改原ID。原订单仍为sync_uncertain时还需原订单恢复入口处理。
- manual/done：仅订单步骤已确认成功且内容未变化、仍为最新任务，才能重新核对关联单据；不会重新POST订单。
- 保存需invoice:write+invoice:sync；执行需invoice:sync；人工结束uncertain需invoice:admin；所有接口先检查发票可见范围。

## 发布与验证

需统一deploy/deploy.bat执行158_invoice_linked_sync迁移，并同时发布后端、前端、Singapore出库poller的新订单锁检查。旧poller不理解关联锁，不能与新功能混跑；发布应先暂停poller，迁移及全部实例更新后再恢复。此次开发未发布或写生产数据。

隔离SQLite验证状态机、幂等、旧版本、过期执行令牌、权限、超收和迁移重启；Node验证前端409修正、超时原key恢复、结果刷新和poller锁。真实组件以模拟数据在本地浏览器验证差异展示和重新核对交互。无生产金融POST验收。

取消、持久推送保护、回款删改登记及出库异常恢复详见 [单据生命周期](invoice-lifecycle.md)。
