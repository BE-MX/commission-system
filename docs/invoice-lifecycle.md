# 方舟与 OKKI 单据生命周期

## 修改与冻结

订单发票通过原 order_id 更新；保存前检查关联任务、出库删除意图和回款发送状态。准备阶段即标记未同步，轮询器只认领 synced 且未取消的订单。每次订单 POST 前持久保存执行令牌和五分钟租约，鉴权重试也校验令牌；超时或进程中断保留 sync_uncertain，禁止盲目重发。半成品预占不因结果未知而释放。

已绑定订单的更新结果不确定时，管理员在订单列表选择“核实原订单更新结果”。系统核对原单客户、币种、产品明细与金额，完整匹配后回写行 ID 和受理证据。若存在半成品预占，先按原库存入口完成恢复，再结束过期的关联任务并重新同步其他资料。远端内容不一致时保持冻结，须在小满核实处理后再核对，不能用新订单替换原 ID。

首次推送超时但小满已建单时，管理员选择“绑定已生成订单”，填写小满订单号 `order_no`。后端在订单镜像中精确查找唯一订单，再核对客户、订单名称及其他发票是否已占用；零条或多条匹配均拒绝。绑定后保存内部订单 ID 与订单号并记录核对依据，订单仍待重新同步，绑定本身不创建出库单。

出库按订单行 ID、产品及 SKU 核对数量，避免相同 SKU 的多行合计掩盖错关联；真实发货、退货及补发由业务处理。价格、地址和备注经人工核对后，可点击“确认出库资料已核对”，系统会再次验证明细与版本。小满接口未提供已验证的服务端并发保护，因此不自动改写已有关联出库单。

## 取消和删除

未同步草稿仍用原删除入口，需独立的 `invoice:delete` 权限。已绑定小满的普通库存/生产订单，可在订单发票列表点击“删除”（取消处理中显示“继续删除”）。系统先只读核对完整关联范围，再用一个确认弹窗展示出库、回款数量及回款金额，无需逐单跳转或填写原因。

确认后自动冻结订单，依次删除对应待出库单、小满回款和小满订单；小满删除结果须回读确认，方舟回款标记远端删除已核实，尚未发送的本地回款作废。原发票、金额、手续费分摊、关联 ID、回款凭证、验货资料和审计记录保留，订单最终取消归档。删除单据不会执行资金退款或库存冲销。

入口要求 `invoice:delete` 和订单可见范围；有关联出库时另要求 `shipping_inspection:delete` 及出库数据范围，有有效远端或本地回款时另要求 `receipt:delete` 及回款数据范围。所有权限和可删除条件在发送任何删除请求前核验。已出库、共享多个订单的出库、预售/批次结算、半成品库存预占、执行中或结果待核对的业务同步均阻止自动删除。确认版本覆盖订单、完整关联范围及回款金额，变化后须重新确认；发送前再次核验单据归属和内容。

角色管理中，`invoice:delete` 显示为“订单发票 → 删除”，名称为“删除订单发票及关联单据”。普通编辑权和管理权不再包含删除；新权限不从 `invoice:write` / `invoice:admin` 自动继承，也不由启动 seed 自动补给 admin 角色，需明确分配（super_admin 按现有规则绕过）。后端启动通过 upsert 登记权限，不新增数据库迁移；前后端一起发布后，分配角色权限并重新登录取得新 token。

`receipt:delete` 显示为“回款单 → 删除”，名称为“删除订单关联回款单”，只授权上述整单删除流程中的关联回款处理，不新增独立回款删除入口，也不授予回款异常核对管理能力。`receipt:read` / `receipt:write` / `receipt:admin` 均不替代删除权；启动 seed 只登记，不自动分配给普通 admin 或已有回款角色，已人工分配的权限保留。发布并重启后端后，在角色管理明确勾选新权限；若页面仍缓存旧权限目录，刷新页面后再配置。业务员重新登录取得当前权限；订单及回款归属检查保持不变。

每一步先保存删除意图再请求小满。部分完成后从列表的“继续删除”入口核对并接续；结果未知的回款/订单请求只回读原 ID，不重发。出库沿用已有持久删除审计和有效列表核验。进程中断后等待原执行租约到期才能接续。自动删除处理中不能通过旧取消入口撤回或解冻订单。流程状态保存在现有 `ark_invoices.cancellation.deletion`，不新增表和迁移。

小满回款软删除后，详情接口仍可能返回原单；`collect_status` 或 `enable_flag` 不能作为删除证据。详情仍可读时，按其更新时间查询同秒完整窗口，连续两轮 `removed=0` 有效列表和 `removed=1` 删除列表必须一致，且原 ID 只存在于删除列表；原订单、币种与更新时间须匹配，核验后再次回读详情排除查询期间变化。窗口超过100条、缺字段、重复ID、列表变化、原单关联变化或读取失败都阻断核验。明确 Not Found 仍需完整有效回款索引证明原 ID 不存在。此前结果未知的删除步骤在确认后仅完成核验并接续，不重发删除请求；金额、费用和凭证保留。

仅需停止业务而保留原小满单据时，仍使用“更多 → 取消 / 恢复”，需要 invoice:admin 和订单可见范围。该入口保留以下人工取消流程：

1. 发起取消：填写至少十字原因并校验编辑版本，状态变为 cancel_pending，冻结修改、推送、新回款发送和自动出库。
2. 核对关联单据：读取小满原单、出库、回款，以及方舟待发送回款和库存预占/出库事实。存在关联事项时阻止自动删除。
3. 无阻碍时尝试删除小满订单（另需 `invoice:delete`）：先登记删除意图，再发一次删除请求，并回读原 ID。只有可靠的不存在证据才归档为“远端已删除”；权限、审批、确认状态及接口错误不能当作已删除。
4. 删除结果不确定：只核对原请求，不自动重发；执行租约结束后可核实结果，或填写货款库存安排选择“保留原单并取消业务”。已有货物和资金记录、原 ID、凭证及日志全部保留，不自动退款或冲销库存。
5. 尚未发起远端删除时，可以撤回取消申请，恢复原业务状态；已发送删除不能简单撤回。

取消是一项业务状态，不表示完成退款、退货或库存结算。有实际货款的订单推荐保留原单取消业务，以免破坏追溯关系。方舟不自动逐张删除下游单据来绕过小满限制。

## 回款与出库异常恢复

订单明细修改后的回款处理详见[改单后的回款处理](invoice-linked-sync.md#改单后的回款处理2026-10-08)。订单编辑页可修正尚未发送/明确失败且无远端 ID 的普通回款；保存后明确重试。已同步金额保留，补收另登记，远端录入纠错按以下核对流程处理；生成意图不重新变成草稿。

- 回款详情“核实远端删改”：receipt:admin 加原回款归属权限，预览与提交均回读远端，并校验本地版本和证据哈希。远端净额/日期变化可登记回本地（保留本地分摊费用，含费金额=远端净额+本地费用；小满手续费非零时先阻断核对）；原回款确已删除时标记 remote_deleted 并释放登记额度。保留原 ID、附件和变更前日志；此操作不执行退款。未核实的远端缺失先冻结额度计算，避免重复收款。
- 漏建或非标建品后的出库任务：订单已同步且产品映射完整、实时确认没有关联出库单后，管理员显式恢复。只允许 missing、failed 或原“通用产品合并跳过”任务；done、uncertain、已删除的任务不能整单重建。
- 出库删除结果不确定：原租约到期后，管理员在出库页核对恢复。原单已消失则完成回执；仍存在则保留原单并终止原删除请求，自动重建继续暂停。原请求不再重发。
- 自动出库意图 `outbound_auto_requested` 在首次订单发送前随执行令牌持久保存；启用自动出库时，人工绑定首次待核对订单也补登记意图。首次完整同步成功后按意图幂等入队，覆盖超时绑定后更新、首推缺行后补齐；绑定后尚未同步、同步失败或半成品收尾回滚时不创建可执行任务。预售不进入整单出库，已有任务不重复创建，只有原等待库存任务按既有规则唤醒。
- 漏建对账取消 24 小时截止，按明确登记意图、当前完整同步成功及成功 create/update 日志补队，不再只认成功 create 日志。历史未登记行默认 0，不批量追建旧订单；已有或结果不确定的任务仍保持原状态，执行端保留实时关联查重、库存与提交意图保护。

### 小满出库删除同步（2026-09-21）

小满删除后的详情接口可能继续返回旧单和 `status=1`。删除核验以[有效出库单列表](https://open.xiaoman.cn/api-3484729)（`removed=0`，不限制待出库/已出库状态）为准。接口 `time_type=2` 按不可变创建时间查询；系统把候选创建日固定为 `00:00:00` 至 `23:59:59`，连续两轮完整分页的 ID 集合一致且不含原 ID，才登记删除回执。保留明确 Not Found 的直接核验；权限错误、超时、无效创建时间、缺页、重复 ID、数量或成员变化均不能证明删除。

方舟发起删除时同步核验；配置小满凭据的单活 Scheduler 每15分钟运行 `okki_outbound_delete_reconcile`。任务按创建日增量持久化有效单快照，每轮最多刷新8日、全局补查16张缺少镜像关联的详情，快照专用详情读取最多等待15秒；详情游标逐张提交，超时或达到预算后下轮续跑，不重复扫描数千张详情。每张有效单同时保存列表行版本和已解析订单关联，版本变化时只重新补查该张。未覆盖/失败日期优先轮转；当天在详情补查后再次双扫确认，只用于保护新建替代单且绝不作为当天候选的删除证据。最早候选日至今全部日期都已完成两轮一致快照和关联补查前不登记删除；完成覆盖后也只处理本轮刚刷新的历史日期。快照失败只记录该日错误并延后，不使用旧或部分结果证明删除。任务与自动建单开关独立；任务执行中、关联同步中或核对期间有新变化则延后处理；同一订单仍有有效出库关联时保留其任务。

删除回执只写方舟审计表并隐藏列表/打印入口，不写业务镜像、不清理验货记录或照片、不重新发删除请求，也不自动重建出库单。后台操作以“系统同步”记录，不冒充原操作人。迁移 `163_okki_presence_days` 新增创建日快照表；开发测试采用隔离 SQLite 和模拟 HTTP，生产由统一发布入口迁移。

## 发布边界

迁移 161_invoice_lifecycle 增加 ark_invoices.sync_attempt、cancellation、outbound_auto_requested，可重复执行且不修改历史单据；禁止降级丢弃审计数据。通过 deploy/deploy.bat 统一迁移并发布前后端，再更新 Singapore poller。升级期间先暂停 poller，所有实例理解新冻结状态后恢复；仅更新前端或后端不足以形成完整保护。

开发验证仅使用隔离 SQLite、模拟 OKKI 响应和本地前端构建。尚未执行生产迁移、真实删单、退款或出库操作；MySQL 实锁竞争及真实接口验收应在受控环境进行。
