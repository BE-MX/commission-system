# 方舟与 OKKI 单据生命周期

## 修改与冻结

订单发票通过原 order_id 更新；保存前检查关联任务、出库删除意图和回款发送状态。准备阶段即标记未同步，轮询器只认领 synced 且未取消的订单。每次订单 POST 前持久保存执行令牌和五分钟租约，鉴权重试也校验令牌；超时或进程中断保留 sync_uncertain，禁止盲目重发。半成品预占不因结果未知而释放。

已绑定订单的更新结果不确定时，管理员在订单列表选择“核实原订单更新结果”。系统核对原单客户、币种、产品明细与金额，完整匹配后回写行 ID 和受理证据。若存在半成品预占，先按原库存入口完成恢复，再结束过期的关联任务并重新同步其他资料。远端内容不一致时保持冻结，须在小满核实处理后再核对，不能用新订单替换原 ID。

出库按订单行 ID、产品及 SKU 核对数量，避免相同 SKU 的多行合计掩盖错关联；真实发货、退货及补发由业务处理。价格、地址和备注经人工核对后，可点击“确认出库资料已核对”，系统会再次验证明细与版本。小满接口未提供已验证的服务端并发保护，因此不自动改写已有关联出库单。

## 取消和删除

未同步草稿仍用原删除入口；已绑定小满的发票使用“取消 / 恢复”，需要 invoice:admin 和订单可见范围。

1. 发起取消：填写至少十字原因并校验编辑版本，状态变为 cancel_pending，冻结修改、推送、新回款发送和自动出库。
2. 核对关联单据：读取小满原单、出库、回款，以及方舟待发送回款和库存预占/出库事实。存在关联事项时阻止自动删除。
3. 无阻碍时尝试删除小满订单：先登记删除意图，再发一次删除请求，并回读原 ID。只有可靠的不存在证据才归档为“远端已删除”；权限、审批、确认状态及接口错误不能当作已删除。
4. 删除结果不确定：只核对原请求，不自动重发；执行租约结束后可核实结果，或填写货款库存安排选择“保留原单并取消业务”。已有货物和资金记录、原 ID、凭证及日志全部保留，不自动退款或冲销库存。
5. 尚未发起远端删除时，可以撤回取消申请，恢复原业务状态；已发送删除不能简单撤回。

取消是一项业务状态，不表示完成退款、退货或库存结算。有实际货款的订单推荐保留原单取消业务，以免破坏追溯关系。方舟不自动逐张删除下游单据来绕过小满限制。

## 回款与出库异常恢复

- 回款详情“核实远端删改”：receipt:admin 加原回款归属权限，预览与提交均回读远端，并校验本地版本和证据哈希。远端金额/手续费/日期变化可登记回本地；原回款确已删除时标记 remote_deleted 并释放登记额度。保留原 ID、附件和变更前日志；此操作不执行退款。未核实的远端缺失先冻结额度计算，避免重复收款。
- 漏建或非标建品后的出库任务：订单已同步且产品映射完整、实时确认没有关联出库单后，管理员显式恢复。只允许 missing、failed 或原“通用产品合并跳过”任务；done、uncertain、已删除的任务不能整单重建。
- 出库删除结果不确定：原租约到期后，管理员在出库页核对恢复。原单已消失则完成回执；仍存在则保留原单并终止原删除请求，自动重建继续暂停。原请求不再重发。
- 漏建对账取消 24 小时截止，按 outbound_auto_requested 明确登记补队；历史行默认 0，不批量追建旧订单。该设置在首次小满受理时持久保存。

## 发布边界

迁移 160_invoice_lifecycle 增加 ark_invoices.sync_attempt、cancellation、outbound_auto_requested，可重复执行且不修改历史单据；禁止降级丢弃审计数据。通过 deploy/deploy.bat 统一迁移并发布前后端，再更新 Singapore poller。升级期间先暂停 poller，所有实例理解新冻结状态后恢复；仅更新前端或后端不足以形成完整保护。

开发验证仅使用隔离 SQLite、模拟 OKKI 响应和本地前端构建。尚未执行生产迁移、真实删单、退款或出库操作；MySQL 实锁竞争及真实接口验收应在受控环境进行。
