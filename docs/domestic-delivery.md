# 内贸分批交付与收款对账

订单继续记录订购数量和成交价格；发货批次记录实际交付的具体件；收款申请与核销记录实际货款及其对应批次。订单生效时仍沿用原账户记账，登记发货不再次扣款。

## 使用

从「订单管理 → 发货与收款」选择客户，或从「客户管理 → 交付对账」进入。

「创建发货批次」跨本人创建的业务订单列出可发明细。一行一条订单明细，显示顾客名称、系统/客户订单号、产品、下单/完工/已发/可发数量、成交单价；支持顾客、订单、产品搜索，搜索与翻页保留选择。桌面紧凑行高约 33px，底部件数与金额汇总固定可见。可输入部分数量；默认按可发件号顺序分配，也可指定实际件号。

选择产品后可修改「本批单价」，默认使用旁边显示的「订单单价」，允许零价及最多两位小数的非负金额。本次金额、批次合计及收款核销上限使用本批单价；调整数量、指定件号、搜索和翻页会保留调价，取消选择后重选则恢复订单单价。保存后的批次展开明细及 CSV 显示本批单价。同一订单明细的后续批次仍默认使用订单单价，不继承前批调价。

可发件必须有效、最后一道工序有未撤销的实际报工、尚未发货。人工跳过不能代替末道实际报工。尚未整行完工也可发其中已完工的件；所有件发出才将原明细置为已发货。原单条发货入口也生成批次，历史原已发货记录不猜配新批次。

「发货批次」支持展开产品/顾客/件号、导出 CSV 清单、登记收货日期。收货确认保留登记人与时间，禁止覆盖历史日期。批次保存交付时价格、产品属性和顾客名称快照。

先下单后付款客户可登记货款收款：金额、实际收款日期、凭证及批次核销分配。复用原资金审核页面；待审核、驳回、撤回均不入账，也不计入已核销。货款收款不改变会员或最近充值记录。

可一批多次收款、一款跨批核销，也可先入账后分配。已入账款的后续核销使用「累计目标金额」；增加部分另存核销增量证据，重试相同目标不重复核销、不再次入账。撤回收款申请后从交付对账重新登记，原申请保留。

## 金额与数据保护

- 未发货订单金额：有效正式订单尚未交付部分，按原订单单价乘剩余数量计算，不受批次调价影响。
- 在途未结：未确认收货批次金额减已审核核销。
- 已收货未结：已确认收货批次金额减已审核核销。
- 待核销收款：已审核货款尚未分配部分。
- 原账户净额包含未发货订购款，不能视为当前交付应付款。历史已发货但未形成批次的记录单独提示，不编造收货或收款事实。

批次调价只影响该批次及其收款，不修改原订单明细单价、订单总额或原账户扣款，不另记调价账本。实际货款审核通过后仍按原收款流程入账；原账户净额与批次应收因调价可能存在差额，二者口径不同。

部分发货后冻结该明细编辑和删除，阻止撤销涉及已发件的报工/放行；订单终止按原订单单价保留已交付数量对应的扣款，仅退未交付金额，发货记录继续保留。发货批次不支持删除、撤销或保存后改价，误发纠正须另行设计有审计的冲销流程。

订单写权限继续按创建人判断；客户归属销售及客户管理员可完成客户对账和资金操作。原订单创建人若不再拥有客户，只能查看本人订单交付。read_all 仅扩大读取范围，不扩大订单发货权限。

## 结构与上线

迁移 `186_domestic_delivery` 接 `185_announcement_push_option`，新增批次、批次明细、逐件交付、收款核销四表，资金申请增加实际收款日期、内容指纹并扩展 receipt 类型。核销的 ledger_id 标识已入账证据；业务键保护增量重放。无历史自动回填，downgrade 拒绝删除业务证据。

正式上线必须通过项目统一部署入口执行一次迁移；开发机不升级共享/生产库。历史欠款和收款需业务员核对期初，不自动分摊。

开发验收使用隔离 SQLite 和 headless Edge，不证明共享 MySQL 的真实并发压力或生产迁移已完成。实现验证记录见 [验收报告](reports/2026-10-12-domestic-delivery.md)。


## 明细数量终止与整单完成

订单详情的“终止明细”弹窗选择终止数量并填写原因，最多可选当前未发货数量。业务订单按原成交价退回所选数量的已扣款；其他产品及剩余数量继续履约。已发货件不会被取消；已有工时仍保留。终止记录显示在对应产品下，已终止二维码不再复用。

有“内贸订单异常跳过”权限时，可在订单详情点“一键跳过全部工序”，填写原因后一次跳过所有剩余工序。未配置路线的有效明细会阻断整次操作，先配路线再执行；已终止、已发货件保留原状态。跳过只影响工序通行和完成判定，不生成报工、工资或发货记录。

所有有效产品已完工（真实末道报工或有效逐道跳过）后，订单显示“已完成”；已发货与已完成产品混合也视为已完成，全部真实发货时保留“已发货”。撤销跳过会重新计算状态，必要时回到生产中。实际发货仍只接受有有效末道报工的单件。
