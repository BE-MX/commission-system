# WhatsApp 话术助手（1.3.0）

在翻译旁点击「话术」，使用当前一对一聊天已加载的最近 20 条可识别文本；可选择 40 条后显式重新生成。不滚动、不读完整历史、不调用 WhatsApp 私有接口。客户和业务员文本都包含；已经展示译文的消息仍取原文，生成内容、引用副本、系统通知不进入上下文。媒体与未知结构跳过并显示缺口。12,000 字符上限按消息边界保留最新文本；最新单条超限则阻断。

面板显示实际条数、已加载文本范围、截断/媒体/未知结构缺口。DOM 无法证明包含服务器最新消息，因此明确显示最新性未知，`latest_visible=false`。本地遮蔽邮箱及可识别电话号码，保留常见尺寸、长度和密度。默认可选草稿仅作为意图；可关闭，最多 2,000 字符。本次目标最多 500 字符。语言优先级由服务端执行：显式选择、多个有意义客户消息、当前聊天语言回退。

首次展示数据去向说明，用户点击生成后只持久化 `replyDisclosureAcknowledged` 布尔值。话术上下文、草稿、请求/会话 UUID、结果、来源不持久化。设备凭据仅后台读取。后台先查询 capability；缺少 `reply.available` 时仅话术失败关闭，不发出携带文本的建议请求。

打开面板及显式生成时，先读取并校验最新 capability，再采集 DOM。字符、消息、草稿和目标上限均取服务端限制与本地硬上限中较小者；默认消息数跟随服务端配置。协议 `requested_limit` 仍为 20/40 的上限档位，实际采集数受服务端默认值和最大值进一步约束，面板展示真实条数及当前上限。服务端将字符限制下调为 6,000 时，仅保留该范围内最新完整消息并显示截断；最新单条超限则停止。缺失、非整数或不合法的能力字段在采集前失败关闭。后台发 POST 前重新查询并校验全部限制，防止配置下调与内容采集之间的竞态；capability 查询使用 `no-store`。

`POST /api/whatsapp-translation/reply-suggestions` 使用统一信封、`cache: no-store`、35 秒超时，无自动重试。运行时请求使用 `reply/suggest {payload}`，仅接受本扩展的 WhatsApp 页面来源；返回对象与请求 UUID、随机会话 epoch、上下文版本、草稿版本逐项校验。模型输出仅以 `textContent` 展示。

每次生成冻结版本、语言和上下文。新消息、切换聊天、任何草稿编辑（包含改回原文）、选项修改、自动识别语言变化、取消或关闭都使未完成请求和结果失效。翻译与话术分别维护忙状态；所有编辑器写入复用 adapter 同一把写锁和写前重检。只有预览后的 `ready` 结果可将 `reply_text` 填入，不自动发送；恢复要求草稿仍未经后续编辑。恢复等待浏览器帧期间发生关闭、取消或上下文/语言变化，也必须取消待写操作；用户随后可以在草稿仍未编辑时显式重试恢复。话术原文保留有意义的换行和段落，现有翻译的单行规范化不变。

## 验证入口

- `npm ci` 安装锁定依赖。
- `npm test` 包含上下文采集、双方方向/译文原文、引用/媒体/未知结构、20/40/字符边界、版本失效、恢复保护、共享写锁、旧 capability、来源校验、错误脱敏及 35 秒无重试验证。
- `npm run test:browser` 在真实 Chromium 的隔离世界运行合成页面、实际 Lexical 编辑器及内容脚本；网络全部拦截。覆盖预览填入恢复、真实输入后撤销、到达新消息、保留翻译功能及既有输入框回归。
- `npm run package` 执行类型检查、生产构建、完整单测与确定性 ZIP 打包；生成目录不提交。

这些验证没有调用真实模型、生产服务，也没有读取真实客户聊天。真实 WhatsApp DOM 与模型策略效果仍需部署获授权后另行验证；不能把合成响应当作模型效果验证。
