# WhatsApp 话术助手（1.6.5）

话术助手分为手动话术与自动接管两条链路，共用同一份 capability 校验、PII 遮蔽和请求/响应校验。所有网络请求经 background 转发，运行时消息仅接受本扩展的 WhatsApp 页面来源；模型输出一律以 `textContent` 展示。

## 手动话术

- 触发：输入框上方工具栏的「话术」按钮打开面板；「生成话术」产出建议，结果下方的「短一点」「柔和一点」「换个策略」按钮以不同风格重新生成。
- 历史档位：「加载历史并生成」（向上滚动累计加载，可取消）、「仅当前已加载消息」、「最近 20 条」、「最近 40 条」。单次请求上限 2,000 条消息 / 120,000 字符（本地硬顶与服务端 capability 取小者，逐次生成前重新校验）。
- PII 遮蔽：发送前在本地遮蔽邮箱和可识别电话号码，保留尺寸、长度、密度等业务数值；草稿意图与本次目标同样遮蔽后才会发出。
- 只填不发送：仅 `ready` 状态的结果可以「填入输入框」，且可随时「恢复原草稿」；扩展从不替用户点击发送。填入、恢复与生成共用 adapter 同一把写锁和写前重检，新消息、草稿编辑、选项修改都会使未完成结果失效。

## 自动接管

- 开启前置条件：已确认数据去向说明、页面处于前台、当前为一对一（direct）聊天、`navigator.locks` 取得 `leshine-whatsapp-auto-takeover` 单窗口锁（另一窗口已在接管则拒绝开启）。
- 轮询与静默：开启后每 1 秒检查一次页面；客户新消息到达后重新计时 3 秒静默期，静默期满才生成。
- 上下文：每次生成采集完整历史（受 capability `max_messages` / `max_context_chars` 约束，本地硬顶 2,000 条 / 120,000 字符），历史超容量、未确认最新可见、存在无法识别发送方的消息、最新消息为媒体或未知结构时直接停止接管。
- `auto_action` 语义：`reply` 按分段发送；`wait` 本轮不回复，继续等待；`handoff` 停止接管，完整回复保留在工具栏折叠区并附中文理由。
- 分段与拟人化延迟：回复分 1–3 段，每段不超过 400 字符（响应校验强制）。首段前等待「阅读延迟」：1,200ms + 客户最后一条消息长度 × 20ms/字符，封顶 4,000ms；后续每段前等待「打字延迟」：800ms + 该段字符数 ×（40–80ms 随机系数）×（0.9–1.1 抖动），封顶 8,000ms。
- 发送双确认：点击发送后必须同时观察到新的卖方气泡且输入框已清空，才记为已提交；结果不确定时绝不重试，立即停止并提示人工核对聊天记录。段间到达新客户消息、输入框或聊天尾部变化时丢弃剩余未发段。
- 即停条件：检测到人工输入或人工点击发送、输入框存在草稿、切换聊天或标题变化、聊天记录整体替换、页面切到后台、修改发送语言或生成要求、切换到手动话术或人工翻译、业务员接管（暂停话术）、后端未启用 `auto_reply_enabled`、发送控件不可用或发送结果未确认、命中名单限制（见下）。

## 询盘记忆

- 手动链路：`create`（生成时自动建立或在面板显式新建）、`commit`（保存本次复盘）、`correct`（人工修正条目状态）、`delete`（删除记录）；另支持 `list`/`read` 预览并恢复已有记录。
- 聊天绑定：chat → inquiry 绑定以聊天标题的加盐 SHA-256 哈希为键（salt 仅存于 background，标题不离开页面），`chatInquiries` 上限 200 条，超出按 FIFO 淘汰。
- 自动接管只读接入：开启时读取绑定的询盘并在请求中附带 `memory_conversation_id` / `memory_revision`；自动链路不 create、不 commit。返回 `reply_memory_conflict` 时自动刷新 revision 供下一轮重接；记录不存在或已停用时解除绑定并继续无记忆运行。

## 安全边界

- 名单与时段限制（`reply/auto-policy/*`，仅当前设备生效）：禁止名单与仅白名单各按聊天哈希保存、上限 500 条 FIFO；「仅白名单自动接管」开启后非白名单聊天拒绝开启；时段为本地时区 HH:MM 起止加周日至周六勾选，非法输入返回 `reply_invalid_request`。被禁聊天开启接管会被拒绝，接管进行中被加入禁止名单会立即停止并提示；不在时段内时不生成不发送，状态提示「不在自动接管时段内」，接管保持开启。面板入口在话术面板「询盘与接管」页的「自动接管名单与时段」。
- 后端金额护栏：auto 模式下回复包含未经知识来源证实的金额时，后端强制降级为 `handoff`，附加 `price_unverified` 与 `auto_reply_review_required` 风险标记；扩展保留完整回复但不发送。
- 后端 `WHATSAPP_REPLY_AUTO_ENABLED=false` 可独立关闭自动接管：capability 返回 `auto_reply_enabled: false`（扩展开启接管时提示后端尚未支持），且 `mode=auto` 的 suggest 请求直接被后端拒绝（`reply_auto_disabled`）。

## 超时

- `reply-suggestions` 的 HTTP 超时跟随当次 capability 的 `timeout_seconds`（本地钳到 ≤180 秒），拿不到时回退 185 秒；background 在每次 suggest 前以 `no-store` 重新拉取 capability。翻译请求为 45 秒且仅传输错误重试一次，其余请求 20 秒。

## 验证入口

- `npm ci` 安装锁定依赖。
- `npm test` 包含上下文采集、双方方向/译文原文、引用/媒体/未知结构、20/40/字符边界、版本失效、恢复保护、共享写锁、旧 capability、来源校验、错误脱敏、拟人化分段延迟、自动接管名单/时段限制及 capability 驱动的超时验证。
- `npm run test:browser` 在真实 Chromium 的隔离世界运行合成页面、实际 Lexical 编辑器及内容脚本；网络全部拦截。覆盖预览填入恢复、真实输入后撤销、到达新消息、保留翻译功能及既有输入框回归。
- `npm run package` 执行类型检查、生产构建、完整单测与确定性 ZIP 打包；生成目录不提交。

这些验证没有调用真实模型、生产服务，也没有读取真实客户聊天。真实 WhatsApp DOM 与模型策略效果仍需部署获授权后另行验证；不能把合成响应当作模型效果验证。
