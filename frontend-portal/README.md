## Integration contract

- `src/api/client.mjs` owns same-origin `/api/portal/v1` fetches. Never inject the
  employee Axios client, Authorization header, or localStorage login marker.
- Instantiate one client per browser app and pass a `BroadcastChannel` dedicated
  to `leshine-portal-session`. A received invalidation clears local state without
  broadcasting again. Provide a storage-event equivalent where unavailable.
  Only `{type: 'portal-session-changed'}` is sent, never identity, CSRF or data.
- Call `restore()` and wait for a verified `session.me` before loading private
  pages. Restore/bootstrap/logout immediately invalidate old request scopes.
  Subscribe to changes and clear cart, quote, orders, object URLs and page state
  on every event other than `authenticated`. Do not retain customer payloads in
  a shared application cache. Compare `scopeVersion` in view-level async work.
- Login is bootstrap → challenge → verify. Invitation activation passes
  `invitationToken` to challenge; UI must remove it from the URL immediately,
  avoid referrers/analytics, and never persist it. Invalid OTP does not discard
  preauth CSRF. Authentication operations are serialized within the client.
- HTTP 401 on a session request clears identity even with a non-JSON body and
  returns `SESSION_EXPIRED`. Ordinary 403 remains an action error. Server error
  messages/issues are text, never HTML. Show trace IDs for support where present.
- Logout clears private state before network completion. If it fails, show that
  server sign-out is unconfirmed and offer manual retry. The client retains only
  the original logout CSRF in memory until success or another identity boundary;
  it does not silently restore the session. Do not show a success message on a
  rejected logout promise. Cross-tab signals cannot recall already-sent bytes.
- API writes are never automatically retried. `uncertain` indicates the server
  may have committed; aborting a browser request cannot roll back the server.
  `STALE_SCOPE` discards the response and retains uncertainty for dispatched writes.
- `src/state/submission.mjs` freezes checkout body and UUID once. Wire
  `state.status` to submit/checking/confirmed/uncertain/failed UI. A lost response
  triggers GET by the original key. A 404 can race a commit and remains uncertain.
  Manual retry uses the exact original key/body. Never create a fresh checkout
  while an earlier result is unknown.
- Pass `sessionStorage` to the submission controller. It persists only the key
  under an account-specific entry, not address/PO/notes/quote or credentials.
  After verified restore, call `restorePending()` then offer `recover()`.
  A restored key cannot reconstruct/retry a POST; it supports read recovery only.
  If storage is unavailable, `refreshRecovery=false` must be shown to the user
  before they leave the in-progress checkout. An unresolved recovered result
  needs a support/history resolution flow before starting a different order.
- PI downloads return a checked Blob only after the scope remains current.
  UI must revoke generated object URLs on scope change/unmount. Do not persist
  attachments in browser caches. Changed/withdrawn PI errors must refresh detail.
- Record versions accept safe integers or decimal strings. Never round a BIGINT
  version before sending quoted `If-Match`.

The backend requires a trusted same-origin proxy to overwrite `X-Real-IP` and
preserve the original TCP peer. The browser never sets that header. A future Vite
proxy must be explicitly local/test-only; no connection to production is implied.

## Same-tab customer action recovery (v1.62)

`actionRecovery.mjs` stores an exact account-scoped query locator before dispatch,
using WebCrypto SHA-256 matching actual Python `ReasonInput`/`content_hash` vectors.
Normalize reason before freezing both the POST and hash: trim leading/trailing
JS whitespace plus NEL, preserve interior content, refuse lone surrogates.
While hashing, an identity change or inserted pending reference stops before POST.
The stored schema permits only public object/revision IDs, action, exact version,
payload digest, proposal digest and PI bound document version. Never persist reason,
customer names, addresses, PO, price or credentials.

Reload restores uncertain/canRetry=false; the visible receipt check calls only
GET `/orders/{request_id}/action-receipt`. Require exact command locator and the
existing action-specific original receipt invariants. A missing result can show
current order status but never proves absence, success or permission for a new
command. POST retry requires the original in-memory body. Remove only the same
account's exact original raw marker. Corrupt/read-denied records block new actions,
preserve the authenticated UI and show a fixed safe message. Write/readback failures
are explicitly memory-only, with no durable-recovery claim.

Run `tests/decisionRecovery.browser.mjs` with the existing loopback preview setup;
it uses synthetic intercepted API and does not contact customers/providers. The
current 130 Node tests, 34-module build and browser scenarios are local evidence,
separate from real isolated MySQL HTTP verification. Closed-tab or cleared-storage
recovery and full production integration remain open.
